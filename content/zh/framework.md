## 核心问题：概率是否对齐价值

LLM 最终仍然通过概率来生成：在当前上下文下，选择下一个 token、下一步推理、下一段结构或下一次工具调用。训练、基于人类反馈的强化学习（RLHF）、偏好优化和推理时思考会改变这个概率分布，但不会让模型直接拥有当前任务的真实效用函数。

因此，真正的机制问题是：

```text
模型最容易生成的方向，是否也是任务价值真正上升的方向？
```

如果是，自回归生成可以非常高效；如果不是，模型越流畅，越可能把错误方向包装得更可信。

## 三种对齐区间

:::cards
### LLM 平庸
Tag: 概率峰值偏离价值峰值

系统在预算内能到达的候选答案，集中在流畅、合理、可局部改进，但远离高价值解的区域。继续采样或润色可能提高平均质量，却仍然无法碰到决定性结构。

自回归平庸是其中的聚合失配子情形：局部 token 概率持续给出合理续写，却把全局价值结构稀释掉。

### 局部对齐
Tag: 最常见的实际状态

模型的局部续写倾向与任务价值的一部分对齐。它能压缩、改写、列举、比较、构造提纲，也能生成有用片段。但全局成功还依赖隐藏状态、长程依赖、真实目标或验证机制。

### LLM卓越
Tag: 概率与价值同向

高价值输出不再是低概率尾部事件，而是容易到达的区域。上下文压缩、语义解压、语体迁移、表层润色、结构化转换、查询构造和边界情况枚举，经常属于这一区间。
:::

## 策略-价值压缩

现代对齐模型不能简单理解为“追随词频”。预训练让模型学会语言和世界模式；监督微调、RLHF、直接偏好优化（DPO）、过程监督等方法，会把某些代理价值压缩进模型策略里，让有帮助、符合偏好、看似正确或安全的轨迹变得更高概率。

这就是 **策略-价值压缩（policy-value compression）**：价值没有被模型直接读取，而是被压缩成概率倾向，在推理时表现为更可能出现的 token、步骤和输出轨迹。

它解释了两个现象：

- 为什么模型越来越强：更多有用行为被推到了高概率区域。
- 为什么失配仍然存在：代理价值不等于当前任务的真实价值，尤其在开放、动态、高风险或目标不完整的任务里。

推理时思考也类似。思维链、搜索、反思和工具调用，会创造中间状态，把原始任务拆成更容易局部对齐的子任务。但如果中间表示本身错了，更长的思考也可能只是更长的错误抽象。

因此，这不是悲观判断，而是校准问题。训练和推理时思考扩大了概率与价值局部对齐的区域，但仍需要判断当前表示是否真的包含任务的决定性变量。

## 为什么多 agent 协作不自动克服 LLM 平庸

很多人会直觉地认为：单个模型容易平庸，那就让多个 agent 互相讨论、分工、批判、投票，问题自然会被解决。这个判断只在一种情况下成立：多 agent 真的引入了新的控制空间、外部状态、验证机制或真实差异化策略。否则，它往往只是把同一种生成过程重复了很多次。

如果几个 agent 只是共享相近模型、相近语料先验、相近奖励塑形和相近任务表示，那么它们的协作在机制上更接近于 **多次采样**。即便表面上有“提案者”“批评者”“裁判”“执行者”这样的角色分化，本质上也仍然是在同一概率地形上来回搜索。它可能提高平均质量，减少明显错误，让输出更完整、更稳健，但不自动改变高价值解仍然位于低概率区域这一事实。

多身份 agent 协作也一样。给同一个模型套上“保守派”“激进派”“用户代表”“架构师”之类的身份，确实会拉长采样路径，制造更多局部扰动和相互修正。但如果这些身份没有绑定不同的信息源、不同的状态访问权、不同的控制对象或不同的验证标准，那么所谓多角色讨论，常常只是把一条自回归轨迹延长成多条彼此纠缠的自回归轨迹。路径变长了，不等于已经脱离自回归引力。

关键点在于：**延长采样路径，不等于改变搜索空间；增加角色数量，不等于改变价值函数。** 如果任务的瓶颈来自聚合失配、状态失配、支持失配、规格失配或拟合边界失配，那么更多 agent 往往只是更充分地暴露这些失配，而不是自动修复它们。它们可能把一个平庸答案变得更有说服力，也可能把一组中等答案做得更一致，却仍然触碰不到决定性结构。

因此，多 agent 不是对抗 LLM 平庸的充分条件。只有当 agent 协作真的把任务重写成新的控制问题，例如显式引入外部状态、验证回路、受治理知识对象、差异化工具权限、结构化控制空间或最小人类接入点时，它才不再只是“多次采样”或“更长的采样路径”，而开始成为改变任务形态的治理机制。

## 五类原始失配

五类失配不是为了给所有失败现象命名，而是为了预测普通输出空间搜索什么时候会进入平台期。

:::cards
### Aggregation：聚合失配

局部改进不能稳定组成全局价值。故事、代码架构、战略方案、客户沟通和复杂推理，经常依赖长程协调、延迟回报或耦合约束。自回归平庸正是在这里作为局部概率机制出现。

### Support：支持失配

真正高价值的答案在当前模型、搜索算子和预算下很难到达。它可能是低显著性的证据、非主流框架、少见结构、反直觉方案或罕见边界条件。

### State：状态失配

答案排序依赖隐藏、变化或未说明的状态。用户情绪、市场状态、法律辖区、生产环境、时间窗口和组织权限，都会让同一个答案在不同状态下价值相反。

### Specification：规格失配

系统能优化的代理目标偏离真实目标。答案可能满足提示、评分规约、风格或测试，却没有满足用户真正关心的成功标准。

### Fitting Boundary：拟合边界失配

系统对局部证据链、指标、场景默认值、角色模板或反馈信号绑定过强。答案局部合理，却无法通过相邻语境的扰动。
:::

一个任务很少只包含一种失配。更有用的诊断是建立 **失配画像（mismatch profile）**：哪类失配占主导，哪些是次要失配，以及它们分别指向什么干预。

::::cards
### 聚合主导

把全局结构变成局部可见对象：依赖图、长程约束、承诺-兑现图、系统边界或验证清单。

### 支持主导

把尾部结构拉进上下文：检索低显著性证据、生成反例、扰动假设、搜索少见框架，并显式种下稀缺选项。

### 状态主导

把状态作为一等对象：枚举情境、适用条件、撤销触发器和条件策略。

### 规格主导

把价值函数外化：写出评分规约、验收标准、拒绝样例、利益相关者优先级和证据要求。

### 边界失配主导

用相邻语境测试局部解释：扰动指标、审计协议、假设、角色模板和反馈来源，再决定某个断言能否作为不变量保存。
::::

## 为什么衍生现象不必不断重命名

顺序敏感轨迹、噪声语境建模失败、语料先验主导、涌现式规格、结构-信号缺口和控制容量崩塌都很重要。但它们通常不是新的原始失配，而是五类失配与表示选择、推理预算、控制策略共同作用后的表面形态。

这种分类纪律很重要。每一个诊断都应该指向不同干预：

- 聚合失配：先显式表示全局结构。
- 支持失配：主动把尾部结构拉进上下文。
- 状态失配：枚举状态，输出条件策略。
- 规格失配：外化价值函数，构造评分规约、反例和验收标准。
- 拟合边界失配：扰动相邻场景，标出每个局部断言的适用边界。

同样，这种纪律也避免分类体系膨胀。如果一个新标签不能预测不同的干预，它通常更适合作为衍生现象，而不是新的原始失配。

## 哪些地方自回归是优势

这套框架不是反生成。它要识别的是：生成在哪里已经与价值正向对齐。

::::cards
### 压缩与语义映射

总结、分类体系、概念图和决策矩阵常常有效，因为模型学到的语义结构有助于把许多关系压缩成紧凑形式。

### 语义解压

一旦强结构提纲、评分规约或控制对象已经存在，把它扩写成文本往往是高对齐操作。

### 语体迁移

在含义保持不变的前提下调整语气、受众和格式，通常能发挥模型的流畅能力；但法律、关系和声誉边界仍需要治理。

### 结构化转换

把材料转换成表格、清单、JSON、SOP、查询或边界情况列表，通常比开放式最终答案更容易验证。
::::

## 从理论到方法

这套机制最后导向一个实践原则：不要总让模型直接解高失配的最终输出任务。更好的做法是保留它已经局部对齐的操作，把失配部分转化成更低失配的中间任务，再验证这些中间对象能否组合成真正的全局价值。

从局部对齐走向全局价值，通常有四步：

1. 利用局部对齐：让模型做压缩、提纲扩展、候选列举、查询构造和表层表达。
2. 找到对齐边界：识别流畅不再预测成功的地方，比如隐藏状态、隐含目标、稀缺不变量、非局部依赖或误导性先验。
3. 治理边界：把边界变成状态矩阵、评分规约、约束、反例、失败模式或 GKO。
4. 稳定后再渲染：让模型从受治理的中间对象生成最终文本，再检查这些控制对象是否被保留下来。

这就是从 LLM 平庸走向LLM卓越的核心路径，也是知识治理要形式化的事情。

因此，机制页到治理页的过渡很直接：机制页回答“为什么直接生成会卡住”，治理页回答“怎样把卡住的任务改写成可搜索、可验证、可复用的工程对象”。如果没有这一层，五类失配只是诊断标签；有了治理流程，它们才会变成可执行的干预。

## 对抗自回归引力的四种方法

这组方法的共同核心是：**不要让模型在原始 token 序列里一路滑向常见模式，而要主动制造可搜索、可评价、可回滚的中间层。** 一旦中间层存在，任务就不再只是“继续写下去”，而变成“在控制空间里搜索、验证、淘汰、重组，再把结果还原成输出”。

:::cards
### 高密度采样、拆分、重组，再回到样本验证
Tag: 支持失配 / 突破局部最优

当高价值答案位于低概率尾部时，直接写最终答案很容易被自回归引力拉回常见模式。更有效的做法，是先在自回归条件下进行海量采样，得到一批候选；再挑出局部上最有潜力的样本，拆成片段、结构、策略或关键转折，然后跨样本重组。

这一步的价值，不只是“拼接更好内容”，而是从样本簇里提取平时不容易显式总结的高 sigma 硬经验：少见但有效的结构、隐藏约束、非显然转折、罕见失败模式或高价值表达手法。提取之后，还要回到样本和新生成结果中验证这些经验是否真的稳定提高价值。

它本质上是一种对抗支持失配的方法：先把低概率但高价值的局部结构从尾部打捞出来，再把它们变成新的控制资源。每到一个新的局部最优附近，都可以重复这一循环。

### 先写控制空间，再生成输出
Tag: 把平庸任务改写成卓越任务

像故事、长文、课程设计、复杂方案这类任务，直接生成最终成品时往往容易平庸；但如果把优秀结果需要满足的元素、节奏、约束、风格边界、情绪曲线、角色关系、伏笔回收或验收标准先写出来，模型在这些子任务上反而常常表现卓越。

更具体地说，可以先构造一个控制空间，例如人物弧线、冲突梯度、主题约束、场景节拍、信息揭示顺序、禁用套路和评分规约。然后让模型在这个控制空间下生成故事，再用相对更可靠的评价任务去检查成品：是否失速、是否失真、是否落入俗套、是否违背前设。

如果结果不够好，不要立即重写全文，而是反过来修改控制空间本身。这个循环利用了生成与评价的不对称性：很多任务上，直接生产卓越成品并不稳定，但识别缺陷、指出俗套、检查约束是否违背，往往更容易。于是，一个 LLM 平庸任务就被改写成一串LLM卓越任务。

### 在控制空间搜索，而不是在输出空间硬搜
Tag: 最通用的方法

这是最通用的思路。面对大多数高失配任务，先切断“原始语义 -> 直接输出”的默认路径，构造一个更容易搜索的控制空间：例如状态矩阵、评分规约、候选框架、依赖图、查询计划、失败模式清单、角色配置或决策表。

随后，不是在最终答案里直接反复采样，而是在控制空间里搜索、扰动、扩展、删减和比较，再把候选控制对象还原到输出空间进行验证。验证不过关，就不要只修改最终文本，而要回到控制空间继续搜索。

这种方法的关键不是增加步骤，而是改变搜索地形。原始输出空间里相邻 token 的流畅性，常常不能代表任务价值；控制空间则让我们搜索真正影响价值的变量、结构和约束。

### 用分层控制空间控制搜索复杂度
Tag: 先粗后细，避免控制空间失控

控制空间并不是越大越好。如果把所有变量、风格、约束、分支和例外一次性塞进一个巨大搜索空间，搜索成本可能并不比在输出空间里盲目重复采样更低，甚至更糟。

因此，复杂任务更适合使用分层控制空间：先做粗粒度搜索，决定大方向、主结构和关键约束；再在下一层搜索局部策略、子结构和具体实现；最后才渲染到最终输出。也可以在每一层都设置不同的验证器、回滚点和升级条件。

分层的价值在于把组合爆炸切开。不是试图一次性找到完整答案，而是先锁定高价值区域，再逐层细化。这样既能保留控制空间搜索的优势，又不会把控制层本身变成新的混乱来源。
:::

把这四种方法合起来，可以得到一条更一般的路径：

```text
原始任务
-> 构造控制空间
-> 在控制空间采样 / 搜索 / 重组
-> 投影回输出空间
-> 评价与验证
-> 不合格则回滚到控制空间继续迭代
```

其中，高密度采样与重组更适合把尾部高价值结构从低支持区域里打捞出来；“先写控制空间，再生成输出”更适合把故事、方案、长文等开放任务改写成更高对齐的子任务；控制空间搜索是最通用的操作骨架；分层控制空间则用来抑制搜索复杂度，避免控制层本身重新坠入平庸。
