## 协作不是分工，而是变量治理

关于人机协作的建议，大多从"分任务"讲起。这页想换一个更细的单位。与其问哪一整块任务归 AI、哪一整块归人，不如治理任务内部的一个个 **控制变量**——也就是那些真正决定任务走向的具体事实、权重和授权。

传统说法会问：哪些工作交给 AI，哪些工作交给人？这个问题太粗。更好的单位不是任务，而是 **控制变量**。

AI 应推进可处理、可搜索、可结构化、可模拟、可检索和可验证的部分。人应治理目标函数、偏好权重、授权边界、品味判断、预算分配、身份选择和责任承担。

因此，好的协作不是 AI 一开始就问一堆问题，也不是 AI 不问人直接做到底。好的协作是：

```text
AI：处理 → 搜索 → 结构化 → 模拟 → 验证
Human：设定价值 → 授权 → 判断品味 → 承担责任
System：把可复用判断沉淀为受治理知识对象 / 受治理升级对象，并提交硬状态转移
```

**一句话：AI 负责把问题推进到"只剩人类必须裁决的变量"；人负责裁决那些无法从环境、反馈、工具或模拟中可靠获得的变量；系统负责把已解决变量提交为硬状态，而不是让它只停留在聊天记录里。**

这页承接治理页的最后一步。控制空间和验证循环可以解决大量结构问题，但仍会遇到价值、授权、责任、品味和真实状态这些不能由模型单独决定的变量。协作页讨论的不是"人多参与一点"，而是怎样让人的参与足够小、足够准，并且能恢复 AI 的自治推进。

## 三层诊断栈

治理式协作建立在机制层之上。它不增加新的原始失配，而是回答：自主执行到底卡在哪里。把下面三张卡片从上往下读，正好走完一条思路：失败为什么会发生、此刻缺的是什么、人用多小的动作就能解除阻塞。

::::cards
### 原始失配

为什么普通生成可能偏离价值？主要轴是聚合、支持、状态、规格、拟合边界和观测-表征。

### 操作阻塞

哪个缺失控制变量阻止了可靠继续？它可能是事实、价值权重、权限边界、验证信号、资源或任务表示。

### 升级协议

什么是能恢复自治的最小人类贡献？最小充分人类问题（MSHQ）和受治理升级对象（GEO）就属于这一层。
::::

## 先判断变量从哪里来

这里说的 AI agent，指能够在边界内自主调用工具、执行步骤并推进任务的 AI 系统。不是所有不确定性都应该问人。agent 应该先判断关键变量能否从环境、反馈或构造场景中获得。

:::cards
### 环境可观察
Tag: 先问环境

如果变量存在于文件、日志、数据库、测试、网页、法规、运行时或当前状态中，AI 应该先读取、检索、运行、验证和交叉检查，而不是问人"你觉得事实是什么"。

### 反馈可学习
Tag: 通过对比显化偏好

有些偏好人也无法预先说清。AI 应生成候选版本、风格轴、正反例和成对比较，让人通过选择、排除和排序逐步显化偏好。

### 特殊环境可构造
Tag: 搭建试炼场

现实反馈暂时不可得时，AI 可以模拟竞争者、监管者、低耐心用户、反方、攻击者、失败场景或不同市场状态，让方案先接受压力测试。

### 人类控制变量
Tag: 才需要问人

当缺失变量无法由 AI 观察、推断、验证或合法授权时，才需要问人。问题应该被压缩成事实、权重、边界、授权、验证信号、资源、责任主体或停止标准。
:::

在提问前，agent 应先尝试有边界的自治恢复：检查上下文、查询工具和文件、运行测试、检索当前来源、模拟场景、生成选项，并重新参数化任务。只有当这些办法都用尽，且剩余变量既关键、又确实由人类治理时，升级才是合理的。

## 五个操作域

协作补充稿把执行阻塞收紧为五个域：

::::cards
### 信息与证据

agent 缺少事实、新鲜状态、验证器、来源、运行时结果、文件、权限或可靠证据。

### 价值与规格

多个动作都可行，但排序取决于目标、品味、预算、风险容忍度、充分标准或利益相关者优先级。

### 权限与责任

agent 可能知道该做什么，却没有合法权限去发送、发布、删除、付款、签署、披露、部署或承担后果。

### 边界与时机

agent 不知道规则何时适用、何时过期、是否等待、是否承诺，或者当前进展是否仍可逆。

### 协调与控制表示

当前拆解、工作流、交接或任务模型可能遗漏了决定性依赖或责任角色。
::::

## 升级门槛

有些情况属于硬性治理门槛，无论 agent 多有把握，都必须停下来升级：对外承诺、敏感披露、删除、付款、签署、发布、部署、越过政策边界，以及任何牵涉法律、财务、安全、雇佣、隐私或声誉责任的动作。

非强制场景下，升级应看预期损失。如果无支持自治的预期错误成本高于中断和延迟成本，就应该问人。可逆性同样重要：可逆草稿可以继续，不可逆承诺必须暂停。

## 最小充分人类问题

好的 agent 不应该问：

```text
我该怎么办？
```

它应该问：

```text
哪个最小问题一旦得到回答，就能让我恢复自治推进？
```

一个好的最小充分人类问题（MSHQ）有五个特征：

- 具体指出当前阻塞变量。
- 给出少量选项，降低回答成本。
- 说明不同答案会改变什么行动。
- 提供安全默认值。
- 不把整个任务交还给人。

一个可复用模板是：

```text
我可以在 ______ 条件下继续自治推进。
唯一阻塞变量是 ______。
请确认或选择：A ______ / B ______ / C ______。
这会改变 ______。
如果你不指定，我会选择 ______，因为它最安全或最可逆。
```

:::cards
### 事实或状态

"请确认一个事实：客户是否仍在退款窗口内？如果是，我将准备退款选项；如果不是，我将准备升级说明。"

### 偏好权重

"这三个方案主要差异是速度、成本和风险。哪个目标应当主导？如果你不指定，我会默认最低风险。"

### 授权

"我可以发送这封邮件，但它包含交付日期承诺。是否授权发送这段具体措辞？选项：发送、先改、不发送。"

### 验证信号

"当前最大风险是时间泄漏。请确认所有特征都在预测时间之前可得，或提供样例/测试结果。"
:::

## 受治理升级对象：治理什么时候问人

受治理知识对象（GKO）管理 AI 应该知道和遵守什么；GEO 管理的则是"问"这个动作本身：AI 什么时候该问人、问什么、问谁，以及无人回答时如何安全处理。

一个 GEO 应至少包含：

- 触发条件：什么情况必须升级？
- 最小问题：要向人问的具体变量是什么？
- 选项与默认值：人不回答时怎么办？
- 风险等级：错了会造成什么后果？
- 人类角色：用户、专家、审批人、数据负责人、审查者还是风险负责人？
- 等待期间可继续的自治工作：哪些草稿、测试、分析可以先做？
- 撤销条件：什么时候这条升级规则不再适用？

当某个人类回答被证明是耐用的，它就可以沉淀成 GKO。例如："这个客户的任何外部承诺都必须在发送前获得明确批准。"反过来也成立：一条 GKO 也可以在未来任务里，当条件再次出现时触发 GEO。

对于长程 agent，人类回答还应更新 agent 的硬状态：确认了哪个事实、哪个边界生效、哪项授权被批准或拒绝、哪个状态转移现在可以发生。这就是协作层与状态治理智能体范式（SGAR）的连接点。

## 协作流程

把前面各部分串起来，一次完整的治理式协作循环大致是这样几步：

1. 低失配工作直接执行。
2. 诊断原始失配和当前操作阻塞。
3. 构造任务模型和选项空间。
4. 查询环境和可用工具。
5. 构造试炼场：场景、反事实、利益相关者视角、红队案例和边界情况。
6. 找出剩余的人类治理变量。
7. 提出 MSHQ 或实例化 GEO。
8. 等待期间继续安全、可逆的工作。
9. 验证回答、恢复自治，并检查结果。
10. 将已解决变量提交为硬状态。
11. 将可复用判断保存为 GKO/GEO，并在条件变化时撤销过期规则。

## 人应该裁决什么

:::cards
### 价值与权重

速度、质量、成本、风险、关系、声誉、长期方向，哪一个更重要？AI 可以建模这些取舍，但不应替人决定最终价值函数。

### 品味与身份

什么是高级、克制、锋利、可信、勇敢或合适？这些判断包含身份位置和长期叙事，不能完全还原成客观指标。

### 授权与责任

发送、发布、承诺、删除、购买、签署、部署等外部动作，需要明确授权。AI 可以准备证据和方案，但不能替人承担后果。

### 边界与停止标准

规则什么时候适用？什么时候撤销？当前输出是内部草稿、外部成稿、可执行方案，还是需要继续验证？
:::

## 好协作的质量指标

好的人机协作不是"人越少介入越好"，而是人介入得更准：

- 升级是否真的对应阻塞变量？
- 问题是否最小、具体、可回答？
- 人回答后，AI 是否能恢复自治？
- AI 是否避免了未经授权的外部动作？
- 可复用判断是否沉淀为 GKO/GEO，而不是在对话里消失？
- 中断后 agent 是否能恢复被承认的状态？

这就是从聊天式使用走向治理式协作：AI 做它擅长的处理、搜索和表达，人治理那些无法由概率生成替代的变量。
