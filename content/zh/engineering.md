## 治理到底在做什么

治理不是把模型“管严一点”，也不是把提示词写得更长。治理真正做的事，是把一个很难直接在最终输出空间里解决的问题，改写成一条更容易搜索、验证和回滚的流程。

很多失败任务原本长这样：

```text
输入 -> 直接采样最终答案 -> 反复润色 -> 仍然不对
```

治理之后，更像这样：

```text
输入 -> 先构造控制空间 -> 在控制空间搜索 -> 投影回输出空间 -> 验证 -> 回写经验
```

一句话：**不要让模型一直在最终答案里盲目挣扎，要先给它一个更适合搜索的中间层。**

这页承接的是机制页的结论：当局部流畅不能预测全局价值时，问题不再是“多生成几版”，而是“生成前应该先显式化什么”。治理页把四类错配翻译成工程动作：构造控制空间、隔离评价器、沉淀经验，并在必要时把剩余变量交给协作协议处理。

如果你想先看完整工程实例，可以回到“案例”页。V4 把这一流程落在故事生成的逻辑空间、评估器和缺陷攻击上；V6 进一步展示，当控制空间已经存在时，系统如何把问题路由到 MetaSpace、LogicSpace、文本、连续性和评价契约等不同层级。

## 一个更像工程的治理流程

可以把治理流程理解为七步：

1. **输出空间采样**：先在原始自回归空间里做大规模探索，拿到稀有但高质量的样本。
2. **经验抽取**：从高质量样本里提炼可迁移的控制变量、生成算子和失败边界。
3. **控制空间构造**：把原任务改写成更低维、可组合、可验证的中间表征。
4. **控制空间搜索**：不再只采最终答案，而是在控制空间里做 beam search、树搜索、进化搜索或局部修复。
5. **输出空间投影**：把控制方案还原成最终文本、代码、方案或作品。
6. **分层验证**：用硬约束、软评分、反向攻击和外部工具检查结果。
7. **经验回写**：把成功和失败都写回经验库，为下一轮搜索提供材料。

这条链路可以写成：

```text
输出空间采样
-> 经验抽取
-> 控制空间构造
-> 控制空间搜索
-> 输出空间投影
-> 分层验证
-> 经验回写
```

这比“让模型再来一版”更有效，因为每一步都在改变问题本身，而不是只改变措辞。

## 控制空间不是一次性设计出来的

很多人会觉得控制空间像是先设计好一个结构，然后模型照着填空。实际上，更稳的做法是：**控制空间本身也要被搜索。**

这里至少有两层搜索：

:::cards
### 内层搜索
Tag: 给定控制空间 C

在一个已经选定的控制空间里，寻找最优输出。比如在固定的故事约束、评分规约或依赖图下，搜索哪个具体方案最好。

### 外层搜索
Tag: 比较不同控制空间

不要默认某一个控制空间就是对的。应该比较 C1、C2、C3 哪个更能稳定地产生高质量输出。很多时候，真正的突破来自换了控制空间，而不是在同一个控制空间里继续死搜。
:::

所以，治理不是“先设计控制空间，再结束”，而是“边搜索输出，边搜索控制空间”。

## 先判断你到底缺什么

当一个任务做不好，问题通常不只是一句“模型不够强”。更有用的判断是：你到底是 **支持不足**、**搜索不足**，还是 **验证不足**。

::::cards
### 支持不足
Tag: 怎么采样都没有好候选

说明系统根本没接触到足够好的材料、知识或能力。此时单纯增加搜索没有用。要引入外部知识、示例、工具、微调、检索或更强模型。

### 搜索不足
Tag: 偶尔能采到好东西，但不稳定

说明好答案并不是不存在，而是你到达它的机制太弱。这里最有效的就是控制空间、树搜索、重组、分层搜索和局部修复。

### 验证不足
Tag: 好坏混在一起，选不出来

说明系统已经能生成一些不错的候选，但评价器太弱，无法稳定挑出真正好的结果。此时需要更强的 judge、pairwise 比较、自动验证和反向攻击。
::::

这三类问题要分开，因为应对方式完全不同：

- 如果是支持不足，单纯增加搜索没有用。
- 如果是搜索不足，控制空间非常有效。
- 如果是验证不足，采样越多反而越危险，因为你会得到更多“骗过评价器”的候选。

## 控制空间里到底放什么

控制空间不需要长得像最终答案。它更像是一组中间对象，用来把真正影响质量的变量拉到台面上。

典型控制对象包括：

- 状态矩阵
- 评分规约
- 候选框架
- 失败模式清单
- 依赖图
- 查询计划
- 约束列表
- 角色配置
- 承诺-回收链

好的控制空间通常满足三点：

- **更低维**：比最终答案更容易搜索。
- **可组合**：局部结构可以重组，不必每次从头生成。
- **可验证**：能直接检查约束、证据和失败边界，而不是只看“读起来像不像对”。

## 生成器和评价器要角色隔离

不要让同一个上下文里的模型既生成、又评价、又修正。这样非常容易产生路径依赖：模型会下意识维护自己前面已经做出的选择，而不是认真推翻它。

更稳的做法是把角色拆开：

:::cards
### Generator

负责生成候选，不负责替自己辩护。

### Critic

负责攻击候选，专门找漏洞、冲突、伪深度和隐藏失败模式。

### Editor

负责局部修复，不重新发明全部结构。

### Judge

负责最终选择，并且尽量使用不同上下文、不同提示和不同评价标准。
:::

即便底层还是同一个模型，也应该通过不同上下文来模拟角色隔离。对于可验证任务，最好再引入专门 verifier 或外部工具。很多任务上，**验证往往比生成更容易做好**；一旦验证器更强，整体质量会明显上升。

## 经验库不要只存成功经验

从高质量样本里抽取正经验非常重要，但只存正经验不够。因为系统可能会反复踩同一类坑，只是每次表面长得不一样。

更好的做法是把经验库拆成两类：

::::cards
### 正经验库
Tag: 什么模式稳定提升质量

保存那些能持续提高质量的结构、控制变量、提示算子、验证动作和搜索策略。

### 负经验库
Tag: 什么模式看起来高级，但经常失败

保存那些常见伪高质量模式。负经验往往更可迁移，因为它能大面积剪掉低价值搜索分支。
::::

以故事任务为例，负经验可能包括：

- 用设定复杂度冒充深度。
- 用反转替代人物选择。
- 用金句替代情绪积累。
- 用悲惨事件替代真正的悲剧结构。
- 用宏大主题替代具体冲突。
- 用“他突然明白了”替代行为改变。

这些负经验不是次要补充，而是搜索剪枝器。

## 不要只按质量搜索，也要按新颖性搜索

如果每一轮都只保留当前最高分样本，你仍然可能被吸进一个更大的局部最优。因为高分不等于高覆盖，高分也不等于最有重组价值。

更稳的做法，是同时维护几种分数：

```text
总分 = 质量分 + 新颖性分 + 约束满足分 - 风险分
```

这里的新颖性不是为了猎奇，而是为了扩大可重组材料的覆盖面。真正有价值的样本，未必是当前总分最高的样本，也可能是某个局部结构异常强、但整体还不成熟的样本。

因此，样本筛选最好至少保留三类：

1. **最高总分样本**
2. **某个局部维度极强的样本**
3. **与现有优秀样本差异最大的样本**

第三类尤其重要，因为它常常是突破当前局部最优的材料来源。

## 可以从失败模式反推控制空间

控制空间不一定只能从好样本里正向抽取，也可以从失败模式里反推出来。这可以叫做 **反向控制空间**。

故事任务里很常见的失败模式包括：

- 平淡
- 俗套
- 人物扁平
- 结尾无力
- 主题空泛

这些失败如果继续停留在形容词层面，几乎没有用。真正有用的是继续往下追问：它们分别缺了什么控制变量？

::::cards
### 平淡

通常不是“文笔不够”，而是缺少不可兼得的选择。

### 俗套

通常不是“表达太常见”，而是冲突结构太常见。

### 人物扁平

通常不是“描写太少”，而是欲望、恐惧、羞耻和行动没有真正冲突。

### 结尾无力

通常不是“收尾太快”，而是前文没有承诺，或者承诺没有回收。

### 主题空泛

通常不是“主题不高级”，而是主题没有通过人物选择付出代价。
::::

如果沿着这些失败模式往回推，控制空间里就应该显式加入：

- 不可兼得约束
- 人物内在矛盾
- 代价函数
- 承诺-回收链
- 场景压力递增
- 选择不可逆点

这比一句“让故事更深刻”有效得多，因为它把模糊要求变成了可搜索、可验证的控制变量。

## 一个更实用的工程判断

治理不是每个任务都要上满。真正值得上治理的场景，通常有几个信号：

- 你反复采样，但稳定好结果很少。
- 偶尔能出好东西，但复现不了。
- 好候选出现了，却选不出来。
- 错误成本高，不能只靠“看起来合理”。
- 同类任务会反复出现，值得沉淀经验库。

相反，如果任务只是压缩、改写、格式转换、常规候选生成，直接生成往往已经够好，不必强行加一层重治理。

治理的目标从来不是让流程更复杂，而是让搜索更有效、验证更可靠、经验能积累。好的治理系统，不是让模型少生成，而是让模型在正确的任务形态里生成。
