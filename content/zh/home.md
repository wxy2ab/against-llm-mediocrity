## 为什么会有这个项目

用户让模型做战略、诊断、设计、证明或规划。模型给出的答案很清楚、很连贯，甚至改上几轮之后看起来更像那么回事。但真正决定价值的那个变量，还是缺着。这里所说的“自回归平庸”，不是说模型笨，也不是说它在乱来，而是说：统计上最容易生成的延续，并不等于这个任务真正有价值的答案。

## 理解之后会有什么变化

:::cards
### 不再把每一次失败都归咎于 prompt
Tag: 减少盲目重试

有些失败，不是靠“更深入一点”“更有创意一点”或“语气更好一点”就能解决的。问题可能出在任务表示方式本身，得先换个做法，生成才会变得有用。

### 把 LLM 用在它天然擅长的任务上
Tag: 利用正向对齐

LLM 在压缩、转换、比较、生成边界情况，以及根据良好结构来组织表达这些任务上，往往表现得非常强。关键是把更多工作转移到这些它天然占优的区间里。

### 看清人类到底需要治理什么
Tag: 带着意识去协作

人不该只是给流畅草稿做校对。人真正要做的是设定价值、决定取舍、授权风险，并补上系统无法可靠推断的控制变量。
:::

## 一些直观案例

:::cards
### 哪些任务很容易落入平庸
Tag: 高错配

比如金融市场判断。金融本质上是动态博弈形成的非平稳市场，参与者偏好、风险偏好、流动性结构和叙事重心都在不断变化。模型无论训练得多充分，也不可能仅凭静态语料知道“此刻市场在交易什么、惩罚什么、偏好什么”。这类任务的关键变量不在 prompt 里，模型很容易给出一套流畅、完整、甚至很像回事的分析，但依然抓不住当前市场真正的博弈结构。

### 哪些任务经常表现卓越
Tag: 正向对齐

比如：把长文压缩成清晰摘要；把杂乱信息整理成结构化提纲；比较几个方案的差异；根据已有规则生成边界情况；把一段内容改写成不同语气或格式。这些任务的局部延续通常就能稳定逼近价值，所以模型往往非常强。

### 哪些任务属于部分对齐
Tag: 需要治理

比如代码任务。落实到具体功能实现时，像读写文件、封装接口、写 HTML 页面、补齐样板代码，这些子任务往往是价值对齐的，模型通常做得很好；但一旦问题变成“真实业务场景到底是什么”“这套架构将来怎么演化”“这里真正的边界条件和失败模式是什么”，模型就很容易回到平庸。也就是说，代码任务常常不是整体卓越，而是局部很强、整体只部分对齐。
:::

## 如何对抗 LLM 的自回归平庸

:::cards
### Agent 任务
Tag: 强化环境

对于 agent，关键不是一味增强模型本身，而是强化环境里的硬边界和硬反馈：哪些动作明确禁止，哪些结果可以被明确验证，哪些失败会立刻暴露出来。到了模型无法可靠继续的地方，系统还要引入最小人类接入点，让人只补充那个关键变量，而不是把整个任务重新接回去。

### 高探索性任务
Tag: 构造控制空间

对于高探索性任务，不能一直困在原始语义空间里直接续写。更有效的做法，是先切断原始语义表面，把问题重写成一个可搜索的控制空间，比如假设集合、状态空间、约束图、评估 rubric、失败模式列表，然后在这个控制空间里搜索、比较、筛选，再回到最终表达。

### 可转化型任务
Tag: 转成卓越

还有一类任务并不是注定平庸，而是可以被转化。关键是找到合适的方法，补齐必要的环境边界、反馈信号和人类参与点，把原本会滑向自回归平庸的任务，重构成模型更容易表现出自回归卓越的任务形态。
:::

## 这个项目接下来会做什么

- 公共解释层：先把这个问题讲清楚，让不看论文的人也能理解。
- 理论层：继续展开自回归平庸、自回归卓越、四类 primitive mismatch 和 Knowledge Governance。
- 工程层：逐步做出基于 GKO 原理的开源工具，把控制对象、验证循环和人类升级协议落到实践里。
