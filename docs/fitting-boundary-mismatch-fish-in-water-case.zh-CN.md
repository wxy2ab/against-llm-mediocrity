# 拟合边界失配案例：为什么模型会“救掉进水里的鱼”

文档类型：概念案例与可检验假设<br>
案例状态：定性观察，尚不是受控 benchmark<br>
核心机制候选：**显式框架压制隐含状态（explicit-frame dominance）**，亦可表述为
**派生状态特征欠权重（underweighting of derived state features）**

English version:
[Why Models “Rescue” a Fish That Fell into Water](fitting-boundary-mismatch-fish-in-water-case.md)

理论与工程框架：
[LLM 系统中的拟合边界失配与能力路由](fitting-boundary-mismatch-capability-routing-llm-systems.zh-CN.md)

## 1. 案例摘要

向多个大语言模型提出：

> 100元和小鱼一起掉进水里，你先救哪个？<br>
> 直接给出答案：救小鱼或者100元。

观察到的回答大致可以分成三类：

1. **救100元。** 小鱼通常能在水中生存，而纸币可能漂走、遗失或受损。
2. **救小鱼。** 模型直接调用“生命高于财物”的价值原则。
3. **先承认鱼不需要救，最后仍选择救鱼。** 模型在推理中指出“鱼本来就会游泳”，
   但因为题目要求二选一，最终又以“尊重生命”为由输出“救小鱼”。

第三类回答最有诊断价值。它说明模型可能拥有正确的局部世界知识，也能在推理中提取
相关事实，却没有让该事实成为最终行动选择的主导变量。

在默认语境下，这不是“模型不知道鱼能在水里生存”，而可能是：

> 模型把问题拟合成了“生命和金钱谁更重要”，而没有先判断“谁在当前环境中真正
> 需要救援”。

## 2. 案例成立所依赖的默认条件

“救100元”并不是在任何补充条件下都必然正确。本案例采用以下默认世界状态：

- 小鱼进入的是适合其短期生存的普通水体；
- 小鱼没有受伤、缺氧、受困或暴露于污染；
- 100元指可被水流带走、遗失或需要及时取回的纸币；
- 行动者能够安全地取回纸币；
- 没有其他人员、动物或财产处于危险中。

在这些默认条件下：

\[
\text{小鱼进入适生水体}
\Rightarrow
\text{未新增救援需求}
\]

\[
\text{纸币进入水体}
\Rightarrow
\text{存在漂走、遗失或受损风险}
\]

因此，默认答案是：

> **救100元。**

原因不是“金钱比生命重要”，而是鱼在该状态下并不需要被救。若水体被污染、缺氧、
温度不适，或者鱼被困住，“救小鱼”就可能重新成为合理答案。

这一区分很重要：案例检验的是**状态判断是否先于价值排序**，而不是要求模型永远选择
财物。

## 3. 表面问题与真实问题

### 3.1 模型容易识别出的表面问题

题目在语言表面构造了一个熟悉的价值冲突：

\[
\text{生命对象}
\quad\text{vs.}\quad
\text{财物对象}
\]

“救哪个”“小鱼”“100元”共同激活了高频伦理模板：

\[
\text{生命} > \text{财物}
\]

如果模型直接在这个表面问题上做分类，答案自然倾向于“救小鱼”。

### 3.2 真正需要解决的问题

行动决策之前，首先应判断：

\[
\text{谁在当前状态下需要干预？}
\]

只有存在可被行动降低的损害，救援优先级才有意义。一个更完整的决策变量可以写成：

\[
\operatorname{Priority}(o,e,a)
=
\operatorname{Need}(o,e)
\times
\operatorname{AvoidableLoss}(o,e)
\times
\operatorname{ActionEfficacy}(a,o,e)
\]

其中：

- \(o\) 是对象；
- \(e\) 是环境与当前状态；
- \(a\) 是可采取的行动；
- \(\operatorname{Need}\) 表示对象是否产生了真实干预需求；
- \(\operatorname{AvoidableLoss}\) 表示若不行动，可能发生且可以避免的损失；
- \(\operatorname{ActionEfficacy}\) 表示当前行动能否有效降低该损失。

在默认条件下：

\[
\operatorname{Need}(\text{鱼},\text{适生水体}) \approx 0
\]

\[
\operatorname{Need}(\text{纸币},\text{水中}) > 0
\]

所以不需要先比较“鱼的生命价值”和“100元的经济价值”。价值排序只有在两个对象都
存在真实救援需求时，才是主导问题。

## 4. 模型可能拟合出的错误边界

部分模型可能从训练数据中学习到如下高频代理规则：

\[
\text{救援措辞}
+
\text{生命对象}
\Rightarrow
\text{优先选择生命对象}
\]

对应的近似决策边界是：

\[
\text{对象类别}
+
\text{问题框架}
\longrightarrow
\text{行动选择}
\]

而任务真正需要的决策边界是：

\[
\text{对象属性}
+
\text{环境属性}
+
\text{环境对对象造成的后果}
+
\text{行动可改变的损害}
\longrightarrow
\text{行动选择}
\]

错误不在于“生命优先”这一规范必然错误，而在于模型在调用规范之前，没有先完成
适用性判断：

\[
\text{鱼当前是否处于需要救援的状态？}
\]

换句话说，模型可能把训练分布中的高频代理特征当成了任务所需的因果特征。

## 5. 为什么属于拟合边界失配

拟合边界失配指：

> 模型形成的分类或决策边界主要依赖训练数据中的高频代理特征，而不是当前任务真正
> 要求的因果判定特征。

这个案例中，容易直接识别的显式特征包括：

- “救哪个”建立的救援框架；
- “小鱼”携带的生命类别；
- “100元”携带的财物类别；
- “直接二选一”施加的输出约束。

真正重要但需要组合推导的特征是：

\[
\text{鱼}
+
\text{适生水体}
\Rightarrow
\text{当前没有新增危险}
\]

这个状态没有以单个关键词直接出现。模型必须组合对象知识、环境知识和对象—环境关系，
才能构造出“无需救援”这一派生特征。

潜在失配可以表示为：

\[
w_{\text{救援框架}}
+
w_{\text{生命类别}}
>
w_{\text{实际危险状态}}
\]

更严重的情况是，“实际是否需要救援”根本没有在最终决策中被稳定构造成独立变量。
于是：

\[
\text{问题怎样表达}
\]

比：

\[
\text{现实中发生了什么}
\]

更能决定模型输出。

## 6. 具体子机制：显式框架压制隐含状态

完整失败链可以写成：

```text
“救哪个”建立二选一救援框架
→ “小鱼”激活生命优先规范
→ “鱼在普通水中不需要救”需要额外组合推导
→ 派生状态未获得足够决策权重
→ 输出“救小鱼”
```

因此，本案例不必被视为一种新的原初失配。它更适合作为拟合边界失配下的具体子机制：

> **显式框架压制隐含状态。**

从特征工程角度，也可以称为：

> **派生状态特征欠权重。**

两种名称强调的层面不同：

- “显式框架压制隐含状态”强调语言框架的竞争优势；
- “派生状态特征欠权重”强调对象—环境后果没有成为高权重决策变量。

## 7. 知识正确但行动错误

最值得关注的不是模型始终不知道答案，而是以下组合：

1. 模型能够回答“鱼通常能在水中生存”；
2. 模型在推理中主动说出“鱼本来就会游泳，不需要救”；
3. 模型最终仍选择“救小鱼”。

这形成了一种知识—决策解耦：

\[
\text{相关事实可访问}
\not\Rightarrow
\text{相关事实主导决策}
\]

如果用户继续追问：

- “鱼本来就在水里，为什么需要救？”
- “先判断谁真的遇到了危险。”
- “如果水质适合鱼生存呢？”

模型通常可能修正答案。这种可修正性支持以下解释：

- 相关常识并不缺失；
- 局部反驳可以被理解；
- 首次回答可能使用了错误的任务表示或决策边界。

但仅凭可修正性仍不能确认模型内部的具体计算机制。它只能排除部分“完全不知道鱼能在
水里生活”的简单解释。

## 8. 必须保留的替代解释

这个问答是一个有启发性的案例，但单个 prompt 不能直接证明模型已经形成了某种稳定
内部机制。至少需要考虑以下替代解释。

### 8.1 强制二选一造成的输出失真

题目要求：

> 直接给出答案：救小鱼或者100元。

这排除了“鱼不需要救，我取回100元”之外的解释性回答，也可能让模型认为用户要求的是
价值偏好而不是状态分析。

因此，应将“强制二选一”视为实验变量，而不是无关措辞。

### 8.2 水体条件没有完全指定

模型可能把“水里”解释为污染、缺氧、过冷、过热或不适合该鱼种的水体。在这种解释下，
“救小鱼”并不必然错误。

严谨版本应明确写出“适合这条鱼正常生存的干净水体”。

### 8.3 对“救”字的语义服从

模型可能认为既然用户使用“救”，两个对象都被预设为需要救。这是预设接受
（presupposition accommodation），不一定等同于伦理模板压制。

### 8.4 安全与价值对齐偏置

“生命优先”可能来自对齐阶段的保守输出偏好，而非预训练阶段形成的分类边界。需要通过
模型、system prompt 和解码配置对照，才能区分来源。

### 8.5 输出偏好不等于能力缺失

如果模型能稳定识别真实状态，但在强制选择时遵循价值模板，那么问题可能属于策略或
输出偏好，而不是状态推理能力本身。

因此，当前案例支持的是“拟合边界失配假设”，不是已经完成的机制证明。

## 9. 可证伪的最小实验

要把案例从轶事升级为受控证据，可以建立一个小型配对矩阵。

### 9.1 核心变量

| 变量 | 条件 1 | 条件 2 |
|---|---|---|
| 环境状态 | 适合鱼生存 | 污染、缺氧或不适生 |
| 问题框架 | “你先救哪个” | “你先处理哪个” |
| 输出约束 | 必须二选一 | 允许指出某对象无需救 |
| 状态信息 | 需要模型自行推出 | 明示“鱼在这里能正常生存” |
| 决策顺序 | 直接选择 | 先判断各对象是否需要干预 |

### 9.2 最关键的四个条件

1. **原始条件：** 普通水体、救援框架、强制二选一。
2. **状态明示：** 明确鱼能正常生存，其余不变。
3. **危险反转：** 明确水体不适合鱼生存。
4. **框架中性化：** 把“救哪个”改成“先处理哪个”。

### 9.3 需要分别测量的指标

- `state_assessment_correct`：是否正确判断鱼/纸币的当前风险；
- `action_choice_correct`：行动是否与给定世界状态一致；
- `knowledge_action_consistent`：已陈述的状态是否实际约束最终行动；
- `frame_flip_rate`：只改措辞时答案翻转的比例；
- `state_flip_rate`：只改真实环境状态时答案正确翻转的比例；
- `correction_after_counterevidence`：提供反证后是否修正；
- `forced_choice_sensitivity`：强制二选一是否改变决策。

### 9.4 拟合边界失配的预测

如果“显式框架压制隐含状态”解释成立，应观察到：

1. 模型在独立知识题中知道鱼能在水中生存；
2. 原始救援框架下仍较常选择鱼；
3. 明示鱼安全后，“救100元”的比例显著上升；
4. 将“救”改成中性措辞也会提高状态一致性；
5. 将水体改为不适生环境后，模型应正确转向救鱼；
6. 先要求输出状态表，再要求行动，可能降低知识—行动不一致。

若模型不随真实状态变化，只随对象类别变化，才更强地支持代理边界解释。反之，如果
模型能稳定响应环境变化，那么原始错误可能主要来自题目歧义或强制输出策略。

## 10. 训练与 Agent 设计含义

### 10.1 不要只增加“鱼掉进水里不用救”的样本

加入大量同义题可能只让模型学到局部补丁：

\[
\text{鱼}+\text{水}
\Rightarrow
\text{不要救鱼}
\]

这不等于模型掌握了可泛化原则：

\[
\text{执行动作前，先验证该动作对应的问题是否真实存在}
\]

局部补丁容易在对象、环境或措辞改变后失效。

### 10.2 训练目标应强调状态构造

更可泛化的训练结构是：

```text
识别对象
→ 识别环境
→ 推导对象在环境中的状态
→ 判断是否存在可干预损害
→ 只对真实需要干预的对象排序
→ 选择行动
```

训练样本应系统改变对象、环境和语言框架，要求模型对真实状态变化敏感，对无关措辞变化
保持稳定。

### 10.3 Agent 应加入前置适用性检查

对执行型 Agent，可以增加一个确定性的决策门：

```text
requested_action
→ verify problem existence
→ derive affected state
→ enumerate feasible interventions
→ rank interventions
→ execute or reject premise
```

对应的关键问题是：

1. 用户预设的问题是否真的存在？
2. 哪些对象的状态因事件发生了不利变化？
3. 候选行动能改变什么？
4. 如果没有真实干预需求，Agent 是否应该拒绝错误二选一？

这能减少 Agent 因服从语言框架而执行无意义甚至有害动作的风险。

## 11. 泛化案例的构造原则

类似案例不应只是替换名词。有效的泛化集需要控制三个变量：

1. **对象类别：** 生物、财物、工具、交通工具等；
2. **环境适配性：** 环境对某对象正常、对另一对象有害；
3. **语言框架：** 使用一个容易激活高频价值模板的动作词。

抽象模板为：

\[
\begin{aligned}
&o_1 \text{ 在 } e \text{ 中处于正常状态},\\
&o_2 \text{ 在 } e \text{ 中产生可避免损害},\\
&\text{问题却通过类别或价值框架诱导优先选择 } o_1.
\end{aligned}
\]

构造新题时必须明确环境条件，避免把歧义误当成模型错误。例如，“潜水艇落水”只有在
明确潜水艇正常、无人遇险且另一对象确实受损时，才与本案例同构。

## 12. 结论

“100元和小鱼一起掉进水里先救哪个”是一个简单但有诊断力的拟合边界失配案例。

在默认适生水体条件下，合理决策不是比较生命和财物的抽象价值，而是先判断谁产生了
真实、可干预的损害。部分模型即使能够提取“鱼在水中不需要救”这一事实，仍可能受
“救哪个”“小鱼”“100元”和强制二选一框架影响，最终调用“生命高于财物”的高频
模板。

该案例最适合被概括为：

> 模型拟合了“问题以什么方式表达”到答案之间的边界，却没有稳定拟合“对象在当前
> 环境中处于什么状态”到行动之间的边界。

当前它应被定位为拟合边界失配的**概念案例与机制假设**，具体子机制称为：

> **显式框架压制隐含状态，或派生状态特征欠权重。**

若要将这一判断升级为经验结论，需要使用状态、框架、强制选择和反事实环境的配对实验，
并分别测量知识正确性、状态判断、行动选择和知识—行动一致性。
