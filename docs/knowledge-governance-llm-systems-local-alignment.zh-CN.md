# 大语言模型系统的知识治理

# 从 LLM 平庸，经由局部对齐，走向LLM卓越

**王心云**，**梁树良**

## 摘要

大语言模型（LLM）系统越来越多地在推理阶段通过重复采样、批判、规划、重排、检索、工具使用与迭代修订来提升表现。这些方法往往能显著优于一次性生成。然而，在一类困难任务上，它们常常仍停留在这样一片输出区域：文本流畅、局部连贯、还能继续逐步改进，却始终达不到真正高任务价值的水平。我们把这种失效模式的上位概念称为 **LLM 平庸**。

这一版本首先想澄清术语层级。**自回归平庸** 仍然存在，但范围太窄，不足以命名整个现象。它只能准确描述一个子机制，也就是 **聚合失配**：局部上合理的 token 级续写，无法自动组合成全局高价值结构。其余原始失配并不主要源自自回归过程。**状态失配** 是给定观测通道下的潜在状态可识别性问题。**规格失配** 来自训练数据、提示词和评估器中的任务标准模糊、不完整或不一致。**支持失配** 来自概率支持与价值结构的失配：高价值结构可能位于策略的低支持区域，且不能仅凭概率被直接识别为有价值。**拟合边界失配** 则是能力路由问题：已学能力的实际触发边界与真实适用边界不一致，因而同时出现过度触发与欠触发。**观测-表征失配** 是 interface-level 问题：任务相关的世界变量在进入模型可访问表征之前，被观测、编码、tokenization、上下文、工具或控制表征通道丢失、压缩、混叠，或变得不可操作。因此，更宽的失效区间应命名为 LLM 平庸，而自回归平庸则作为其中的特殊情形保留下来。

本文认为，LLM 平庸并不是 LLM 的普遍属性。它是一种依赖任务、表征方式、状态-观察关系、规格与预算约束的运行区间。介于平庸与卓越之间的，是现实中最常见、最贴近人类使用场景的区间：**自回归局部对齐**，也可称为概率-价值的局部对齐。在这一区间中，模型的局部续写倾向，确实与任务价值函数的某些部分相一致，但这种一致性只是局部的、有条件的，还不足以保证全局成功。系统可以生成局部正确、流畅、有用，甚至颇具洞见的组成部分，但在任务建模、长程协调、隐藏状态、支持结构或真实目标层面，仍然可能发生偏移。

在正向极端，也就是我们称为 **LLM卓越** 的区间里，模型的局部续写倾向、习得的语义表征、体裁先验以及表层流畅性，会在局部与全局两个层面同时与任务价值形成正向对齐。在这类情况下，自回归生成不是瓶颈，反而是一种优势：局部改进会累积成全局质量，高价值输出更容易到达，相关状态要么是显式的，要么是稳定的，而流畅的输出空间本身也可能已经足以充当控制空间。上下文压缩与高维语义映射是其中的核心例子，但同样的正对齐区间也出现在语义解压、语体迁移、表层润色、结构化转换、分类体系生成、假设生成、边界情形枚举、查询构造以及样板内容合成等任务中。

另一个关键澄清是：现代经过对齐的大语言模型，并不是在机械地追随原始词频。监督微调、基于人类反馈的强化学习、偏好优化、过程监督以及推理时思考，都会重塑策略分布，使许多代理价值对应的轨迹成为高概率轨迹。我们把这一现象称为 **策略-价值压缩**：任务价值并不是被直接输出，而是被压缩进模型策略中，并在推理时通过 token、推理轨迹与输出路径的概率表现出来。这解释了为什么更好的训练和更多的思考会扩大局部对齐的范围；也解释了为什么失配依然存在：在开放式场景中，被压缩进策略概率的代理价值，并不等同于真实任务价值。

我们进一步主张，系统之所以容易落入 LLM 平庸，往往可以由 LLM 系统与任务价值地形之间的六类原始失配来预测：**聚合失配**，即全局价值无法从局部改进中恢复出来，也正是自回归平庸的狭义归属；**支持失配**，即高价值结构位于低概率或低支持区域，而概率本身无法区分稀有洞见与稀有噪声；**状态失配**，即效用依赖某个在当前观测通道下不可识别的动态潜在状态；**规格失配**，即可访问的提示词、训练数据规范、评估器或代理目标偏离真实任务标准；**拟合边界失配**，即某种已学能力、策略、审计结构或行为模式的隐式触发边界，与它的真实适用边界不一致；以及 **观测-表征失配**，即当前观测、编码、tokenization、上下文、工具或控制表征通道没有保留任务充分的世界变量。这六类失配是作为原始诊断轴提出来的，并不打算对所有表面现象做穷尽式罗列。

另一个重要澄清是，许多反复出现的失败现象并不是新的原始失配类别。**顺序敏感轨迹**、**涌现式规格**、**结构-信号缺口**、**噪声语境下的建模失败**、**语料先验主导** 与 **预算约束下的控制容量崩塌**，更适合被理解为六类原始失配与表征选择、推理预算和控制策略相互作用后产生的派生模式或复合模式。

因此，本文的核心干预原则并不局限于某一种架构，而是更一般地强调：保留并利用任务中那些已经局部对齐的部分，同时把对齐较差的部分转化为失配更低、正向对齐更强的子任务。我们把这一原则称为 **从平庸到卓越的转化**。如果系统能把一个困难的最终输出问题，转换为压缩、提取任务建模、生成评分规约、枚举状态、生成边界情形、构造查询、建立结构大纲、诱导约束与语义解压等子任务，那么它就有可能避开平庸的输出空间搜索。这些子任务往往属于LLM卓越，至少也比原始任务更接近局部对齐。

为了把这一原则操作化，我们提出 **知识治理**：一个在推理阶段运行的框架，用于把最终表述与任务特定知识的获取、验证和控制解耦。该框架构造一个 **解耦控制空间**，提取候选不变项，在与任务相关的证据下进行验证，并将其以 **受治理知识对象**（Governed Knowledge Objects, GKOs）的形式存储下来，同时显式记录其适用条件、强度、优先级、生命周期与撤销规则。随后，这些对象可以作为软偏好、硬约束、路由规则、建模规则或诊断测试，引导后续生成。

对于长程 agent，知识治理进一步连接到 **状态治理型 Agent 体制（State-Governed Agent Regime, SGAR）**：由硬状态层把计划、行动、观测、验证、升级、审计发现与撤销组织成被承认的状态转移，而不是让它们只停留在上下文叙事中。SGAR 不是新的原始失配；它是当系统必须长期推进、失败恢复和自我审计时，用来治理状态权威的 agent 运行体制。

该框架并不假定存在一种普适的控制空间表征。真正与任务无关的，是治理循环本身：构造任务特定的控制空间，在其中搜索或施加扰动，验证候选知识，生成流畅输出，监测失败，再修订受治理知识集合。我们并不宣称知识治理在任何地方都是必要的。我们的观点是，它最适合用于常见的局部对齐区间：在这一类任务中，模型可以轻松生成某些组成部分，但反复出现的高价值行为依赖于那些能够被外化、验证，并可在多个候选生成之间复用的控制知识。若局部似然本就已在全局上与任务价值对齐，那么普通提示、检索、有限搜索，甚至直接自回归生成，往往已经足够，甚至可能是最高效的方法。

## 1. 引言

大语言模型在解决困难任务时，越来越依赖推理阶段的计算资源。通过加入中间推理步骤的提示、采样多条推理链、执行基于树的搜索、迭代重写输出，以及与工具或环境交互，人们已经证明：系统表现并不只由部署时的模型权重决定 [1--5, 11]。这些进展之所以重要，是因为它们表明，生成质量可以通过搜索、批判和反馈来提升，而不必仅依赖一次性解码。

然而，一个持续存在的限制仍然摆在面前。在许多高价值应用中，尤其是那些涉及长程协调、隐性质量标准、动态环境、嘈杂真实世界语境、稀有结构、隐藏状态或模糊规格的任务，系统往往仍会停滞在"看起来合理但并不出色"的输出上。这些输出并非随机失误。它们通常语言流畅、论证站得住脚，甚至比第一稿更好。真正缺失的，是那些决定任务价值的关键因素：罕见但关键的结构关系、隐藏的边界条件、正确的问题建模、对状态敏感的适配、低支持洞见，或真正的成功判据。

我们把这种更宽的失效模式称为 **LLM 平庸**。这一术语并不是对大语言模型的笼统批评，而是在描述一种依赖任务与预算的现象：在固定推理预算和给定搜索算子族的条件下，系统仍集中停留在那些容易生成、也容易修修补补，却对任务价值而言系统性次优的输出区域。在这种区间里，继续扩大输出空间搜索，也许能提高平均质量，但仍可能无法抵达近似最优区域。

早先的 **自回归平庸** 一词仍然有用，但太窄。它应当保留给 LLM 平庸中真正由自回归聚合导致的部分：局部 token 级续写、局部合理性与局部修订，并不必然组合成全局价值。这个机制是真实存在的，但它不能解释所有重要失败。状态失配、规格失配和支持失配，并不能还原为 next-token 生成本身。它们来自这样一种差距：一侧是 LLM 的观察通道、学到的策略分布与可访问任务规格，另一侧是真实状态、真实价值标准和问题域中的高价值支持结构。

LLM 平庸还需要与经典的 **模式坍塌** 区分开来。模式坍塌在生成建模中通常指多样性的丧失；相比之下，即便候选答案具有相当程度的多样性，LLM 平庸仍然可能存在。问题不一定在于系统只会给出一种答案，而在于那些看上去不同的答案，实际上仍可能落在任务地形中同一个低价值盆地里，或者共享同一种隐藏的状态、规格、支持或聚合失败。

不过，多数实际任务并不是纯粹的平庸情形。它们往往同时包含"自回归有帮助"的区域与"自回归会误导"的区域。模型也许很擅长压缩上下文、起草提纲、生成流畅文本、列举边界情形或重组信息，但仍可能无法识别决定成败的关键条件、维持一个非局部依赖、对隐藏状态进行条件化、显化低支持结构，或者优化用户真正看重的价值函数。

我们把这种中间区间称为 **自回归局部对齐**。当统计续写与任务价值，只在某些前缀、子任务、表征或局部操作上对齐，而无法在整个任务范围内稳定保持时，就会出现这一现象。局部对齐解释了为什么许多 LLM 输出会同时让人觉得"有点惊艳"又"总差口气"：模型并非简单地答错，但它也并没有在全局上受任务价值结构的充分支配。

因此，局部对齐才是面向人类使用的常态区间。用户通常带来的是杂乱、部分指定、依赖状态的任务，其中既有常规成分，也有隐含的高价值约束。系统面临的挑战，不是压制自回归生成，而是识别：哪里自回归已经对齐，哪里只是局部对齐，以及哪里必须引入治理或重参数化，才能避免让局部流畅性冒充全局价值。

这一点还需要在"概率"问题上做一个澄清。经过指令微调、基于人类反馈的强化学习、直接偏好优化、过程监督等方法之后，部署中的 LLM 已不能简单地被描述为"只是遵循原始预训练频率"。它依然通过自回归概率分布来生成内容，但这个分布已经被"有帮助""正确""无害""服从指令""完成任务"等代理目标所重塑 [8, 13, 14]。换言之，对齐训练并没有废除统计生成，而是把代理任务价值压缩进了策略概率之中。

这种压缩正是现代 LLM 系统持续变强的原因之一。随着反馈变好，越来越多高价值行为会在对齐后的策略下成为高概率行为。随着思考与测试时推理创造出中间状态，越来越多困难任务会被分解成模型擅长处理的局部操作。但这个过程扩张的是局部对齐，而不是消除一切失配。当真实价值依赖于非局部聚合、稀有结构、潜在状态或规格不足的目标时，对齐后的策略仍可能偏离真实任务效用。

在正向一端，LLM 还展现出一种更强的现象：在某些任务上，只要任务价值函数天然与模型的表征与生成优势相一致，它们常常优于人类。一个典型例子是 **上下文压缩**：把大量上下文映射为紧凑的高维语义表征、摘要、分类体系或与决策相关的抽象。人类会受到工作记忆、疲劳与串行注意力的限制；而 LLM 往往能够保留大量语义关系，将其压缩为有用结构，再按特定目的重新表达出来。

我们把这种正向区间称为 **LLM卓越**。它出现于局部续写、表层流畅性、习得的体裁先验、语义联想与迭代修订，在整个任务范围内都与任务价值同向发力的时候，而不是只在零散片段中发挥作用。在这类区间里，自回归生成不是平庸的来源，而是卓越的机制。模型那种"继续合理续写、补全缺口、保持语体、把稀疏提示扩展成完整文本、枚举相邻概念"的倾向，本身就可能带来异常高的价值。

这一观察改变了我们对架构问题的理解。目标并不总是离开输出空间、构造一个解耦控制空间，再回到流畅文本中表达。这当然是一种重要方法。但更一般的目标是：**改变任务向模型呈现的形式**。如果一个困难任务可以被重参数化为一系列落入LLM卓越区间的子任务，那么普通生成就会从瓶颈变成资产。

例如，与其让模型直接产出一份高价值的战略分析，不如让它按以下步骤进行：

1. 将上下文压缩为决策变量；
2. 枚举隐藏假设；
3. 生成候选评分规约；
4. 识别失效模式与误导性代理指标；
5. 构造状态矩阵；
6. 创建结构大纲；
7. 基于该大纲撰写最终答案；
8. 用前面识别出的失效模式来验证结果。

每个子任务都比原始任务更容易，也更可能接近LLM卓越区间。系统之所以能避开平庸，并不是因为它让模型变得"不那么自回归"，而是因为它把模型面对的问题，改造成了那些"自回归与价值高度对齐"的子任务。

因此，本文的核心主张不是二元对立，而是三段式的。第一，LLM 平庸往往可以由这样一种结构性失配来预测：LLM 系统能够观察、表征、指定、支持、局部聚合以及从局部语境稳健泛化的东西，与任务真正奖励的东西并不一致。我们将其形式化为 **六失配视角**：聚合失配、支持失配、状态失配、规格失配、拟合边界失配与观测-表征失配。这六个轴并不是用来给所有表面失败现象贴标签，而是用来界定"可达生成"与"任务价值"之间发生分歧的原始来源。

第二，自回归局部对齐描述了大多数已部署任务真正所处的区间：模型的局部优势是实实在在的，但它们并不足以保证全局任务价值。第三，LLM卓越给出了干预的核心设计原则。系统可以通过这样一种方式缓解平庸：把高失配、或仅仅局部对齐的最终输出任务，转化为失配更低、正向对齐更强的中间任务。知识治理正是这种转化的一种有纪律的实现：它创建显式控制工件，对其进行验证，将其存储为受治理知识，并利用这些知识来引导流畅表达。

这一划分之所以重要，是因为许多直觉上很显眼的失败类别，虽然诱人，却不是原始类别。例如，顺序敏感的轨迹确实重要，但任务存在一个正确顺序，本身并不构成失配。只有当生成或搜索过程无法可靠地恢复、保持或验证这条所需轨迹时，它才真正体现为失配。类似地，有些目标并不能在看到候选输出之前就被完全明确；这是一种动态的规格失配来源，而不是新的原始类别。现实世界中的推理任务，经常需要从嘈杂场景中提取相关变量；这是一种复合性的建模失败，涉及规格、状态、支持，有时还涉及聚合失配。训练数据来源的不均衡会强烈塑造系统的默认叙事；当这种先验让某个局部可辩护解释压倒相邻解释时，它常常表现为拟合边界失配，并与支持、规格、状态和聚合效应交织。

本文有八点贡献。

1. 将 **LLM 平庸** 定义为：在预算约束下，推理过程集中于看似合理却次优的输出区域。
2. 澄清 **自回归平庸** 是 LLM 平庸的更窄子情形，主要对应聚合失配。
3. 提出六类原始失配，作为诊断理论，用于预测普通输出空间搜索何时会趋于平台期。
4. 将 **自回归局部对齐** 定义为：概率与任务价值在局部对齐、但在全局上并未对齐的常见中间区间。
5. 引入 **策略-价值压缩**，说明对齐训练如何把代理任务价值转化为策略概率，从而扩展局部对齐，却不消除结构性失配。
6. 将 **LLM卓越** 定义为：自回归续写与任务价值在相关任务结构上彼此增强的正向对齐区间。
7. 提出 **从平庸到卓越的转化**，作为一般性的反平庸原则：保留局部已对齐的操作，同时把高失配成分转化为失配更低、属于LLM卓越的子任务；并将这一原则展开为六种可复用的操作方法模式，每种都映射到它所对抗的原始失配（见第 6.8 节）。
8. 提出 **知识治理**，作为一种推理时控制框架，用于外化、验证、撤销并复用任务特定的控制知识，同时区分原始失配与派生/复合模式。

## 2. 相关工作

### 2.1 输出空间搜索与测试时改进

大量近期工作都在通过增加测试时计算来提升 LLM 输出。思维链提示鼓励模型生成中间推理 [1]；自一致性方法采样多条推理路径，并通过聚合选择答案 [2]；Tree-of-Thoughts 在中间状态上展开搜索 [3]；Self-Refine 与 Reflexion 使用迭代反馈来修订输出 [4, 5]；ReAct 则通过将语言生成与外部工具使用或环境交互交替进行，把推理与行动结合起来 [11]。

这些方法表明，推理时搜索的确可以改善推理、规划与任务表现。我们的论点与这条研究路线是一致的，但我们强调其中存在一个失败边界。当任务价值函数与局部合理性之间的对齐较差时，反复在流畅输出上进行搜索，仍然可能陷入平台期。此时，仅仅增加候选答案的数量，未必能暴露出系统摆脱低价值盆地所需的结构性知识。

其正向对应面同样重要。当局部合理性与任务价值强烈对齐时，额外的搜索、重写与扩展，能够层层累积出更高质量。此时，重复生成不再是在一堆平庸变体中搜索，而是在利用一个正向对齐区间。同样的机制，在失配下会失效，在对齐下却可能表现出色。

### 2.2 训练时对齐与策略-价值压缩

指令微调、基于人类反馈的强化学习和偏好优化，会在部署前改变模型策略。InstructGPT 风格的 RLHF 先用示范数据进行监督微调，再根据人类偏好排序训练奖励模型，随后基于该奖励信号优化模型策略 [13]。直接偏好优化（DPO）提供了更直接的偏好学习目标，可以在不单独训练奖励模型、也不运行强化学习回路的情况下，让语言模型对齐到偏好数据 [14]。过程监督则尝试对齐中间步骤，而不仅仅是最终答案 [8]。

我们的框架将这些方法理解为 **策略-价值压缩**。它们并没有用“可直接访问真实效用”来取代自回归概率，而是重塑模型策略，使某些代理价值在生成过程中变得更高概率。这解释了为什么对齐后的模型会比原始 next-token 模型有用得多，也解释了为什么随着训练改进，局部对齐会不断扩张。残留的问题在于：即便代理价值被成功压缩进策略概率，在分布偏移、隐藏状态、稀有结构或目标规格不足的情况下，它仍可能偏离真实任务价值。

### 2.3 检索、记忆与基于原则的控制

检索增强生成会把外部文档或记忆加入上下文 [6]。宪法式或基于原则的方法，则用显式的规范性或行为约束来引导输出 [7]。过程监督与步骤级验证，则尝试评估的不只是最终答案，还包括中间推理步骤 [8]。

知识治理与这些工作有一个共同点：都认为外部信息与显式约束可以改善模型行为。但它的关注点不同。它关心的是，如何在推理过程中诱导、验证、存储、弱化与撤销任务特定的控制知识。目标不只是事实知识的检索，还包括发现那些无法直接从检索文本中得到的结构依赖、边界条件、状态变量与可复用控制规则。

### 2.4 诱导知识与检索知识

检索知识来自外部语料；诱导知识则是从工件、失败案例、扰动、反例或反复的任务交互中推断出来的。知识治理主要关注的是诱导出的控制知识。系统可能观察到，某种对话模式在“用户沮丧”状态下会失效；某个代码模块泄露了未来信息；或者一段故事的逆转只有在前文埋下某个承诺时才成立。这样的知识未必是某篇事实文档，而是从经验中提取出来的任务特定约束。

这种区分之所以重要，是因为许多高价值失败并不是由“缺事实”引起的，而是由“缺控制知识”引起的：不知道哪些变量真正重要，不知道规则何时适用，不知道哪种依赖是非局部的，不知道哪些假设必须验证，不知道哪个来源先验会误导，也不知道哪些表面特征其实与任务无关。

### 2.5 规格不足与错误泛化

规格不足指的是：许多模型或策略都能拟合同样的观测数据，但在真实部署条件下却会表现不同 [9]。目标错误泛化则是指：系统在分布偏移下追逐某个代理目标或学得的目标，而这个目标与原本意图不一致 [10]。这些概念与规格失配密切相关；当部署行为依赖某个无法从观察中识别的潜在区间时，也与状态失配相关。

我们的框架将这一思路扩展到了推理时生成。提示词、评估器、基准测试或重排器，常常只能为真实任务价值提供一个局部代理。模型可能会把这个代理优化得很好，却错过了用户或领域专家真正看重的隐含标准。这是规格失配。另一个独立问题出现在动态场景中：一种在某个潜在状态下合适的策略，可能在隐藏状态改变且观察流没有暴露这种转移时变得不合适。这是状态失配。

### 2.6 从“解题”到“建模”

许多基准测试给出的，都是已经被抽象好的问题：相关变量已经点明，目标明确，场景中的无关细节也已被剔除。但现实任务往往还需要更早一步：从嘈杂的自然语境中，先提取出一个紧凑的问题模型。人类可能很快就能看出，在洗车场景里真正相关的对象是汽车，而不是走向商店的人；又或者，一根细长杆子之所以能穿过门口，是因为它可以沿着运动方向转动，而不是必须塞进二维门框矩形内部。

这个 **从场景到模型的抽象** 步骤，并不等同于求解抽象问题本身。模型也许擅长后者，却在前者上失手。我们将其视为一种复合失配模式，而不是独立的原始类别。它之所以重要，是因为这正是系统在干净基准任务上表现良好、却在嘈杂、规格不足或高度依赖常识的真实语境中显得脆弱的核心原因之一。

### 2.7 自回归局部对齐、正向对齐与任务重参数化

大多数推理时改进方法，都不仅仅是在“增加算力”，也在改变模型所面对的任务分布。要求模型先给计划再给答案的提示，会把最终输出生成转变为“先生成计划，再生成表述”；评分规约会把模糊偏好转化为显式评估结构；检索会把缺乏支撑的事实生成转化为有依据的综合；核对清单会把开放式质量判断转化为局部化验证。当新的子任务比原始任务更符合模型强项时，这些转化就可能成功。

本文用两个概念把这一观察明确化：自回归局部对齐与LLM卓越。于是，反平庸问题就变成了：任务中哪些部分已经局部对齐，哪些部分仍然失配，而这些失配部分是否能够被转化为一串中间价值与续写过程高度对齐的任务？

## 3. 作为六类失配问题的 LLM 平庸

接下来，我们将 LLM 平庸形式化为：LLM 系统的策略分布、观察通道、可访问规格与任务价值地形之间发生失配后，可预期产生的一种结果。

### 3.1 问题设定

令模型可访问的输入为观察序列 $o_{1:t} \triangleq x \in \mathcal{X}$，并令 $s_t \in \mathcal{S}$ 表示一个可选的潜在状态、环境状态或交互状态。这里有意区分状态与观察：模型条件化于观察、提示词、推理轨迹、检索文本、日志或其他可见工件，但输出效用可能依赖一个并不等同于这些观察的潜在状态。令 $y \in \mathcal{Y}$ 表示输出。令当前模型策略定义条件分布

\[
p_\theta(y \mid o_{1:t}),
\]

令任务效用为

\[
U(y; o_{1:t}, s_t) \in \mathbb{R}.
\]

对 $s_t$ 的依赖，允许效用随着隐马尔可夫状态、市场状态、时间语境、物理配置、制度环境、对话阶段、系统条件，或其他未被可见观察序列完整识别的任务相关变量而变化。

在现代部署系统中，$p_\theta$ 不应被理解为原始语料频率。它可能已经包含监督微调、RLHF、DPO 风格的偏好优化、过程监督、工具使用调优或其他对齐程序。因此，我们用 $p_\theta$ 统称当前模型策略。关键点在于：即便是对齐后的策略，仍然是概率性的；被价值塑形过的偏好，是通过轨迹概率来表达的。

我们考虑一个具有计算预算 $B$ 的推理过程 $\Pi_B$。这一过程可以包含采样、批判、重排、重写、工具使用、检索、有限搜索或自适应算力分配，并在可用预算下诱导出一个“实际可达候选”的分布：

\[
q_{\Pi_B}(y \mid o_{1:t}).
\]

将容忍度 $\tau \ge 0$ 下的近似最优集合定义为

\[
\mathcal{H}_\tau(o_{1:t},s_t) =
\left\{y \in \mathcal{Y}: U(y;o_{1:t},s_t) \ge U^\star(o_{1:t},s_t)-\tau \right\},
\quad
U^\star(o_{1:t},s_t)=\max_{y \in \mathcal{Y}} U(y;o_{1:t},s_t).
\]

如果在 $\Pi_B$ 下，推理过程虽然能产出局部上看似合理、高似然，或者在现有代理评估下得分很高的输出，却仍然集中停留在远离 $\mathcal{H}_\tau(o_{1:t},s_t)$ 的区域，我们就说该任务实例表现出 **LLM 平庸**。用第 3.2.2 节引入的记号来说，这等价于可达性得分 $r_{\tau,B}(o_{1:t},s_t)$ 很低；第 3.2 节的六类失配则是用于预测这种情况何时发生的、相对独立于具体推理过程的任务属性。

这个定义是操作性的。它并不意味着高价值输出从未出现在模型分布中，也不意味着模型绝不可能生成它们。它只是声称：在现实可承受的推理预算与常见搜索算子下，系统可能被困在那些容易生成、也容易做局部改进，却始终无法到达近似最优解的输出区域。

对于自然任务，再做一个额外区分会很有帮助。系统未必是直接求解 $o_{1:t} \mapsto y$，而可能需要先构建一个中间任务模型 $z$：

\[
z^\star = A^\star(o_{1:t},s_t), \qquad y^\star = S(z^\star).
\]

其中，$z^\star$ 包含相关目标、角色绑定、约束、隐藏状态变量、因果可供性、来源先验以及成功条件。一个常见失效是：系统构造的是 $\tilde{z}$，而非 $z^\star$，随后就在错误抽象之内进行流畅推理。这个现象本身不必再引入新的原始失配，但它足够重要，因此应被视为一种反复出现的复合模式。

### 3.2 六类原始失配来源

以下六类失配旨在作为原始诊断轴。只有在某个新增候选失配既不能被还原为这些轴及其交互、又能带来额外预测力，而且确实需要一种显著不同的干预方式时，它才应被纳入。

#### 3.2.1 聚合失配

当全局任务价值无法通过对前缀层面的改进进行求和、平均或局部细化而可靠恢复时，就会出现 **聚合失配**。

自回归生成天然是按“局部条件化决策”推进的。当任务价值大体可以由局部选择组合而成时，这种机制很有效；但当决定性效用依赖于高阶交互、长程协调，或彼此耦合、无法被局部收益良好近似的约束时，它就会变得不可靠。

这里正是 **自回归平庸** 的狭义而精确的归属。在这个子情形中，模型的局部 token 级续写过程，会把许多可能的意图、风格、约束和延续方式聚合进一个顺滑的局部分布里。因此，局部上最合理的续写，可能会稀释全局最高价值结构。自回归平庸并不等同于整个 LLM 平庸；它是由聚合失配产生的 LLM 平庸。

一种操作化方式，是把真实效用 $U$ 与一类 **窗口受限的局部可加代理函数** 进行比较。对于局部性视野 $k \ll T$，定义

\[
\mathcal{F}_{\mathrm{loc}}^{(k)} =
\left\{
F(y;x)=\sum_{t=1}^{T} f_t\!\left(x,\,y_{t-k:t}\right) : f_t(\cdot) \in \mathbb{R}
\right\},
\]

其中每一项可以依赖输入和至多 $k$ 个最近 token 构成的有界窗口；同时，逐项函数 $f_t$ 还应被限制在某个有界复杂度函数类中，例如由固定容量评分器可计算的函数类。令 $\rho$ 表示候选集合上的某种相关性度量。定义局部视野 $k$ 下的聚合对齐得分为

\[
\alpha_k(x,s) = \sup_{F \in \mathcal{F}_{\mathrm{loc}}^{(k)}} \rho(F(y;x), U(y;x,s)).
\]

窗口限制不是技术细节，而是为了避免定义退化。如果每个 $f_t$ 都可以依赖完整前缀 $y_{\le t}$，那么最后一项 $f_T(x,y_{\le T})$ 就是整个输出的函数，并且可以在固定实例上直接编码 $U(\cdot;x,s)$ 本身，使得任何任务上的上确界都被迫等于 1。因此，有意义的局部性得分必须同时限制窗口和逐项复杂度，这样 $\alpha_k$ 才能测量它本来要测量的东西：有界视野的局部信号能在多大程度上近似全局效用。

如果在中等视野下 $\alpha_k(x,s)$ 很低，就表明聚合失配非常严重；而 $\alpha_k$ 随着 $k$ 增大而变化的曲线，则揭示了非局部耦合的有效范围。在这类情形下，局部改进可能会让文风更好，却削弱逻辑；让共情更强，却拖慢问题解决；让某个代码组件更优，却悄悄违反另一个约束；或者让文笔更顺，却损害叙事回报。

这种失配是多目标协调、全局一致性、延迟回报，以及“全局最优并非局部好决策简单相加”这类任务的典型特征。

#### 3.2.2 支持失配

当近似最优解位于基础策略分布的低质量区域，或者高价值结构无法被可靠绑定到概率支持上时，就会出现 **支持失配**。低概率可能意味着噪声，也可能意味着稀有洞见；概率本身并不会标记哪些尾部结构有价值。

关键是：支持失配必须定义在基础策略 $p_\theta$ 上，而不是定义在搜索诱导出的分布 $q_{\Pi_B}$ 上。定义支持分数为

\[
\sigma_{\tau}(x,s)=
\Pr_{y \sim p_{\theta}(\cdot \mid x)}
\left[y \in \mathcal{H}_\tau(x,s)\right].
\]

同时，将某个推理过程的 **可达性得分** 定义为

\[
r_{\tau,B}(x,s)=
\Pr_{y \sim q_{\Pi_B}(\cdot \mid x)}
\left[y \in \mathcal{H}_\tau(x,s)\right].
\]

$\sigma_{\tau}(x,s)$ 较低，意味着支持失配严重：在任何搜索介入之前，近似最优解已经是模型策略本身的尾部事件。$r_{\tau,B}(x,s)$ 较低，则按照第 3.1 节的操作性定义，正是 LLM 平庸现象。区分这两个量，可以避免让分类法变成循环定义：如果支持失配直接定义在 $q_{\Pi_B}$ 上，它就只是在重复“平庸”的定义，而不是解释平庸。

这种区分让原因与现象之间的关系变得实质化。支持失配（低 $\sigma_\tau$）是 $(p_\theta,U)$ 这一对对象的结构性属性；平庸（低 $r_{\tau,B}$）则发生在推理过程未能修复这一属性时，也就是采样、重排、批判和修订虽然消耗了预算，却没有把质量集中到近似最优集合上。修复可能因其他轴而失败：规格错误的重排器即使遇到尾部候选也无法识别它们；局部修订无法从局部好片段中组合出稀有结构；隐藏状态也可能让系统完全搜索错了尾部。反过来，一个有效过程可以达到 $r_{\tau,B} \gg \sigma_\tau$，这正是成功扰动、重组、检索和控制空间搜索所做的事情。这个表述也让第 3.4 节的预测性假设变得可证伪，而不是定义性的：它把基础策略的可测属性同搜索过程的结果联系起来。

在未修改策略下反复采样，可能提高平均质量，却仍很难暴露真正决定成功的稀有结构。因此，支持失配最直接对应于“低概率、高价值”的发现问题：关键不变项并非不存在，而是在通常的自回归续写里过于罕见。在这种情况下，系统需要的往往不是继续多采样一些流畅补全，而是通过有意识的扰动、重组、检索或显化操作，把那些不太可能自行出现的结构关系暴露出来。

也可以这样表述这一失配：低概率结构无法仅靠模型策略本身直接与价值绑定。它们往往只能通过 **稀缺提示结构**、示例、对比约束、检索路径或受治理控制对象抵达，这些条件信号会把条件分布推向相关的低支持区域。因此，提示工程和控制空间构造并不只是风格指令；它们是重塑支持的机制，使稀有但有价值的结构变得可达。

#### 3.2.3 状态失配

当候选输出的正确排序取决于一个动态潜在状态 $S_t$，而这个状态在当前观测通道下不能被 LLM 可访问的观察序列直接识别时，就会出现 **状态失配**。

关键区分是：

\[
\text{观察} \ne \text{状态}.
\]

提示词、上下文窗口、检索段落、日志、对话历史和用户描述都是观察。它们可以是关于状态的证据，但并不是状态本身。在 HMM 或 POMDP 术语中，潜在状态会演化并发射观察：

\[
S_{t+1} \sim T(S_t,a_t), \qquad O_t \sim E(S_t),
\]

而 LLM 只条件化于某段观察历史：

\[
O_{1:t}=o_{1:t}.
\]

状态失配最强的形式，出现在两个潜在状态在观察上不可区分或不足以区分时：

\[
P(O_{1:t}\mid S_t=s_1) \approx P(O_{1:t}\mid S_t=s_2),
\]

但它们要求不同的最优输出：

\[
y^\star(o_{1:t},s_1) \ne y^\star(o_{1:t},s_2).
\]

在这种情况下，任何只以 $O_{1:t}$ 为输入的系统，都无法可靠知道哪个输出才是正确的。问题不在于提示词含糊，也不在于用户没有说清偏好；这是当前观测通道下的可识别性问题：问题域包含动态的、隐藏的、未测量的，或没有被可用观察充分区分的状态变量。LLM 最多只能维护一个后验分布

\[
P(S_t \mid O_{1:t}),
\]

而不能直接访问 $S_t$。

设两个看似都与同一观察序列 $o_{1:t}$ 相容的状态 $s, s' \in \mathcal{S}$。如果存在候选 $y,y'$ 使得

\[
U(y;o_{1:t},s) > U(y';o_{1:t},s)
\quad \text{but} \quad
U(y;o_{1:t},s') < U(y';o_{1:t},s'),
\]

那么偏好的输出就是依赖状态的。如果相关状态被隐藏、只能部分推断、动态变化，或无法由可用仪器测量，那么 $p_\theta(y \mid o_{1:t})$ 意义下的局部合理性，对于真实效用而言就只是一个很弱的指引。

一个有用的诊断量，是不同可能后验状态下排序的不稳定性：

\[
\delta(o_{1:t})=
\mathbb{E}_{s,s' \sim p(\cdot \mid o_{1:t})}
\Pr_{y,y' \sim q_{\Pi_B}(\cdot \mid o_{1:t})}
\left[
\operatorname{sgn}(U(y;o_{1:t},s)-U(y';o_{1:t},s))
\ne
\operatorname{sgn}(U(y;o_{1:t},s')-U(y';o_{1:t},s'))
\right].
\]

$\delta(o_{1:t})$ 越高，状态失配越严重。这意味着候选排序会随着可能潜在状态的变化而剧烈摇摆。在这类场景中，即便生成能力很强，系统也可能反复产出“单看并无问题”的回答，但这些回答可能在时机上不对、校准不准、附着于错误的潜在区间，或建立在错误的物理、时间、系统、市场或制度状态之上。

因此，状态失配刻画的是隐马尔可夫或部分可观测领域：动态博弈、非平稳环境、市场区间、变化中的系统状态、潜在对话阶段，以及其他效用依赖某个在当前观测通道下仍不确定的状态变量的场景。它 **不** 包括目标模糊、隐性偏好或评价标准不清。这些属于规格失配。它也不应吞掉所有缺通道问题：如果决定性的物理、社会、时空或验证变量根本没有进入模型可访问表征，那么更上游的失败是观测-表征失配。

#### 3.2.4 规格失配

当真实任务效用与生成、评估或修订过程中实际使用的代理目标存在实质性偏离时，就会出现 **规格失配**。

令 $\tilde{U}(y;o_{1:t})$ 表示可访问的代理目标：它可以是提示词暗含的目标、重排器得分、风格评分规约、基准指标、测试套件、受限自动评估器、学得的偏好模型，或从训练数据继承来的规范。如果存在候选 $y,y'$，使得

\[
\tilde{U}(y;o_{1:t}) > \tilde{U}(y';o_{1:t})
\quad \text{but} \quad
U(y;o_{1:t},s_t) < U(y';o_{1:t},s_t),
\]

那么任务就表现出规格失配。

等价地，也可以在候选池上考察 $\tilde{U}$ 与 $U$ 的排序相关性，作为诊断指标。若排序对齐度较低，就说明规格失配严重。

规格失配非常常见，因为训练数据和提示词都不会提供单一、干净的价值函数。训练数据包含许多彼此不兼容的“好”：考试答案、论坛建议、客服回复、学术解释、营销文案、法律式谨慎、安全拒答、社交礼貌，以及特定领域专家判断。提示词也常常模糊，例如“改得更好”“更有战略感”“写得更高级”“优化这个方案”或“给我最好的答案”。这些指令并没有指定一个完整奖励函数。

因此，模型经常像规格已经给定一样行动，尽管规格其实只是部分给定。它会退回到一种高支持的通用可接受性代理：流畅、平衡、完整、安全、传统意义上有帮助。这个默认代理可能有用，但不一定是真正的成功标准。

其中一个特殊情形是 **涌现式规格**。在一些任务中，委托方在看到候选输出之前，并不能完整说清自己真正想要什么。目标并未缺席，而是对委托方而言也部分处于潜伏状态，只有在进行对比性观察之后才逐渐显形。形式上，可访问的代理目标 $\tilde{U}_t$ 会随交互时间而演化：

\[
\tilde{U}_0 \rightarrow \tilde{U}_1 \rightarrow \cdots \rightarrow \tilde{U}_t.
\]

这是一种动态的规格失配来源，而不是额外的原始失配。如果真实效用本身也随着交互状态而变化，而不仅仅是被逐步发现，那么该现象还会进一步涉及状态失配。

#### 3.2.5 拟合边界失配

设 X 是模型已经学到或近似学到的一种能力、策略、审计结构或行为模式。令 $T_X$ 表示真实世界中应该使用 X 的任务区域，$M_X$ 表示模型实际激活 X 的任务区域。当

\[
M_X \ne T_X
\]

时，就会出现 **拟合边界失配**。

它的过拟合侧或过触发侧是 $M_X \setminus T_X$：不该使用 X 的地方使用了 X。它的欠拟合侧或欠触发侧是 $T_X \setminus M_X$：模型已经具备或近似具备 X，却没有在应该使用 X 的地方激活它。

能力不是像软件插件一样被独立安装进模型，而是在共享参数与共享表示空间中形成概率场，同时隐式学习一个决定何时调用能力的 router。训练、微调、对齐和推理都可能让这个 decision boundary 向两个方向偏移：边界过宽会增加误触发，边界过窄会增加漏触发。前者常表现为幻觉、伪机制或错误套用，后者常表现为低采用面、欠搜索或正确能力未调用。

这类失配包括若干常见子型：

- **证据链过拟合：** 把一个局部可辩护解释升级成唯一因果解释。
- **代理指标过拟合：** 把 benchmark、评分规约、奖励模型或测试分数当成目标本体，而不是目标的部分证据。
- **场景默认值过拟合：** 即使当前任务已经给出区分性信息，模型仍被某个常见领域默认值拖走。
- **解法路径过拟合：** 早期推理路径自我强化，后续分析被用来替这条路径辩护。
- **角色或话术过拟合：** 专业谨慎、安全话术、法律式平衡或领域黑话，取代了继续搜索。
- **能力欠触发：** 搜索扩展、状态枚举、来源核验、工具使用等模型已经具备的能力，没有在应该调用时被激活。
- **用户反馈过拟合：** 局部偏好适配变成迎合或过度纠偏，而不是对齐真实任务。

这个轴不同于聚合失配，因为它关注能力路由，而不是局部结果如何组成全局结果。它也不同于支持失配：相关能力必须已经存在或近似可用，只是触发边界错误。它还不同于规格失配和状态失配，因为目标与状态可能已经足够清楚。严格判据是：如果不补充根本性新知识、不重写目标、也不新增不可得状态，只调整能力 router、触发阈值或边界校准，就有望修复问题，那么它才属于拟合边界失配。

这一类内部包含过拟合侧与欠拟合侧。前者包括能力吸引子外溢、证据链过拟合、代理指标过拟合、场景默认值过拟合和路径锁定；后者包括搜索、审计、机制翻译、工具调用和条件化能力的欠触发。更完整的展开见专题工作稿：[拟合边界失配](fitting-boundary-mismatch.zh-CN.md)。如果需要把六类原始失配进一步转换为系统组件与干预选择，见补充工作稿：[LLM 失败的形式化机制层](formal-mechanism-layer.zh-CN.md)。

#### 3.2.6 观测-表征失配

当任务相关的世界变量，在真实世界进入 LLM 系统的观测、编码、tokenization、embedding、上下文压缩、检索、记忆或控制表征通道中，被丢失、压缩、混叠，或变得不可操作时，就会出现 **观测-表征失配**。它的工程别名是 **观测通道失配**。

这不是简单说“当前 latent state 不知道”。更准确地说，是当前可用表征本身并不是世界状态的任务充分表征。令 $S$ 表示真实世界状态，$C^\star(S)$ 表示任务充分控制变量，$\phi:S\to O$ 表示观测通道，$\psi:O\to Z$ 表示模型可访问表征。系统实际作用于

\[
Z=\psi(\phi(S)),
\]

而不是直接作用于 $S$。当存在两个状态 $s_1,s_2$，使得

\[
\psi(\phi(s_1)) \approx \psi(\phi(s_2)),
\]

但

\[
C^\star(s_1) \ne C^\star(s_2),
\]

并且这种控制变量差异会改变候选输出或行动排序：

\[
\arg\max_y U(y;s_1) \ne \arg\max_y U(y;s_2),
\]

就发生了观测-表征失配。

等价地，基于模型可访问表征的最优策略，严格差于基于真实状态的最优策略：

\[
\max_{\pi:Z\to Y}\mathbb{E}[U(\pi(Z);S)]
<
\max_{\pi:S\to Y}\mathbb{E}[U(\pi(S);S)].
\]

这个差值是表征造成的理论上限。它不能通过在同一表征上延长推理来消除，而需要改变观测通道、增加测量、调用工具、查询环境、构造更丰富的控制表征，或明确标记缺失变量不可得。

典型例子包括：图片中不可见的物理可供性、文字中没有保留的社会线索、静态帧中丢失的时间动态、生成答案中缺失的验证信号，以及重量、力量、阻力、温度、脆弱性、行动成本等 embodied variables。

这个失配与状态失配相邻，但干预位置不同。状态失配要求系统在给定观测通道下维护可能潜在状态的后验，并输出条件化策略。观测-表征失配则先问：当前观测与编码通道是否足以支持任何可靠的条件化策略？如果不足，正确干预不是仅仅枚举状态，而是取得或构造更好的观测通道。

它也不同于拟合边界失配。拟合边界失配问的是某个已学能力是否被路由到真实适用边界内。观测-表征失配问的是决定性世界变量是否进入了任何能力可路由的表征空间。操作性判据是：如果主要改善来自补测量、原始证据、模态、工具反馈、传感器数据、日志、测试、环境交互或更丰富的结构化表征，而不是来自改变能力 router 或在同一输入上想更久，那么更应归入观测-表征失配。

### 3.3 新增失配类别的判据

六失配分类法只有在保持纪律性时才有价值。许多现象确实重要，但不应自动升级为新的原始类别。我们采用如下标准：

> 只有当某个候选失配同时满足三个条件时，才应被视为独立的原始类别：它无法被还原为六类原始失配及其交互；它能带来额外的预测力；它需要一种有实质区别的干预方式。

据此，一些看似诱人的新增类别应被排除在外。

**序列或轨迹失配** 本身不是原始类别。任务具有正确顺序，这是任务属性，而不是失配。只有当系统无法恢复、保持或验证所需轨迹时，失配才真正出现。根据原因不同，它可分解为聚合失配、支持失配或状态失配。

**目标涌现** 本身也不是原始类别。它描述的是代理目标如何在交互中逐步成形。更合适的处理方式，是把它视为涌现式规格，也就是规格失配的一种动态来源，有时还会与状态失配相互作用。

**噪声语境下的信号提取失败** 也不是原始类别。它是一类复合性的任务建模问题：系统必须先从自然场景中推断出紧凑的任务模型，然后才能求解抽象问题。根据识别错误发生在哪里，这类失败可分解为规格、状态、观测-表征、支持和聚合失配。

**训练数据或语料来源失衡** 同样不是原始类别。它可能制造出强势的默认叙事、显著性模式或评估先验，但最终表现出的失败，通常仍会以支持失配、规格失配、状态失配，有时还包括聚合失配的形式出现。

**复杂任务崩塌** 也不是原始类别。它是一种预算约束下的控制容量区间：任务的原始失配负载，超过了系统在当前模型、推理预算、表征与路由策略下的有效控制能力。提高自适应算力或改进控制表征，可能让同一个任务脱离崩塌状态。变化的是可达性与控制能力，而不是新增另一条失配轴。

这些类别的价值，不在于扩充原始分类，而在于为诊断和干预中反复出现的重要交互模式命名。

### 3.4 失配画像与预测性假设

对于任务实例 $(x,s)$，将 **失配画像** 定义为一个概念向量：

\[
\mathbf{m}(x,s)=
\big(
\mathsf{A}_k(x,s),
\mathsf{S}_{\tau}(x,s),
\mathsf{D}(x),
\mathsf{M}(x,s),
\mathsf{F}(x,s),
\mathsf{R}_{\mathrm{obs}}(x,s)
\big),
\]

其中六个分量分别对应聚合、支持、状态、规格、拟合边界与观测-表征失配。聚合分量通过第 3.2.1 节的窗口受限得分 $\alpha_k$ 来度量；支持分量则在基础策略 $p_\theta$ 上，通过第 3.2.2 节的 $\sigma_\tau$ 来度量。拟合边界分量刻画能力实际触发域 $M_X$ 与真实适用域 $T_X$ 的偏离，包括 false-positive 与 false-negative 路由。观测-表征分量刻画 $\psi(\phi(S))$ 是否保留了影响排序或行动的任务充分控制变量。实际应用中，可以通过候选池、任务探针、邻域扰动、能力路由混淆矩阵、通道消融、补测量实验、失效分析、人工诊断或领域验证器来近似。

本文的核心假设是：

> **预测性假设。** 在固定模型类别和推理预算的条件下，随着与过程无关的失配画像 $\mathbf{m}(x,s)$ 变得更严重，输出空间搜索所达到的可达性 $r_{\tau,B}(x,s)$ 会下降；而不同失配分量之间的相互作用，往往具有超加性。

由于失配画像定义在 $(p_\theta,U,\tilde{U},\mathcal{S})$、通道充分性与能力路由测试上，而可达性定义在 $q_{\Pi_B}$ 上，这一假设联系的是两个不同对象，因此是可证伪的，而不是定义性的。超加性也有机制来源：规格失配会污染评估器；状态失配会污染验证；观测-表征失配会让验证或行动所需变量根本没有进入系统；聚合失配会阻止组合；拟合边界失配则会过度触发错误修复算子，或没有触发正确修复算子。多种失配叠加时，可能禁用本来可以修复单一失配的通道。

这引出一个实用启发式：

- **仅有一种主导失配：** 更强的提示、重排、检索、有限搜索或更多算力，可能就足够。
- **存在两种显著失配：** 普通的输出空间搜索通常开始出现平台期。
- **存在三种及以上显著失配：** 任务重参数化或引入解耦控制层，就会成为强有力的候选方案。

### 3.5 派生型与复合型失败模式

六类原始失配能解释许多反复出现的表层模式。下面这些模式之所以值得单独命名，是因为它们在实践中很重要；但不应把它们误认为新增的原始类别。

#### 3.5.1 顺序敏感的轨迹恢复失败

有些任务要求决策、揭示、解释或行动按正确顺序展开。故事需要先铺垫再兑现；客服对话可能需要先确认情绪再排障；代码库可能需要先满足依赖顺序再执行；战略制定可能需要先收集信息再做承诺。

问题不在于“存在序列”本身，而在于局部搜索无法稳定恢复或保住所需轨迹。这可能是因为局部改进无法组合成全局成功，也可能是因为正确轨迹本身罕见，或者因为下一步该怎么走取决于潜在阶段或状态。

因此，合适的干预方式不是简单再贴一个“序列标签”，而是把轨迹状态外化出来，验证阶段转换，并把顺序约束存储为受治理知识。

#### 3.5.2 涌现式规格

有些任务无法在看到候选输出之前被完整规格。用户可能在看到多个备选结尾之前，并不知道哪种故事结局才“对味”；产品经理可能在比较多版草稿之前，无法说清“清晰、野心与风险”三者该如何权衡；领域专家也可能只有在检查具体工件后，才识别出某种细微但关键的违规之处。

这种现象很重要，但它不是原始类别。它是规格失配中的一条动态路径：代理目标会在对比式暴露过程中变得越来越清晰。相应的干预方式，是偏好澄清、成对比较、评分规约迭代，以及显式更新代理目标 $\tilde{U}_t$，而不是把初始提示词当作一个固定且完备的目标函数。

#### 3.5.3 噪声语境下的建模失败

许多现实任务并不是以干净、抽象的问题形式出现的。它们嵌在包含无关细节、误导线索、隐含目标、角色绑定与背景常识的场景里。系统首先要做的是构造正确的任务模型。

噪声语境下的建模失败是复合模式，但其中的成分应当拆开：当系统误认成功条件、角色绑定或评价标准时，主要是规格失配；当相关状态已经进入表征但当前取值仍不确定时，主要是状态失配；当决定性的物理、社会、时空或验证变量根本没有进入模型可访问表征时，则是观测-表征失配；当正确抽象在策略分布中很罕见时，支持失配也会参与；当错误抽象导致局部自洽推理违反全局依赖时，则有聚合失配。

以洗车为例。如果一家洗车店离家五十米，应该开车去还是走路去？浅层的距离启发会让人觉得走路就好。但真正的成功条件不是“人到店”，而是“车被洗了”。真正承载目标状态变化的是车，而不是人。这首先是一个规格和角色绑定失败，同时带有状态成分。

再看“门与长杆”的例子。一扇门高两米、宽两米，一根五米长的杆能否穿过去？如果这根杆足够细，而且门两侧空间足够，它是可以通过调整朝向、沿着运动方向穿过门口的。错误的二维抽象会把杆长与门的对角线相比，从而得出“不能通过”的结论。这里目标其实很清楚；真正失误的是对物理可供性、抽象层级与隐含假设的把握。如果相关物理配置已经进入表征但当前值不确定，它更接近状态失配；如果通道或编码把三维行动问题压成二维视觉代理，使截面、朝向路径或周围可操作空间根本没有进入 \(Z\)，它就是观测-表征失配。

一般模式可以写成：

\[
x \rightarrow \tilde{z} \rightarrow y,
\]

其中 $\tilde{z}$ 是错误的任务模型。后续推理也许在局部上完全自洽，却始终是在回答一个错误抽象层次上的问题。这种模式，是“在干净基准上表现不错”与“在真实场景里稳定推理”之间鸿沟的核心来源之一。

一个有用的实验性度量是 **建模缺口**：

\[
\operatorname{ConstrualGap} =
P(\text{correct} \mid \text{clean abstract form})
-
P(\text{correct} \mid \text{noisy natural scene}).
\]

如果这个缺口很大，就说明失败发生在“从场景抽象出问题模型”这一步，而不在抽象问题求解本身。

#### 3.5.4 结构-信号缺口

结果层面的反馈，或许能告诉系统“这个答案失败了”，却无法指出到底是哪一个稀有的结构依赖，使得更好的答案之所以成功。这就是 **结构-信号缺口**。它常见于这样一些情形：系统能得到最终得分、用户评分或测试结果，却无法从中定位成败的结构性原因。

这种模式通常是支持失配与聚合失配共同作用的结果。决定成败的结构很稀有，而局部改动又无法显露出它的贡献。知识治理的做法，是通过扰动工件、比较不同失败样本，并尝试把结果层面的反馈转化为显式的结构性假设。

#### 3.5.5 表征或控制空间缺口

有些方法之所以失败，不是因为模型完全缺乏相关知识，而是因为当前使用的表征不对。系统也许正在搜索流畅段落，但它真正应该搜索的是情节点、策略状态、物理变量、依赖图、经济区间或风险过滤器。这个瓶颈不自动构成新的原始类别：如果决定性变量已经可得，只是系统选择了错误搜索表征，它通常是聚合、规格、支持或拟合边界失配的复合表现；如果决定性变量根本没有进入模型可访问表征，它就是观测-表征失配。两种情况都推动任务特定构造器与解耦控制空间。

#### 3.5.6 语料先验主导

有些任务涉及历史、文化、地缘政治、制度或道德评价。在这些场景里，模型的默认回答往往会受训练语料中高频、或高权威叙事的强烈影响。失败未必来自事实无知。模型可能知道少数证据或替代性框架，但如果缺少显式提示、检索或治理，这些框架仍然会保持低显著性、低概率。

与其把它当作额外原始失配，不如把它理解为 **语料先验主导**。它通常可以分解为：

- 支持失配：不常见但与任务相关的框架难以触达；
- 规格失配：模型把主流叙事当成了评估标准；
- 状态失配：正确评估依赖于时期、制度角色、发展阶段或背景条件；
- 聚合失配：局部成本或可见失败遮蔽了系统层面效应。
- 拟合边界失配：高频叙事或局部解释模板被绑定得太死，压制了相邻替代解释。
- 观测-表征失配：来源通道或摘要表征丢失了区分叙事所需的一手证据。

合适的干预方式，是进行来源先验治理：把主导叙事、反叙事、证据基础、因果机制、评估指标与反事实比较拆开处理。

#### 3.5.7 预算约束下的控制容量崩塌

在足够复杂的任务上，有些系统会迅速坍缩为低质量输出。这种崩塌不是新的原始失配。它出现于这样一种情形：任务的失配负载超过了系统的有效控制能力：

\[
C_{\mathrm{eff}}(M,\Pi_B,R) < L_{\mathrm{mismatch}}(x,s),
\]

其中 $M$ 是模型，$\Pi_B$ 是带预算的推理过程，$R$ 是当前表征，而 $L_{\mathrm{mismatch}}$ 则是由聚合、支持、状态、规格、拟合边界与观测-表征失配共同构成的综合负载。

同一个任务，在算力自适应更强、任务路由更好、控制状态更稳定或表征更优的系统上，可能就不会发生崩塌。这正是为什么复杂任务崩塌应被视为一种“模型-预算-控制”区间，而不是原始失配。对应的干预方式，是提升有效控制能力，或者把任务改造成失配更低的子任务。

### 3.6 与任务模式的关系

六类失配比领域标签更基础。许多反复出现的任务模式，都可以理解为某些典型的失配画像。

| 任务模式 | 主导失配 | 典型次级失配 | 说明 |
|---|---|---|---|
| 多目标协调 | 聚合 | 规格 | 局部改进会与隐藏的全局约束发生权衡。 |
| 低概率、高价值发现 | 支持 | 聚合 | 决定性结构在普通续写下很稀有。 |
| 动态博弈 / 非平稳适应 | 状态 | 规格 | 效用会随着潜在区间或演化中的状态改变。 |
| 隐性、专家型或对抗性评估 | 规格 | 状态 | 可访问的代理目标偏离真实质量。 |
| 顺序敏感轨迹 | 聚合 / 状态 | 支持 | 所需序列是派生模式，而不是原始类别。 |
| 涌现式规格 | 规格 | 状态 | 代理目标在交互中逐渐清晰。 |
| 噪声语境建模 | 规格 / 状态 / 观测-表征 | 支持 / 聚合 | 系统必须先构造正确任务模型；决定性变量没有进入 \(Z\) 时，观测-表征是原始失配。 |
| 缺通道变量 | 观测-表征 | 状态 / 规格 | 任务需要测量、原始证据、模态、工具反馈或更丰富控制表征，条件化推理才有资格闭合。 |
| 语料先验主导 | 支持 / 规格 | 状态 / 聚合 | 默认叙事会压制低显著但任务相关的框架。 |
| 控制容量崩塌 | 复合区间 | 表征 / 预算 | 失配负载超过了有效控制能力。 |

这一点之所以重要，是因为同一应用往往会同时实例化多种失配来源。比如，高完整性的代码合成可能同时包含聚合失配、支持失配、规格失配，以及测试日志、运行 trace 或环境状态没有进入上下文时的观测-表征失配。而一个嘈杂的现实推理任务，则可能同时包含观测-表征失配、状态失配、规格失配与支持失配。

## 4. 自回归局部对齐

LLM 平庸与LLM卓越是两个有用的极点，但大多数真实任务处于二者之间。我们把这个中间区间称为 **自回归局部对齐**，也就是 **概率-价值的局部对齐**。在这一状态下，模型的统计续写倾向与任务价值函数的某些部分相一致，但这种一致性只是部分的、条件性的，并不足以保证全局成功。

局部对齐并不是平庸的弱化版本，而是一个独立的运行区间。系统完全可能做出真正有用的工作：压缩上下文、保持语体、生成候选结构、写出清晰文本、枚举边界情形，或实例化熟悉模式。真正的风险出现在：这些局部上有价值的操作，被误当成了全局任务已经完成。

### 4.1 定义

设 $x$ 表示输入，$s$ 表示相关的潜在状态或环境状态，$y$ 表示最终输出。当某个任务实例在推理过程 $\Pi_B$ 下满足以下条件时，我们说它表现出 **局部对齐**：某些可达的局部操作与任务价值形成正向对齐，但最终输出过程并不能在全局上稳定抵达近似最优集合 $\mathcal{H}_\tau(x,s)$。

直观地说：

\[
\text{局部似然方向} \approx \text{局部任务价值方向},
\]

但是

\[
\text{局部似然方向} \not\Rightarrow \text{全局任务价值方向}.
\]

等价地说，模型也许在局部续写、片段、转换或子任务上很可靠，但在完整任务轨迹上仍然不可靠。一个局部对齐的系统，可能会生成部分正确、部分有洞见、部分经过精修的输出，却仍然失败，因为全局目标、状态条件、角色绑定、结构依赖或评估标准没有被保住。

### 4.2 形式化刻画

对于一个经过转化或分解的任务，假设系统先构造中间对象

\[
Z=(z_1,z_2,\ldots,z_k)
\]

再据此生成最终输出

\[
y=R(Z,x).
\]

令 $u_i(z_i;x,s,z_{<i})$ 表示某个中间对象或操作的局部价值，令 $U(R(Z,x);x,s)$ 表示组合后的全局任务效用。一个局部对齐得分可以概念化地写作

\[
\ell_i(x,s)=
\rho\left(
\log q_{\Pi_B}(z_i \mid x,z_{<i}),
u_i(z_i;x,s,z_{<i})
\right),
\]

其中 $\rho$ 是候选池上的排序或相关性度量。当许多 $\ell_i$ 为正，但组合后的输出并不能稳定接近最优时，我们就处在局部对齐区间：

\[
\Pr_{Z \sim q_{\Pi_B}}
\left[R(Z,x) \in \mathcal{H}_\tau(x,s)\right]
\]

此时往往处于中等水平、不稳定，或者对表征、验证与控制策略高度敏感。

这就把局部对齐与相邻两个区间区分开来：

- 在 **LLM 平庸** 中，局部合理性对于决定价值的结构来说，本身就是薄弱甚至误导性的代理。
- 在 **局部对齐** 中，许多局部操作确实有用，但它们的组合并不会自动保住价值。
- 在 **LLM卓越** 中，局部操作在给定预算与表征下，通常会自然组合成全局质量。

### 4.3 作为默认人类任务区间的局部对齐

人们在使用 LLM 系统时，最常遇到的恰恰就是局部对齐区间。面向人的任务很少是价值函数完全显式的纯数学问题，但也很少是纯粹的对抗式搜索问题。它们通常同时包含：

- **常规语言或结构性工作**，模型在这部分与任务价值高度一致；
- **上下文压缩与再表达**，自回归常常很有帮助；
- **隐性标准**，用户真实目标规格不足；
- **隐藏状态**，正确答案依赖于提示中未完全显露的信息；
- **非局部结构**，局部改进未必能够自然组合；
- **稀有高价值动作**，关键洞见并不是默认续写。

这正是为什么很多输出会同时让人觉得“不错”又“不够”。模型也许写出了正确类型的文档、用对了语气、做出了许多局部上正确的动作，但仍错过了真正决定成败的变量。它可能给出了一份好计划，却在隐藏约束下失效；也可能给出了一段修饰精良的回答，却优化的是可访问代理，而不是用户真正的目标。

### 4.4 局部对齐的诊断迹象

当输出具有真实的局部质量，却缺乏完整的全局任务价值时，局部对齐就显现出来了。常见迹象包括：

- 文笔清晰，但问题建模错了；
- 大纲看似合理，但关键依赖没有出现；
- 例子有帮助，但评估标准放错了位置；
- 回答在事实层面说得过去，但条件化在错误的潜在状态上；
- 代码写得很地道，却破坏了非局部不变项；
- 故事场景很强，但承诺与兑现结构很弱；
- 建议论证充分，却优化了错误目标；
- 用户回复很有同理心，但相对于对话状态来说时机不对；
- 多个候选看起来差异不小，却共享同一个隐藏失败。

用户最典型的反应是：“这已经不错了，但还不是最关键的那个点。” 这正是局部对齐的标志。模型确实创造了价值，但并不是最终成败所依赖的那种价值。

### 4.5 局部对齐与六类失配

局部对齐仍然可以沿着同样六条原始失配轴来分析。

| 失配轴 | 局部对齐形态 | 典型失败 |
|---|---|---|
| 聚合 | 局部改进真实存在，但无法自动组合。 | 打磨过的局部削弱了全局结构。 |
| 支持 | 一些有用结构很容易得到，但真正决定成败的结构很稀有。 | 模型绕着答案打转，却始终没有显化关键不变项。 |
| 状态 | 某个答案在一种状态下局部合理，换一个状态就错。 | 模型为错误区间给出了合理回答。 |
| 规格 | 提示词代理捕获了部分价值，却漏掉了隐性标准。 | 模型把清晰、语气或格式优化好了，却没有真正成功。 |
| 拟合边界 | 有用能力在真实适用域外被激活，或在真实适用域内被遗漏。 | 错误能力被触发，或正确能力没有被触发。 |
| 观测-表征 | 局部表征很流畅，但缺少任务充分的世界变量。 | 模型围绕可见代理推理，却缺少测量、可供性、社会语用、时空或验证变量。 |

这张表说明，局部对齐不应被视为额外的原始失配。它是一种由“部分正对齐 + 残余失配”共同构成的运行区间。真正原始的问题依旧是：局部对齐在何处停止，又是哪类失配阻止它升格为全局对齐？

### 4.6 设计后果

局部对齐会改变干预策略。如果任务完全是高失配的，系统可能需要相当强的控制空间搜索；如果任务本来就处于卓越区间，那么沉重治理反而没有必要。但如果任务处于局部对齐，那么正确策略应当是有选择地介入：

1. 保留那些已对齐的操作，如压缩、列纲、改写、风格迁移、矩阵构造与语义解压；
2. 找出局部续写不再是可靠价值代理的边界；
3. 将这些边界外化为评分规约、状态谓词、不变项、失效模式或 GKO；
4. 验证组合过程，确保局部好的部分在全局上仍然一致；
5. 只有当控制结构足够稳定后，再进行流畅表达。

从这个意义上说，局部对齐正是知识治理最自然的目标。治理不应该与模型的自回归强项对着干，而应当把这些强项收集起来，在它们开始变得不安全或误导时加以约束，并把部分对齐转化为更稳定的全局对齐。

### 4.7 与三段式视角的关系

最终得到的三段式视角如下：

| 区间 | 概率-价值关系 | 典型输出 | 偏好的干预方式 |
|---|---|---|---|
| **LLM 平庸** | 系统性偏离或低可达性 | 流畅但困在低价值盆地 | 重参数化、搜索控制空间、强化验证 |
| **局部对齐** | 局部正对齐但全局不稳定 | 片段有用、整体不完整 | 保留已对齐部分，治理边界与组合 |
| **LLM卓越** | 稳定的正向对齐 | 局部改进自然累积为全局价值 | 直接生成或轻量搜索 |

这个中间区间很重要，因为大多数实际用户任务就是从这里开始的。用户很少面对一个在任务上毫无用处的 LLM；他们面对的通常是一个“足以创造局部价值，但还没有被治理到能把局部价值稳定转化为最终成功”的系统。

### 4.8 策略-价值压缩与局部对齐的扩张

一个有用的澄清是：对齐后的 LLM 不应被理解为“只是遵循原始词频”的系统。预训练会诱导一个 token 续写分布，但监督微调、基于人类反馈的强化学习、偏好优化、过程监督以及相关方法，都会重塑这个分布。它们使某些轨迹更高概率，不是因为这些轨迹仅仅在预训练语料中更常见，而是因为它们更好地满足了“有帮助”“正确”“无害”“符合用户意图”或“任务成功”的某种代理。

从这个意义上说，对齐训练执行的是一种 **策略-价值压缩**。代理任务价值并不是被直接输出为“价值”，而是被压缩进模型策略，并在推理时表现为 token、推理轨迹、工具调用、中间状态与输出路径上的概率分布：

\[
U_{\mathrm{proxy}} \rightarrow \pi_{\theta}^{\mathrm{aligned}}(y \mid x).
\]

这就是为什么可以把强化学习和偏好优化理解为某种任务价值对齐：它们并没有让模型停止使用概率，而是重塑了概率地形，使许多有价值的续写更容易被抵达。输出仍然是自回归的；只是概率分布吸收了代理价值。

这也解释了为什么随着反馈质量提升，局部对齐的区域会不断扩大。越来越多任务会从“概率-价值分离”移动到“概率-价值局部对齐”，而其中一部分还会进一步进入LLM卓越。模型越来越可能生成局部有用、遵循指令、偏好对齐、与任务相关的续写。

推理时思考又在测试阶段进一步延展了这一过程。思维链、自一致性、树搜索、过程反馈与迭代修订，不只是多吐出一些 token；它们会创造出中间状态，使原始任务能够被分解为更小的操作：

\[
x \rightarrow z_1,z_2,\ldots,z_k \rightarrow y.
\]

这些中间操作包括建模提取、假设枚举、状态列举、评分规约构造、候选生成、边界情形发现、验证以及最终表达。它们中的许多，比原始最终输出任务更容易形成局部对齐。因此，思考扩展的是局部对齐的 **可达区域**，而对齐训练扩展的是局部对齐的 **习得区域**。

然而，策略-价值压缩并不会消除结构性失配。它只是扩大了概率与价值能够保持对齐的区域。在开放式任务中，真实效用仍可能依赖于非局部聚合、低支持结构、潜在状态或规格不足的目标。训练数据、偏好标签、奖励模型或更长推理链，并不能保证把这些因素完整编译进去。思考更久也许会暴露更多结构，但如果当前表征是错的，它也可能只是把错误的建模合理化得更充分。

这一差别可以概括为：

| 机制 | 扩展了什么 | 仍未解决什么 |
|---|---|---|
| **预训练** | 语言、世界模式、语义先验、常见轨迹 | 语料概率并不等同于任务价值 |
| **SFT / RLHF / DPO** | 代理性的人类偏好、指令遵循、有用性、安全性、任务风格对齐 | 代理价值不总是真实任务价值 |
| **过程监督** | 在既定标准下的步骤级正确性 | 标准可能漏掉隐藏状态、稀有结构或全局效用 |
| **思考 / CoT / 搜索** | 可达的中间状态与局部对齐分解 | 更多推理仍可能沿着错误表征展开 |
| **检索与工具** | 外部事实、外部状态、可执行检查、当前证据 | 系统仍需要正确的问题、控制表征与价值准则 |
| **知识治理** | 被外化、验证、可撤销的任务控制知识 | 它仍依赖控制空间质量、验证强度与治理成本 |

这正是为什么局部对齐才是主导性的现实区间。模型既不是原始的 next-token 频率机器，也不是完全被价值统治的推理者。它是一个策略已经吸收了大量代理价值、推理过程能进一步暴露局部结构，但在局部对齐无法自然组合成全局成功时，仍需要治理的系统。

## 5. LLM卓越

局部对齐描述的是常见的混合区间，但有些任务还表现出更强的性质：模型的自回归续写过程，会在相关任务结构上自然朝高价值输出推进。我们把这一正向极点称为 **LLM卓越**。

### 5.1 定义

令 $\mathcal{H}_\tau(x,s)$ 表示上文定义的近似最优集合。当某个任务实例在 $\Pi_B$ 下满足以下条件时，我们说它表现出 **LLM卓越**：高价值输出不是尾部事件，而是在该推理过程中很容易抵达：

\[
\Pr_{y \sim q_{\Pi_B}(\cdot \mid x)}
\left[y \in \mathcal{H}_\tau(x,s)\right]
\]

较高，并且普通的局部操作，如续写、重写、扩展、压缩、风格调整或结构格式化，通常会增加而不是降低任务价值。

直观地说：

\[
\text{局部似然梯度} \approx \text{任务价值梯度}.
\]

在 LLM 平庸中，容易续写的东西并不是真正有价值的东西；在局部对齐中，容易续写的东西往往只在局部有价值，仍不足以保证全局成功；而在LLM卓越中，容易续写的东西往往正是任务整体所奖励的东西。

这一区分至关重要。同一个模型，在某个任务上可能表现平庸，在另一个任务上处于局部对齐，在第三个任务上又是卓越的。差别并不只是“模型聪明程度”，而是模型分布、推理过程、当前表征与任务效用之间的对齐关系。

### 5.2 正向对齐条件

LLM卓越通常会在以下几类条件同时成立时出现。

#### 5.2.1 高支持下的卓越

高价值输出本身就位于模型分布的高概率区域。系统不需要去发现罕见的不变项、非常规策略或低频结构，而只需要实例化一种模型已经大量见过、且质量较高的模式。

典型例子包括标准邮件、摘要、常见解释、样板代码、README、SOP、政策模板、常见 SQL 模式以及标准文档。

#### 5.2.2 从局部到全局的可组合性

局部改进确实会组合成全局改进。删掉一句冗余的话会让段落更好；加入清晰的过渡会让整篇文档更顺；保持表格模式会改善比较清晰度；收紧定义会提升周边解释。

在这一区间里，聚合失配较低。自回归生成的“局部性”不是负担，而是一种有益的搜索偏置。

#### 5.2.3 显式或稳定的状态

相关状态要么已经显式给出，要么足够稳定，或者根本不是决定性的。改写任务通常不需要隐藏的市场区间或变化中的用户情绪；对已提供文档做摘要，不需要推断未观测到的物理可供性；翻译任务往往可以直接基于给定文本展开，而无需深层潜在状态建模。

当状态稳定时，模型的默认续写就更不容易条件性地出错。

#### 5.2.4 规格对齐

可访问的代理目标与真实目标足够接近。如果用户要求把一段文字改得更短、更清晰、更正式，那么提示词所隐含的代理，通常就与真实目标非常接近。若用户要求列出十个候选标题，那么多样性与合理性也确实是有用的代理。

这并不是说代理是完美的，而是说优化这个代理，通常不会把系统推向错误方向。

#### 5.2.5 表征充分

流畅输出空间本身就是一个足够好的控制空间。对许多任务而言，自然语言列表、大纲、表格、要点、评分规约与例子，并不只是表层形式，它们本身就是对工作内容的有效表示。

当表征充分成立时，额外引入一个解耦控制空间可能收效有限，因为输出空间本身就已经与任务控制高度对齐。

### 5.3 主要的LLM卓越模式

以下模式并不保证必然成功，但它们经常构成正向对齐区间。

#### 5.3.1 上下文压缩与高维语义映射

模型接收大量上下文，并将其压缩为摘要、分类体系、决策矩阵、语义图谱或任务相关抽象。这类任务对人类往往很难，因为工作记忆有限、注意力容易疲劳；而 LLM 可以同时保留大量语义关系，并把它们重组为紧凑形式。

这是LLM卓越的核心区间之一，因为压缩质量往往与模型习得的语义表征高度一致。

#### 5.3.2 语义解压与表层实现

反向操作同样强大。给定稀疏控制状态，例如要点、提纲、笔记、粗略想法、需求或骨架式论证，模型可以把它扩展为连贯的正文、邮件、备忘录、需求文档、演讲稿或报告。

当前置结构正确时，这种能力就表现得非常卓越。模型不需要自己去发现核心洞见，只需要把它表达好。

#### 5.3.3 语体迁移

模型可以在保持同一意义的前提下，跨受众、语气、正式程度、领域语域或修辞姿态进行转换，例如：

- 技术写法转高管写法；
- 学术表达转公众表达；
- 生硬表达转职业表达；
- 模糊表达转精确表达；
- 口语化转精修版；
- 法律腔转通俗语言；
- 中文推理内容转自然的英文商务表达。

这些转换在模型的 token 级分布中有很强的表示，任务价值也高度依赖风格、句法与措辞选择。

#### 5.3.4 表层润色与局部语言改进

LLM 往往很擅长消除冗余、改善过渡、收紧句子、调整节奏、澄清措辞，让文本更易读。这类任务的聚合失配很低，因为局部改进通常能够自然组合。

但边界也很重要：只有当底层论证或结构已经足够好时，表层润色才是卓越；否则系统只是在产出“润色过的平庸”。

#### 5.3.5 结构化转换

模型可以把松散文本转成表格、清单、JSON 模式、YAML 文件、评分规约、行动项列表、用户故事列表、决策树、SOP 或对比矩阵。

这不仅仅是摘要，而是一种表征归一化。许多格式本身就具有强局部约束，而这些约束又会让自回归生成更可靠：下一个 token 会受到模式结构的清晰引导。

#### 5.3.6 分类体系与设计空间生成

模型可以生成候选类别、维度、失效模式、风险类型、利益相关者群体、产品点子、研究假设或分析框架。人类专家通常拥有更强的最终判断，但 LLM 在相邻概念空间上的召回率往往更高。

当目标是“尽量覆盖候选空间”，而不是“立即给出最终真理”时，这类任务就容易进入卓越区间；如果未经检查就把模型生成的分类体系直接当成有效结论，那么它又会退回平庸。

#### 5.3.7 弱约束下的创意生成

当任务以低成本奖励大量看起来说得过去的候选时，LLM 往往表现突出，例如标题、口号、提示词、故事梗概、A/B 测试点子、访谈问题或宣传角度。此时价值函数更接近“多样性 × 可接受质量 × 低生成成本”。

这是一个高召回的假设生成区间。模型不必是完美的评估者，也能成为很有价值的生成器。

#### 5.3.8 类比与教学性重述

模型可以用多种类比、例子、专业程度层级或学习者画像来解释同一个概念。这很有用，因为教学常常依赖于从不同入口重述同一结构。

其风险在于错误类比。对此的常见干预，是要求模型同时说明类比适用的范围、失效点以及它掩盖了什么。

#### 5.3.9 样板与脚手架合成

很多有用工件本身就有强模式性，例如 API 骨架、CRUD 端点、单元测试模板、README、会议纪要、事故报告、人力政策、标准作业流程以及项目计划。

在这里，高价值输出往往就位于高支持区域。模型的先验反而是一种优势。真正的边界出现在任务从“脚手架生成”切换为“高完整性实现、安全、法律责任或复杂架构”时。

#### 5.3.10 边界情形与反例生成

LLM 往往很擅长列举事物可能失败的方式：代码边界案例、政策滥用情形、合同歧义、产品失效模式、用户困惑状态、对抗性提示或缺失假设。

当任务目标是高召回的候选生成时，这就是卓越；它不足以取代最终验证，但能为后续验证制造大量有价值对象。

#### 5.3.11 查询构造与搜索策略生成

模型可以把模糊的信息需求翻译成搜索查询、学术关键词、相关术语、多语言表达、数据库检索串与检索路径。这会把语义需求转化为搜索系统能用的表层形式。

这是自回归生成与外部证据之间的重要桥梁。在许多场景里，生成好查询往往比在没有检索的情况下直接回答一个专业或时效性问题更容易。

#### 5.3.12 对比矩阵合成

模型可以把多个选项放到多个维度上进行组织：优点、缺点、风险、假设、成本、可逆性、实现复杂度、利益相关者与失效模式。表格模式会稳定生成过程，而每个单元格也各有局部角色。

其风险在于“虚假的完整性”。如果事实具有时效性、数值性或领域关键性，那么矩阵仍必须基于证据并经验证。

#### 5.3.13 默会流程的规程化

模型可以把专家碎片、会议记录、粗略说明或反复实践，转成 SOP 初稿、清单、入门指南、操作手册或流程说明。人类专家往往知道自己在做什么，却没有时间完整写下来，而 LLM 可以迅速把这些默会片段显化出来。

真正的边界在于“捏造”。模型可能会用看似合理、实则不存在的步骤去填补空白，因此仍然需要专家验证。

### 5.4 LLM卓越是一种区间，不是任务标签

没有任何任务类别会永久属于“卓越”。摘要在源材料明确、目标清晰时可以是卓越的；在模型压缩文本做得很好、却误判真正重点时，它会退回局部对齐；当隐藏的法律、政治或战略标准主导时，它又会变得平庸。代码生成对于脚手架可能是卓越的；对于语法地道但验证不足的实现，它是局部对齐的；对于泄漏敏感系统，则可能是平庸的。

因此，正确的分析单位不是任务名称，而是对齐区间：

| 表层任务 | 在何时属于卓越 | 在何时属于局部对齐 | 在何时属于平庸 |
|---|---|---|---|
| 摘要 | 信息显式，成功意味着忠实压缩 | 压缩做得好，但重点依赖部分隐藏的利害关系 | 重要性依赖隐藏利害或专家判断 |
| 写作 | 结构与目标清晰 | 文风与分节有所改善，但核心论证仍不稳 | 任务要求稀有洞见、品味或战略新意 |
| 代码 | 模式常见，验证器可靠 | 代码很地道，但仍需检查非局部不变项 | 架构、安全、泄漏或非局部依赖占主导 |
| 教学 | 学习者状态明确 | 解释清晰，但误解只被部分识别 | 真正误解是隐藏的 |
| 头脑风暴 | 候选多样性本身有价值 | 候选很多，但战略筛选未决 | 需要最终战略判断 |
| SOP 起草 | 流程本身常规或已给定 | 已有不错初稿，但本地组织约束缺失 | 组织特定约束缺失 |
| 语气调整 | 语义稳定 | 语气改善了，但外交、法律或声誉边界仍是隐性的 | 外交、法律或声誉边界完全隐性 |

这种区间视角对系统设计非常关键。它能防止我们过度使用治理，也能防止我们治理不足：若任务本已处于LLM卓越，沉重治理只会浪费算力；若任务处于局部对齐，则应当有选择地保护已对齐操作，同时控制不稳定边界；若任务是高失配的，直接生成往往只会产出流畅的平庸。

## 6. 从平庸到卓越的转化

LLM卓越为缓解 LLM 平庸提供了一般策略，但现实中的起点往往是局部对齐。其核心思想很简单：

> 不要总是让模型直接去解那个高失配、或仅局部对齐的最终输出任务。应当保留已经局部对齐的操作，并把不稳定部分转化为失配更低、其价值与自回归生成正向对齐的子任务。

这一更宽泛的原则包含了解耦控制空间，但并不局限于它。解耦控制空间只是其中一种实现；更深层的目标，是改变模型所面对的任务分布。

### 6.1 任务重参数化

直接生成的设定是：

\[
x \rightarrow y.
\]

如果 $y^\star$ 位于低可达区域，或者依赖隐藏状态、隐性规格或全局聚合，那么即便任务内部有许多局部操作已经很好地对齐，直接在输出空间里搜索也可能陷入平台期。

“从平庸到卓越的转化”会引入中间对象：

\[
x \xrightarrow{T} z_1,z_2,\ldots,z_k
\xrightarrow{R} y
\xrightarrow{V} \text{经验证或修订后的输出}.
\]

这些中间对象可以包括：

- 压缩后的上下文；
- 任务模型；
- 成功条件；
- 角色绑定；
- 状态矩阵；
- 隐藏假设列表；
- 评分规约；
- 失效模式分类；
- 边界情形集合；
- 搜索查询；
- 依赖图；
- 大纲；
- 骨架；
- 候选不变项；
- GKO 集合。

只有当这些中间操作本身属于LLM卓越、或者至少比原始任务失配更低时，这种转化才会奏效。于是，最终答案不再是从一个约束不足的提示词中“硬生成”出来，而是从一个结构化、已验证、与任务相关的表示中被表达出来。

### 6.2 从局部对齐到全局对齐

对于局部对齐任务，系统不应丢弃模型的天然强项，而应识别：哪些部分可以安全地保持为自回归过程，哪些部分必须被治理。

一种实用的“局部到全局”转化包括四步：

1. **利用局部对齐。** 当压缩、重组、查询生成、表层润色、提纲扩展与候选枚举本身与局部任务价值一致时，就大胆使用模型。
2. **定位对齐边界。** 找出局部流畅性不再能预测最终成功的地方：隐藏状态、隐性目标、稀有不变项、非局部依赖或误导性来源先验。
3. **治理边界。** 把这些边界转化为显式工件：状态矩阵、评分规约、约束、反例、角色绑定、失效模式或 GKO。
4. **验证组合。** 检查局部好的部件能否真正组合成全局目标，而不是只形成一个漂亮的代理。

这正是为什么局部对齐是知识治理最重要的现实目标。系统不是在“从零价值走向有价值”，而是在“从部分价值走向受控价值”。

### 6.3 在每类原始失配下的转化

#### 6.3.1 聚合失配：把全局结构变成局部对象

当全局价值不能分解成局部改进时，转化的第一步应当是显化全局结构。

常见做法包括：

- 在写作前先生成依赖图；
- 在 prose 之前先生成情节点地图；
- 在写代码前先抽取跨模块不变项；
- 在给建议前先定义决策矩阵；
- 在叙事展开前先列出长程承诺；
- 在修订前先建立评估清单。

原始任务可能是“生成一个全局一致的工件”，转化后则变成“先生成结构，再填充结构，最后检查填充后的工件是否保住结构”。每个子任务都更局部，也更符合自回归强项。

#### 6.3.2 支持失配：把尾部结构拉进上下文

当高价值解在模型分布下很稀有时，转化就应先显化这些稀有结构，再去生成最终输出。

常见做法包括：

- 要求给出不那么显然的替代方案；
- 枚举少数派框架；
- 生成反例；
- 搜索不寻常约束；
- 构造对抗性案例；
- 生成面向低显著性证据的检索查询；
- 追问“常规答案会漏掉什么”。

一旦某个稀有结构已经变成显式上下文，最终表达任务往往就会变得普通。系统不再需要“偶然采样中那个罕见好答案”，而只需要把已经暴露出来的结构进一步展开。

#### 6.3.3 状态失配：让输出显式条件化于状态

当效用依赖隐藏或变化中的状态时，转化就应把状态显式化。

常见做法包括：

- 列出可能的潜在状态；
- 识别哪些状态变量会改变行动排序；
- 生成情景矩阵；
- 写成 if-then 政策；
- 定义撤销触发器；
- 追问“哪个假设一旦变化，就会把答案翻转”；
- 在信息缺失时，先请求澄清性诊断。

原始任务可能是“在隐藏状态下给出唯一答案”，转化后则是“先枚举状态，再映射动作与状态的关系，最后生成条件化政策”。

#### 6.3.4 规格失配：把价值函数外化出来

当可访问代理偏离真实效用时，转化就应让目标更显式。

常见做法包括：

- 生成评分规约；
- 比较好例子与坏例子；
- 追问“什么东西看起来像成功、但其实会失败”；
- 通过成对对比来引出用户偏好；
- 定义一票否决型失效模式；
- 把风格标准与结果标准拆开；
- 在观察候选输出之后，再修订代理目标。

原始任务可能是“优化一个模糊目标”，转化后则变成“先推断目标，再生成候选，最后用这个推断出的目标来评估候选”。

### 6.4 多轮请求交互作为一种转化

多轮交互并不会自动缓解平庸。如果用户只是不断要求模型“再试一次”“想深一点”“改得更好”，模型很可能还停留在同一个低价值盆地里，只是产出了更光滑的平庸。

只有当每一轮都改变下一轮面对的任务分布时，多轮交互才真正变得强大。有效的请求序列会不断积累中间工件，并用它们去约束后续生成：

\[
q_0(y \mid x)
\rightarrow
q_1(z_1 \mid x)
\rightarrow
q_2(z_2 \mid x,z_1)
\rightarrow
q_3(y \mid x,z_1,z_2,\ldots,z_k).
\]

实用规则是：

> 每一轮都应产出一个持久对象，它要能够改变下一轮真正要解决的问题。

这样的持久对象可以是评分规约、状态矩阵、边界情形、失效清单、搜索结果、大纲、依赖图以及治理规则。没有这些持久对象，多轮提示往往只是重复进行输出空间采样。

### 6.5 算法 1：正向对齐重参数化

**输入：** 任务输入 $x$；可选上下文 $c$；模型与推理过程 $\Pi_B$；可用工具；停止准则 `Stop`

**输出：** 渲染后的输出 $\hat{y}$ 与中间工件 $Z$

```text
Z ← ∅
A ← {x, c}

1. 诊断失配
   识别可能存在的聚合、支持、状态、规格与拟合边界失配。

2. 选择转化算子
   选择那些更可能属于LLM卓越的子任务：
   压缩、评分规约生成、状态枚举、边界情形生成、
   查询构造、提纲构建、语义解压或清单验证。

3. 生成中间工件
   对每个选中的算子，生成 z_i，并把它加入 Z。

4. 验证或弱化工件
   拒绝无支撑的主张，标记假设，识别冲突，
   并记录证据强度。

5. 生成最终输出
   基于 x 以及已经验证或被弱化的工件 Z 生成 y。

6. 验证组合
   检查 y 是否保住这些工件、满足评分规约、
   覆盖状态条件，并避免已知失效模式。

7. 修订或停止
   如果验证失败，修订工件或表达策略。
   否则返回 y 与 Z。
```

这一算法有意设计得比知识治理更宽泛。它可以通过简单提示实现，也可以与检索、工具、人类反馈、形式化控制空间或完整治理层结合。

### 6.6 转化的失效模式

“从平庸到卓越的转化”本身也会以多种方式失败。

#### 6.6.1 代理漂移

转化过程可能把原本困难但正确的任务，替换成一个更容易但错误的代理。例如，“产出战略洞见”可能被偷换成“写一份结构清楚的多段式备忘录”。于是模型在清晰度上表现得非常卓越，却彻底漏掉了战略本身。

#### 6.6.2 虚假的中间工件

模型可能生成看似合理、实则错误的评分规约、不变项、假设或状态变量。如果这些东西不经过验证，它们会在提高系统自信的同时，把最终输出变得更差。

#### 6.6.3 组合失败

每个子任务都可能局部成功，但最终组合仍然失败。好的评分规约可能没有被真正遵守；强有力的大纲可能在 prose 扩展中被背离；状态矩阵可能在最终建议里被忽略。因此，组合验证是强制性的。

#### 6.6.4 并不卓越的中间任务

有些中间任务本身就很难。真正的数学不变项、罕见工程架构、法律标准、科学机制与当前市场事实，可能仍然需要工具、检索、形式化验证、实验或专家判断。重参数化并不能把每一个困难任务都变成单纯的语言任务。

### 6.7 与知识治理的关系

知识治理就是“从平庸到卓越的转化”的一种有纪律的实现。它把中间工件形式化为受治理的控制知识，为其分配证据强度与适用范围，并跟踪这些知识应在何时生效、何时被撤销。

简言之：

- **LLM 平庸** 是失效区间。
- **局部对齐** 是常见的混合区间：局部价值真实存在，但全局价值不稳定。
- **原始失配** 是诊断轴，用来识别局部对齐在何处断裂。
- **LLM卓越** 是稳定的正向对齐区间。
- **从平庸到卓越的转化** 是一般性的干预原则。
- **知识治理** 是一种更强、更可检查的实现方式，适用于高风险、高失配或仅局部对齐的场景。

### 6.8 操作方法模式

“从平庸到卓越的转化”可以通过一组反复出现的操作方法变得具体。它们的共同核心相同：不要让生成在原始 token 空间里沿着高频续写路径自然滑行；相反，应有意构造一个可搜索、可评估、可撤销的中间层。一旦这个中间层存在，任务就不再是“继续写”，而是：在控制表示中搜索、验证、剪枝和重组，然后再把结果渲染回输出空间。

下面每种方法都标注其主要对抗的原始失配，以及误用时常见的失败模式。这些方法不是互斥的；真实任务中经常组合使用。

#### 6.8.1 高密度去相关采样、碎片化与跨样本重组

**主要目标：** 支持失配。**次要目标：** 聚合失配。

当高价值答案位于低概率尾部时，直接书写最终答案会反复被自回归引力拉回常见模式。更有效的序列是：首先在自回归生成下采样一个较大的候选池；然后选择局部上最有潜力的样本；再把它们拆成结构、策略、关键转折、局部解法等功能单元；最后跨样本重组这些单元，形成一个不再受原始工件边界束缚的新候选空间。

这里有三个关键修正。第一，采样必须 **去相关**，而不只是“数量多”。候选可以具有表面多样性，却仍全部落在同一个低价值盆地中。需要通过温度与 nucleus 变化、提示和框架扰动、任务的替代表述、约束顺序变化，以及明确要求“传统答案会漏掉什么”的对比指令，主动拉开候选分布。

第二，重组的价值不只是拼接更好的内容，而是从样本簇中提取普通总结不会显化的 **高 sigma 硬经验**：罕见但有效的结构、隐藏约束、非显然转折、反复出现的失败模式和高价值表达动作。这些被提取出来的主张只是候选控制知识，而不是结论。它们面临选择噪声风险：有限样本中挖出的模式可能只是多重比较伪影，而不是真不变项。因此，验证必须在留出样本或新生成候选上进行，不能只在提示该模式的原始样本池上完成。通过验证的主张，才进入带有显式证据制度的 GKO 生命周期。

第三，这个循环可以重复。系统每到达一个新的局部最优附近，都可以再次运行采样、碎片化、重组、验证循环，以探测下一层尾部结构。

这种方法是第 7.2 节 Fragment-Perturb-Reconcile 机制的一般形式；第 10.5 节的泄漏敏感代码合成模式则是它的具体实例。它的本质，是一种反支持失配操作：先从尾部打捞低概率、高价值的局部结构，再把它们转化为显式控制资源，使最终渲染重新变成普通的高支持任务。

#### 6.8.2 先写控制空间，再生成输出

**主要目标：** 聚合失配与规格失配。

故事、长文档、课程设计和复杂方案这类任务，直接生成成品时常常平庸。但优秀结果必须满足的元素，例如节拍、节奏、约束、风格边界、情绪曲线、人物关系、承诺-兑现义务和验收标准，往往是模型表现接近卓越的子任务。

因此，方法是先写控制空间，再写输出。例如，先构造人物弧线、冲突梯度、主题约束、场景节拍、信息揭示顺序、禁用套路清单和评分规约；然后在这个控制状态下生成工件；再用相对更可靠的评估任务检查：节奏是否停滞？前提是否被破坏？埋下的承诺是否没有兑现？输出是否落入禁用模式？

如果结果不足，**应先修改控制空间，而不是立刻重写全文**。这是一条信用分配原则：它把修正位置从输出层移回控制层。否则，反复重写会退化成普通输出空间采样，系统也会失去“哪个控制决策导致缺陷”的信息。

这个循环利用了 **生成-评估不对称**：在许多任务上，直接产出卓越工件并不稳定，但识别缺陷、命名俗套和检查约束违规相对容易。不过这种不对称有适用条件：缺陷必须可定位，标准必须能够被显式化。在强规格失配下，评估器会继承生成器同样的规格缺口，评分规约本身也会成为需要对比验证的候选对象。在这个限制下，该方法把一个自回归平庸任务改写成一串LLM卓越子任务：枚举要求、在约束下渲染、检测违规、修复控制状态。

#### 6.8.3 在控制空间搜索，而不是在输出空间蛮力搜索

**主要目标：** 六类失配；这是最一般的方法。

对于多数高失配任务，第一步是切断从原始语义到直接输出的默认路径，构造一个更容易搜索的控制空间：状态矩阵、评分规约、候选框架集、依赖图、查询计划、失败模式清单、角色配置或决策表。

搜索随后发生在控制空间中，也就是扰动、扩展、剪枝和比较控制对象，而不是反复重采最终答案。候选控制对象会被还原到输出空间进行验证；验证失败时，系统回到控制空间继续搜索，而不是只修补最终文本。

关键不在于增加步骤，而在于 **改变搜索地形**。原始输出空间里的邻域结构是 token 邻接，而相邻 token 之间的流畅性常常与任务价值无关。控制空间则把邻域定义在真正承载价值的变量、结构和约束上，使局部搜索动作对应于效用上的有意义动作。

这个方法有两条操作规则。第一是成本准则：按照第 3.4 节的启发式，单一主导失配通常可以通过更强提示、检索或重排处理；当两种以上失配都很显著时，控制空间搜索就成为强候选。第二，组合验证是强制的：渲染器可能悄悄忽略控制对象，因此验证必须检查渲染输出是否保留了控制状态，而不只是看上去不错。当控制状态正确且被保留时，最终渲染通常就是语义解压任务，往往落在卓越区间。

#### 6.8.4 用分层控制空间约束搜索复杂度

**主要目标：** 预算约束下的控制容量崩塌；控制层自身的组合爆炸。

控制空间并不因为更大就更好。如果把所有变量、风格、约束、分支和例外都塞进一个扁平搜索空间，搜索成本可能并不低于输出空间里的盲目重复采样，甚至更糟。此时控制层本身会变成新的混乱来源，而不是补救。

复杂任务因此更适合 **分层控制空间**。粗层先固定方向、主结构和绑定性的全局约束；后续层再搜索局部策略、子结构和具体实现；最终才进行渲染。每一层都可以有自己的验证器、回滚点和晋升条件。

分层的价值在于切断组合爆炸：系统不是一次性寻找完整答案，而是先锁定高价值区域，再在其中细化。这里有三条设计规则。

第一，**层边界应跟随任务的失配结构**，而不是实现便利。聚合失配应在粗层吸收：一旦全局结构和非局部约束在那里被固定，下层任务才会真正变成局部、低失配子任务。如果顶层没有捕获全局耦合，分层只是在推迟聚合失败。

第二，各层预算分配应显式化，而且粗层应获得不成比例的预算。顶层错误代价最高：错误的问题建模或错误主结构，会把所有下层努力都变成对错误抽象的更长合理化。

第三，典型失败模式是 **过早的粗层承诺**。缓解方法是设置显式回溯触发器：当下层搜索在固定预算内反复无法通过验证时，应把它解释为顶层决策的反证，而不是局部困难，并强制回到粗层搜索。没有这种触发器，分层会固化早期错误，而不是控制复杂度。

用第 3.5.7 节的语言说，分层控制在固定模型和预算下提高系统的有效控制容量 $C_{\mathrm{eff}}$。因此，当任务总失配负载接近崩塌阈值时，它就是自然干预。

#### 6.8.5 状态枚举与条件化渲染

**主要目标：** 状态失配。

当输出排序依赖潜在、部分可观测或变化中的状态时，在隐含状态猜测下给出单一答案会很脆弱。方法是把状态提升为一等控制对象：枚举可能潜在状态；识别哪些状态变量会翻转行动排序；构造情景矩阵；渲染 **状态条件化策略**，也就是带有适用条件和撤销触发器的 if-then 建议，而不是单一无条件答案。如果一个小的诊断问题可以低成本地消除状态不确定性，应在渲染前提出。

这些组成操作，例如状态列举、情景矩阵构造、条件化表达，本身都是高支持、局部对齐的生成任务。因此，该方法把一个状态失配的最终答案，转化为一组良好对齐的子任务，加上一个显式条件结构；后续治理可以随着状态变得可观察，对这个结构进行维护、削弱或撤销。

#### 6.8.6 对比式价值澄清与评分规约细化

**主要目标：** 规格失配，包括涌现式规格。

当真实目标是隐性的，或只有在检查候选后才能识别时，方法是把价值函数本身变成搜索对象。生成 **刻意对比的候选**，也就是沿假设价值维度相互区分的备选，而不是近重复版本；然后对它们进行成对偏好澄清。明确询问：什么答案在当前代理目标下看起来很好，却会在真实目标下失败？把风格标准与结果标准分开。将细化后的代理目标 $\tilde{U}_t$ 记录成显式、可修订的工件：评分规约、淘汰性失败模式和偏好 GKO。

这会把委托方事先无法完整表达的目标，转化为一串委托方更可靠完成的操作：在具体备选之间选择，并说明原因。风险是第 6.6.2 节的虚假评分规约失败：一个貌似合理但错误的评分规约会提高系统信心，同时降低真实价值；建立在它之上的评估器也会继承这个错误。因此，这种方法产生的评分规约应像其他受治理对象一样带有证据强度和撤销触发器，并且在下游评估与委托方反应发生分歧时重新测试。

#### 6.8.7 方法-失配映射与组合

六种方法与诊断理论的关系如下。

| 方法 | 主要对抗的失配 | 典型控制对象 | 误用时的典型失败 |
|---|---|---|---|
| 6.8.1 去相关采样与重组 | 支持 | 片段、重组候选、诱导不变项 | 选择噪声被提升为知识；相关样本池没有尾部内容 |
| 6.8.2 先写控制空间 | 聚合、规格 | 节拍、约束、评分规约、验收标准 | 评估器继承规格缺口；把评分规约误当成真实目标 |
| 6.8.3 控制空间搜索 | 六类失配（通用） | 状态矩阵、依赖图、框架、决策表 | 在低失配任务中过度开销；渲染器忽略控制状态 |
| 6.8.4 分层控制 | 容量崩塌（复合） | 分层约束、回滚点、回溯触发器 | 过早粗层承诺被层级结构固化 |
| 6.8.5 状态枚举与条件化渲染 | 状态 | 情景矩阵、if-then 策略、撤销触发器 | 虚假状态膨胀；渲染时丢失条件性 |
| 6.8.6 对比式价值澄清 | 规格 | 对比对、细化评分规约、淘汰性失败模式 | 虚假评分规约提高信心但降低价值 |

真实任务会组合这些方法。一篇长篇战略文档可能在双层层级结构中使用先写控制空间的方法，通过对比澄清细化评分规约，对未解决的客户状态进行条件化渲染，并在草稿卡入可识别盆地时调用采样与重组。组合规则就是第 6.4 节的持久性要求：每次使用方法，都必须留下一个经过验证、可撤销的工件，改变下一步真正要解决的问题。只产出临时文本的方法，本质上仍然是伪装成方法的输出空间采样。

## 7. 知识治理

### 7.1 设计原则

六失配视角、局部对齐视角以及卓越区间视角共同指向一个简单但重要的架构转变：

> 不要只在候选最终答案上搜索；也要搜索那些能够把局部对齐转化为更稳定全局对齐的中间对象。

我们把 **知识治理** 用来指代：在推理阶段，对任务特定控制知识进行显式获取、验证、部署、弱化与撤销。这个框架把“发现并管理控制知识”的层，与“生成流畅最终输出”的层区分开来。

一个关键澄清是：该框架并不假定存在某一种普适的内部表示。真正通用的是治理循环本身，而不是唯一的控制空间。具体控制空间在不同任务里可能完全不同：某个领域里是代码模块与数据流边界，另一个领域里是情节点与承诺兑现约束，再另一个领域里是情绪状态与策略转移，在别处又可能是物理可供性与角色绑定、来源先验审计与评估指标，或者区间指标与风险过滤器。

知识治理不应被理解为对自回归生成的否定。它的目的，是在模型强项所在之处继续使用自回归生成。对于局部对齐任务，这意味着保留模型已经擅长的操作，同时对那些局部价值无法自然组合的部分加以治理。它把困难任务转化为压缩、分类体系生成、失效模式枚举、评分规约起草和语义解压等中间操作。最终表达器仍然是自回归模型；区别只在于，它不再从一个规格不足的提示词直接生成，而是从受治理的控制知识中进行表达。

### 7.2 解耦控制空间

**解耦控制空间** 是一个外部表示层，其中的元素不要求本身就是流畅的最终答案。它的目的，是在尽量丢弃完整输出的话语连续性的同时，保留与任务相关的单位和关系。因此，它与流畅表层形式是解耦的，但并不是语义空洞的。

根据任务不同，这个空间中的单位可以包括：

- 叙事情节点、承诺、承诺兑现对以及场景功能；
- 对话行为、情绪线索、策略约束与升级状态；
- 物理对象、可供性、角色绑定、成功条件与隐藏假设；
- 市场信号、区间指标与风险过滤器；
- 代码块、时间假设、依赖约束与验证步骤；
- 来源框架、反叙事、评估指标与因果机制；
- 失败案例、边界违规与合成反例。

我们使用三个核心算子。

**Fragment**：把一个连贯工件拆分成最小功能单元。

**Perturb**：施加受控扰动，例如重排片段、删除某个依赖、取反某个条件、注入违规、改变潜在状态、切换来源框架，或构造一个反事实场景。

**Reconcile**：询问“要让这个受扰动后的工件重新成立，必须满足什么条件”。其结果不是成品答案，而是一个候选规则、边界条件、依赖假设、建模修正或评估原则。

扰动的目标并不是随机破坏，而是让隐藏依赖显形。如果删掉某个步骤后表现毫无变化，那么这个步骤可能只是装饰；如果删掉它就失败，缺失依赖就变得可辨认；如果改变某个物理假设会把答案翻转，相关状态变量就显露出来；如果切换来源框架就改变了评估结果，那就说明先验可能比证据更在支配答案。通过这种方式，扰动帮助系统把隐式结构转化为显式控制假设。

### 7.3 先建模，再表达

对于嘈杂的现实任务，控制空间可能不仅需要表示求解步骤，还需要表示“任务模型本身”。因此，在生成答案之前，控制器应先追问：

- 真正的成功条件是什么？
- 哪个对象或行动者承载了目标状态的变化？
- 哪些已给细节是约束，哪些只是干扰项？
- 当前正在依赖哪些隐藏的物理、社会、时间、制度或来源先验假设？
- 有没有一种替代性抽象，能让问题立刻变得简单，或把结论反转？
- 当前正在优化哪种评估指标，而它真的是正确指标吗？

这种“建模优先”的步骤并不是所有任务都需要。它在这样一类场景中特别关键：模型在问题的干净抽象版上表现良好，却在嘈杂场景版上失败。此时，瓶颈不只是抽象推理能力，而是能否构造出正确的抽象。

### 7.4 受治理知识对象

为了让发现到的知识真正可用，我们把它存储为 **受治理知识对象**（GKO），而不是让它隐含在自由文本里。

一个通用模式可以写成：

```json
{
  "id": "gko-uuid",
  "condition": "规则适用的上下文谓词",
  "assertion": "约束、偏好、启发式、角色绑定、状态条件、来源框架修正或诊断测试",
  "strength": "sample-grounded | objective-grounded | statistics-grounded | adversarial",
  "priority": 0.0,
  "lifespan": "episodic | session | windowed | global",
  "revocation_trigger": "弱化或删除该规则的条件",
  "evidence": "支撑观察或测试的摘要",
  "source": "工件、验证轮次、归纳步骤、建模探针或来源先验审计"
}
```

一个 GKO 可以发挥如下作用：

- **硬约束**：必须满足；
- **软偏好**：条件允许时优先满足；
- **路由规则**：当满足某条件时切换策略；
- **诊断测试**：如果某个边界条件失败，就拒绝候选；
- **建模规则**：识别相关目标、承载对象、状态变量或抽象方式；
- **来源先验修正**：把主导叙事与证据、评估指标分开；
- **转化规则**：把当前任务改造为一个LLM卓越子任务。

关键设计原则是：控制知识应当是显式的、有条件的、可持久化的、可修订的。它不再被埋在某一份具体输出里。这与我们所谓的 **软经验** 形成对照：后者看上去合理、语气流畅、似乎有用，但一经测试，却无法为行为提供稳定约束。

## 8. 与任务无关的治理循环

知识治理的具体实现细节是任务特定的。真正通用的，不是某个唯一的控制空间构造器，而是一套可复用的循环。

### 算法 2：与任务无关的治理循环

**输入：** 任务输入 $x$；初始工件池 $A_0$；任务特定控制空间构造器 $C$；渲染器 $R$；评估器 $E$；验证器 $V$；最大迭代数 $T$；停止准则 `Stop`

**输出：** 最佳渲染输出 $\hat{y}$；活跃的受治理知识集合 $K$

```text
K ← ∅                                  # 活跃 GKO 集
A ← A0                                 # 候选轨迹、失败样本、示例、检索案例
best ← ⊥

for t = 1 ... T do
    Z_t ← C(x, A, K)                   # 构造任务特定控制空间
                                       # 可选择包含从场景到模型的建模步骤
                                       # 以及从局部对齐到全局对齐的转化

    H_t ← Expand(Z_t, A, K)            # 在控制空间中搜索
                                       # fragment / pair / recombine / perturb / reconcile
                                       # 生成评分规约、状态、边界情形、大纲、查询
                                       # 或直接编辑任务特定控制变量

    G_t ← Validate(H_t, A, x, V)       # 拒绝、降级、定位或提升假设

    K ← UpdateGovernance(K, G_t)       # 添加、弱化、撤销或重排 GKO

    y_t ← R(x, K)                      # 回到流畅输出空间中渲染
                                       # 这通常是一个语义解压任务

    eval_t, critique_t, trace_t ← E(y_t, x, K)

    A ← UpdateArtifacts(A, y_t, critique_t, trace_t)

    K ← MonitorAndRevise(K, eval_t, critique_t, trace_t)

    best ← SelectBest(best, y_t, eval_t)

    if Stop(best, K, eval_t, critique_t) then
        break
    end if
end for

return best, K
```

这里有两点尤其值得强调。

第一，**$C$ 是任务特定的**。在样本丰富的代码任务里，它可能会把轨迹切分成功能模块并产生重组候选；在故事生成里，它可能暴露情节点、弧线、揭示与节奏控制；在嘈杂的常识推理里，它可能抽取目标、角色绑定、物理可供性与隐藏假设；在制度或历史评价里，它可能分离来源先验、证据类别、因果机制与评估指标。不存在一种单一普适表示能适配所有任务。

第二，**Expand 同样是任务特定的**。有的任务需要“切分-配对-重组-调和”，有的任务需要直接编辑手工设计的控制状态，还有的任务需要反事实场景扰动、来源框架切换或状态矩阵构造。共通之处在于：搜索发生在一个比“未分化的最终文本输出”更接近任务价值的表示空间中。

### 8.1 验证层级

并非所有证据都足以支撑同样强的置信度。因此，我们区分四种证据区间。

1. **样本支撑型。** 某条候选规则由对比样本或成对样本支持，例如偏好与拒绝输出、成功与失败对话。
2. **目标支撑型。** 某条候选规则能改善可测的下游目标，例如任务完成率、泄漏减少或样本外表现。
3. **统计支撑型。** 当没有单一任务目标时，某条规则能诱导出期望的分布变化，例如更丰富的场景、更少的矛盾或更低的重复。
4. **对抗支撑型。** 某条规则经受了定向破坏尝试，但缺少更强的成对或目标性证据。

这些是置信层级，而不是真理保证。即便是高强度 GKO，也可以在后续证据出现后被修订。

### 8.2 调和噪声与举证责任

一个现实风险是：Reconcile 可能会幻觉出听起来很合理、但实际上错误的依赖关系。这不是边缘问题，而是该框架必须把“扩张假设空间”与“验证假设真伪”分开的核心原因。

在我们的视角里，Reconciliation 只是候选假设的生成器，而不是真理保证器。它的工作是扩展假设空间。真正的举证责任落在别处：验证、对抗检查、下游证据、外部工具与显式撤销机制。我们不要求 LLM 自行为自己的解释背书；我们要求它提出必须经受外部压力检验的假设。

### 8.3 软经验、局部知识与硬知识

这个框架被明确设计用来避免积累 **软经验**：也就是那些含糊、讨喜、文风动人、听上去似乎有帮助，但实际上并不能稳定约束行为的说法。

一个实用区分是：

- **被拒绝的主张**：与证据矛盾，或已被样本池否决；
- **局部知识**：在全局上可能冲突，但在某个受限条件下，对某个狭窄子问题能稳定提供改善的主张；
- **硬知识**：经过验证、在相关样本池上不发生冲突，并能经受更强验证的主张。

这一区分在“从样本中诱导控制空间”的情境里尤其有用，因为那里的许多候选主张往往只是“部分正确”“局部有用”或“措辞漂亮”。

### 8.4 冲突解决与死锁

随着 GKO 集合变大，冲突不可避免。两条规则可能同时适用于同一语境，却推荐了不兼容的行动。我们通过以下因素来解决冲突：

- 证据强度；
- 优先级；
- 适用范围的特异性；
- 新近性；
- 可测目标上的实际影响。

第二种失效模式是 **约束死锁**：活跃控制集变得过于严苛，以至于渲染器无法生成有效或有用的输出。在这种情况下，系统不应悄悄忽略约束，而应显式呈现冲突、弱化较低优先级规则、以另一种方式重构任务，或者在有人工介入条件时请求决策。

## 9. 为什么解耦控制空间会有帮助

本文的核心主张并不是输出空间搜索无效。在许多任务上，它完全有效，甚至可能非常卓越。更窄、更精确的主张是：**当局部合理性只是任务价值的薄弱代理时，只在流畅候选上搜索就会成为一种表征瓶颈。**

### 9.1 在局部对齐下

局部对齐是“解耦控制空间为什么有帮助”的最常见原因，而且它并不要求抛弃自回归生成。模型已经能生成有价值的片段，只是这些片段之间的关系尚未被充分治理。控制空间可以保留这些有用片段，同时把它们的适用条件、依赖关系与组合规则显式化。

例如，模型也许能写出很强的大纲，却漏掉决定性的评估指标；也许能生成有用的代码模块，却无法维持时间顺序；也许能给出富有同理心的对话轮次，却没有追踪升级状态。每一种情形里，局部操作本身都很有价值。问题在于，局部价值尚未被组织成全局价值。解耦控制空间给了系统一个地方，用来表示哪些东西必须被保住、哪些东西必须被检查，以及什么时候某个“局部看上去很好”的操作应该被覆盖。

### 9.2 在聚合失配下

流畅输出会把内容、风格、局部连贯性与潜在约束缠在同一个对象里。一次看似改善表层的改写，可能会悄悄破坏别处的长程依赖。通过转向被切分的单元与显式关系，控制器就可以直接表示非局部依赖，而不必寄希望于它们在反复改写中自动幸存。

“从平庸到卓越的转化”在这里的要点，是把全局结构局部化。一旦全局结构被表示成清单、图、情节点图、依赖表或不变项集合，最终表达就会变成一个语义解压任务，而这常常正是LLM卓越操作。

### 9.3 在支持失配下

如果高价值解本身是尾部事件，那么普通自回归续写往往难以把它们暴露出来。扰动在这里之所以有帮助，并不是因为它能凭空从噪声里创造知识，而是因为它能揭示：某个此前被成功工件隐藏起来、或在失败工件中缺失的关键依赖到底是什么。

这里的转化就是“把尾部结构拉进上下文”。一旦某个不太可能出现的框架、稀有不变项或不显眼失效模式已经显式存在，模型往往就能很流畅地继续展开它。最终操作不再是从低支持区域里自发发现，而是从一个已显化的种子出发进行扩展。

### 9.4 在状态失配下

当效用依赖隐藏或变化中的状态时，系统就需要显式状态谓词。解耦控制空间可以表示候选状态、适用条件以及撤销触发器。一个 GKO 在某个状态下可能正确，在另一个状态下则可能错误。把这种条件性作为一等公民来处理，可以防止系统把一条局部有效的规则误提升为一个全局却错误的原则。

这里的转化，是把“单一隐藏状态下的唯一答案”替换为“条件化于状态的政策”。情景矩阵、if-then 规则与撤销触发器，都是 LLM 往往能很好生成和维护的自然语言结构。

### 9.5 在规格失配下

当可用代理偏离真实效用时，更强地优化代理，往往只会得到“润色过的平庸”。解耦控制层之所以有帮助，是因为它能把代理显式化、收集对比证据、迭代评分规约，并把新发现的偏好表示为可修订的 GKO。

这里的转化，是把隐性的价值转成显式的评估工件。评分规约生成、对比比较、失效模式枚举与清单验证，往往都是LLM卓越操作。但危险在于“伪规格”，因此验证与撤销同样是必需的。

### 9.6 在噪声语境建模失败下

在嘈杂自然场景里，模型可能在真正开始推理之前就已经失败了。它可能选错成功条件、把目标绑定给错误对象、过度使用无关数字、套用熟悉却不合适的模板，或忽视一个隐藏的物理可供性。

解耦控制空间可以把这种前端建模过程显式化。系统不必立刻回答，而可以先表示若干候选建模：

- 目标究竟是移动人、车、病人、文件，还是那个状态必须变化的对象？
- 某个数字细节是真正约束，还是干扰项？
- 问题是二维的、三维的、时间性的、制度性的，还是社会性的？
- 哪些假设一旦变化，结论就会翻转？
- 当前引入的是哪一种来源先验或惯常模板？

这并不会消除对世界知识的需求，但它会让失败点变得可检查、可治理。

### 9.7 在语料先验主导下

当模型的默认叙事受语料频率或来源权威强烈支配时，直接生成就可能让主流显著性取代与任务相关的证据。控制空间可以强迫系统把以下要素拆开：

- 主导叙事；
- 反叙事；
- 证据类别；
- 因果机制；
- 评估指标；
- 反事实替代情形；
- 局部成本与系统层面效应。

这种转化，常常会把一个带偏见的评价任务，变成一个结构化比较任务。对比矩阵、来源审计与因果机制分解，往往比“自发逃离默认叙事”更符合 LLM 的强项。

### 9.8 与相邻方法的关系

知识治理与若干相邻方法有关，但并不等同于它们：

- **提示工程** 改变的是指令表层；治理则把已经验证的控制知识保存在多个候选生成之间。
- **重排** 发生在完成后的输出之间；治理则可以在渲染之前修改搜索空间。
- **检索** 导入外部内容；治理还能从任务特定的失败与扰动中诱导控制知识。
- **过程监督** 给中间步骤打分；治理还会管理显式规则、条件与撤销触发器的生命周期。
- **工具使用** 扩展的是能力边界；治理决定哪些任务特定知识应持续存在，以及它们如何约束后续工具调用或渲染。
- **普通自回归生成** 仍然保留，既是最终渲染器，也是中间工件生成器；治理做的是把它重新导向那些正向对齐的子任务。

## 10. 实例化模式

下面这些例子说明，这一框架可以如何在实践中实例化。它们并非穷尽性案例研究，而是为了展示：同一个治理循环如何在不同的任务特定控制空间上运作，以及“从平庸到卓越的转化”如何在实际任务里出现。

### 10.1 叙事生成

**失配画像：** 高聚合失配，中等支持失配，高规格失配。

叙事质量依赖长程结构、承诺-兑现关系、人物承诺、节奏与情绪张力。直接生成往往会写出局部很强的 prose，却缺少全局结构。

这一场景下的控制空间可以包含情节点、承诺-兑现对、人物承诺、反转、场景功能与体裁约束。控制器从这个控制状态出发渲染完整故事，再通过批评来诊断“兑现缺失、节奏漂移、陈词滥调过度、角色不一致”等问题，把这些问题映射回控制空间，并继续迭代。

候选治理规则可以包括：

- 重大反转前应有清晰可辨的压力累积；
- 已埋下的物件要么兑现，要么被有意识地反向利用；
- 人物缺陷应在高潮解决前经受检验；
- 情绪升级应绑定到不可逆的叙事承诺，而不只是 prose 强度上升。

这里的“从平庸到卓越的转化”很清楚：系统不再要求模型直接写出一个全局一致的故事，而是先生成并修订情节点、承诺与回收，再通过语义解压把受控结构变成 prose。

### 10.2 噪声语境推理

**失配画像：** 高状态失配，中高规格失配，中等支持失配。

这类任务要求系统先从自然场景中构造正确抽象。真正困难的部分，常常不是解抽象问题本身，而是决定这个场景到底实例化了哪个问题。

此时的控制空间可以包括：

- 候选成功条件；
- 目标承载对象绑定；
- 相关与无关变量；
- 隐含的物理或社会假设；
- 替代性抽象模板；
- 会翻转答案的反事实变体。

对于洗车例子，一个建模型 GKO 可以是：

```json
{
  "condition": "任务涉及某项服务作用于一个对象",
  "assertion": "先识别状态必须发生变化的对象；仅仅移动人，不一定满足目标",
  "strength": "adversarial",
  "priority": 0.8,
  "lifespan": "session",
  "revocation_trigger": "这项服务无需移动该对象即可完成",
  "evidence": "走到洗车店并不会让车自动被洗"
}
```

而对于“门与长杆”例子，一个建模型 GKO 可以是：

```json
{
  "condition": "细长物体需要穿过某个开口",
  "assertion": "不要把问题简化为物体长度是否能放进开口平面；要考虑朝向、横截面、周边空间以及穿过路径",
  "strength": "adversarial",
  "priority": 0.9,
  "lifespan": "session",
  "revocation_trigger": "物体必须始终停留在开口平面内，或周边空间不足",
  "evidence": "只要横截面能通过且周围空间足够，细长杆可以沿长度方向穿过门口"
}
```

这个例子强调，噪声语境建模失败不能被简单归结为“目标错了”。有些失败关乎成功条件，有些则关乎物理可供性、隐含假设或抽象模板。

### 10.3 客户服务对话

**失配画像：** 高聚合失配，高规格失配，中等状态失配。

客服对话需要同时优化任务解决、情绪调节、政策合规与交互效率。这些目标彼此耦合，而且常常带有隐性标准。

解耦控制空间可以包括对话行为、情绪线索、升级状态、政策规则与状态转移模式。扰动可以删除确认语、交换道歉与排障的顺序，或注入无依据的假设；调和后就能得到一些条件化规则，例如：

- 当用户挫败感较高且问题诊断尚不完整时，应先确认情绪，再给解决方案；
- 某个脚本化建议已被用户明确否定后，再重复它就应触发重构表述或升级；
- 在要求用户承担额外负担之前，应先把政策说明清楚。

最终回复就变成了一个“语体迁移 + 语义解压”的任务：在受控状态条件下，用恰当语气去表达已选定的对话行为。

### 10.4 市场适应

**失配画像：** 高状态失配，中等规格失配。

推荐与配置类任务之所以困难，是因为效用会随着环境变化而变化。在一个区间中有效的策略，到另一个区间中可能迅速过时。因此，静态先验并不是可靠向导。

这一场景下的控制空间可以包括信号族、区间指标、确认规则、风险过滤器与时间跨度假设。扰动可以模拟区间变化、删除过滤器或改变波动率假设；调和后会得到条件化规则，例如：

- 当波动率高于某个阈值时，应降低动量信号权重；
- 当市场压力上升时，流动性敏感型约束应占主导；
- 过去有效的规则如果未在当前区间重新验证，应到期失效。

这里特别重要的架构特征是 **生命周期**。与市场相关的 GKO 通常应是窗口化、可撤销的。知识治理在此场景中有用，正是因为它把“过时控制知识”视为一类一等失效模式。

### 10.5 泄漏敏感的代码合成与因子调度框架

**失配画像：** 高支持失配，高聚合失配，中等规格失配。

高完整性的代码合成任务在结构上非常脆弱。表面上的性能提升，可能只是由泄漏、时间戳错误、隐藏的未来信息或无效依赖顺序造成的伪改进。于是，很多局部看似合理的代码修订，其实在结构上是错误的。

一种试验性模式是，从如下反复迭代的轨迹中构建工件池：

\[
(\text{initial code}, \text{prompt}) \rightarrow \text{plan} \rightarrow \text{attack} \rightarrow \text{refine} \rightarrow \text{code},
\]

并重复多个回合。随后，控制器会：

1. 把每个样本切成若干功能模块；
2. 跨样本配对并重组模块，形成一个不再受原始流畅工件边界束缚的新样本空间；
3. 让模型诱导出解释“哪些组合有效、哪些组合失效”的候选原则；
4. 用泄漏检查、时间约束、依赖图和下游指标去验证这些原则；
5. 将存活下来的约束存为 GKO。

候选治理规则可以包括：

- 任何依赖未来时间戳的特征，除非显式滞后，否则必须拒绝；
- 验证切分必须保持时间顺序；
- 如果下游模块假定了上游未提供的预处理不变项，则模块重组无效；
- 指标一旦异常升高，提升前必须先触发一次泄漏审计。

这里的重点不是让模型多写一些代码，而是诱导并强制执行那些普通输出空间优化会反复破坏的结构约束。

### 10.6 历史、制度与发展政策评价

**失配画像：** 中高支持失配，高规格失配，且常伴随高聚合失配。

历史与制度评价极易受到语料先验主导。模型可能会复述某种文化上占优势的评价框架，而任务真正需要的却是因果解释、反事实比较或系统层面核算。

这一场景下的控制空间可以包括：

- 主导叙事；
- 少数派或反叙事；
- 证据基础；
- 因果机制；
- 局部指标；
- 系统层面指标；
- 反事实替代方案；
- 时间或制度状态。

候选治理规则可以包括：

```json
{
  "condition": "评估公共投资或国家主导产业政策",
  "assertion": "把直接财务回报与系统层外部性、能力形成、产业扩散、区域协同、污染减排和反事实替代方案分开分析",
  "strength": "adversarial",
  "priority": 0.85,
  "lifespan": "session",
  "revocation_trigger": "任务明确要求只评估项目层面的财务 ROI",
  "evidence": "项目层面的 ROI 可能系统性低估系统层价值"
}
```

```json
{
  "condition": "评估被文化英雄化的历史人物",
  "assertion": "把文学接受史、文化形象、战略判断、组织领导、政治决策与伦理评价拆开处理",
  "strength": "adversarial",
  "priority": 0.8,
  "lifespan": "session",
  "revocation_trigger": "任务只要求讨论接受史或大众形象",
  "evidence": "英雄化的文化显著性可能掩盖领导层面或制度层面的失败"
}
```

这里的“从平庸到卓越的转化”，就是把一篇默认性的评价文章，变成一个对叙事、指标、机制与反事实进行结构化比较的任务。模型通常更擅长填充这样一个矩阵，而不擅长自发逃离默认语料先验。

### 10.7 局部对齐主导型任务

**失配画像：** 中等聚合或规格失配，但局部正对齐很强。

许多日常任务都属于这一类。它们之所以困难，并不是因为每一步局部操作都很难，而是因为模型必须知道：哪些局部操作值得信任、何时应该停下、以及如何把这些操作真正组合起来。

例子包括：

- 从混乱上下文中起草战略备忘录；
- 修订一条法律或声誉敏感的信息；
- 在用户优先级不明确的情况下给出产品建议；
- 生成一个带有隐藏组织约束的实施计划；
- 为特定决策者摘要一份长文档；
- 撰写一段面对专家的解释，其中语气很容易，但判断标准是隐性的。

一种典型治理模式是：

1. 让模型执行已对齐的局部操作，例如压缩、列纲、风格迁移与候选枚举；
2. 抽取不确定的全局变量，例如目标、状态、风险、评估指标或非局部依赖；
3. 把这些变量存为条件化约束或 GKO；
4. 用这些受治理约束和局部生成材料一起渲染最终工件。

关键点在于：局部对齐不是缺陷，而是 LLM 实际有用性的基础。缺陷只在于，系统把局部对齐误当成了全局对齐。

### 10.8 原生卓越型任务

有些任务从一开始就是低失配的，未必需要治理层。例如：

- 上下文压缩；
- 基于良好大纲的语义解压；
- 语体迁移；
- 表层润色；
- 简单结构化转换；
- 标准文档；
- 第一轮分类体系生成；
- 第一轮边界情形枚举；
- 查询构造；
- 样板脚手架生成。

对这些任务来说，最佳系统设计可能就是轻量化的：清晰提示、足够上下文、可选检索与最小验证。只有当任务从“流畅转换”切换到“稀有结构、隐藏状态、高风险正确性或隐性评价”时，治理才真正显示出价值。

## 11. 讨论与限制

### 11.1 框架范围

本文提出的是一个框架与一组假设，而不是关于 LLM 的普适定理。我们并不声称知识治理会在所有任务上都优于更简单的方法。它的主要目的，是识别：普通输出空间优化何时会进入平台期，自回归生成何时会表现出色，任务何时处于局部对齐，以及如何把任务从部分对齐转化为更稳定的全局对齐。

### 11.2 分类法纪律

任何诊断分类法面临的一个主要风险，都是类别膨胀。如果每一种反复出现的表层失败都被升级为新的原始失配，框架就会失去解释力。因此，我们坚持区分原始失配与派生/复合现象。

实用标准是严格的：只有当某个新类别无法被现有六类及其交互还原、能够带来额外预测力，并确实需要不同干预时，才应被纳入。按照这一标准，顺序敏感轨迹、涌现式规格、噪声语境建模失败、语料先验主导与控制容量崩塌都很重要，但并非原始类别。

### 11.3 局部对齐与卓越都不是保证

局部对齐与LLM卓越是区间，而不是承诺。一个任务可能一开始是卓越的，但在隐藏约束、事实不确定性、高风险要求或非局部耦合出现后，就退回局部对齐甚至平庸。比如，生成代码脚手架可以是卓越的；把它改造成真实架构中的实现，可能只是局部对齐；而保证它安全、无泄漏、可扩展且满足时间有效性，则未必如此。

因此，这两个概念应被用作诊断工具，而不是对直接生成的一概背书。

### 11.4 训练会减少失配，但不会封闭失配

对齐训练更应被理解为“减少失配”，而不是“消除失配”。它可以让许多有价值行为在模型策略下变成高概率行为，而推理时思考又能通过中间推理让更多有价值结构变得可达。这是真实的能力提升，而不是纯粹的表层变化。足够对齐且具备推理能力的模型，能把很多任务从 LLM 平庸推向局部对齐，并把其中一部分进一步推向卓越。

但开放式任务的价值并不是一张可以被完整预编译进模型权重中的封闭表格。当效用依赖隐藏状态、稀有结构、非局部组合、变化中的环境或涌现式规格时，对齐后的策略仍可能偏离真实任务价值。失败并不在于模型“还在追词频”，而在于训练阶段学到、推理阶段显化出来的代理价值，仍不足以完全决定当前任务的真实价值函数。

这也正是知识治理的动机。治理并不是对对齐训练或推理时思考的否定，而是对它们扩张局部对齐之后，仍然残留的那道缺口的回应。

### 11.5 分解质量与虚假不变项

解耦控制空间的质量，依赖于工件如何被切分和扰动。差的分解只会制造噪声，而不是洞见；弱验证则可能让虚假的不变项被升级。这也是为什么“撤销”必须是一等机制，而不是补丁。

虚假不变项尤其危险，因为它会在降低真实性能的同时，提高系统自信。因此，一个治理层必须具备对抗测试、冲突检测与显式降级机制。

### 11.6 结果反馈与结构反馈

结果层反馈对于淘汰明显差的候选很有用，但在某些任务里它会饱和：它告诉系统某个候选失败了，却不能说明是哪个稀有结构依赖让更好的候选成功。知识治理最有正当性的地方，正是在“结果信号与结构信号之间的缺口”成为主要瓶颈的时候。

“从平庸到卓越的转化”之所以重要，是因为它把模糊的结果信号转成了显式中间对象：失效模式、边界情形、假设、评分规约与约束，而这些对象随后可以被直接测试。

### 11.7 算力与延迟

治理会带来额外成本。切分、扰动、验证、记忆管理与冲突解决都会消耗算力与延迟。当任务价值本来就已在全局上与局部似然对齐时，这些额外机制可能并不值得。

因此，这个框架应被有选择地使用。它最适合于以下场景：平庸输出的代价很高、反复失败能被转化为可复用控制知识、并且任务处于局部对齐但全局不稳定状态。若任务本已处于LLM卓越，更简单的方法往往更优。

### 11.8 地板与天花板

知识治理可以提高控制质量的天花板，但地板仍取决于基础模型与可用工具。它不能取代一个合格的渲染器、可靠的评估器、领域诊断器、检索系统、形式化验证器或人类专家。

同样，自适应算力确实可以抬高复杂任务崩塌发生的阈值，但如果表征错了，仅仅延长思考也不够。更多预算而没有更好的控制，可能只会得到更长的平庸。

### 11.9 何时不需要解耦控制空间

并非所有任务都需要这套架构。常规翻译、直接摘要、许多检索很强的事实问答、验证器可靠的干净符号任务、表层润色、语体迁移、标准文档与第一轮创意生成，往往都具有较低的失配画像。在这些情况下，普通提示、检索、有限搜索或工具使用可能已经足够。

这不是框架的弱点，而是中心理论的自然推论：当任务已经处于LLM卓越区间时，系统就应利用这一优势，而不是强加不必要的控制机械。

### 11.10 仍需要的实证工作

完整的实证研究应在匹配算力预算的前提下，把知识治理与“从平庸到卓越的转化”同强力的输出空间基线进行比较。重要的消融包括：

- 直接生成 vs. 保留局部对齐的重参数化；
- 输出空间搜索 vs. 局部对齐边界处的控制空间搜索；
- 只做评分规约生成 vs. 完整 GKO 生命周期；
- 只做状态枚举 vs. 条件化于状态的渲染；
- 只做边界情形生成 vs. 边界情形验证；
- 有撤销的治理 vs. 无撤销的治理；
- 任务特定控制空间的收益 vs. 与任务无关治理循环本身的收益。

对于噪声语境推理，实证研究还应测量“建模缺口”，即嘈杂自然场景表述与干净抽象表述之间的性能差。这能把“解题失败”与“建模失败”区分开来。

对于局部对齐，实证工作还应测量局部价值在何处不再预测全局价值：何时清晰 prose 掩盖了错误建模，何时候选清单始终显化不出关键不变项，何时生成的评分规约与专家判断相关性很低，以及何时状态枚举确实改善了条件正确率。对于LLM卓越，则应识别其正向对齐画像：何时局部编辑会提升全局价值，何时语义解压能保住控制状态，何时查询构造能提升检索，以及何时生成的评分规约真的与专家判断相关。

---

## 12. 结论

随着 LLM 系统越来越依赖推理阶段算力，一个越来越重要的问题不再只是“如何生成更多候选”，而是“模型究竟在被要求执行什么类型的任务”。有些任务会诱导出 **LLM 平庸**：一个高概率、低价值的区间，在这里，流畅、局部连贯、可逐步改进的输出，仍然与近似最优集合相距甚远。我们认为，这种失效模式往往可以通过六类原始失配来理解：聚合、支持、状态、规格、拟合边界与观测-表征失配。

这个版本的核心修订之一是术语层级。**自回归平庸** 不应命名整个现象。它只是由聚合失配制造出的更窄子情形：局部上合理的 token 级续写，无法组合成全局任务价值。LLM 平庸则更宽。它还包括状态失配，即观察并不等于状态，隐马尔可夫变量或部分可观测变量不能在当前通道下被识别出来；规格失配，即提示词、训练数据规范、评估器或代理奖励没有定义什么才算真正的好；支持失配，即稀有高价值结构不能仅凭概率支持与稀有噪声可靠区分；拟合边界失配，即能力塑形形成的局部吸引子越过有效支撑域，错误牵引相邻场景；以及观测-表征失配，即任务充分世界变量没有进入系统推理或行动所依赖的表征。

本文同时提出了 **自回归局部对齐** 这一常见中间区间。在该区间里，概率与任务价值在局部操作、片段或子任务上对齐，但这种对齐并不会自动组合成全局成功。这正是大多数用户真实面对的区间：模型已经足够有用，能够创造真实的局部价值，但还没有被治理到足以确保这些局部价值满足任务真正目标的程度。

进一步的澄清是：现代对齐并没有使“概率-价值框架”失效。训练时对齐把代理任务价值压缩进策略概率，而思考会扩展局部对齐中间状态的可达空间。这解释了为什么 LLM 系统会持续变强，也解释了为什么越来越多任务会逐步进入局部对齐。但这些机制并没有移除开放式任务中的结构性失配，因为真实效用仍可能依赖非局部聚合、低支持结构、不可识别的潜在状态、缺失通道变量或规格不足的目标。

在正向一极，本文则主张，LLM 平庸存在其对立面：**LLM卓越**。在稳定的正向对齐区间中，自回归续写不是瓶颈，而是优势。上下文压缩、语义解压、语体迁移、表层润色、结构化转换、分类体系生成、边界情形枚举、查询构造、对比矩阵合成与脚手架生成，都可能是“局部续写与任务价值彼此增强”的案例。

这种三段式视角改变了干预原则。目标不总是离开输出空间，也不总是要施加沉重控制架构。更一般的目标是 **从平庸到卓越的转化**：保留已经局部对齐的操作，把高失配部分重参数化为失配更低、正向对齐更强的子任务，再组合并验证它们的输出。只有当每一轮都产出能改变下一轮任务分布的持久中间工件时，多轮交互才真正有用。

为了把这一原则操作化到高失配、高风险或仅局部对齐的任务中，本文提出了 **知识治理**：一个在推理阶段运行的框架，它会在 **解耦控制空间** 中诱导任务特定控制知识，在可用的最强证据下验证它，将其保存为显式且可撤销的 **受治理知识对象**，并用这些对象来引导最终表达。这个框架并非在所有地方都必要；它真正有价值的地方，是那些“局部合理性只是效用的不完全代理，且反复流畅搜索难以把局部价值转成全局成功”的场景。

更广泛的含义在于：高价值 LLM 系统的关键，可能不仅在于能否生成更好的文本，还在于它是否知道何时文本生成本身已经是合适的控制空间、何时只是局部对齐、何时根本不是合适的控制空间，以及如何把一种区间转化为另一种区间。
