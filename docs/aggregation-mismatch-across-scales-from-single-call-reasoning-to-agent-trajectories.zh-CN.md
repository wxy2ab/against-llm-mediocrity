## 摘要

聚合失配发生在这样一类顺序决策系统中：部署过程每次只能提交一个局部决策，却没有精确使用全局 value-to-go；任务价值主要由完整结构决定，早期决策又会形成前缀、改变后续可达空间，使局部代理偏好的选择不一定属于全局高价值解。自回归链式分解本身可以精确编码全局依赖；失配来自代理、搜索或提交策略与全局补全价值的偏离。

在 LLM 系统中，聚合失配至少存在两个尺度：

1. **单次推理级聚合失配**：模型逐 token、逐局部推理步骤生成，但任务价值由完整输出序列决定。模型内部 reasoning 通过计划、候选、比较、回溯和验证，尽量使局部生成服从完整输出价值。
2. **Agent 轨迹级聚合失配**：Agent 每次只能执行一个 action、完成一次状态转移，但任务价值由多次调用、工具执行、环境反馈和状态变化形成的完整轨迹决定。Agent 的 Plan、Candidate、Audit、Hard State、Patch、Rollback 与 Replan，负责让局部动作持续服从更长时间尺度上的终局价值。

两者具有同构的基本矛盾，但并非同一个问题。单次推理中的前缀锁定主要是**语义性的**；Agent 轨迹中的路径锁定则进一步具有**因果性、状态性与不可逆性**。

本文的核心论断是：

> **Reasoning 对抗输出序列的语义前缀锁定；Agent 对抗状态轨迹的因果路径锁定。**

因此，强 reasoning 模型并没有消除 Agent 中 Plan 和 Candidate 的必要性。模型内部的 Plan/Candidate 是当前一次推理的认知结构；Agent 中的 Plan/Candidate 则是跨调用、跨阶段、跨状态转移持续生效的全局控制对象与搜索前沿。

## 一、聚合失配的统一定义

设一个任务的最终产物由一串顺序决策组成：

\[
z=(d_1,d_2,\ldots,d_T)
\]

系统在第 \(t\) 步只能根据当前前缀选择下一个局部决策：

\[
d_t \sim \pi(d_t\mid d_{<t},x)
\]

但任务价值评价的是完整聚合结果：

\[
V(z)=V(d_1,d_2,\ldots,d_T)
\]

令局部决策器当前使用的代理评分为：

\[
q_t(d\mid d_{<t},x)
\]

而某个局部决策在最佳后续补全下能够达到的真实全局价值为：

\[
Q_t^*(d)
=
\sup_{d_{t+1:T}}
V(d_{<t},d,d_{t+1:T})
\]

当局部排序与全局 value-to-go 排序不一致时：

\[
\arg\max_d q_t(d)
\neq
\arg\max_d Q_t^*(d)
\]

就出现了聚合失配。

### 1.1 任务非局部性不是系统失配严重度

设 `α_k` 表示真实效用能被窗口为 `k`、复杂度受限的局部可加函数近似到什么程度。`α_k` 不包含模型、`q_t`、搜索器或提交策略，因此它测量的是 **任务局部可分解性**；`1-α_k` 是任务非局部性剂量，不是聚合失配严重度。

聚合失配必须相对于被部署系统测量。令 `μ_eval` 是跨系统固定的评估历史分布，在预先固定的评估决策集 `C_eval(h_t)` 上定义

\[
\hat d_t=\arg\max_{d\in C_{\mathrm{eval}}(h_t)}q_t(d\mid h_t),
\qquad
d_t^\star=\arg\max_{d\in C_{\mathrm{eval}}(h_t)}Q_t^\star(h_t,d).
\]

则可报告 argmax 不一致率

\[
e_{\mathrm{agg}}=\Pr_{h_t\sim\mu_{\mathrm{eval}}}[\hat d_t\ne d_t^\star]
\]

以及全局补全价值后悔

\[
\operatorname{Reg}_{\mathrm{agg}}=
\mathbb E_{h_t\sim\mu_{\mathrm{eval}}}
\left[Q_t^\star(h_t,d_t^\star)-Q_t^\star(h_t,\hat d_t)\right].
\]

`μ_eval`、`C_eval` 与 tie-breaking 都应在比较前固定。`C_eval` 若只包含两套系统都已获得的候选，主要隔离排序与提交质量；若使用完整可行集，则量中还会包含支持与搜索不足，必须明确标注。若另用系统自己的 `μ_Π`，测得的是 on-policy 聚合负担，应单独报告。GF(2) 一类任务可以具有很低的任务局部可分解性，但在完整约束被外部化后呈现接近零的系统聚合后悔。

这个问题不是泛泛的“系统可能犯错”，而具有四个结构条件：

1. **顺序提交**：系统不能同时完成全部决策，只能逐步形成结果。
2. **价值不可完全分解**：完整任务价值不能被准确写成每一步局部价值的简单相加。
3. **前缀依赖**：已经提交的决策改变后续可选空间与概率分布。
4. **早期锁定**：错误的早期选择难以被后续局部修补完全消除，甚至使高价值解永久不可达。

聚合失配的本质因此不是“模型没有计划”，而是：

> **局部选择必须在不知道完整未来、无法精确计算终局价值的情况下被提前提交。**

## 二、单次推理级聚合失配

### 2.1 基本形式

对一次 LLM 调用，输出为：

\[
y=(y_1,y_2,\ldots,y_T)
\]

模型逐 token 生成：

\[
y_t\sim p_\theta(y_t\mid x,y_{<t})
\]

但任务评价的是完整序列：

\[
J(y_1,\ldots,y_T)
\]

这里不能把自回归条件概率本身当成局部性假设。链式法则

\[
p_\theta(y\mid x)=\prod_t p_\theta(y_t\mid x,y_{<t})
\]

可以精确表示任意联合分布，条件项也可以编码全局约束。单次推理级聚合失配比较的是部署中的局部代理 $q_t$ 与全局补全价值：

\[
Q_t^\star(d)=\sup_{y_{>t}}J(y_{<t},d,y_{>t}),
\qquad
\arg\max_d q_t(d)\ne\arg\max_d Q_t^\star(d).
\]

$q_t$ 可以包含近似条件概率、贪心或截断解码得分、有限搜索启发式与当前控制状态。只有在这种排序偏离与前缀锁定同时存在时，当前局部选择才构成聚合失配。

单次推理级聚合失配表现为：

- 早期表述决定后续语义吸引域；
- 局部流畅性压过全局结构；
- 模型过早选择一个解释、方案或叙事路线；
- 后续 token 主要负责为已有前缀补全，而不是重新寻找全局更优结构；
- 全文重写容易破坏已经正确的高价值局部结构；
- 一个看似合理的局部推理步骤可能把完整答案带入错误方向。

### 2.2 Reasoning 的功能

Reasoning 的价值不只是“输出更多 token”，而是在最终回答生成之前或过程中建立一个内部搜索过程：

```text
任务理解
→ 内部计划
→ 候选假设
→ 局部比较
→ 约束检查
→ 回溯修正
→ 最终输出
```

它试图把由部署局部代理支配的生成，提升为更接近长程补全价值的选择；这改变的是近似、搜索与可用控制状态，不是自回归分解的表达能力。

因此可以把 reasoning 理解为：

> **模型内部用于缓解单次输出聚合失配的微型搜索与治理层。**

它不能消除自回归生成，但可以让模型在提交最终文本之前，先构造更高层的全局表示、保留若干候选，并利用完整候选进行后验比较。

## 三、对抗单次推理级聚合失配的主要手段

### 3.1 全局计划与控制结构

在正式生成之前，先构造：

- 任务目标；
- 全局结构；
- 关键约束；
- 依赖关系；
- 必须同时满足的不变量；
- 完整输出的验收标准。

Plan 的作用是把完整任务价值压缩成后续局部 token 可以持续引用的控制结构：

\[
\text{Global Value}
\rightarrow
\text{Local Generation Constraints}
\]

对故事、方案、代码、分析等聚合任务，优秀产物往往取决于多个跨段落、跨模块、跨阶段结构的共同成立。先建立这些结构，可以减少生成过程中被局部语言概率带偏。

但 Plan 不是越详细越好。过度细化会把早期不成熟判断冻结成新的局部最优。更合理的目标是形成**最小充分 Plan**：保留决定全局价值的关键结构，同时给局部生成留下修正空间。

### 3.2 Candidate：延迟过早承诺

单一路径生成会迅速形成语义前缀锁定。Candidate 的作用是暂时保留多个可能的完整方向：

```text
候选结构 A
候选结构 B
候选结构 C
```

随后依据完整候选，而不是依据生成早期的局部感觉进行选择。

有效 Candidate 不应只是同一表述的近义改写，而应在关键假设、结构、搜索空间或解题路线方面形成真实差异。其价值在于：

- 防止第一个高概率方案过早垄断后续生成；
- 让低概率但高任务价值的结构获得进入选择阶段的机会；
- 使评价器能够看到完整候选，而不是只看到生成前缀；
- 为拆分、变异、重组与局部修补提供材料。

### 3.3 生成与选择分离

生成器面对的问题是“构造一个完整产物”；选择器面对的问题是“在已经完整呈现的候选中判断哪个更好”。两者的信息条件不同。

生成时，模型必须同时解决大量合取约束；选择时，完整候选已经存在，许多错误和价值差异变得可见。因此应尽可能采用：

```text
Generate multiple complete candidates
→ Evaluate complete structures
→ Select / merge / repair
```

而不是在生成早期依据局部 score 直接坍缩到 Top-1。

如果 selector 与 generator 使用完全相同的信息、相同上下文和相同偏差，二者仍可能高度相关。更强的选择过程应引入：

- 不同的评价视角；
- 独立上下文；
- 外部规则或测试；
- 反例与证据；
- 明确的任务价值分解。

### 3.4 将高聚合任务转换为一系列局部可解任务

很多困难生成任务的问题不在于每个局部元素都难，而在于大量局部元素必须在完整产物中同时成立。

因此可以先建立控制空间，再逐层渲染：

```text
全局目标
→ 结构骨架
→ 子结构
→ 局部内容
→ 完整产物
```

这相当于把一个“完整序列价值难以直接优化”的任务，转换为一系列局部目标更清晰、验证成本更低的任务。

关键不是机械分解，而是让每个中间对象都承担真实的全局约束功能。没有后续消费和验证的中间文本，只会增加 token，不会真正改变搜索问题。

### 3.5 完整产物审计与证据寻找

模型生成时依赖前缀；审计时则可以观察完整结果。只要评价完整产物比直接生成完整产物更容易，就存在生成—验证不对称。

有效审计包括：

- 对照全局规格检查缺失约束；
- 寻找支持或反对当前结论的证据；
- 构造反例；
- 比较候选之间的结构差异；
- 通过编译器、测试、执行结果等获得硬反馈；
- 将失败定位为可修改的局部结构。

审计的价值不来自“换一个角色再想一次”，而来自完整结果、新证据或外部反馈使裁决条件发生变化。

### 3.6 Artifact 化与 Patch 优先

当完整产物已经包含大量正确结构时，全文重写会重新暴露所有位置，使已正确部分再次受到自回归采样影响。

Patch 的结构优势在于：

\[
\text{保留已验证结构}
+
\text{只重新搜索失配局部}
\]

因此对于稀疏修改任务，应优先：

```text
持久化完整 artifact
→ 定位缺陷
→ 生成局部 patch
→ 验证 patch
```

而不是反复全文 rewrite。

Patch 不能保证每次都优于重写；当全局结构本身已经错误、局部修改无法恢复一致性时，需要整体重构。但只要正确结构占比高、修改稀疏，Patch 能显著降低重新采样带来的结构损失。

### 3.7 独立分支、变异与重组

同一上下文中依次列出的多个候选往往共享前缀和隐含假设。要真正扩大搜索支持，需要：

- fresh-context 独立分支；
- 不同假设或不同表示空间；
- 对候选做聚类与去重；
- 从多个候选中提取可复用局部结构；
- 对高价值局部结构进行变异和重组；
- 重新回到完整任务验证。

这类方法的价值不是单纯增加采样数，而是降低候选之间的相关性，并提高进入不同语义吸引域的概率。

### 3.8 Typed Abstain 与停止

当候选集中没有足够可靠的解时，强迫系统选择一个合法候选，会把“不知道”转换成错误执行。

因此，应允许：

- abstain；
- needs clarification；
- request evidence；
- defer；
- escalate。

Abstain 本质上是为搜索空间加入一个合法的 null action，避免系统因接口设计而被迫过早坍缩。

## 四、Agent 轨迹级聚合失配

### 4.1 基本形式

Agent 的完整产物不是单段文本，而是一条与环境交互的轨迹：

\[
\tau=(s_0,a_0,o_1,s_1,a_1,o_2,\ldots,s_T)
\]

其中：

- \(s_t\)：外部状态；
- \(a_t\)：Agent 当前动作；
- \(o_{t+1}\)：工具或环境反馈；
- \(U(\tau)\)：完整任务轨迹的最终价值。

Agent 在第 \(t\) 步必须依据当前历史选择一个 action：

\[
a_t\sim\pi(a_t\mid h_t)
\]

但真正最优的当前动作取决于其后全部可能状态转移与未来动作：

\[
Q^*(h_t,a)
=
\sup_{\pi_{t+1:T}}
\mathbb E[U(\tau)\mid h_t,a]
\]

现实 Agent 无法精确求得 \(Q^*\)，通常只能依赖当前可见代理量：

- 这一步是否完成；
- 当前测试是否通过；
- 当前文本是否合理；
- 当前动作是否容易；
- 当前指标是否提高。

于是可能出现：

\[
\arg\max_a \hat q_{\text{local}}(a\mid h_t)
\neq
\arg\max_a Q^*(h_t,a)
\]

这就是 **Agent 轨迹级聚合失配**。

### 4.2 从语义前缀锁定到因果路径锁定

单次推理中，错误前缀主要改变后续 token 分布；Agent 中，错误动作还会真实改变外部世界：

- 写入文件；
- 修改状态；
- 消耗预算；
- 触发副作用；
- 丢失信息；
- 关闭某些未来路径；
- 让后续阶段建立在错误产物上。

因此，Agent 轨迹级聚合失配比单次推理多出三种困难：

1. **状态性**：后续决策面对的是被前一步改变后的真实状态。
2. **因果性**：action 不只是文本提议，而会产生实际结果。
3. **不可逆性**：部分状态转移不能通过“再想一次”恢复。

可以定义当前历史下的最高可达价值：

\[
V_{\text{reachable}}(h_t)
=
\sup_{\tau\in\mathcal R(h_t)}U(\tau)
\]

某个局部上合理的动作，可能大幅缩小未来可达集合：

\[
V_{\text{reachable}}(h_{t+1})
\ll
V_{\text{reachable}}(h_t)
\]

Agent 级对抗聚合失配的核心，因此不仅是提高当前动作质量，还包括：

> **尽量保持高价值未来仍然可达。**

## 五、对抗 Agent 轨迹级聚合失配的主要手段

### 5.1 持久化全局 Plan：把终局价值持续投影到当前动作

Agent Plan 不只是一次调用中的思考提纲，而是多个未来阶段共同消费的控制对象。它至少应保存：

- 最终目标与任务契约；
- 全局不变量；
- 子任务依赖图；
- 阶段顺序；
- 验收条件；
- 未解决的不确定性；
- 资源与预算分配；
- 失败回退层级；
- 已完成且不得破坏的结构。

其功能是让每个 action 不只回答：

> 现在做什么最容易？

而是回答：

> 当前什么动作最有利于维持通往高价值终局的路径？

Agent 必须不断“看全局”，但这不等于每一步都全文重新规划。正确方式是：

```text
冻结目标与关键不变量
→ 持久化当前 Plan
→ 每一步检查局部动作是否仍服务全局
→ 用新证据局部 patch Plan
→ 关键假设失效时才整体 replan
```

Plan 应采用单一事实源，避免 Planner、Executor、Critic 各自维护不同版本并产生 plan drift。

### 5.2 持久化 Candidate Frontier：保留多个未来轨迹

Agent 中的 Candidate 不只是当前调用里短暂考虑的几个答案，而是一个跨步骤持续存在的搜索前沿：

- 候选计划；
- 候选假设；
- 候选实现路线；
- 候选恢复动作；
- 候选完整 artifact。

Candidate Frontier 的功能包括：

- 延迟不可逆承诺；
- 在证据不足时保留多个未来；
- 为不同路线分配不同工具和预算；
- 根据环境反馈重新排序；
- 淘汰已证伪分支；
- 在当前路径陷入局部最优时切换吸引域；
- 从不同分支重组高价值局部结构。

Candidate 的核心不是“数量多”，而是候选是否真正对应不同可达轨迹，并能够被后续独立执行、验证和更新。

### 5.3 分层的全局回看机制

Agent 不应只在开始时看一次全局，也不应每个 action 后都完整 replan。更合理的是建立三种不同频率的控制环：

#### Action Loop

每一步检查：

- action 是否符合当前 stage；
- 是否违反全局不变量；
- 是否造成越权或不可逆风险；
- 是否需要先获得更多信息。

#### Stage Loop

每个阶段完成后检查：

- stage 目标是否真实完成；
- 输出能否被后续阶段消费；
- Plan 与 Candidate Frontier 是否需要局部更新；
- 当前路径是否仍然保持高价值未来可达。

#### Mission Loop

只有在以下触发条件出现时才整体 replan：

- 关键假设被证伪；
- 环境发生重大变化；
- 当前路线连续无进展；
- 候选前沿全部失效；
- 全局验收标准无法由现有结构达到。

因此，“不断看全局”的准确含义是：

> **让全局目标持续参与局部裁决，而不是不断全文重写全局。**

### 5.4 Hard State：使 action 真正作用于明确状态

如果 Agent 的“状态”只是自然语言上下文中的软声明，模型可能随时重新解释：

- 当前处于哪个阶段；
- 哪些工作已经完成；
- 哪些动作被允许；
- 哪些约束仍然有效。

Hard State 将这些信息外部化为环境约束：

- stage 状态机；
- action allowlist；
- 可验证的状态转移；
- commit / rollback / replay；
- 权限边界；
- 完成条件与失败状态。

这使 action 不再只是“模型说自己做了什么”，而成为对真实状态的受控转移。

Hard State 的作用不是直接找到全局最优，而是防止：

- 状态漂移；
- 职责混淆；
- stage 震荡；
- 已完成任务被反复重做；
- 局部动作破坏全局执行边界。

### 5.5 Execute–Observe：用真实环境反馈修正轨迹

模型可以预测工具结果，但预测不等于真实执行。Agent 级聚合失配只能通过真实闭环被持续修正：

```text
选择 action
→ 执行
→ 观察环境变化
→ 获得新证据
→ 更新 Plan 与 Candidate
```

高价值反馈包括：

- 编译器；
- pytest；
- 运行时错误；
- SQL 执行结果；
- 文件 diff；
- 数值指标；
- 权限拒绝；
- 外部系统状态。

真实反馈使 Agent 能够发现：局部上看似成功的动作，是否真的提高了完整任务价值。

### 5.6 全局审计：区分局部成功与任务推进

Agent 很容易把以下信号误认为全局进展：

- 当前步骤已执行；
- 当前输出格式正确；
- 某个局部测试通过；
- 当前指标小幅提高；
- 生成了更多文本或代码。

Audit 的职责是检查：

- 局部产物是否满足全局规格；
- 当前动作是否破坏后续依赖；
- 当前成功是否只是代理指标改善；
- 是否存在未被覆盖的高价值约束；
- 当前路径是否正在局部最优中震荡；
- 新证据是否要求改变 Plan 或 Candidate 排序。

有效审计必须尽可能获得生成阶段没有的信息：完整结果、环境 witness、反例、测试差异或可复现证据。否则，同模型同信息的“自我批评”可能只是额外 reasoning，而不是真正的轨迹裁决。

### 5.7 Artifact、版本与局部 Patch

Agent 长程任务中的核心状态应以 artifact 形式持久化，而不是只存在于对话上下文：

- Plan；
- 代码；
- 文档；
- Candidate；
- Evidence ledger；
- 验收记录；
- 当前状态快照。

随后优先使用局部 patch：

```text
已有 artifact
→ 定位失配
→ 局部修改
→ 验证
→ commit
```

这样可以：

- 保留已验证结构；
- 减少全文重写导致的漂移；
- 支持 diff、审计和回滚；
- 让不同阶段共享同一真实状态；
- 使错误定位与修复具有明确边界。

### 5.8 Branch、Rollback 与 Replan

Agent 对抗因果路径锁定，必须拥有恢复可达空间的机制：

- **Branch**：在不确定时保留多个状态分支；
- **Rollback**：撤销造成负价值的状态转移；
- **Patch**：局部修复而不破坏其余结构；
- **Replan**：关键假设失效后重新构造全局路线；
- **Stop**：当前没有安全高价值动作时停止继续破坏状态。

这组机制对应单次推理中的回溯，但更强，因为它们必须处理真实环境状态，而不仅是重新生成文本。

### 5.9 预算化搜索与候选组合管理

无限候选和无限 replan 会使协调成本吞噬收益。Agent 应将搜索看作一个受预算约束的组合管理问题：

- 为高不确定、高潜力候选分配探索预算；
- 淘汰重复或低上界分支；
- 对关键候选增加验证预算；
- 当边际信息增益下降时停止扩展；
- 在 exploration 与 exploitation 之间动态分配资源。

目标不是穷尽全局搜索，而是在有限成本下提高到达更高价值区域的概率。

### 5.10 Typed Failure、Abstain 与升级

当 Agent 无法判断当前状态、缺少必要能力或候选均不可靠时，继续动作会将不确定性转化为真实损失。

因此，Agent 接口必须支持：

- typed abstain；
- needs clarification；
- missing capability；
- evidence required；
- retryable failure；
- unrecoverable failure；
- human escalation。

这些状态为 Agent 提供合法的“暂不提交路径”，避免因接口强制而产生因果轨迹锁定。

## 六、两层聚合失配的同构与差异

| 原语 | 单次推理级功能 | Agent 轨迹级功能 |
|---|---|---|
| Plan | 当前调用中的认知规划 | 跨调用、跨阶段持续生效的控制面 |
| Candidate | 当前推理中暂时考虑多个答案 | 持久化、可独立执行的轨迹搜索前沿 |
| Verify | 对完整输出做语义检查 | 读取真实执行、环境状态和外部证据 |
| Backtrack | 重新生成前文或改变推理路线 | 回滚真实状态、切换分支或重新规划 |
| Patch | 修复当前输出局部 | 修改持久 artifact，并保留已验证状态 |
| Stop / Abstain | 不强制输出低置信答案 | 不执行可能造成真实副作用的 action |
| Final selection | 选择完整输出 | commit 一条会改变未来可达空间的轨迹 |

两者的共同结构是：

```text
局部顺序决策
+
完整结构价值
+
前缀依赖
+
早期锁定
```

两者的核心差异是：

```text
单次推理：语义前缀锁定
Agent 轨迹：因果路径锁定
```

因此可以称为一种**多尺度聚合失配**：相同的局部—全局矛盾，在 token、输出、调用、action、stage 和完整任务轨迹上递归出现。

## 七、Plan 与 Candidate 何时不是重复 reasoning

强 reasoning 模型已经会主动计划、列候选和反思。外部 Agent 再加入同名阶段，确实可能重复。但判断标准不应是“模型是否已经想过”，而应是外部结构是否承担了新的全局功能。

### 7.1 Plan 具有独立价值的条件

只要 Plan 满足以下任一条件，它就不只是 reasoning trace：

1. 被两个以上后续阶段共同消费；
2. 约束 action 顺序、权限或预算；
3. 持久化并支持局部 patch；
4. 定义阶段退出和全局验收条件；
5. 支持 rollback 与 replan 定位；
6. 被新证据持续更新；
7. 成为多个组件共享的单一事实源。

如果 Plan 生成后不再被引用、不约束状态转移、也不参与验收，它很可能只是一次重复说明。

### 7.2 Candidate 具有独立价值的条件

Candidate Stage 需要满足：

1. 候选具有结构性差异，而非近义改写；
2. 候选被独立保存；
3. 候选可以获得不同执行或证据；
4. 候选在后续仍可重新排序、淘汰或恢复；
5. 候选影响资源分配和路径选择；
6. 选择发生在完整结果或新证据出现之后。

如果同一模型在同一上下文中列出五个相似候选，立即选择第一个，其他候选从未被执行、验证或再次使用，那么该 Candidate Stage 主要只是额外 token。

### 7.3 精确结论

> **模型内部的 Plan/Candidate 是提案；Agent 中的 Plan/Candidate 是控制面与搜索前沿。**

Agent 不应把 reasoning 机械重复一遍，而应把 reasoning 产生的暂时结构升级为：

- 可持久化；
- 可共享；
- 可验证；
- 可局部修改；
- 可控制状态转移；
- 可接受后续证据更新；
- 可支持分支与回滚；

的系统对象。

## 八、统一的聚合失配控制栈

可以把两层机制放在同一个体系中：

```text
                     最终任务价值 / Mission Contract
                                  │
                 ┌────────────────┴────────────────┐
                 │                                 │
          持久化 Plan Graph                Candidate Frontier
                 │                                 │
                 └──────────────┬──────────────────┘
                                │ 选择当前路径
                         Local Action Contract
                                │
                 ┌──────────────┴──────────────┐
                 │                             │
          Native Reasoning                工具与环境状态
    plan / candidate / compare                 │
                 │                             │
                 └──────────────┬──────────────┘
                                │
                         Execute → Observe
                                │
                   Verify / Audit / Evidence
                                │
              Patch / Branch / Rollback / Replan / Stop
                                │
                 更新 Plan、Candidate 与 Hard State
                                └──────────────↺
```

模型与 Agent 的职责可以收敛为：

> **模型负责生成和修改全局结构；Agent 负责使全局结构在真实轨迹中持续有效。**

进一步说：

```text
Reasoning 生成局部 Plan
Agent 持久化、验证并执行 Plan

Reasoning 提出 Candidates
Agent 隔离、调度、验证并裁决 Candidates
```

## 九、对抗聚合失配的五类基础干预

虽然具体方法很多，但可以归纳为五个基础方向。

### 9.1 Globalize：把全局价值投影到局部决策

对应方法：

- Plan；
- Contract；
- 全局不变量；
- 阶段依赖；
- 完整输出评价；
- 定期全局回看。

目标是减少局部动作只服从即时流畅性或短期代理指标。

### 9.2 Preserve Options：保留多个未来

对应方法：

- Candidate；
- Branch；
- Top-K shortlist；
- 延迟承诺；
- Abstain；
- 候选变异与重组。

目标是防止单路径过早坍缩，并保持高价值未来可达。

### 9.3 Externalize State：把关键结构外部化

对应方法：

- Artifact；
- Hard State；
- Plan Graph；
- Evidence Ledger；
- Version；
- Commit history。

目标是避免全局结构只存在于易漂移的上下文和模型记忆中。

### 9.4 Close the Loop：引入真实反馈

对应方法：

- Execute–Observe；
- 编译器与测试；
- 外部证据；
- Audit；
- 反事实测量；
- verifier。

目标是让系统根据真实结果而不是模型想象修正路径价值。

### 9.5 Restore Reachability：恢复被错误动作压缩的解空间

对应方法：

- Patch；
- Rollback；
- Rebranch；
- Replan；
- Typed failure；
- Stop。

目标是在局部错误发生后，尽量恢复高价值路径，而不是让后续步骤继续为错误前缀补全。

## 十、与当前 Routing Reliability 实验的关系

当前 RR 实验不是对“多尺度聚合失配”整体理论的直接证明，但提供了若干一致的局部信号。

### 10.1 冗余阶段不自动产生全局价值

RR4 中，额外 route、compile 与重复 invoke 把动作数从 1 增加到 4，但任务成功率没有提高。这说明：

> 如果额外阶段没有引入新的状态、信息、候选路径或验证能力，它很可能只是重复编排。

### 10.2 Candidate Frontier 可以优于过早 Top-1 坍缩

CSP-1 中，Top-5 shortlist 保持当前 fixture 的任务成功，同时显著降低 picker token；直接 ranker Top-1 则明显更差。这与以下机制一致：

> 保留一个最小充分候选前沿，再基于完整候选进行选择，可能优于在弱局部 score 上直接坍缩到单一路径。

### 10.3 Typed Abstain 防止强制错误承诺

P0-A-ood 中，允许 typed abstain 显著降低错误但合法 Skill 的执行。这说明候选集中“没有正确答案”必须被表示为一等状态，而不是强迫系统从错误路径中选一个。

### 10.4 局部代理分数不足以承担全局裁决

CSP-2/CSP-2R 中，BM25 score/margin Top-1 路线没有通过预注册门槛。即使部分放行样本中暂未观察到错误，覆盖率和统计边界仍不足以支持生产门控。

这与聚合失配的核心一致：

> 局部检索 score 或 margin 不必然等价于完整任务轨迹价值。

这些结果应被视为机制上的实验锚点，而不是把当前小型 fixture 外推成完整理论证明。

## 十一、实验上如何验证两层聚合失配

### 11.1 单次推理级实验

公平比较必须控制总计算预算，至少包括：

```text
R0：原生 reasoning，标准预算
R1：原生 reasoning，增加到与 scaffold 等成本
P1：显式 Plan
C1：同上下文 Candidate
C2：fresh-context 独立 Candidate
V1：完整候选后验选择
A1：外部 verifier / audit
D1：Artifact + Patch
```

关键指标包括：

- 完整任务价值；
- 全局约束保持率；
- 候选结构多样性；
- 错误前缀恢复率；
- Patch 对已正确结构的保留率；
- token、延迟与调用成本。

最重要的比较不是“短回答 vs 多阶段 Agent”，而是：

\[
\text{外部结构}
\quad vs \quad
\text{等预算 native reasoning}
\]

只有前者仍然提高任务价值，才能证明结构增益，而不是单纯更多计算。

### 11.2 Agent 轨迹级实验

至少比较：

```text
无持久 Plan
vs 持久 Plan

单一路径
vs Candidate Frontier

只做局部检查
vs 分层全局回看

全文重写
vs Artifact + Patch

无回滚
vs Rollback / Branch

软状态
vs Hard State
```

必须在真实环境执行，并记录：

- 最终任务价值；
- 局部成功率与最终成功率的差异；
- 不可逆错误率；
- plan drift；
- state oscillation；
- candidate collapse；
- rollback 次数；
- reached dead-end rate；
- token、延迟、工具调用和协调成本。

还应按 action、stage 和 task family 聚类，不能把同一任务的多次运行当成独立样本。

### 11.3 一个关键新指标：可达价值保持

Agent 对抗轨迹级聚合失配的目标不应只看当前 action 是否成功，还应估计：

> 当前动作之后，高价值终局是否仍然可达。

虽然真实 \(V_{\text{reachable}}\) 很难直接观测，但可以用以下代理量测量：

- 是否破坏关键不变量；
- 是否关闭其他候选路径；
- 是否引入不可逆副作用；
- 是否需要整体重做；
- 是否仍有至少一个候选能够通过终局 verifier；
- 失败后能否通过 Patch/Rollback 恢复。

这比单纯记录“当前步骤完成”更接近 Agent 全局价值。

## 十二、设计原则

### 原则一：全局功能优先于阶段名称

不能因为一个组件叫 Planner、Critic 或 Candidate Generator 就假定它有价值。应检查它是否真实改变：

- 全局约束；
- 搜索前沿；
- 外部状态；
- 反馈信息；
- 可恢复性。

### 原则二：最小充分 Plan，而不是最大 Plan

Plan 必须覆盖全局依赖和验收边界，但不应冻结所有局部细节。过度 Plan 会形成计划刚性，使早期错误扩散到整个轨迹。

### 原则三：最小充分 Candidate Frontier

Candidate 数量不是越多越好。应在保持必要 recall、结构差异与未来可达性的前提下，压缩候选规模和协调成本。

### 原则四：局部执行，全局治理

模型可以专注当前局部任务，但 Agent 控制面必须持续维护：

- 全局目标；
- 当前 stage；
- 候选前沿；
- 全局不变量；
- 终局验收；
- 可回滚状态。

### 原则五：不要每一步重写全局

全局应持续参与裁决，但只在关键假设失效时整体 replan。正常情况下使用局部状态更新与 Plan patch。

### 原则六：选择完整结构，而不是迷信局部 score

只要任务价值依赖完整序列或完整轨迹，就不应把局部概率、检索分数或当前步骤成功直接等价为全局价值。

### 原则七：优先保留可恢复性

在多个局部收益相近的 action 中，应优先选择：

- 副作用更低；
- 可回滚；
- 保留更多候选路径；
- 更容易获得信息；
- 更少破坏已验证结构；

的动作。

### 原则八：Agent 结构必须和强 reasoning 基线比较

传统 scaffold 可能已被模型内部 reasoning 部分吸收。任何 Plan、Candidate、Reflect 组件都必须证明其收益来自全局系统功能，而不是重复模型已经完成的认知操作。

## 十三、理论边界

### 13.1 不能保证全局最优

Plan、Candidate、Audit、Patch 与 Rollback 不能保证找到全局最优，因为：

- 搜索空间无法穷尽；
- 全局价值可能不可观测；
- verifier 可能不完整；
- 候选可能相关；
- 初始 Plan 可能错误；
- 环境状态可能部分不可逆；
- 预算通常不足。

它们能更稳妥地支持的结论是：

> 减少局部吸引子造成的过早终止，保留更多高价值未来，并提高从当前局部最优迁移到更高任务价值区域的概率。

### 13.2 严格使用 Agent 轨迹级聚合术语

Agent 外层不一定是严格意义上的 token autoregressive model。它可能包含确定性代码、工具、状态机和环境转移。

因此，严格术语应使用：

> **Agent 轨迹级聚合失配**

“Agent 级自回归平庸”不再作为直观术语保留。它既会把结构类比误写成生成机制，也会把支持侧的概率质量集中与聚合侧的局部—全局偏离再次混在一起。跨尺度的共同结构直接称为 **Agent 轨迹级聚合失配**。

### 13.3 对抗机制本身也可能产生新的局部最优

- Plan 可能形成计划刚性；
- Candidate 可能高度相关；
- Audit 可能优化错误指标；
- Patch 可能保留错误全局结构；
- Hard State 可能锁死错误状态定义；
- Rollback 可能造成反复震荡；
- 过度全局回看可能吞噬执行预算。

因此，对抗聚合失配的目标不是无限增加结构，而是建立：

> **最小充分的全局控制、候选保留、真实反馈、状态稳定与可恢复机制。**

---

## 十四、核心命题

### 命题一：单次推理级聚合失配

当完整输出价值不可由部署局部代理准确恢复，局部代理排序偏离全局 value-to-go，且生成前缀会约束后续可达序列时，局部代理偏好的 token 不必属于全局高价值输出。Reasoning 通过内部 Plan、Candidate、比较、回溯与验证，使局部生成更接近完整输出价值。该命题不把自回归分解本身视为失配来源。

### 命题二：Agent 轨迹级聚合失配

当完整任务价值取决于多次 action 与状态转移形成的轨迹，且早期动作会改变未来可达空间时，局部上合理的 action 不必属于高价值终局轨迹。Agent 通过持久 Plan、Candidate Frontier、Hard State、Execute–Observe、Audit、Patch、Rollback 与 Replan，使每次局部状态转移尽量保持在通往更高任务价值的可达区域内。

### 命题三：两层递归

模型 reasoning 与 Agent scaffold 不是简单重复，而是作用于不同时间尺度：

```text
Reasoning：对抗单次输出中的语义前缀锁定
Agent：对抗多步执行中的因果路径锁定
```

### 命题四：全局功能决定 Plan/Candidate 是否必要

如果 Plan 与 Candidate 只是在相同信息上再次生成文本，它们可能是冗余 scaffold；如果它们成为跨阶段共享、可持久化、可验证、可更新、可控制状态转移的全局对象，则它们是 Agent 对抗轨迹级聚合失配的基础设施，不能因模型内部已经 reasoning 而被弱化。

---

## 十五、最终结论

聚合失配不是仅存在于 token 生成层的偶然缺陷，而是一种会在顺序决策系统中跨尺度递归出现的结构性问题。

在单次调用内，模型逐 token 提交局部语义选择，完整任务价值却由整段输出决定；reasoning 通过内部计划、候选、比较与回溯，对抗语义前缀锁定。

在 Agent 系统中，模型与环境逐 action 提交真实状态转移，完整任务价值却由整条执行轨迹决定；Agent 通过持久 Plan、Candidate Frontier、Hard State、真实反馈、Audit、Patch、Rollback 与 Replan，对抗因果路径锁定。

所以，Agent 的目标不是机械重复模型内部 reasoning，而是把 reasoning 无法独自维持的全局结构放到模型外：

- 让全局目标持续参与局部动作；
- 让多个未来在证据不足时仍然可达；
- 让真实环境反馈修正路径价值；
- 让正确结构可以被保留和局部修改；
- 让错误状态可以回滚；
- 让关键假设失效时能够重新规划。

最凝练的表述是：

> **Reasoning 对抗语义前缀锁定；Agent 对抗因果轨迹锁定。Plan 把全局价值持续投影到局部决策，Candidate 保留多个未来可达路径，Audit 与环境反馈不断修正路径价值。它们不能保证全局最优，但能够减少过早坍缩、维持高价值未来的可达性，并提高系统游走到更高任务价值区域的概率。**
