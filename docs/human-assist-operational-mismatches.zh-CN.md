## 摘要

《知识治理》主文用六类原始失配解释任务价值为何会与生成过程分离：聚合失配、支持失配、状态失配、规格失配、拟合边界失配和观测-表征失配。本文在此之上提出面向 agent 系统的协作层诊断：**人类协助型操作失配**。

操作失配出现在以下情形：agent 无法可靠继续，因为某个任务关键控制变量不可获得、不确定，或超出其合法权限；而一次有针对性的人类输入可以解除阻塞。操作失配不是新的原始失配类别。它回答的是另一个问题：自治执行具体在哪里被阻塞，以及什么最小人类输入能够恢复推进。

本文的核心对象是 **最小充分人类问题（MSHQ）** 和 **受治理升级对象（GEsO）**。这里的 `GEsO` 有意区别于对象模型中的 **受治理执行对象（GEO）**。MSHQ 只询问缺失的人类治理变量；GEsO 则记录何时必须升级、谁应回答、安全默认是什么、等待期间可以继续做什么，以及升级规则何时过期或撤销。对于长程 agent，回答随后应被提交进硬状态，而不是只作为上下文记忆存在。

## 1. 范围与核心命题

人类协助的目标，不是把任务退回给人，而是提供能够恢复 agent 自治的最小控制变量。

升级前，agent 应先尝试合理的自主修复：

1. 检查现有上下文和受治理知识；
2. 查询工具、文件、日志、数据库或当前来源；
3. 运行测试、模拟、检索或构造反例；
4. 重参数化任务或生成可比较选项；
5. 判断剩余阻塞是否确实由人类治理。

只有此时才应提问：

> 哪个最小、可由人回答的问题，能够恢复可靠自治？

## 2. 与主框架的关系

| 层级 | 核心问题 | 示例 |
|---|---|---|
| 原始失配 | 为什么生成会偏离任务价值？ | 聚合、支持、状态、规格、拟合边界、观测-表征 |
| 操作阻塞 | 哪个控制变量阻止可靠继续？ | 状态、价值选择、授权、证据、资源 |
| 升级协议 | 应问什么，回答后如何继续？ | MSHQ、GEsO、安全默认、答案验证、恢复自治 |

操作阻塞通常是原始失配在执行层的表现：

- 隐藏状态表现为缺少可观察事实；
- 规格失配表现为偏好权重或验收标准缺失；
- 聚合失配可能要求确认全局约束；
- 支持失配可能要求获得专家、来源、工具或非常规选项；
- 拟合边界失配可能要求人类或外部验证器检查某个局部断言能否通过相邻案例。
- 观测-表征失配可能要求先补测量、原始证据、更丰富模态、工具反馈、日志、传感器或结构化控制表征，再判断是否需要问人。

## 3. 定义与升级门槛

当以下条件同时成立时，存在人类协助型操作失配：

1. 动作排序或可执行性显著依赖某个缺失控制变量；
2. agent 无法以可接受成本自主获得或验证它；
3. 缺少它继续行动会产生实质错误、风险、浪费或越权；
4. 有针对性的人类或人类治理系统能够解决它。

升级应通过以下两类门槛之一。

### 3.1 硬治理门槛

下列情形必须升级：

- 发送、发布、删除、支付、签署或作出外部承诺；
- 披露敏感信息；
- 承担法律、财务、安全、雇佣或声誉责任；
- 越过显式政策、审批或权限边界。

### 3.2 预期损失门槛

非强制情形下，当无支持自治的预期损失高于打断和延迟成本时升级：

\[
\operatorname{Escalate}
\quad \text{if} \quad
P(\text{实质错误}) \times C(\text{错误})
>
C(\text{打断}) + C(\text{延迟}).
\]

可逆性、证据质量和可用的自主修复路径都会改变门槛。

## 4. 五个操作域

原先较宽的操作失配列表被收紧为五个面向行动的操作域。更细标签仍可作为子类型使用，但不再与原始失配并列。

### 4.1 信息与证据

agent 缺少事实、当前状态、可靠证据、验证器或新鲜上下文。

常见子类型：

- 可观察性；
- 验证；
- 记忆与时效性；
- 文件、工具、运行环境、API 或权限访问。

MSHQ 示例：

> 我只需要确认一个事实：该字段是否在预测时间之前可用？如果无法确认，我会把它视为泄漏风险并使用滞后版本。

### 4.2 价值与规格

多个动作都可行，但排序取决于人类治理的目标或验收标准。

常见子类型：

- 偏好或效用权重；
- 品味与身份；
- 预算与风险承受；
- 停止或充分性标准；
- 利益相关者优先级。

MSHQ 示例：

> 这些方案主要在速度和运营风险之间取舍。哪项应主导？若不指定，我会选择最低风险且可逆的方案。

### 4.3 权限与责任

agent 可能知道该做什么，但没有合法权限执行，或无法判断谁承担后果。

常见子类型：

- 授权与委托；
- 责任与风险归属；
- 隐私与披露许可；
- 外部承诺。

MSHQ 示例：

> 这条消息包含交付承诺。是否授权发送这段具体文字？无人批准时，我只保留草稿。

### 4.4 边界与时机

agent 不知道规则何时适用、何时撤销，或当前应探索、起草、等待、承诺还是执行。

常见子类型：

- 规则适用范围与撤销条件；
- 时间紧迫性；
- 承诺程度；
- 可逆推进与不可逆动作。

MSHQ 示例：

> 这条规则适合普通退款案例。若怀疑欺诈或账户接管，它是否仍然适用？

### 4.5 协调与控制表示

当前任务表示、分解、工作流或人机交接可能遗漏决定性依赖。

常见子类型：

- 表示与任务分解；
- 工作流责任；
- 交接界面；
- 多个委托方冲突。

这类阻塞通常应先通过构造任务模型、依赖图、选项集或工作流自主解决。只有控制表示或组织流程无法推断和验证时，才应问人。

MSHQ 示例：

> 我把任务建模为按成本、速度和风险组织的决策备忘录。是否还存在会改变决策的治理维度或必需审批步骤？

## 5. 最小充分人类问题

高质量 MSHQ 应具备：

1. **具体：** 命名阻塞变量；
2. **决策型：** 询问事实、价值选择、授权、边界或证据；
3. **低负担：** 尽可能给出简洁选项；
4. **说明后果：** 解释答案会改变什么；
5. **有默认：** 说明无人回答时的安全动作；
6. **不甩回任务：** 不要求人重新完成整个问题；
7. **可路由：** 指明适合回答的人类角色。

低质量：

> 我该怎么办？

更好：

> 唯一阻塞决策是速度与运营风险谁优先。因为动作难以撤销，我建议优先最低风险。

## 6. 受治理升级对象

GEsO 保存可复用的升级规则。

```json
{
  "id": "geso-uuid",
  "domain": "information | value | authority | boundary | coordination",
  "subtype": "authorization",
  "condition": "触发升级的条件",
  "autonomous_recovery_attempted": ["context", "tools", "tests", "reparameterization"],
  "minimal_question": "最小可回答问题",
  "options": ["A", "B", "C"],
  "recommended_option": "B",
  "default_if_no_response": "安全默认或暂停条件",
  "mandatory_gate": true,
  "error_cost": "low | medium | high",
  "reversibility": "reversible | costly-to-reverse | irreversible",
  "human_role": "user | expert | approver | operator | reviewer | risk owner",
  "evidence_needed": "fact | preference | authorization | validation | boundary",
  "autonomous_work_allowed": "等待期间允许继续的工作",
  "answer_validation": "如何确认回答真正解除阻塞",
  "lifespan": "one-shot | session | project | until revoked",
  "revocation_trigger": "升级规则何时失效",
  "source": "policy, failure, user instruction, validator, or prior escalation"
}
```

`error_cost` 与 `reversibility` 必须分开。不可逆性不是普通风险等级。

## 7. 人类协助治理闭环

```text
1. 诊断原始失配与当前操作阻塞。
2. 尝试有边界的自主修复：
   检查 → 检索 → 测试 → 模拟 → 重参数化。
3. 应用硬治理门槛。
4. 若不存在硬门槛，比较无支持自治的预期损失与打断、延迟成本。
5. 构造 MSHQ，并实例化或更新 GEsO。
6. 等待期间继续安全、可逆的工作。
7. 验证人类回答：是否充分、被授权、内部一致、仍然有效？
8. 若回答含糊，只提出一个更窄问题，或路由给正确角色。
9. 在已解决变量下恢复自治。
10. 验证最终动作或工件。
11. 当已解决变量改变任务状态、授权、边界或义务时，将它提交为硬状态转移。在对象模型中，这通常落到 `transition_contract` 约束下的 `state_record`，而控制改动也可额外发出 `control_delta`。
12. 将持久答案存为 GKO，将重复升级规则保留为 GEsO。
13. 当状态、政策、权限或工具改变时撤销过时 GKO/GEsO。
```

无人回答时：

- 不得越过权限、隐私或不可逆动作的强制门槛；
- 只有真正安全时才使用显式默认；
- 继续可逆的准备工作；
- 记录未解决阻塞，而不是静默猜测。

## 8. GKO 与 GEsO 的结合

| 对象 | 治理内容 | 核心问题 |
|---|---|---|
| GKO | 知识、约束、条件、诊断 | agent 应知道或遵守什么？ |
| GEsO | 升级、缺失变量、权限、交接 | agent 何时问、问谁、然后做什么？ |
| SGAR 状态 | 被承认的位置、转移、恢复、审计 | agent 的操作状态发生了什么变化？ |

GEsO 的人类回答可以成为 GKO：

> 对该客户不得直接承诺退款；必须升级给账户负责人。

GKO 也可以触发 GEsO：

> 所有外部承诺在发送前必须获得明确批准。

GEsO 的回答也可能触发硬状态转移：

> 账户负责人批准了修订后的承诺措辞；agent 现在可以发送且只能发送该版本，此批准在本次消息后失效。

## 9. 评估指标

除最终任务结果外，还应评估协作质量：

- 升级精确率；
- 升级召回率；
- 问题最小性；
- 人类认知负担；
- 自治恢复率；
- 错误自治事件；
- 不必要升级事件；
- 回答解除阻塞率；
- GEsO 复用与撤销质量；
- 硬状态吸收率：已解决变量是否成为可恢复状态，而不是消失在聊天中。

## 10. 局限与研究议程

这是一套方向性的分类，而不是封闭本体。操作标签只有在改善路由、问题构造或安全行动时才值得保留。

重要的开放问题包括：

- 在不同风险与打断成本下校准升级门槛；
- 识别人类回答是否错误、过时、未授权或不充分；
- 处理多个委托方之间的冲突；
- 防止过度升级和习得性无助；
- 保护升级过程中收集的敏感信息；
- 在相同预算下衡量 MSHQ/GEsO 是否提升任务价值。

## 结论

当 agent 无法可靠观察、推断、验证或授权少量关键控制变量时，人类协助最有价值。agent 应先穷尽合理的自主修复，再提出最小、结构化的问题，尊重硬治理边界，验证回答，在改变操作状态时提交已解决变量，然后恢复自治。

可靠委托既不是完全自动化，也不是持续监督，而是在自治工作与精确人类介入之间进行受治理的切换。
