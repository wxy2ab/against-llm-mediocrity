## 摘要

一次生成能有多好，取决于系统做出不可撤回的提交时，手里有什么可以依据。本文把这组内容称为**提交时刻的工作集**，并用它比较三种生成方式。直接输出只能依据任务表征和已经写出的前缀。Thinking（模型内部推理）在提交之前多了一份自己写的草稿，增加的是计算，但只限于单次上下文和预算装得下的那部分。Agent 一方面能把计算摊到多个上下文里、按需分配预算，另一方面在提交之前还能拿到外部观测、独立检查和已提交的中间状态。

由此得到四个结论：

1. Thinking 不能提高任务在信息上的可达上限。在这个上限之下它能走多远，受单次上下文的有效计算容量限制：预算只够展开 5 个方案时，第 6 到第 20 个方案覆盖不到。
2. Agent 相对 thinking 的增益有两种。一种是程度上的：更多、可以自由分配的计算。预算足够、训练得当的 thinking 原则上可以追上。另一种是种类上的：新信息。Thinking 无论多长都给不了。
3. 一个外部结构如果既不带来新信息，也没有扩大有效计算，就只是在重复 thinking。
4. 迭代只有在每一轮都带来新信息、独立裁决或持久对象时才有回报。

这些结论合起来给出一个职责划分。决定性信息不在输入里时，agent 的主要职责是取得观测和反馈。信息在输入里、但超过单次调用的有效容量时，主要职责是信息的构造和组织。两者都不成立时，agent 能增加的很少。

本文是一份待检验的草稿。第 8 节给出三组实验设计和证伪条件，第 9 节标明每条主张目前的证据等级。

## 1. 起点：为什么先展开再输出会更好

聚合失配的现行定义是：部署中的局部代理、有限搜索或不可逆提交，偏离了全局补全价值。自回归链式分解可以精确表示任意联合分布，所以它不是病因。病因是两件事：模型学到的条件分布只是近似；内容一旦写出就不能收回。

直接输出时，写下第 `t` 个 token 所依据的条件分布，必须隐含地考虑后面所有可能的写法。这个要求很高，近似误差就出在这里。Thinking 换了一种做法：先把一种完整的写法写出来，再以它为条件生成最终输出。隐含的“考虑所有后续”被一份具体的草稿替代。[审计工程](./audit-engineering-failure-localization-control-space-writeback.zh-CN.md)一稿把这称为前缀-完成不对称：完整候选会暴露首次生成时还看不见的接口、矛盾和依赖。

需要说准确的是，thinking 并没有消除“当前选择依赖全序列”这件事。草稿本身也是逐 token 写出来的，用的是同一个局部代理。Thinking 改变的是提交结构：

- 草稿里的选择不交付，可以推翻；
- 最终输出以一份完整候选为条件。

代价是锚定。一份草稿通常只代表一个结构盆地，最终输出会沿用它的框架。[多尺度](./aggregation-mismatch-across-scales-from-single-call-reasoning-to-agent-trajectories.zh-CN.md)一稿把这叫作语义前缀锁定。

## 2. 提交时刻的工作集

**提交**指交付一段输出，或执行一次不可撤回的状态转移。**提交时刻的工作集** `W_c` 指做出这次提交的那次调用所能依据的全部内容。把它拆成五部分：

```math
W_c = Z \cup D \cup O \cup A \cup S
```

| 记号 | 内容 | 来源 |
|---|---|---|
| `Z` | 任务表征：提示、给定的上下文 | 任务开始时已有 |
| `D` | 草稿与推导 | 由模型自己生成；thinking 只有同一上下文里的，agent 可以有多个上下文各自生成的 |
| `O` | 观测：工具结果、文件、测试输出、人的回答 | 任务开始后从外部取得 |
| `A` | 评估：对候选的检查结论 | 另一个上下文，或外部验证器 |
| `S` | 已提交状态：通过验证的决定、结果和未决事项 | 前面各轮留下 |

三种生成方式的区别，就是 `W_c` 里有哪几部分：

| 方式 | `W_c` 的组成 | 相对上一行增加的资源 |
|---|---|---|
| 直接输出 | `Z` 和已写出的前缀 | 无 |
| Thinking | `Z`、单次上下文里的 `D` | 计算，限于单次上下文与预算 |
| Agent | `Z`、多个上下文的 `D`、`O`、`A`、`S` | 可扩展的计算、信息、独立性、持久性 |

`W_c` 是任务层面的概念。它说的是提交时系统能拿到什么，不是模型内部的注意力权重。工作集里有，不等于被用上；内容越多，稀释越重。这是第 5 节要处理的问题。

## 3. Thinking 的边界

### 3.1 增加的是计算，不是信息

草稿 `D` 由模型参数、`Z` 和采样随机性生成，无论它出自一个上下文还是多个上下文。给定 `Z`，它不含任何关于世界的新信息：

```math
I(D; S_{\text{world}} \mid Z) = 0
```

记 `V_X` 为只依据 `X` 时任何策略所能达到的最高期望效用。那么：

```math
V_{Z \cup D} = V_Z \le V_{Z \cup O}
```

等号说的是：模型自己生成的内容不能抬高 `V_Z`，不管生成了多少。它的作用是让一个计算有限的模型更接近 `V_Z`，也就是把 `Z` 和模型参数里已有、但一次前向用不上的东西变得可用。能接近到什么程度，是 3.2 节的问题。不等号说的是：只有观测才能抬高上限本身。

这与[通道治理](./observation-representation-mismatch-channel-governance-llm-systems.zh-CN.md)一稿的分解一致：`V_feas − V_Z` 那一段是可行通道没接上造成的损失，想得再久也补不回来。

### 3.2 上限之下：有效计算容量

信息上限之下还有两层。记 `V_θ` 为这个模型在预算不设限、计算组织得当时能达到的值，`V_θ(B)` 为单次上下文、预算 `B` 的 thinking 能达到的值：

```math
V_\theta(B) \le V_\theta \le V_Z
```

第一个不等号的差距来自预算。假设一个任务要综合 20 个结构不同的方案才能可靠地得到好结果，而单次 thinking 的预算只够展开 5 个，那么其余 15 个覆盖不到，`V_θ(B)` 就明显低于 `V_θ`。

加预算能缩小这个差距，但单次上下文还有两个软限制，让有效容量低于名义预算：后面的方案以前面的方案为条件（3.3 节），内容越长稀释越重（3.5 节）。

原则上，如果预算不设上限，训练也让模型学会使用很长的 thinking，`V_θ(B)` 可以逼近 `V_θ`。所以这一层的差距是程度问题，不是种类问题。Agent 在这里的优势是实践上的：它不受单次调用的预算上限约束，可以把计算摊到多个互不干扰的上下文里，并且把预算投到更有希望的方向上。

### 3.3 一份草稿，一个盆地

Thinking 通常只展开一条路线。后面的自我修订以这条路线为条件，改的是细节，很少换结构。要保留多个结构不同的方向，需要把候选独立保存、分别推进，这超出了单次上下文能稳定做到的范围。

### 3.4 自检不独立

同一上下文里的自我批评，读的是同一份草稿、同一套框架，它的错误和草稿的错误高度相关。草稿没看见的东西，自检多半也看不见。

### 3.5 越长越稀

Thinking 越长，工作集里与当前决定无关的内容越多，早先的约束会被后面的文字冲淡。

## 4. “更高阶的内容”是几种不同的资源

说 agent 能“展开更高阶的内容”，容易把几件事混在一起：

| 所谓“高阶内容” | 本质 | Thinking 能否提供 |
|---|---|---|
| 推导的推导、后果的后果 | 计算 | 能，受预算和工作集容量限制 |
| 更多结构不同的候选方案 | 计算的规模 | 部分能：预算内展开得了几个算几个 |
| 文件内容、测试结果、当前真实状态 | 信息 | 不能 |
| 不受同一份草稿影响的检查 | 独立性 | 实践中不能 |

再加上跨轮次保留已验证结果的能力，也就是持久性，agent 能做的事可以列成下表。前四行是常见的说法；第五行来自预算的自由分配；最后两行容易漏掉，却决定前面各行是否有效。

| Agent 的动作 | 增加的资源 | 主要修复的失配 | 对应工作稿 |
|---|---|---|---|
| 展开高相关的隐藏上下文 | 信息 | 观测-表征 | [通道治理](./observation-representation-mismatch-channel-governance-llm-systems.zh-CN.md) |
| 以不同角度重组上下文 | 可用性：让已有内容被用上 | 聚合 | [注意力治理](./attention-governance.zh-CN.md) |
| 独立审计：裁掉不相关内容，定位缺陷 | 独立性 | 规格、聚合 | [审计工程](./audit-engineering-failure-localization-control-space-writeback.zh-CN.md) |
| 多次循环迭代 | 修订机会 | 聚合 | [Step 与 Stage 实验](./aggregation-mismatch-v18-v19-step-vs-stage-iteration.zh-CN.md) |
| 跨上下文展开候选，按需分配预算 | 可扩展的计算 | 支持 | [支持失配与控制空间搜索](./support-mismatch-control-space-search-llm-systems.zh-CN.md) |
| 提交已验证的结果 | 持久性 | 状态 | [SGAR](./state-governed-agent-regime-for-governed-llm-systems.zh-CN.md) |
| 接入外部判据 | 保真度 | 规格 | [Oracle 分类](./oracle-classification-audit-agent-sgar-engine-routing.zh-CN.md) |

四点说明。

第一，这张表里只有一部分是聚合修复。展开隐藏上下文修的是观测-表征失配，接入外部判据修的是规格失配。Agent 的增益横跨几类失配。

第二，独立审计买到的是带宽，不是保真度。换一个上下文再看一遍，能发现更多可疑之处；这些发现是不是真的，要靠外部判据来定。没有外部判据时，审计只是同一个模型的第二意见。

第三，多尺度一稿第七节列出了 Plan 和 Candidate “不是重复 reasoning”的条件，那些条件可以归到这里的资源上。被多个阶段消费、持久化、作为单一事实源，属于持久性。候选独立保存、获得不同证据、在新证据出现后再做选择，属于独立性加信息。

第四，这些资源的性质不同。信息是种类上的差别：`Z` 里没有的东西，thinking 无论多长都给不了。可扩展的计算是程度上的差别：单次 thinking 的预算上限提高、模型学会使用更长的 thinking 之后，它会缩小。独立性和持久性居中：足够长、训练得当的 thinking 原则上可以在内部重新推导和记账，实践中受锚定和稀释限制。这与[受控实验](./why-agent-engineering-needs-controlled-experiments.zh-CN.md)一稿的判断一致：训练可以吸收治理策略，但不能凭空创造缺失的观测。

## 5. 三种情形下 agent 的职责

“有没有新信息”要看相对谁。相对整个任务，输入里的材料都算已有信息。相对某一次调用，只有进入它有效工作集的部分才算数。输入超过单次调用的有效容量时，决定性的内容可能就在输入里，却不在任何一次调用的工作集里。这时把它送进工作集，对任务来说没有增加信息，对这次调用来说却是新的。

所以 agent 的职责由两个问题决定：决定性信息在不在输入里；输入和判断所需的结构，单次调用装不装得下。

| 情形 | 判别条件 | agent 的主要职责 | 主要对应的资源 |
|---|---|---|---|
| 封闭且小 | 决定性信息在输入里，单次调用装得下 | 很少；所需候选超过预算时，跨上下文展开候选 | 可扩展的计算 |
| 封闭且大 | 决定性信息在输入里，但超过单次调用的有效容量 | 信息的构造和组织 | 可用性、独立性、持久性 |
| 开放 | 决定性信息不在输入里 | 用工具取得观测和反馈 | 信息 |

三种情形可以叠加：一个又大又开放的任务，两种职责都要承担。

用[注意力治理](./attention-governance.zh-CN.md)一稿的话说，决策工作集描述一步判断必须保持有效的内容，`W_c` 描述提交时实际能依据的内容。“封闭且大”就是前者需要的内容在输入里，却没有进入后者。

### 5.1 封闭任务里的两种瓶颈

不加外部信息时，结果上不去有两种不同的原因：

- **注意力容量**：输入太大，或跨部分的依赖太纠缠，判断所需的内容没有同时留在工作集里。对策是重组。
- **计算容量**：要展开的候选太多，预算不够。对策是跨上下文展开候选（3.2 节）。

两者可以用干预来区分。把输入裁到只剩相关部分后结果变好，瓶颈在注意力。输入不变、多给几个独立尝试后结果变好，瓶颈在计算。它们分别对应注意力治理一稿 6.3 节的情况 A 和情况 B，开放情形对应情况 D。

### 5.2 “重组”包含的操作

| 操作 | 绕开的限制 |
|---|---|
| 选取：为当前判断挑出相关材料 | 稀释 |
| 换表示：把隐含关系做成显式结构，例如人物表、时间线、依赖图 | 每次判断都要重新推导同一组关系 |
| 拆判断：把大问题拆成各自只需小工作集的子判断 | 单次工作集容量 |
| 独立复核：换一个上下文再查 | 自检与草稿相关 |
| 持久记账：留下已确认的发现，跟踪跨部分的约束 | 遗忘和反复 |

这些操作产生的选取结果和派生结构都由模型从输入算出，属于第 2 节的 `D` 和 `S`，不抬高信息上限。它们的作用是让每一次调用的工作集小而充分。注意力治理一稿给出了一个必要条件：证据包不能把需要不同判断的材料压成同一个输入，否则重组本身就丢了信息。

### 5.3 重组方案由谁给出

重组方案本身可能携带外部信息。由人来决定按什么结构重组时，他对材料的了解和对“什么算好”的判断就进入了系统。这属于观测和规格上的输入，不属于封闭条件下的增益。要检验“不靠外部信息也能提升”，重组方案必须由系统自己产生，或者来自与具体材料无关的固定规则。

这一节的动机来自长文稿处理的经验：一本几十万字的书稿同时超出了注意力和单次 thinking 的有效范围，多次重组上下文结构之后，最终结果的质量有明显提升。这是一条未经对照的个案观察，重组也是在人的主导下完成的。它说明这种情形存在，不能当作封闭条件下增益的证据。

## 6. 迭代什么时候有回报

多轮迭代本身不产生价值。一轮迭代要有回报，至少要带来下面三样之一：

- 新的观测；
- 独立于上一稿的裁决；
- 一个通过验证并保留下来的对象，它会改变下一轮要解决的问题。

三样都没有，循环就是在同一个分布里重采样，还可能在几个局部合理的版本之间来回摆动。

现有实验与这个判断方向一致，但都不是为检验它而设计的：

- **V18/V19**：在有全局依赖和精确全局验证器的合成任务上，先把整个方案做完、再依据完整残差重新规划（Stage），远好于在信息还不完整时逐步修订（Step）。V19 中 Stage 为 33/48，Step 为 5/48，而且 Stage 用的调用更少。这是与预注册方向相反的次级证据（见 [V18/V19](./aggregation-mismatch-v18-v19-step-vs-stage-iteration.zh-CN.md)）。
- **V20R**：低负荷长文上，多阶段流程的 token 约为直接生成的 1.52 倍，质量没有提高。
- **V25**：高负荷子集上，成稿之后的阶段修复相对固定流程的质量差为 +0.69，区间 [0, 1.62]，正式裁决是不确定，token 约为 4.46 倍（两条均见 [V20–V25](./aggregation-mismatch-v20-v25-writing-and-stage-repair.zh-CN.md)）。

更频繁的反馈不等于更多的修复信息。

## 7. 聚合失配的位置

“聚合失配是生成优质结果时最重要的失配”这句话，要加一个条件才成立：决定性信息已经进入表征，目标也已经说清。上游没解决时，修聚合没有用。

两条实验结果支持这个顺序：

- **V4**：把正确信息外部化，周期构造的成功数从 13/54 升到 53/54；等量的随机位置正确 bits 是 54/54。起作用的是信息进来了，结构位置没有显示出额外优势（见 [V4](./aggregation-mismatch-v4-claims-theory-gap.zh-CN.md)）。
- **V5**：模型自己推断计划时，Patch 与 Rewrite 是 2/96 对 0/96。计划层不过关，交付方式的差别无从体现（见 [V5](./aggregation-mismatch-v5-stable-editing-agent.zh-CN.md)）。

更稳的说法是：信息和目标都到位之后，聚合是剩下最难的一层。Thinking 处理其中“单次输出内部”的部分，agent 处理“跨观测、跨检查、跨轮次”的部分。

## 8. 可检验的预测

### 8.1 设计 A：信息、独立性与持久性

以等预算的 thinking 为基线，对三种资源做 2×2×2 析因：

| 因子 | 关 | 开 |
|---|---|---|
| 观测 `O` | 不能调用工具 | 可以读取文件、运行测试 |
| 独立评估 `A` | 同一上下文自检 | 新上下文审计 |
| 持久状态 `S` | 每轮只带上一稿 | 带已验证的决定和未决事项 |

控制条件：

- 所有臂使用同一模型、同一温度、同一重试规则，总 token 预算相同，并且不超过单次上下文能有效使用的范围；基线把多出的预算全部用于 thinking。
- 任务分两层：**封闭任务**的决定性信息都在 `Z` 里，**开放任务**的决定性信息只能靠工具取得。
- 加一个无关观测臂：给等长但与任务无关的工具输出，用来区分“信息”和“更长的上下文”。
- 主要终点是外部判据下的最终任务价值。次要指标是缺陷检出率、检出的误报率、轮次间的反转率、token 与耗时。
- 冻结设计之前先做难度校准和功效分析，避免地板和天花板。

### 8.2 设计 B：计算的规模与分配

只用封闭任务，把“计算摊到多个上下文”这一项单独拿出来检验：

| 臂 | 做法 |
|---|---|
| `T(B)` | 单次 thinking，预算 `B` |
| `T(kB)` | 单次 thinking，预算 `kB`，在服务允许的范围内 |
| `M(k×B)` | `k` 个互不可见的上下文各用预算 `B`，再做一次选择或综合 |

控制条件：

- 任务按“可靠命中所需的结构不同候选数”分层，至少有一层明显超过单次预算 `B` 能展开的数量。
- `T(kB)` 与 `M(k×B)` 的总 token 相同，比较的是组织方式；`T(B)` 与 `M(k×B)` 比较的是规模。
- 选择步骤分两种：由外部判据选，和由模型自己选。两者的差距说明增益有多少卡在选择上。
- 其余控制与设计 A 相同。

### 8.3 设计 C：大输入下的重组

只用封闭任务，输入规模明显超过单次调用的有效容量：

| 臂 | 做法 |
|---|---|
| `W` | 整体上下文：把全部输入交给模型，允许分页浏览和多轮，总预算与其他臂相同 |
| `R_m` | 模型自己生成重组方案，再按方案选取、换表示、拆判断 |
| `R_f` | 与具体材料无关的固定通用视图 |
| `R_h` | 人给的重组方案；作为上界，并标明含外部信息 |

控制条件：

- 任务按输入规模和跨部分依赖密度分层，包含一层小输入作为负对照。
- 各臂总 token 相同，`R_m` 生成方案的开销计入预算。
- 终点与设计 A 相同，另报告“决定性材料进入工作集的比例”作为中介指标。
- `R_h − R_m` 估计人给的方案带入了多少，`R_f − W` 估计通用结构本身能带来多少。
- 任务和 `W` 基线可以直接复用注意力治理一稿 8.2 节的设置；这里新增的是把重组方案的来源作为因子。

### 8.4 预测与证伪条件

| 编号 | 预测 | 什么结果会推翻它 |
|---|---|---|
| P1 | 封闭任务上，总预算在单次上下文的有效容量之内时，三个因子全关的多轮结构不优于等预算 thinking | 这种结构稳定地高出预注册的最小效应 |
| P2 | 封闭任务上，所需候选数超过单次预算能展开的数量时，`M(k×B)` 优于 `T(B)`，也优于等总预算的 `T(kB)`；差距随所需候选数增大 | `T(kB)` 不差于 `M(k×B)`，或差距不随所需候选数变化 |
| P3 | 观测的增益随 `Z` 里缺失的决定性信息增多而上升，封闭任务上接近零；无关观测臂没有增益 | 封闭任务上观测臂有明显增益，或无关观测臂有同等增益 |
| P4 | 新上下文审计能检出同上下文自检漏掉的缺陷；没有外部判据时，这一优势只部分转化为最终质量 | 等预算下两者的检出率没有差别 |
| P5 | 三轮以上时，带持久状态的循环持续改善；不带的循环在第一、二轮之后停滞，反转率高 | 两种循环的最终质量和反转率没有差别 |
| P6 | 迭代的回报主要来自它与 `O` 或 `A` 的交互；单独增加轮数的主效应接近零 | 单独增加轮数就有稳定增益 |
| P7 | 提高单次 thinking 的预算上限后，封闭任务上 agent 的增益缩小，开放任务上由观测带来的增益不缩小 | 两类任务上的增益同步缩小，或都不缩小 |
| P8 | 封闭且大的任务上，`R_m` 优于 `W`；增益随输入规模和跨部分依赖密度上升，小输入层上接近零 | 大输入层上 `R_m` 不优于 `W`，或小输入层上有同等增益 |

四条预测的含义需要单独说明：

- 如果 P1 被推翻，说明即使在容量之内，“换一种方式组织同样的计算”也有价值，锚定和稀释的影响比本文估计的更大。
- 如果 P2 被推翻，说明单次 thinking 的有效容量并不低于名义预算，“可扩展的计算”这一项不成立。
- P7 用来区分程度上的差别和种类上的差别。
- 如果 P8 被推翻，说明强整体上下文基线已经够用，“封闭且大”这一情形里 agent 的职责比本文估计的小。

## 10. 边界

- “单次调用的有效容量”目前没有独立于结果的测量方法，只能用裁剪输入或增加独立尝试后的效果来反推（5.1 节）。在给出独立的测量之前，三种情形的判别带有循环成分。
- 本文不主张 agent 总是优于 thinking。封闭任务上，只要所需的探索在单次上下文的容量之内，预测恰恰是没有增益。
- 几种资源在实现上会重叠：一次工具调用可以同时带来信息和独立裁决，多个上下文既扩大了计算也带来了独立性。设计 A 靠任务分层和无关观测臂把它们分开，设计 B 靠等总预算的对照。
- 成本没有进入主张。Agent 的每一种资源都要花 token 和时间，已有实验里的开销从约 1.5 倍到 4 倍以上不等。是否值得，要按任务的风险和价值另算。
- 这里的“工作集”不是对模型内部机制的描述，只是对提交时可用内容的记账。
