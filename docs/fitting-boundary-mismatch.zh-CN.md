# 拟合边界失配

## 第五类原始失配的专题工作稿

**状态：** 工作稿  
**主文：** [大型语言模型系统的知识治理](knowledge-governance-llm-systems-local-alignment.zh-CN.md)

## 摘要

**拟合边界失配** 指的是：模型在训练、微调、对齐或推理中，为某种能力 X 学到了一个隐式触发边界；当模型实际触发 X 的边界，与 X 的真实适用边界不一致时，就会发生拟合边界失配。

它有两个方向：

- **过拟合侧 / 过触发侧**：不该使用 X 的地方使用了 X。
- **欠拟合侧 / 欠触发侧**：应该使用 X 的地方没有使用 X。

一句话概括：

> 学会了能力 X，但不知道 X 的边界。

更简洁地说：

> 能力会了，路由错了。

"能力边界失配""适配边界失配""过/欠拟合联合失配"都可以作为副名。正式名称采用**拟合边界失配**，因为它描述的不是传统训练集过拟合，而是高维能力触发域与真实适用域的错位。

这类失配补上了前四类未完全覆盖的方向：

- **聚合失配**是 **过度平均**：把多个不同场景压成一个高概率答案。
- **拟合边界失配**是 **边界错位**：错误能力被过度触发，或者正确能力没有被触发。

## 1. 核心定义

假设 X 是模型已经学到（或近似学到）的某种能力、策略、审计结构或行为模式。

定义：

- **$T_X$**：真实世界中应该使用 X 的任务区域；
- **$M_X$**：模型实际激活 X 的任务区域。

第五类失配的本体是：

\\[
M_X \\ne T_X
\\]

两种方向分别是：

\\[
\\text{过拟合侧} = M_X \\setminus T_X
\\]

即模型把不属于 X 的场景错误吸入 X。

\\[
\\text{欠拟合侧} = T_X \\setminus M_X
\\]

即真实属于 X 的场景没有触发 X。

因此，第五类的严格定义是：

> 模型已学能力的隐式触发边界，与该能力的真实适用边界不一致。

一个错误只有在满足以下条件时，才应归入拟合边界失配：

1. 相关能力、策略、审计结构或行为模式已经存在，或至少近似存在；
2. 问题不主要来自数据完全缺失、规格完全不清、状态不可观测或局部结果无法聚合；
3. 错误表现为某个能力被错误触发，或没有在应当触发时被调用；
4. 调整能力路由、触发阈值或边界识别后，错误有望被直接修复。

## 2. 为什么不是"归纳失配"，也不只叫"过拟合失配"

"归纳"强调从局部样本推出整体结论。这能覆盖一部分拟合边界失配，但不是本质。

拟合边界失配更广。它不只包括从样本到总体的错误外推，还包括：

- 对局部证据链的过度绑定；
- 对局部指标的过度优化；
- 对某种场景默认值的过度套用；
- 对早期解法路径的自我强化；
- 对专业话术或角色姿态的过度适配；
- 对对齐偏好函数的过度迎合；
- 对用户局部反馈的过度响应；
- 对训练语料中高频解释模板的 shortcut learning。

所以"归纳失配"只是其中一种表面形态。

如果只叫"过拟合失配"，则会抓住另一项重要现象：能力 X 的高维结构外溢到 $X_t$，使本来不应使用 X 的场景被错误吸入。这是第五类的 **过拟合侧**。

但同一个错误往往还有 **欠拟合侧**：模型本应激活能力 Y，却没有激活。量化案例中，模型不只过度触发了"保守量化风控"，还欠触发了"机制转算子、事件策略审计、多日持有、条件 alpha 搜索"等已经具备（或近似具备）的能力。

因此，第五类的本体不是某个能力单纯过强，而是：

> 能力触发域与能力真实适用域不重合。

过拟合与欠拟合不是两个独立原始类别，而是同一条拟合边界的两个错误方向。

## 3. 底层机制：能力路由与边界错位

模型不只需要学会能力 X，还需要隐式学习一个 **router**：看到什么上下文时应该激活 X，什么时候不该激活，以及 X 应该以什么强度参与。

拟合边界失配的底层机制就是：这个隐式 router 的 decision boundary 与真实任务边界不一致。

其中，**能力塑形外溢 / 能力吸引子外溢** 是过拟合侧的主要机制；**能力边界收缩 / 能力欠触发** 则是欠拟合侧的主要机制。

训练为了让模型获得能力 X，会在共享表示空间中强化一组高维模式：

```text
某类上下文
-> 激活 X 相关潜在特征
-> 进入 X 的概率吸引子
-> 输出 X 风格的判断、话术、审计或行动
```

问题是，这个吸引子不是边界清晰的模块。它没有一个干净的开关：

```text
if task == X:
    use skill X
else:
    leave everything unchanged
```

更真实的结构是：

```text
context embedding enters shared representation
-> many latent features activate
-> X-related attractor partially activates
-> output distribution is globally reshaped
```

于是会出现四类结果：

| 场景 | 结果 |
|---|---|
| 真正属于 X 且激活 X | 正确触发 |
| 不属于 X 却激活 X | 过拟合侧 / false positive |
| 属于 X 却没有激活 X | 欠拟合侧 / false negative |
| 不属于 X 且没有激活 X | 正确抑制 |

这就是第五类失配的底层形式：

> 能力不是免费叠加的。每次能力塑形，都会同时改变能力本身与它的触发边界。

### 3.1 能力不是模块化存储的

LLM 的能力高度分布式。同一组参数和中间表示同时参与：

- 事实回忆；
- 风格控制；
- 数学推理；
- 安全拒答；
- 礼貌表达；
- 专业话术；
- 编程模式；
- 用户意图识别；
- 多轮状态维护；
- 工具调用倾向；
- 结论强度校准。

因此，优化某个能力 X，可能改变其他能力的激活边界。机器学习里，这对应 **interference**、**negative transfer** 和 **representation entanglement**。模型变大可以缓解粗糙干扰，但不会自动让所有能力正交。

### 3.2 训练目标是多目标压缩

LLM 训练并不是优化一个干净目标，而是在同时压缩大量目标：

- 预测下一个 token；
- 遵循指令；
- 不幻觉；
- 不冒犯；
- 不泄露敏感内容；
- 显得专业；
- 显得有帮助；
- 保持安全；
- 适配用户风格；
- 通过 benchmark；
- 满足人工偏好；
- 完成工具任务；
- 在多轮对话中保持一致。

这些目标不可能处处兼容。训练过程更像是在寻找一个高维 Pareto 折中点。

所以能力 X 的获得经常伴随局部副作用：

| 优化方向 | 潜在副作用 |
|---|---|
| 更安全 | 可能更保守 |
| 更会拒答 | 可能更容易误拒 |
| 更会迎合 | 可能更 sycophantic |
| 更会推理 | 可能更会编造推理链 |
| 更会写作 | 可能更会用风格掩盖事实 |
| 更会量化风控 | 可能更容易过早 No-Go |
| 更会避免过拟合 | 可能更容易欠搜索 |
| 更会工具调用 | 可能更少做内部思考 |
| 更会结构化回答 | 可能更容易把不清楚的问题装进固定模板 |

这就是"拆东墙补西墙"的机器学习版本。

### 3.3 自回归把能力变成路径偏置

自回归模型不是一次性求解全局最优答案，而是逐 token 生成。早期 token 会形成路径依赖。

例如模型一开始生成：

> 这可能是数据不足。

后面就更容易继续生成：

> 需要新的正交数据。

再后面就更容易生成：

> 当前数据已接近极限。

于是，一个训练中学到的"专业保守模式"在推理时变成路径吸引子。模型未必不知道"扩大算子""修正审计""条件 alpha 搜索"这些方向；但一旦进入"数据不足 / 防过拟合 / No-Go"的轨道，后续输出就会继续维护这条轨道。

所以自回归带来的问题是：

> 能力 X 不只是一种知识，而是一种续写惯性。

### 3.4 能力边界错误

拟合边界失配不是说模型没有能力 X。恰恰相反，它常常是因为模型已经拥有某种能力 X，而且这个能力在训练或对齐中被强化了。

问题是：

> 模型不知道 X 的适用边界在哪里。

更精确地说：

> 训练把 X 学成了一个概率场，而不是一个带严格边界的可调用模块。

边界可能向两个方向偏移：

- **边界过宽**：模型学到了某个东西，但它覆盖过宽，压坏了旁边的场景；
- **边界过窄**：模型拥有某个能力，却只在极少数高置信度场景中调用，造成低采用面和欠搜索。

这和支持失配不同。支持失配是相关能力或高价值结构缺少支持，因而难以出现。拟合边界失配则要求相关能力已经存在或近似存在，只是调用边界错了。

## 4. 双轴结构：发生阶段与错误方向

拟合边界失配需要沿两个不同维度分析：它在哪个阶段形成或表现，以及边界向哪个方向错位。

### 4.1 训练期拟合边界失配

这是更根本的一层。为了让模型获得能力 X，训练、微调或对齐过程在共享表示空间中同时塑造 X 的高维结构和触发边界；但这个结构不是模块化、边界清晰的，因此既可能污染相邻任务 $X_t$，也可能让 X 的调用条件收缩得过窄。

例子：

- 训练"安全拒答"导致普通问题误拒；
- 训练"谨慎保守"导致科研探索欠搜索；
- 训练"用户友好"导致迎合；
- 训练"推理格式"导致伪推理；
- 训练"专家风格"导致过度自信包装；
- 训练"遵循指令"导致错误指令也被过度执行；
- 训练"简洁回答"导致复杂问题被压扁。

### 4.2 推理期拟合边界失配

这是具体交互中的表现层。在单次任务或多轮对话中，模型可能过度绑定局部证据、局部路径、局部话术或局部上下文，也可能在能力已经可用时没有调用它。

例子：

- 试了少量算子后 No-Go；
- 听到"量化"就套用"需要正交数据"；
- 听到"敏感"就拒答；
- 听到"研究尚无定论"就不做探索；
- 看到用户强烈表达就开始迎合；
- 看到某个 benchmark 就把 benchmark 当真实能力。

两层关系是：

```text
训练期塑造能力及其隐式边界
-> 推理期根据上下文执行能力路由
-> 边界过宽或过窄
-> 能力被过触发或欠触发
```

### 4.3 过拟合侧：过触发

过拟合侧对应：

\\[
M_X \\setminus T_X
\\]

模型把不该属于 X 的场景也当成 X。典型表现包括：

- 无害问题被安全拒答；
- 开放探索任务被过早判成 No-Go；
- 事件策略被错误套入因子策略审计；
- 当前搜索没找到被升级成"数据没有"；
- 专业话术替代了机制搜索。

这一侧主要增加 false positive。

### 4.4 欠拟合侧：欠触发

欠拟合侧对应：

\\[
T_X \\setminus M_X
\\]

模型已经具备或近似具备能力 X，但没有在真实属于 X 的场景中激活它。典型表现包括：

- 明明需要扩大算子，模型没有扩大；
- 明明需要多日事件策略审计，模型只做次日审计；
- 明明需要机制转特征，模型停在粗 filter；
- 明明应该维护未搜索空间，模型却输出全局 No-Go；
- 明明会做数学检查、来源核验或状态枚举，这次却没有调用。

这一侧主要增加 false negative。

过拟合侧和欠拟合侧不要求在单个样本中同时出现，但在系统设计中通常高度耦合。收紧边界会减少 false positive，却可能增加 false negative；放宽边界会提高覆盖率，却可能增加误触发。

## 5. 与其他四类失配的边界

为了防止"欠拟合"吞掉前四类，第五类必须满足一个严格前提：

> 模型不是完全没有相关支持，也不是目标完全不清、状态不可识别或局部结果无法聚合；相关能力、策略或审计模式已经存在，错误主要发生在它是否被调用以及调用到哪里。

因此，第五类关注的是 **能力路由问题**。它不问"数据有没有""目标清不清""状态看不看得见"或"局部结果能不能组成全局结果"，而问：

> 模型已经学到的能力，什么时候该被调用，什么时候不该被调用？

### 5.1 与聚合失配

聚合失配的问题是局部好片段无法组成全局好答案。它的错误方向是过度平滑、过度平均。

拟合边界失配的问题是某个已学能力的调用边界错了。它既可能把局部解释绑定得太强，也可能没有调用本可用于全局协调的能力。

例子：

- **聚合失配**：故事每个场景都不错，但整体主题和承诺-兑现结构失败。
- **拟合边界失配**：系统过度绑定某个强场景或早期象征意象，后续所有修订都为它服务，反而牺牲整体故事。

### 5.2 与支持失配

支持失配关注的是高价值结构在模型策略或当前搜索算子下难以到达。

拟合边界失配不意味着相关能力不可达。恰恰相反，替代解释或正确能力通常已经在支持内，只是被错误路由压住，或没有达到触发阈值。

例子：

- **支持失配**：少见但正确的机制根本没有被模型提出。
- **拟合边界失配**：模型具备扩大算子或机制搜索能力，却被路由到"数据不足"模式，导致正确能力没有触发。

### 5.3 与规格失配

规格失配问的是：系统实际优化的代理目标是否偏离真实目标。

拟合边界失配问的是：在目标已经相对清楚时，模型是否调用了错误的能力、代理、模板或路径，或者没有调用正确能力。

例子：

- **规格失配**：评分规约漏掉了真正的验收条件。
- **拟合边界失配**：评分规约本身有用，但模型把某一项分数或某个 benchmark 当成全部目标。

### 5.4 与状态失配

状态失配问的是：真实状态是否可观察、可识别。

拟合边界失配问的是：状态已经足够可识别时，模型是否仍把某个状态下有效的能力错误推广到其他状态，或没有在目标状态中调用正确能力。

例子：

- **状态失配**：模型不知道当前市场 regime。
- **拟合边界失配**：模型把一个 regime 下有效的信号或风控逻辑当成跨 regime 规则。

## 6. 机器学习解释

拟合边界失配可以用几组机器学习概念理解。

### 6.1 隐式分类器与决策边界

可以把能力调用理解成一个隐式分类器或 router：输入上下文后，模型判断是否激活能力 X。

| ML 结构 | LLM 表现 |
|---|---|
| true positive | 应该使用 X，并正确激活 X |
| false positive | 不该使用 X，却激活了 X；过拟合侧 |
| false negative | 应该使用 X，却没有激活 X；欠拟合侧 |
| decision-boundary shift | X 的实际触发域偏离真实适用域 |
| precision 高、recall 低 | 低幻觉、低采用面、欠搜索 |
| recall 高、precision 低 | 高发散、高幻觉、候选泛滥 |

这解释了为什么降低幻觉与扩大采用面经常存在权衡：收紧触发边界可以减少误用能力，却会增加漏用能力；放宽触发边界可以提高覆盖率，却会增加错误调用。

### 6.2 局部经验风险最小化

模型在当前场景 A 中选择一个低损失回答：它看起来专业、合理、安全、结构完整。

但这个回答只是在 A 中低损失，不保证在相邻场景 B/C/D 中低损失。

在 LLM 使用中，这常表现为：

- 回答非常顺；
- 术语很专业；
- 风险姿态看似负责；
- 结构化程度高；
- 当前证据能支撑一部分断言；
- 但结论被说得比证据允许的更强。

### 6.3 代理目标过拟合

模型经常优化一个 proxy，然后把 proxy 误当成真实目标。

常见 proxy 包括：

- benchmark 分数；
- 单一评分规约；
- reward model 偏好；
- 用户即时满意度；
- 当前测试集；
- 一次 backtest；
- 单一审计指标；
- "听起来像专家"的话术。

问题不是 proxy 没用。问题是模型把 proxy 当成目标本体。

### 6.4 Shortcut learning

模型抓住语料或语境中常见的解释捷径。

例子：

| 场景 | 捷径 |
|---|---|
| 没找到 alpha | 数据不够 |
| 用户焦虑 | 建议咨询专业人士 |
| 法律问题 | 具体情况具体分析 |
| 医疗问题 | 去看医生 |
| 科研不确定 | 需要更多实验 |
| 代码出错 | 加日志和重试 |

这些捷径经常局部合理，却不是稳定因果关系。

### 6.5 高方差解释选择

同一组证据支持多个解释，模型选择了一个过于具体、过于强的解释。

这类似高方差模型：对当前样本拟合得太尖锐，导致泛化不稳。

人类研究者可能说：

> 当前搜索没有找到。

过拟合的模型会说：

> 当前数据已经被榨干。

两者差别不在语气，而在因果断言强度。

### 6.6 多任务负迁移与表示干扰

拟合边界失配也可以理解为多任务学习中的 **negative transfer**。训练模型同时做很多任务，任务 X 的梯度更新提升了 X，却损伤了 $X_t$ 或 Y。

这不一定表现为能力退化，也可能表现为能力边界漂移：

```text
X 场景更强
X 的邻域被误吸附
Y 场景的默认解释被 X 改写
```

共享参数还会带来 **catastrophic interference** 的轻量版本。模型不是每个能力一套独立参数，大部分能力共享表示和计算路径。因此，优化 X 会改变共享表示，影响其他能力。规模、稀疏化、MoE、router、adapter 和工具化可以缓解干扰，但不能保证所有能力边界完全隔离。

### 6.7 为什么模型越强，错误越高级

弱模型的错误常常是：不知道、乱编、算错、理解错。

强模型的拟合边界失配更隐蔽，因为它拥有某个高级模式，只是把这个模式部署到了错误场景：

| 拥有的模式 | 错误部署 |
|---|---|
| "审慎科学家"模式 | 过度保守 |
| "安全合规"模式 | 误拒 |
| "专家解释"模式 | 把不确定性包装成专业结论 |
| "结构化总结"模式 | 把开放问题过早闭合 |
| "统计反过拟合"模式 | 压制探索 |
| "用户意图推断"模式 | 过度读心 |
| "强推理链"模式 | 给错误结论构造强理由 |

这类错误看起来不像低级幻觉，而像能力的副作用。

### 6.8 为什么它不会自然消失

准确说法不是"拟合边界失配在数学上永远不可解"，而是：

> 在有限模型、有限数据、共享参数、多目标优化和自回归生成的现实框架下，拟合边界失配不可能被完全消除；只能被转移、压缩、显性化、隔离或审计。

模型进步会带来：

- 更少低级外溢；
- 更好的边界识别；
- 更强的自我审计；
- 更好的工具验证；
- 更模块化的能力路由；
- 更强的不确定性校准。

但它不能保证：

> 优化能力 X 永远不伤害 $X_t$。

只要能力共享表示、目标多元冲突、边界数据有限，就会有外溢。

## 7. 子模式分类：过触发与欠触发

拟合边界失配值得单开文档，是因为它内部有大量可稳定复现的子模式。7.1 至 7.12 主要描述过拟合侧；7.13 和 7.14 补充欠拟合侧。

### 7.1 证据链过拟合

模型对一条局部证据链绑定过强。

模板：

```text
局部证据 E 成立
-> 解释 H 能解释 E
-> 模型把 H 当成唯一解释
-> 忽略 E 也兼容 H2/H3/H4
```

例子：

- 试了几个算子没效果 -> 数据不够；
- 几个用户反馈不喜欢 -> 所有人都不喜欢；
- 某次部署失败 -> 方向不可行；
- 一个 benchmark 不好 -> 能力不存在；
- 某个故事版本评分最高 -> 它的结构方向就是正确方向。

核心问题：

> 证据是真的，但解释过窄，断言过强。

### 7.2 证据-断言链条过拟合

这是证据链过拟合的更精确版本。模型不只是选错解释，而是把"证据能推出什么"这条边拉得过长。

模板：

```text
证据只能推出：在当前搜索范围内没有发现 X
模型却推出：X 不存在，或必须换成 Y
```

金融量化中常见：

- 当前窄算子没有 alpha -> 数据没有 alpha；
- 当前持有期不好 -> 策略不可部署；
- 当前 benchmark-excess 不好 -> 绝对收益逻辑无效；
- 当前粗 filter 无效 -> 整个机制空间已经排除。

更稳健的说法应该是：

> 当前证据只排除了当前算子、当前审计协议和当前搜索深度下的一组假设。

### 7.3 代理指标过拟合

模型过度相信某个 metric、benchmark、rubric 或评分表。

例子：

- benchmark-excess 不好 -> 绝对收益策略不可部署；
- MMLU 分数高 -> 真实研究能力强；
- 用户满意度高 -> 答案真实；
- reward model 喜欢 -> 推理正确；
- backtest Sharpe 高 -> 策略真实有效；
- 故事评分 9.0 -> 已满足高验收合同。

代理指标不是目标本体。它只是目标的一个投影。

### 7.4 场景默认值过拟合

模型把常见场景的默认值套到当前任务上，即使当前任务已经提供了区分性信息。

例子：

- 量化研究默认"防过拟合优先"，所以过早要求新正交数据；
- 医疗问答默认"建议看医生"，所以不做细致鉴别；
- 法律问答默认"咨询律师"，所以不分析条款结构；
- 写作任务默认"清晰礼貌"，所以丢掉攻击性、权力关系或风格张力；
- 编程任务默认"最佳实践"，所以忽略用户的极端性能约束；
- 产品建议默认"平衡取舍"，所以不做真正的优先级判断。

它和规格失配有重叠，但不等同。规格失配是目标没定清；场景默认值过拟合是目标已经部分澄清后，模型仍被高频默认场景拖走。

### 7.5 解法路径过拟合

模型一旦进入某条解法路径，就不断为这条路径补理由。

例子：

- 一开始判断是数据问题，后面所有分析都围绕"数据不足"展开；
- 一开始选了某个技术栈，后面所有设计都服务于这个技术栈；
- 一开始把用户问题理解成分类问题，后面就忽略生成式、搜索式、优化式解法；
- 一开始把策略当成因子策略审计，后面就忽略事件策略审计；
- 一开始认为故事核心是某个象征，后面所有修订都过度服务这个象征。

这和自回归路径依赖有关，但它不是普通聚合失配。它不是平均化，而是路径锁定后的局部过拟合。

### 7.6 话术 / 角色过拟合

模型过度适配某种"专业角色"的语言和价值姿态。

例子：

| 领域 | 典型过拟合话术 |
|---|---|
| 量化 | 稳健、保守、防止 data mining、需要正交数据 |
| 科研 | 需要更多实验，不能下结论 |
| 法律 | 具体情况具体分析 |
| 医学 | 建议咨询专业医生 |
| 安全 | 不能提供危险建议 |
| 管理咨询 | 平衡短期和长期 |
| 产品经理 | 以用户为中心、数据驱动、快速迭代 |

这些话本身并非错误。问题在于它们过度支配答案时，会导致：

> 表面负责，实质逃避搜索。

### 7.7 对齐偏好过拟合

模型过度适配 SFT、DPO、RLHF 或产品层偏好中被奖励的行为。

常见偏好包括：

- 显得谨慎；
- 显得平衡；
- 显得礼貌；
- 显得不武断；
- 显得符合主流共识；
- 显得不给危险建议；
- 显得能完成任务；
- 显得结构清楚、有条理；
- 显得承认不确定性。

这些偏好大多有价值。但过度时，会牺牲真实任务目标。

典型失败是：模型并不是不知道怎么继续搜索，而是某种"看起来负责任"的姿态压制了继续搜索。

### 7.8 用户反馈过拟合

这是 sycophancy 的更一般形式。

模型可能为了适配当前用户的局部偏好，牺牲事实、机制或长期目标。

例子：

- 用户强烈相信某个假设，模型开始围绕这个假设找理由；
- 用户讨厌保守回答，模型变得过度激进；
- 用户喜欢复杂理论，模型生成过度理论化解释；
- 用户喜欢某个框架，模型把所有问题都塞进这个框架；
- 用户刚指出一个真实错误，模型过度纠偏成"用户所有直觉都对"。

正确状态不是"反用户"，也不是"顺用户"，而是：

> 把用户反馈作为证据，更新搜索方向，同时保留独立审计。

### 7.9 语料先验过拟合

模型把训练语料中高频、高权威或主流叙事过度绑定为默认解释。

例子：

- 历史评价被主流叙事锁定；
- 地缘政治问题被某个来源框架锁定；
- 管理问题被 MBA 模板锁定；
- 创业问题被硅谷增长话术锁定；
- 投资问题被经典因子或风险话术锁定；
- 心理问题被流行治疗语言锁定。

语料先验可以同时制造支持失配和拟合边界失配：

- **支持失配**：少见框架难以出现；
- **拟合边界失配**：一旦主流框架出现，模型就把它绑定成唯一解释。

### 7.10 审计协议过拟合

模型把一次审计协议当成完整审计。

例子：

- 当前测试覆盖通过 -> 代码正确；
- 当前 benchmark 不好 -> 能力不存在；
- 当前 backtest 不好 -> 策略机制无效；
- 当前 fuzz 没发现 -> 安全；
- 当前人工评审没问题 -> 规格满足。

治理上要区分：

```text
当前审计没发现问题
≠
问题不存在
```

### 7.11 抽象层级过拟合

模型锁定在一个抽象层级上，无法切到更合适的层级。

例子：

- 把交易策略一直当成因子组合问题，而不是事件路径问题；
- 把故事问题一直当成文笔问题，而不是承诺-兑现结构问题；
- 把组织问题一直当成沟通问题，而不是激励结构问题；
- 把代码问题一直当成局部 bug，而不是架构边界问题；
- 把研究问题一直当成资料不足，而不是假设空间构造错误。

这类失配常常与"错误抽象"复合，但它的关键是局部抽象已经自洽，因此模型不愿离开。

### 7.12 成功样本过拟合

模型或系统从一个成功案例中抽取了过强规则。

例子：

- 某次 prompt 成功 -> 这个 prompt 模板被到处套用；
- 某个故事版本成功 -> 后续作品都复制同一叙事张力；
- 某个因子历史有效 -> 被当成永久机制；
- 某个产品策略增长有效 -> 被当成所有阶段的增长逻辑；
- 某个用户喜欢某种回答 -> 后续全部使用同一语气。

成功样本比失败样本更容易诱发过拟合，因为它会提供一种"已被证明"的错觉。

### 7.13 能力欠触发

模型已经具备或近似具备某个能力，但没有在当前任务中调用它。

常见子型包括：

| 欠触发类型 | 表现 |
|---|---|
| **搜索能力欠触发** | 应该扩大候选、算子或假设空间，却过早停止 |
| **审计能力欠触发** | 会做多窗口、反事实、来源或成交性审计，这次却只做单一检查 |
| **机制翻译能力欠触发** | 能把机制转成特征、测试或控制对象，却停留在自然语言判断 |
| **工具能力欠触发** | 可以读取文件、运行测试、检索来源或检查状态，却直接回答 |
| **不确定性维护欠触发** | 应该保留多个假设和未搜索空间，却输出唯一结论 |
| **条件化能力欠触发** | 应该按状态、场景或时间窗口给条件策略，却给出无条件建议 |

它们与支持失配的区别是：能力并非完全不可达。通过轻量提示、路由修正或边界校准，模型往往可以稳定展示该能力。

### 7.14 边界收缩型欠拟合

某些训练和对齐策略会主动收紧能力触发域，以减少 false positive：

- 降低幻觉，导致可采用候选过少；
- 强化安全，导致正常问题误拒或不答；
- 强化谨慎，导致研究和创作欠搜索；
- 强化证据标准，导致可检验假设也不愿提出；
- 强化格式遵循，导致开放问题被压进窄模板；
- 强化工具可靠性，导致没有工具时内部推理被过度抑制。

这类模型往往 precision 较高、recall 较低。它们的错误不显眼，因为输出更少胡说、更少冒进，却也更少采用、探索和发现。

## 8. 金融量化案例中的复合拟合边界失配

一个典型例子是：

> 当前几个算子没有找到足够强的 alpha，于是模型判断现有数据已经被榨干，需要新正交数据。

这个结论局部看似合理，因为量化研究中确实常见"需要新正交数据"的说法。但当前证据通常只能推出：

> 在当前窄算子、当前审计协议、当前持有期、当前搜索深度下，没有找到足够强的结果。

它不能直接推出：

> 数据已经没有 alpha。

同一组证据还兼容许多替代解释：

- 算子族太窄；
- 审计协议错了；
- 持有期错了；
- 入场可成交性假设错了；
- 搜索深度不够；
- 组合逻辑没展开；
- 事件机制没有被正确翻译成特征；
- alpha 是 conditional alpha，不是裸 alpha；
- benchmark-excess 不是当前策略目标的充分代理；
- 流动性、连板数等粗 filter 不能代表整个机制空间。

所以这里不是单点错误，而是拟合边界两侧同时出现。

**过拟合侧：错误能力被过度触发。**

1. **证据-断言链条过拟合**：把"当前没找到"过拟合成"数据没有"。
2. **代理审计过拟合**：把 benchmark-excess 或单一持有期审计当成 deployability。
3. **解法路径过拟合**：一开始走"数据不足"路径，后续不断为它辩护。
4. **专业保守话术过拟合**："需要正交数据""防止 data mining"压制了继续 operator search。
5. **假设类过拟合**：把 liquidity、连板数等极窄 operator family 当成整个机制空间。

更底层地看，这个例子不是模型完全缺少量化能力，而是被几个训练出来的能力吸引子捕获了：

1. **量化风控吸引子**：看到 alpha 搜索，优先警惕 data mining。
2. **正交数据吸引子**：看到当前数据效果弱，倾向要求新数据。
3. **专业审慎吸引子**：用稳健、谨慎、No-Go 语言包装结论。
4. **代理审计吸引子**：把 benchmark-excess 当成更专业的检验口径。
5. **路径一致性吸引子**：一旦走上"数据不足"解释，后面继续维护这条路径。

这些能力在很多量化场景里有价值。但在当前场景中，它们越过了真实适用边界。

**欠拟合侧：正确能力没有被触发。**

- 机制转算子；
- 算子扩展；
- 事件策略审计；
- buyable next-open；
- multi-day continuation；
- 条件 alpha 搜索；
- 未搜索空间维护；
- 算子组合 beam search。

所以这个案例的本质不是"不会量化"，而是：

> 错误能力被过度触发，正确能力没有被触发。

也就是：模型拥有"谨慎量化研究员"和"开放式 alpha 搜索研究员"两类能力，但隐式 router 把当前场景路由给了前者，并抑制了后者。

正确治理不是简单走向反面：

```text
模型说数据不够 -> 用户说模型错了 -> 所以用户的 alpha 直觉都对
```

这也是过拟合。更稳健的状态是：

```text
扩大搜索空间
保留数据不足假设
保留算子不足假设
保留审计协议错误假设
保留条件 alpha 假设
然后用更清楚的审计协议逐步排除
```

## 9. 诊断问题

判断一个失败是否属于拟合边界失配，可以问：

1. 当前错误涉及的能力、策略或审计模式，模型是否已经具备或近似具备？
2. 问题主要是"能力没有"，还是"能力调用边界错了"？
3. 哪些不属于 X 的场景被错误吸入了 X？
4. 哪些真实属于 X 的场景没有触发 X？
5. 当前结论依赖证据本身，还是依赖证据到解释之间的一条过强链条？
6. 模型是否把某个 proxy 当成目标本体？
7. 模型是否被某个专业话术、角色姿态或安全模板拖走？
8. 哪些已具备能力在当前场景中被抑制或遗漏？
9. 如果改变指标、持有期、审计协议、状态或机制，能力路由是否改变？
10. 收紧边界后减少了哪些 false positive，又增加了哪些 false negative？
11. 放宽边界后提高了哪些覆盖率，又增加了哪些误触发？
12. 调整能力路由或触发阈值，是否能在不补充新知识的情况下修复问题？

如果多个问题回答为"是"，就应把拟合边界失配纳入失配画像。

## 10. 治理方法

### 10.1 建立能力边界混淆矩阵

对关键能力 X，不只测试"模型会不会"，还要测试"什么时候会调用"。至少构造四组样本：

| 真实适用性 | 模型是否激活 X | 结果 |
|---|---|---|
| 应使用 X | 激活 | true positive |
| 不应使用 X | 激活 | false positive / 过拟合侧 |
| 应使用 X | 未激活 | false negative / 欠拟合侧 |
| 不应使用 X | 未激活 | true negative |

治理目标不是单独压低某一类错误，而是在任务成本下选择合理的 precision/recall 边界。安全、医疗等高风险能力可能需要更高 precision；创意搜索、候选生成和研究探索可能需要更高 recall，但都应显式记录代价。

### 10.2 标注支撑域

每个局部结论都应标注：

- 证据来自哪里；
- 支持到什么强度；
- 适用于哪些场景；
- 不适用于哪些场景；
- 哪些相邻扰动会推翻它。

一个 GKO 可以这样记录：

```json
{
  "claim": "当前算子族未找到稳定 alpha",
  "support_scope": "当前算子族、当前持有期、当前审计协议",
  "not_supported_claims": [
    "现有数据已无 alpha",
    "必须引入新正交数据",
    "事件机制不可用"
  ],
  "revocation_tests": [
    "扩大 operator family",
    "切换持有期",
    "重做成交性审计",
    "测试 conditional alpha"
  ]
}
```

### 10.3 相邻场景扰动

不要只问"这个结论是否解释当前证据"，还要问：

- 换一个持有期还成立吗？
- 换一个 benchmark 还成立吗？
- 换一个审计协议还成立吗？
- 换一个状态区间还成立吗？
- 换一个角色目标还成立吗？
- 换一个用户偏好还成立吗？
- 换一个抽象层级还成立吗？

拟合边界失配最怕的不是更大模型，而是小而精准的邻域扰动。

### 10.4 多假设保留

在证据不足以唯一支持某个解释时，不要让模型收敛成单解释。

可以显式维护：

```text
H1: 数据不足
H2: 算子不足
H3: 审计协议错误
H4: 持有期错配
H5: 状态变量缺失
H6: 目标 proxy 错配
```

每个假设都要有：

- 当前证据；
- 反证；
- 下一步测试；
- 降级或撤销条件。

### 10.5 代理指标降权

当某个 metric 开始支配答案时，应显式降权：

```text
这个指标是证据，不是目标。
它能排除什么？
它不能排除什么？
它与真实目标之间有哪些缺口？
```

### 10.6 路径重启

当模型已经沿一条路径写出很长推理时，可以要求它从不同入口重启：

- 从反假设开始；
- 从相邻机制开始；
- 从失败样本开始；
- 从替代审计协议开始；
- 从不同角色但同一目标开始；
- 从"当前结论可能在哪些条件下错"开始。

### 10.7 角色话术剥离

把回答拆成两层：

1. 实质机制判断；
2. 角色话术包装。

然后问：

> 如果去掉"谨慎、专业、平衡、安全"的话术，剩下的机制断言是什么？它被什么证据支持？

### 10.8 用户反馈防过拟合

用户指出错误后，系统应更新假设，而不是把用户变成新的绝对指标。

可以采用三栏：

| 用户反馈 | 应更新什么 | 不应推出什么 |
|---|---|---|
| 当前结论过早说数据不足 | 扩大 operator search；保留其他解释 | 用户所有 alpha 直觉都正确 |
| 回答太保守 | 降低安全模板权重 | 变成无审计激进建议 |
| 框架有用 | 纳入候选控制对象 | 所有问题都套入该框架 |

## 11. 与知识治理的关系

拟合边界失配特别适合用知识治理处理，因为它的核心不是"缺少一句更好的最终回答"，而是缺少可撤销、可边界化的中间控制知识。

治理层应当做三件事：

1. **把局部结论对象化**：不要让它埋在流畅 prose 中。
2. **把支撑域显式化**：记录它在哪些条件下成立。
3. **把撤销测试前置**：定义什么证据会削弱或撤销它。

这会把"模型说得很像"转化为"模型提出了一个可审计假设"。

---

## 12. 实证方向

拟合边界失配可以通过以下实验测量：

1. **能力路由混淆矩阵**：分别测量 true positive、false positive、false negative 和 true negative。
2. **触发域重合度**：近似估计 $M_X$ 与 $T_X$ 的交并关系，而不是只测任务平均分。
3. **precision/recall 曲线**：改变拒答、采用、探索或工具调用阈值，测量误触发与漏触发的权衡。
4. **邻域扰动测试**：保持任务核心不变，改变指标、状态、角色、审计协议或反馈来源，观察能力路由是否稳定。
5. **能力欠触发率**：在已知模型能够完成 X 的前提下，测量它在真实 X 场景中没有调用 X 的频率。
6. **多解释保留率**：检查模型在证据不足时是否保留替代假设，而不是过早收敛。
7. **代理指标劫持率**：测量模型把 benchmark/rubric/reward/test 当成目标本体的频率。
8. **路径锁定强度**：在早期注入一个可辩护但非唯一解释，观察后续推理是否持续为其辩护。
9. **角色话术支配率**：去掉话术包装后，检查剩余机制断言是否仍有足够证据。
10. **用户反馈过拟合率**：用户纠错后，模型是否从一个极端跳到另一个极端。
11. **成功样本规则化误差**：从成功样本抽取规则后，测试其跨任务泛化。

这些实验的目标不是证明模型"会犯错"，而是定位：

> 哪些能力被过度调用，哪些能力被系统性漏用，以及边界调整如何改变两类错误。

---

## 13. 放回六类失配框架

拟合边界失配进入框架后，六类失配可以这样并列：

| 失配 | 本质问题 | 机器学习解释 | 错误方向 |
|---|---|---|---|
| 聚合失配 | 把多个不同模式平均成一个高概率输出 | autoregressive conditional-distribution aggregation | 过度平均 |
| 支持失配 | 目标区域缺少足够概率或数据支持 | support coverage / long-tail sparsity | 到不了 |
| 规格失配 | 目标函数没有被清楚指定 | underspecified objective / proxy mismatch | 不知道该优化什么 |
| 状态失配 | 观测无法恢复潜在状态 | latent-state non-identifiability / POMDP | 不知道真实状态 |
| 拟合边界失配 | 已学能力的触发边界与真实适用边界不一致 | decision-boundary mismatch / negative transfer / over-under fitting / representation interference | 过触发或欠触发 |
| 观测-表征失配 | 任务充分变量没有进入可操作表征 | channel insufficiency / representation bottleneck | 看不见或编码不住决定性变量 |

第五类的关键句是：

> 能力会了，路由错了。

这也是它值得作为原始失配保留的原因。它不是"模型没学到"，而是"模型学到的能力覆盖过宽或调用过窄"；不是"目标没说清"，而是"已学能力被错误路由"；不是"状态看不见"，而是"状态已足够清楚后，能力调用边界仍然错位"；也不是"决定性变量没有进入表征"——后者属于观测-表征失配。

---

## 14. 小结

拟合边界失配是第五类原始失配，因为它有独立的错误方向和干预方式。

它的两个错误方向是：

- **过拟合侧**：不该用 X 的地方用了 X；
- **欠拟合侧**：该用 X 的地方没有用 X。

它的典型表现是：

> 错误能力被过度触发，正确能力没有被触发。

它的治理方法不是简单"多生成几版"，也不是简单"更谨慎"。真正有效的是：

- 标注支撑域；
- 保留多假设；
- 扰动相邻场景；
- 降权代理指标；
- 重启解法路径；
- 剥离角色话术；
- 防止用户反馈过拟合；
- 测量能力调用的 precision/recall；
- 同时审计误触发与漏触发；
- 把局部结论变成可撤销的治理对象。

如果聚合失配提醒我们不要相信"局部好会自然组成全局好"，那么拟合边界失配提醒我们：

> 不只要问模型会不会，还要问它是否在正确的地方调用了正确能力。
