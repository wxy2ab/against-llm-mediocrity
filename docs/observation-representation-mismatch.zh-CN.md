# 观测-表征失配

## 第六类原始失配的专题工作稿

**状态：** 工作稿  
**别名：** 观测通道失配  
**主文：** [大型语言模型系统的知识治理](knowledge-governance-llm-systems-local-alignment.zh-CN.md)

## 摘要

**观测-表征失配**指的是：真实任务所需的世界变量，在经由观测、编码、tokenization、embedding、上下文压缩、记忆或控制表征等通道进入 LLM 系统时，被丢失、压缩、混叠，或变得无法操作。

它不只是说"当前 latent state 未知"。更准确地说，当前模型可访问的表征本身，并不是世界状态的任务充分表征。系统也许在已有变量上推理得很好，但其理论上限被那些根本没有进入可控表征的变量卡住了。

工程上可以把它称为 **观测通道失配**。正式名称采用 **观测-表征失配**，因为瓶颈既可能发生在感知、报告、模态转换，也可能发生在编码、tokenization、embedding、摘要、检索、记忆或任务控制表征中。

两者的核心区分在于：

> 状态失配问：在当前观测通道下，现在是哪一个潜在状态？  
> 观测-表征失配问：决定任务价值的世界变量，是否进入了模型可操作的表征？

## 1. 核心命题

LLM 系统并不直接作用于真实世界。它作用于一条通道形成的表征：

\[
S_{\text{world}}
\xrightarrow{\phi}
O_{\text{observation}}
\xrightarrow{\psi}
Z_{\text{model representation}}
\xrightarrow{\pi}
Y_{\text{output/action}}.
\]

其中：

- \(S_{\text{world}}\)：真实世界状态；
- \(\phi\)：观测通道，例如文字、图片、音频、视频、传感器、日志、trace、人类报告、文件或工具输出；
- \(O\)：被观察到的内容；
- \(\psi\)：编码、tokenization、embedding、检索、摘要、上下文压缩或任务模型构造；
- \(Z\)：模型实际可访问、可操作的表征；
- \(Y\)：输出或行动。

状态失配主要问：在给定观测通道下，\(O\) 是否足以识别 \(S\)。观测-表征失配问的是更前置的 interface-level 问题：

\[
Z=\psi(\phi(S))
\quad \text{是否保留了任务充分变量？}
\]

令 \(C^\star(S)\) 表示任务充分控制变量。当存在两个世界状态 \(s_1,s_2\)，使得：

\[
\psi(\phi(s_1)) \approx \psi(\phi(s_2)),
\]

但：

\[
C^\star(s_1) \ne C^\star(s_2),
\]

并且这种差异会改变候选输出或行动的排序：

\[
\arg\max_y U(y;s_1) \ne \arg\max_y U(y;s_2),
\]

就发生了观测-表征失配。

等价地说，基于模型可访问表征的最优策略，严格差于基于真实状态的最优策略：

\[
\max_{\pi:Z\to Y}\mathbb{E}[U(\pi(Z);S)]
<
\max_{\pi:S\to Y}\mathbb{E}[U(\pi(S);S)].
\]

这个差值就是通道造成的理论上限损失：

\[
\Delta_{\text{channel}}
=
U^\star_S-U^\star_Z.
\]

这不是“模型没想明白”，而是模型的最优策略也只能优化它看得见、编码得住、能操作的状态投影。继续在同一个表征上延长推理，无法消除这个上限。真正的修复需要改变观测通道、增加测量、查询环境、调用工具、请求原始数据、构造更丰富的控制表征，或者明确标记缺失变量不可得。

## 2. 通道决定的六类上限

### 2.1 信息充分性上限

如果任务价值依赖变量 \(v^\star(S)\)，但该变量没有进入 \(Z\)，那么即便模型无限聪明，也只能达到“基于 \(Z\) 的贝叶斯最优”，不能达到“基于真实世界状态 \(S\) 的最优”。

典型表现包括：基于省略关键证据的摘要做决策、基于过期快照给建议、把用户描述当作完整状态，而不是把它视为部分观察。

### 2.2 可供性上限

图片可以显示物体外观，但不一定显示重量、温度、质地、摩擦、弹性、脆弱性、可抓取性、阻力、是否烫手、是否粘连、是否被固定。这些不是普通语义属性，而是 action-relevant affordances。

例如：

\[
\text{cup looks normal} \not\Rightarrow \text{cup is safe to grab}
\]

\[
\text{rod fits visually} \not\Rightarrow \text{rod can be maneuvered through space}
\]

没有可供性通道，行动问题就会被退化成视觉或语言代理问题。

### 2.3 时空连续性上限

单张图片、截断视频、摘要日志或转录文本，常常会丢失速度、加速度、接触先后、动作意图、运动轨迹、事件顺序、微小延迟，以及可逆或不可逆状态变化。

很多任务依赖的不是“对象是什么”，而是 state transition：医疗观察、体育判断、驾驶、机器人操作、金融微观结构、事故响应、客服升级时机都属于这一类。如果通道对状态转移采样不足，系统就无法构造正确的动态控制变量。

### 2.4 社会语用上限

文字转录会丢失语气、停顿、表情、共同注意对象、权力关系、羞辱感、讽刺、紧张、疲惫、亲密度和场景压力。

“好啊，你厉害”在文字层可能是赞扬，也可能是讽刺、愤怒、投降、撒娇或调侃。如果系统只得到 text token，多个互动状态会被压成同一个 observation。状态失配可以描述 latent dialogue state 的不确定性；观测-表征失配则指出更底层的原因：社会状态没有通过当前通道充分进入模型表征。

### 2.5 验证上限

LLM 可以生成一个看似合理的答案，但如果没有测试结果、传感器、运行日志、真实用户反馈、外部数据或专家验收，它无法知道候选输出是否真的满足任务。

这和“幻觉”不是同一件事。幻觉是模型输出了不真实内容；观测-表征失配是验证信号没有进入系统，因此模型无法把候选输出和真实后果绑定。更多 thinking 只会在同一个未验证表征上产生更长的错误。

### 2.6 任务构造上限

很多真实任务不是已经抽象好的问题。系统必须先从自然场景中抽取任务模型。观测-表征失配解释了其中一个更底层的失败来源：场景里真正决定任务的变量，没有以可抽取、可验证、可控制的形式进入表征。

在洗车问题中，关键不是“人怎么移动”，而是“哪个对象的状态需要改变”。在门与长杆问题中，关键变量可能是三维空间、杆的截面、朝向、路径和周围可操作空间。模型也许能解干净抽象题，却解不了自然观察形式，因为正确控制变量没有进入 \(Z\)。

## 3. 与状态失配的区分

| 维度 | 状态失配 | 观测-表征失配 |
|---|---|---|
| 核心问题 | 现在处于哪个 latent state？ | 当前通道是否保留任务充分变量？ |
| 数学对象 | \(P(S_t \mid O_{1:t})\) 的不确定性 | \(\psi(\phi(S))\) 是否是任务充分表征 |
| 典型条件 | 动态、隐藏、变化或部分可观测状态 | 场景稳定也会失败，因为通道丢变量 |
| 主要错误 | 给出对某状态合理、对另一状态错误的答案 | 把物理、社会、时空或验证问题压成可见代理 |
| 标准修复 | 状态枚举、scenario matrix、if-then policy、撤销触发器 | 新测量、新模态、工具、传感器、原始数据、环境查询、结构化表征 |
| 成功判据 | 条件策略覆盖相关状态 | 改变观测或表征通道后性能跃迁 |

状态失配的标准干预是把 state 显式化：列出 plausible latent states，找出会改变行动排序的变量，做 scenario matrix、if-then policy 和 revocation trigger。

观测-表征失配的第一问题不同：

> 当前观测通道是否有资格支持这个判断？

如果没有，正确动作不是先多列几个状态，而是测量、检查、运行、感知、查询、检索、换观察角度、取得原始证据，或构造更丰富的表征。

## 4. 与拟合边界失配的区分

拟合边界失配关注的是能力路由：

\[
M_X \ne T_X.
\]

模型已经学到或近似学到能力 \(X\)，但在真实适用域之外过触发，或在真实适用域之内欠触发。

观测-表征失配关注的是更上游的通道：

\[
S_{\text{world}} \rightarrow O \rightarrow Z.
\]

问题在于：任务充分变量是否进入了任何能力可路由的表征空间。两者的边界可以这样写：

- **拟合边界失配：** 能力在，路由错。
- **观测-表征失配：** 决定性变量没有充分进入可路由表征。

## 5. 独立预测特征

### 5.1 通道增强带来非线性跃迁

同一个模型、同一个任务，只要补足缺失通道，性能可能突然提升：

- 只给图片，物理判断错误；加深度、尺寸、材质、重量，判断正确；
- 只给客服文字，回复失当；加语音、停顿、历史拒绝次数、情绪标签，回复正确；
- 只给代码片段，只能猜 bug；加运行日志、失败栈、输入样例，就能定位。

如果性能提升主要来自“通道补足”，而不是“更长推理”，这就是观测-表征失配的签名。

### 5.2 状态枚举无法闭合决策

状态失配下，做完 state matrix 后通常能给出条件策略：

\[
s_1 \rightarrow y_1,\quad s_2 \rightarrow y_2.
\]

在观测-表征失配下，状态枚举往往只能暴露缺失变量：

\[
\text{需要测量 } v^\star.
\]

例如：如果杯子是热的，不要拿；如果不热，则可以拿。但当前图片无法判断温度，因此真正的下一步不是自信回答，而是测温或标记温度不可得。

### 5.3 错误集中在通道盲区

典型的错误并非模型不知道规则，而是过度依赖可见代理：

- 用外观代理重量；
- 用文字代理情绪；
- 用单帧代理动作趋势；
- 用流畅叙述代理真实因果；
- 用局部日志代理系统状态；
- 用静态截图代理交互流程；
- 用用户描述代理客观事实；
- 用二维投影代理三维可操作空间。

其共同形式是：

\[
\text{visible proxy} \ne \text{task-relevant variable}.
\]

### 5.4 干净抽象形式能恢复能力

如果模型在自然观察形式下失败，但把隐藏通道变量显式写成结构化变量后能力恢复，那么问题未必是“不会推理”，而可能是“没有从通道中抽出正确控制变量”。

例如，原图让模型误判长杆不能过门；但当结构化变量包含截面、朝向、净空和两侧可操作空间时，模型就能解。

### 5.5 输出空间搜索收益低，测量收益高

反复让模型"try again / think harder / make it better"收效有限；而一旦加入测量、工具、原始信号、日志、环境 API 或结构化多模态变量，提升往往显著。

这里的重参数化不只是把任务变成 state matrix，而是先把世界转化为可观察、可测量、可编码、可控制的变量。

## 6. 干预手册

当怀疑存在观测-表征失配时，系统应优先修复通道，而不是用语言制造确定性：

1. 找出任务充分变量 \(v^\star\) 或控制变量 \(C^\star\)；
2. 判断 \(v^\star\) 是否存在于 \(O\)，并在 \(Z\) 中被保留；
3. 如果缺失，改变观测通道或取得测量；
4. 如果已观测但不稳定，构造结构化表示、状态表、trace、feature set 或控制对象；
5. 如果缺验证信号，运行测试、查询日志、调用验证器、检查外部数据或请求专家验收；
6. 如果无法取得，明确标记变量不可得，并输出条件化或有边界的答案。

常见修复包括：

- 换观察角度，增加深度信息、时间采样或传感器；
- 检索来源文件、原始日志、运行 trace 或数据库记录；
- 运行测试、模拟、查询或探针；
- 请求原始数据，而不是摘要；
- 把语音、视频、图像或社会语境转成显式变量；
- 增加工具、评估器、验证器或环境 API；
- 记录哪些缺失变量阻止可靠回答。

## 7. 与知识治理的关系

知识治理把任务特定控制知识外化为可治理对象。观测-表征失配指出这件事的前置条件：控制变量必须先进入一种可存储、可验证、可修订、可撤销的表征。

如果表征有误，更多 thinking 只会产生更长的 mediocrity。一旦表征被修复，同一个模型可能在转化后的任务上进入局部对齐，甚至进入卓越区间。

设计上的核心结论是：

> 在要求模型更努力推理之前，先问真实世界是否已经以任务充分形式进入系统。

## 结论

观测-表征失配有资格成为第六类原始失配，因为它满足三条标准：

1. 它不能被完全还原为推理层的状态枚举；
2. 它能预测通道增强带来的非线性性能跃迁；
3. 它需要不同干预位置：interface、sensing、encoding、measurement、verification 和 control representation。

状态失配问：“现在是哪一个状态？”观测-表征失配问：“这个状态中真正重要的变量，有没有进入模型可操作的表征？”
