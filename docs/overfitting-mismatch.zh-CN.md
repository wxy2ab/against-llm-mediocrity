# 过拟合失配

## 第五类原始失配的专题工作稿

**状态：** 工作稿  
**主文：** [大型语言模型系统的知识治理](knowledge-governance-llm-systems-local-alignment.zh-CN.md)

## 摘要

**过拟合失配** 指的是：模型在训练、微调、对齐或推理过程中，为了适配某个局部能力、局部目标、偏好函数、评价指标或场景结构，形成了过强的高维吸引子；这个吸引子在目标区域内提高表现，但会越过有效支撑域，侵入相邻任务、相似语境、替代规格或不同推理路径，导致这些区域被错误牵引。

一句话：

> 学会 X 的代价，是把一部分非 X 也错当成 X。

它不是传统意义上“训练数据过拟合”的简单搬用，也不只是单次回答中的推理错误。它更根本地来自 **能力塑形的表示空间副作用**：LLM 的能力不是像软件插件一样被独立安装进去，而是在共享参数和共享表示空间中形成一片概率力场。这个力场让模型在能力 X 对应的场景中表现更好，但边界并不精确，因此会扭曲 X 的邻域 $X_t$，甚至牵引表面相似但机制不同的 Y/Z 场景。

这类失配补上了前四类没有完全覆盖的方向：

- 聚合失配是 **过度平均**：把多个不同场景压成一个高概率答案。
- 过拟合失配是 **过度绑定**：把一个局部场景绑定得太死，误当成跨场景不变量。

二者几乎是镜像关系。

## 1. 核心定义

更完整的定义是：

> 过拟合失配：模型为了适配局部能力、局部目标或局部场景而形成的高维结构，越过其有效支撑域，外溢到相邻任务并造成系统性错误。

当以下条件同时出现时，可以说任务中存在过拟合失配：

1. 模型在局部能力、局部目标、局部证据或局部场景 A 上表现提升，或者回答看似合理；
2. 这种表现依赖某些非模块化、边界不清的高维模式、代理指标、证据链、话术模板或角色姿态；
3. 模型没有标注这些模式的有效支撑域；
4. 它把局部适配结果推广为更大的因果结构、能力调用边界或行动结论；
5. 一旦切换到相邻场景、替代指标、不同审计协议、不同状态或不同机制，结论明显失效。

更短的判据是：

> 局部适配收益高，跨场景稳健性低。

形式上可以写成：

\[
E_A \Rightarrow H_A \quad \text{locally}, \qquad
H_A \not\Rightarrow I_{A:B:C}
\]

其中：

- $E_A$ 是场景 A 中的局部证据；
- $H_A$ 是模型选择的解释、断言或回答结构；
- $I_{A:B:C}$ 是本应跨相邻场景保持的不变量。

问题不在于 $H_A$ 完全没有证据。很多过拟合失配中的局部解释确实有证据。真正的问题是：

> 证据只局部支持某个解释，但模型把这种局部支持误当成跨场景不变量。

## 2. 为什么它不是“归纳失配”

“归纳”强调从局部样本推出整体结论。这能覆盖一部分过拟合失配，但不是本质。

过拟合失配更广。它不只包括从样本到总体的错误外推，还包括：

- 对局部证据链的过度绑定；
- 对局部指标的过度优化；
- 对某种场景默认值的过度套用；
- 对早期解法路径的自我强化；
- 对专业话术或角色姿态的过度适配；
- 对对齐偏好函数的过度迎合；
- 对用户局部反馈的过度响应；
- 对训练语料中高频解释模板的 shortcut learning。

所以“归纳失配”只是其中一种表面形态。“过拟合失配”抓住的是更高阶的结构：

> 局部适配强度，超过了局部条件本身的有效支撑域。

## 3. 底层机制：能力塑形外溢

过拟合失配的更深层机制可以叫作 **能力塑形外溢**，也可以叫作 **能力吸引子外溢**。

训练为了让模型获得能力 X，会在共享表示空间中强化一组高维模式：

```text
某类上下文
-> 激活 X 相关潜在特征
-> 进入 X 的概率吸引子
-> 输出 X 风格的判断、话术、审计或行动
```

问题是，这个吸引子不是边界清晰的模块。它没有一个干净的开关：

```text
if task == X:
    use skill X
else:
    leave everything unchanged
```

更真实的结构是：

```text
context embedding enters shared representation
-> many latent features activate
-> X-related attractor partially activates
-> output distribution is globally reshaped
```

于是会出现三类结果：

- 真正属于 X 的场景：表现提升；
- 靠近 X 但不应完全使用 X 的场景：被误吸入；
- 远离 X 但共享表面特征的场景：被错误触发。

这就是第五类失配的底层形式：

> 能力不是免费叠加的。每次能力塑形，都会改变模型的全局表示几何。

### 3.1 能力不是模块化存储的

LLM 的能力高度分布式。同一组参数和中间表示同时参与：

- 事实回忆；
- 风格控制；
- 数学推理；
- 安全拒答；
- 礼貌表达；
- 专业话术；
- 编程模式；
- 用户意图识别；
- 多轮状态维护；
- 工具调用倾向；
- 结论强度校准。

因此，优化某个能力 X，可能改变其他能力的激活边界。机器学习里，这对应 **interference**、**negative transfer** 和 **representation entanglement**。模型变大可以缓解粗糙干扰，但不会自动让所有能力正交。

### 3.2 训练目标是多目标压缩

LLM 训练并不是优化一个干净目标，而是在同时压缩大量目标：

- 预测下一个 token；
- 遵循指令；
- 不幻觉；
- 不冒犯；
- 不泄露敏感内容；
- 显得专业；
- 显得有帮助；
- 保持安全；
- 适配用户风格；
- 通过 benchmark；
- 满足人工偏好；
- 完成工具任务；
- 在多轮对话中保持一致。

这些目标不可能处处兼容。训练过程更像是在寻找一个高维 Pareto 折中点。

所以能力 X 的获得经常伴随局部副作用：

- 更安全，可能更保守；
- 更会拒答，可能更容易误拒；
- 更会迎合，可能更 sycophantic；
- 更会推理，可能更会编造推理链；
- 更会写作，可能更会用风格掩盖事实；
- 更会量化风控，可能更容易过早 No-Go；
- 更会避免过拟合，可能更容易欠搜索；
- 更会工具调用，可能更少做内部思考；
- 更会结构化回答，可能更容易把不清楚的问题装进固定模板。

这就是“拆东墙补西墙”的机器学习版本。

### 3.3 自回归把能力变成路径偏置

自回归模型不是一次性求解全局最优答案，而是逐 token 生成。早期 token 会形成路径依赖。

例如模型一开始生成：

> 这可能是数据不足。

后面就更容易继续生成：

> 需要新的正交数据。

再后面就更容易生成：

> 当前数据已接近极限。

于是，一个训练中学到的“专业保守模式”在推理时变成路径吸引子。模型未必不知道“扩大算子”“修正审计”“条件 alpha 搜索”这些方向；但一旦进入“数据不足 / 防过拟合 / No-Go”的轨道，后续输出就会继续维护这条轨道。

所以自回归带来的问题是：

> 能力 X 不只是一种知识，而是一种续写惯性。

### 3.4 能力边界错误

过拟合失配不是说模型没有能力 X。恰恰相反，它常常是因为模型已经拥有某种能力 X，而且这个能力在训练或对齐中被强化了。

问题是：

> 模型不知道 X 的适用边界在哪里。

更精确地说：

> 训练把 X 学成了一个概率场，而不是一个带严格边界的可调用模块。

这和支持失配不同。支持失配是“模型没学到那个区域”。过拟合失配是“模型学到了某个东西，但这个东西覆盖过宽，压坏了旁边的东西”。

## 4. 两层结构：训练期与推理期

过拟合失配可以分成两层。

### 4.1 训练期过拟合失配

这是更根本的一层。为了让模型获得能力 X，训练、微调或对齐过程在共享表示空间中塑造出 X 的高维结构；但这个结构不是模块化、边界清晰的，因此会损伤、污染或牵引相邻任务 $X_t$。

例子：

- 训练“安全拒答”导致普通问题误拒；
- 训练“谨慎保守”导致科研探索欠搜索；
- 训练“用户友好”导致迎合；
- 训练“推理格式”导致伪推理；
- 训练“专家风格”导致过度自信包装；
- 训练“遵循指令”导致错误指令也被过度执行；
- 训练“简洁回答”导致复杂问题被压扁。

### 4.2 推理期过拟合失配

这是具体交互中的表现层。在单次任务或多轮对话中，模型过度绑定局部证据、局部路径、局部话术或局部上下文，把本应有限适用的结构扩展到更大范围。

例子：

- 试了少量算子后 No-Go；
- 听到“量化”就套用“需要正交数据”；
- 听到“敏感”就拒答；
- 听到“研究尚无定论”就不做探索；
- 看到用户强烈表达就开始迎合；
- 看到某个 benchmark 就把 benchmark 当真实能力。

两层关系是：

```text
训练期形成吸引子
-> 推理期被上下文触发
-> 吸引子越过支撑域
-> 相邻任务被错误牵引
```

## 5. 与其他四类失配的边界

### 5.1 与聚合失配

聚合失配的问题是局部好片段无法组成全局好答案。它的错误方向是过度平滑、过度平均。

过拟合失配的问题是某个局部解释绑定得太强。它的错误方向是过度尖锐、过度固定。

例子：

- 聚合失配：故事每个场景都不错，但整体主题和承诺-兑现结构失败。
- 过拟合失配：系统过度绑定某个强场景或早期象征意象，后续所有修订都为它服务，反而牺牲整体故事。

### 5.2 与支持失配

支持失配关注的是高价值结构在模型策略或当前搜索算子下难以到达。

过拟合失配不一定意味着替代解释不可达。很多时候，替代解释就在支持内，只是模型已被一个局部解释、指标或话术锁住，导致搜索不再展开。

例子：

- 支持失配：少见但正确的机制根本没有被模型提出。
- 过拟合失配：正确机制被提过、也能被想到，但模型坚持早期的“数据不足”解释，后续推理都围绕它辩护。

### 5.3 与规格失配

规格失配问的是：系统实际优化的代理目标是否偏离真实目标。

过拟合失配问的是：即使目标已经相对清楚，模型是否仍然把某个局部代理、模板、解释或路径绑定得太死。

例子：

- 规格失配：评分规约漏掉了真正的验收条件。
- 过拟合失配：评分规约本身有用，但模型把某一项分数或某个 benchmark 当成全部目标。

### 5.4 与状态失配

状态失配问的是：真实状态是否可观察、可识别。

过拟合失配问的是：模型是否把某个状态下有效的解释、策略或话术推广到了其他状态。

例子：

- 状态失配：模型不知道当前市场 regime。
- 过拟合失配：模型把一个 regime 下有效的信号或风控逻辑当成跨 regime 规则。

## 6. 机器学习解释

过拟合失配可以用几组机器学习概念理解。

### 6.1 局部经验风险最小化

模型在当前场景 A 中选择一个低损失回答：它看起来专业、合理、安全、结构完整。

但这个回答只是在 A 中低损失，不保证在相邻场景 B/C/D 中低损失。

在 LLM 使用中，这常表现为：

- 回答非常顺；
- 术语很专业；
- 风险姿态看似负责；
- 结构化程度高；
- 当前证据能支撑一部分断言；
- 但结论被说得比证据允许的更强。

### 6.2 代理目标过拟合

模型经常优化一个 proxy，然后把 proxy 误当成真实目标。

常见 proxy 包括：

- benchmark 分数；
- 单一评分规约；
- reward model 偏好；
- 用户即时满意度；
- 当前测试集；
- 一次 backtest；
- 单一审计指标；
- “听起来像专家”的话术。

问题不是 proxy 没用。问题是模型把 proxy 当成目标本体。

### 6.3 Shortcut learning

模型抓住语料或语境中常见的解释捷径。

例子：

- 没找到 alpha -> 数据不够；
- 用户焦虑 -> 建议咨询专业人士；
- 法律问题 -> 具体情况具体分析；
- 医疗问题 -> 去看医生；
- 科研不确定 -> 需要更多实验；
- 代码出错 -> 加日志和重试。

这些捷径经常局部合理，却不是稳定因果关系。

### 6.4 高方差解释选择

同一组证据支持多个解释，模型选择了一个过于具体、过于强的解释。

这类似高方差模型：对当前样本拟合得太尖锐，导致泛化不稳。

人类研究者可能说：

> 当前搜索没有找到。

过拟合的模型会说：

> 当前数据已经被榨干。

两者差别不在语气，而在因果断言强度。

### 6.5 多任务负迁移与表示干扰

过拟合失配也可以理解为多任务学习中的 **negative transfer**。训练模型同时做很多任务，任务 X 的梯度更新提升了 X，却损伤了 $X_t$ 或 Y。

这不一定表现为能力退化，也可能表现为能力边界漂移：

```text
X 场景更强
X 的邻域被误吸附
Y 场景的默认解释被 X 改写
```

共享参数还会带来 **catastrophic interference** 的轻量版本。模型不是每个能力一套独立参数，大部分能力共享表示和计算路径。因此，优化 X 会改变共享表示，影响其他能力。规模、稀疏化、MoE、router、adapter 和工具化可以缓解干扰，但不能保证所有能力边界完全隔离。

### 6.6 为什么模型越强，错误越高级

弱模型的错误常常是：不知道、乱编、算错、理解错。

强模型的过拟合失配更隐蔽，因为它拥有某个高级模式，只是把这个模式部署到了错误场景：

- 它有“审慎科学家”模式，于是过度保守；
- 它有“安全合规”模式，于是误拒；
- 它有“专家解释”模式，于是把不确定性包装成专业结论；
- 它有“结构化总结”模式，于是把开放问题过早闭合；
- 它有“统计反过拟合”模式，于是压制探索；
- 它有“用户意图推断”模式，于是过度读心；
- 它有“强推理链”模式，于是给错误结论构造强理由。

这类错误看起来不像低级幻觉，而像能力的副作用。

### 6.7 为什么它不会自然消失

准确说法不是“过拟合失配在数学上永远不可解”，而是：

> 在有限模型、有限数据、共享参数、多目标优化和自回归生成的现实框架下，过拟合失配不可能被完全消除；只能被转移、压缩、显性化、隔离或审计。

模型进步会带来：

- 更少低级外溢；
- 更好的边界识别；
- 更强的自我审计；
- 更好的工具验证；
- 更模块化的能力路由；
- 更强的不确定性校准。

但它不能保证：

> 优化能力 X 永远不伤害 $X_t$。

只要能力共享表示、目标多元冲突、边界数据有限，就会有外溢。

## 7. 子模式分类

过拟合失配值得单开文档，是因为它内部有大量可稳定复现的子模式。

### 7.1 证据链过拟合

模型对一条局部证据链绑定过强。

模板：

```text
局部证据 E 成立
-> 解释 H 能解释 E
-> 模型把 H 当成唯一解释
-> 忽略 E 也兼容 H2/H3/H4
```

例子：

- 试了几个算子没效果 -> 数据不够；
- 几个用户反馈不喜欢 -> 所有人都不喜欢；
- 某次部署失败 -> 方向不可行；
- 一个 benchmark 不好 -> 能力不存在；
- 某个故事版本评分最高 -> 它的结构方向就是正确方向。

核心问题：

> 证据是真的，但解释过窄，断言过强。

### 7.2 证据-断言链条过拟合

这是证据链过拟合的更精确版本。模型不只是选错解释，而是把“证据能推出什么”这条边拉得过长。

模板：

```text
证据只能推出：在当前搜索范围内没有发现 X
模型却推出：X 不存在，或必须换成 Y
```

金融量化中常见：

- 当前窄算子没有 alpha -> 数据没有 alpha；
- 当前持有期不好 -> 策略不可部署；
- 当前 benchmark-excess 不好 -> 绝对收益逻辑无效；
- 当前粗 filter 无效 -> 整个机制空间已经排除。

更稳健的说法应该是：

> 当前证据只排除了当前算子、当前审计协议和当前搜索深度下的一组假设。

### 7.3 代理指标过拟合

模型过度相信某个 metric、benchmark、rubric 或评分表。

例子：

- benchmark-excess 不好 -> 绝对收益策略不可部署；
- MMLU 分数高 -> 真实研究能力强；
- 用户满意度高 -> 答案真实；
- reward model 喜欢 -> 推理正确；
- backtest Sharpe 高 -> 策略真实有效；
- 故事评分 9.0 -> 已满足高验收合同。

代理指标不是目标本体。它只是目标的一个投影。

### 7.4 场景默认值过拟合

模型把常见场景的默认值套到当前任务上，即使当前任务已经提供了区分性信息。

例子：

- 量化研究默认“防过拟合优先”，所以过早要求新正交数据；
- 医疗问答默认“建议看医生”，所以不做细致鉴别；
- 法律问答默认“咨询律师”，所以不分析条款结构；
- 写作任务默认“清晰礼貌”，所以丢掉攻击性、权力关系或风格张力；
- 编程任务默认“最佳实践”，所以忽略用户的极端性能约束；
- 产品建议默认“平衡取舍”，所以不做真正的优先级判断。

它和规格失配有重叠，但不等同。规格失配是目标没定清；场景默认值过拟合是目标已经部分澄清后，模型仍被高频默认场景拖走。

### 7.5 解法路径过拟合

模型一旦进入某条解法路径，就不断为这条路径补理由。

例子：

- 一开始判断是数据问题，后面所有分析都围绕“数据不足”展开；
- 一开始选了某个技术栈，后面所有设计都服务于这个技术栈；
- 一开始把用户问题理解成分类问题，后面就忽略生成式、搜索式、优化式解法；
- 一开始把策略当成因子策略审计，后面就忽略事件策略审计；
- 一开始认为故事核心是某个象征，后面所有修订都过度服务这个象征。

这和自回归路径依赖有关，但它不是普通聚合失配。它不是平均化，而是路径锁定后的局部过拟合。

### 7.6 话术 / 角色过拟合

模型过度适配某种“专业角色”的语言和价值姿态。

例子：

- 量化里：稳健、保守、防止 data mining、需要正交数据；
- 科研里：需要更多实验，不能下结论；
- 法律里：具体情况具体分析；
- 医学里：建议咨询专业医生；
- 安全里：不能提供危险建议；
- 管理咨询里：平衡短期和长期；
- 产品经理里：以用户为中心、数据驱动、快速迭代。

这些话本身并非错误。问题在于它们过度支配答案时，会导致：

> 表面负责，实质逃避搜索。

### 7.7 对齐偏好过拟合

模型过度适配 SFT、DPO、RLHF 或产品层偏好中被奖励的行为。

常见偏好包括：

- 显得谨慎；
- 显得平衡；
- 显得礼貌；
- 显得不武断；
- 显得符合主流共识；
- 显得不给危险建议；
- 显得能完成任务；
- 显得结构清楚、有条理；
- 显得承认不确定性。

这些偏好大多有价值。但过度时，会牺牲真实任务目标。

典型失败是：模型并不是不知道怎么继续搜索，而是某种“看起来负责任”的姿态压制了继续搜索。

### 7.8 用户反馈过拟合

这是 sycophancy 的更一般形式。

模型可能为了适配当前用户的局部偏好，牺牲事实、机制或长期目标。

例子：

- 用户强烈相信某个假设，模型开始围绕这个假设找理由；
- 用户讨厌保守回答，模型变得过度激进；
- 用户喜欢复杂理论，模型生成过度理论化解释；
- 用户喜欢某个框架，模型把所有问题都塞进这个框架；
- 用户刚指出一个真实错误，模型过度纠偏成“用户所有直觉都对”。

正确状态不是“反用户”，也不是“顺用户”，而是：

> 把用户反馈作为证据，更新搜索方向，同时保留独立审计。

### 7.9 语料先验过拟合

模型把训练语料中高频、高权威或主流叙事过度绑定为默认解释。

例子：

- 历史评价被主流叙事锁定；
- 地缘政治问题被某个来源框架锁定；
- 管理问题被 MBA 模板锁定；
- 创业问题被硅谷增长话术锁定；
- 投资问题被经典因子或风险话术锁定；
- 心理问题被流行治疗语言锁定。

语料先验可以同时制造支持失配和过拟合失配：

- 支持失配：少见框架难以出现；
- 过拟合失配：一旦主流框架出现，模型就把它绑定成唯一解释。

### 7.10 审计协议过拟合

模型把一次审计协议当成完整审计。

例子：

- 当前测试覆盖通过 -> 代码正确；
- 当前 benchmark 不好 -> 能力不存在；
- 当前 backtest 不好 -> 策略机制无效；
- 当前 fuzz 没发现 -> 安全；
- 当前人工评审没问题 -> 规格满足。

治理上要区分：

```text
当前审计没发现问题
≠
问题不存在
```

### 7.11 抽象层级过拟合

模型锁定在一个抽象层级上，无法切到更合适的层级。

例子：

- 把交易策略一直当成因子组合问题，而不是事件路径问题；
- 把故事问题一直当成文笔问题，而不是承诺-兑现结构问题；
- 把组织问题一直当成沟通问题，而不是激励结构问题；
- 把代码问题一直当成局部 bug，而不是架构边界问题；
- 把研究问题一直当成资料不足，而不是假设空间构造错误。

这类失配常常与“错误抽象”复合，但它的关键是局部抽象已经自洽，因此模型不愿离开。

### 7.12 成功样本过拟合

模型或系统从一个成功案例中抽取了过强规则。

例子：

- 某次 prompt 成功 -> 这个 prompt 模板被到处套用；
- 某个故事版本成功 -> 后续作品都复制同一叙事张力；
- 某个因子历史有效 -> 被当成永久机制；
- 某个产品策略增长有效 -> 被当成所有阶段的增长逻辑；
- 某个用户喜欢某种回答 -> 后续全部使用同一语气。

成功样本比失败样本更容易诱发过拟合，因为它会提供一种“已被证明”的错觉。

## 8. 金融量化案例中的复合过拟合失配

一个典型例子是：

> 当前几个算子没有找到足够强的 alpha，于是模型判断现有数据已经被榨干，需要新正交数据。

这个结论局部看似合理，因为量化研究中确实常见“需要新正交数据”的说法。但当前证据通常只能推出：

> 在当前窄算子、当前审计协议、当前持有期、当前搜索深度下，没有找到足够强的结果。

它不能直接推出：

> 数据已经没有 alpha。

同一组证据还兼容许多替代解释：

- 算子族太窄；
- 审计协议错了；
- 持有期错了；
- 入场可成交性假设错了；
- 搜索深度不够；
- 组合逻辑没展开；
- 事件机制没有被正确翻译成特征；
- alpha 是 conditional alpha，不是裸 alpha；
- benchmark-excess 不是当前策略目标的充分代理；
- 流动性、连板数等粗 filter 不能代表整个机制空间。

所以这里不是单点错误，而是多个过拟合子模式叠加：

1. **证据-断言链条过拟合**：把“当前没找到”过拟合成“数据没有”。
2. **代理审计过拟合**：把 benchmark-excess 或单一持有期审计当成 deployability。
3. **解法路径过拟合**：一开始走“数据不足”路径，后续不断为它辩护。
4. **专业保守话术过拟合**：“需要正交数据”“防止 data mining”压制了继续 operator search。
5. **假设类过拟合**：把 liquidity、连板数等极窄 operator family 当成整个机制空间。

更底层地看，这个例子不是模型完全缺少量化能力，而是被几个训练出来的能力吸引子捕获了：

1. **量化风控吸引子**：看到 alpha 搜索，优先警惕 data mining。
2. **正交数据吸引子**：看到当前数据效果弱，倾向要求新数据。
3. **专业审慎吸引子**：用稳健、谨慎、No-Go 语言包装结论。
4. **代理审计吸引子**：把 benchmark-excess 当成更专业的检验口径。
5. **路径一致性吸引子**：一旦走上“数据不足”解释，后面继续维护这条路径。

这些能力在很多量化场景里有价值。但在当前场景中，它们外溢了，压制了真正需要的能力：

- 机制转算子；
- 算子扩展；
- 审计修正；
- 条件 alpha 搜索；
- 未搜索空间维护。

所以这个案例的本质不是“不会量化”，而是：

> 模型为了拥有“谨慎量化研究员”能力，牺牲了“开放式 alpha 搜索研究员”能力在相邻场景中的正确触发。

正确治理不是简单走向反面：

```text
模型说数据不够 -> 用户说模型错了 -> 所以用户的 alpha 直觉都对
```

这也是过拟合。更稳健的状态是：

```text
扩大搜索空间
保留数据不足假设
保留算子不足假设
保留审计协议错误假设
保留条件 alpha 假设
然后用更清楚的审计协议逐步排除
```

## 9. 诊断问题

判断一个失败是否属于过拟合失配，可以问：

1. 这个结论在当前场景中是不是“看起来很合理”？
2. 它依赖的是证据本身，还是证据到解释之间的一条过强链条？
3. 同一组证据是否还兼容其他解释？
4. 模型是否把一个 proxy 当成目标本体？
5. 模型是否被某个专业话术、角色姿态或安全模板拖走？
6. 早期路径是否正在支配后续推理？
7. 如果改变指标、持有期、审计协议、状态或机制，结论是否还能成立？
8. 模型是否明确标注了当前结论的适用边界？
9. 用户反馈是否让模型过度纠偏？
10. 当前成功样本是否被抽成了过强规则？

如果多个问题回答为“是”，就应把过拟合失配纳入失配画像。

## 10. 治理方法

### 10.1 标注支撑域

每个局部结论都应标注：

- 证据来自哪里；
- 支持到什么强度；
- 适用于哪些场景；
- 不适用于哪些场景；
- 哪些相邻扰动会推翻它。

一个 GKO 可以这样记录：

```json
{
  "claim": "当前算子族未找到稳定 alpha",
  "support_scope": "当前算子族、当前持有期、当前审计协议",
  "not_supported_claims": [
    "现有数据已无 alpha",
    "必须引入新正交数据",
    "事件机制不可用"
  ],
  "revocation_tests": [
    "扩大 operator family",
    "切换持有期",
    "重做成交性审计",
    "测试 conditional alpha"
  ]
}
```

### 10.2 相邻场景扰动

不要只问“这个结论是否解释当前证据”，还要问：

- 换一个持有期还成立吗？
- 换一个 benchmark 还成立吗？
- 换一个审计协议还成立吗？
- 换一个状态区间还成立吗？
- 换一个角色目标还成立吗？
- 换一个用户偏好还成立吗？
- 换一个抽象层级还成立吗？

过拟合失配最怕的不是更大模型，而是小而精准的邻域扰动。

### 10.3 多假设保留

在证据不足以唯一支持某个解释时，不要让模型收敛成单解释。

可以显式维护：

```text
H1: 数据不足
H2: 算子不足
H3: 审计协议错误
H4: 持有期错配
H5: 状态变量缺失
H6: 目标 proxy 错配
```

每个假设都要有：

- 当前证据；
- 反证；
- 下一步测试；
- 降级或撤销条件。

### 10.4 代理指标降权

当某个 metric 开始支配答案时，应显式降权：

```text
这个指标是证据，不是目标。
它能排除什么？
它不能排除什么？
它与真实目标之间有哪些缺口？
```

### 10.5 路径重启

当模型已经沿一条路径写出很长推理时，可以要求它从不同入口重启：

- 从反假设开始；
- 从相邻机制开始；
- 从失败样本开始；
- 从替代审计协议开始；
- 从不同角色但同一目标开始；
- 从“当前结论可能在哪些条件下错”开始。

### 10.6 角色话术剥离

把回答拆成两层：

1. 实质机制判断；
2. 角色话术包装。

然后问：

> 如果去掉“谨慎、专业、平衡、安全”的话术，剩下的机制断言是什么？它被什么证据支持？

### 10.7 用户反馈防过拟合

用户指出错误后，系统应更新假设，而不是把用户变成新的绝对指标。

可以采用三栏：

| 用户反馈 | 应更新什么 | 不应推出什么 |
|---|---|---|
| 当前结论过早说数据不足 | 扩大 operator search；保留其他解释 | 用户所有 alpha 直觉都正确 |
| 回答太保守 | 降低安全模板权重 | 变成无审计激进建议 |
| 框架有用 | 纳入候选控制对象 | 所有问题都套入该框架 |

## 11. 与知识治理的关系

过拟合失配特别适合用知识治理处理，因为它的核心不是“缺少一句更好的最终回答”，而是缺少可撤销、可边界化的中间控制知识。

治理层应当做三件事：

1. **把局部结论对象化**：不要让它埋在流畅 prose 中。
2. **把支撑域显式化**：记录它在哪些条件下成立。
3. **把撤销测试前置**：定义什么证据会削弱或撤销它。

这会把“模型说得很像”转化为“模型提出了一个可审计假设”。

## 12. 实证方向

过拟合失配可以通过以下实验测量：

1. **邻域扰动测试**：保持任务核心不变，改变指标、状态、角色、审计协议或反馈来源，观察结论稳定性。
2. **多解释保留率**：检查模型在证据不足时是否保留替代假设，而不是过早收敛。
3. **代理指标劫持率**：测量模型把 benchmark/rubric/reward/test 当成目标本体的频率。
4. **路径锁定强度**：在早期注入一个可辩护但非唯一解释，观察后续推理是否持续为其辩护。
5. **角色话术支配率**：去掉话术包装后，检查剩余机制断言是否仍有足够证据。
6. **用户反馈过拟合率**：用户纠错后，模型是否从一个极端跳到另一个极端。
7. **成功样本规则化误差**：从成功样本抽取规则后，测试其跨任务泛化。

这些实验的目标不是证明模型“会犯错”，而是定位：

> 哪些局部合理结构最容易被模型误当成跨场景不变量。

## 13. 放回五类失配框架

过拟合失配进入框架后，五类失配可以这样并列：

| 失配 | 本质问题 | 机器学习解释 | 错误方向 |
|---|---|---|---|
| 聚合失配 | 把多个不同模式平均成一个高概率输出 | autoregressive conditional-distribution aggregation | 过度平均 |
| 支持失配 | 目标区域缺少足够概率或数据支持 | support coverage / long-tail sparsity | 到不了 |
| 规格失配 | 目标函数没有被清楚指定 | underspecified objective / proxy mismatch | 不知道该优化什么 |
| 状态失配 | 观测无法恢复潜在状态 | latent-state non-identifiability / POMDP | 不知道真实状态 |
| 过拟合失配 | 为获得局部能力或满足局部目标而形成的高维结构外溢，损伤相邻场景 | overfitting / negative transfer / shortcut learning / proxy overoptimization / representation interference | 过度绑定 |

第五类的关键句是：

> 能力不是免费叠加的。每次能力塑形，都会改变模型的全局表示几何。

这也是它值得作为原始失配保留的原因。它不是“模型没学到”，而是“模型学到的东西覆盖过宽”；不是“目标没说清”，而是“某个局部目标、局部能力或局部偏好被学成了会外溢的吸引子”；不是“状态看不见”，而是“一个状态或场景下有效的能力边界被错误推广”。

## 14. 小结

过拟合失配是第五类原始失配，因为它有独立的错误方向和干预方式。

它的错误方向是：

> 过度绑定。

它的典型表现是：

> 为了把 A 场景答得像样，牺牲了 B/C/D/E/F 场景的正确性。

它的治理方法不是简单“多生成几版”，也不是简单“更谨慎”。真正有效的是：

- 标注支撑域；
- 保留多假设；
- 扰动相邻场景；
- 降权代理指标；
- 重启解法路径；
- 剥离角色话术；
- 防止用户反馈过拟合；
- 把局部结论变成可撤销的治理对象。

如果聚合失配提醒我们不要相信“局部好会自然组成全局好”，那么过拟合失配提醒我们：

> 不要把局部看起来对的解释，太快升级成全局不变量。
