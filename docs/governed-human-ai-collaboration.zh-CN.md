## 1. 核心命题

AI 与人之间最好的分工，不是静态地把"AI 做什么"和"人做什么"分清楚，而是治理任务中的关键变量。

AI 应向前推进一切可生成、可搜索、可结构化、可模拟、可测试和可验证的部分。人类应治理那些需要合法价值判断、偏好、预算、授权、品味、责任或真实经验的变量。

```text
AI：处理 → 搜索 → 结构化 → 模拟 → 验证
Human：设定价值 → 分配预算 → 授权 → 判断品味 → 承担责任
System：将持久判断保存为 GKO/GEO -> 提交受治理状态转移 -> 恢复 AI 自治
```

协作的单位不是整个任务，而是 **控制变量**。对于长程 agent，被解决的控制变量还应成为硬状态更新：事实、权限、边界、义务、撤销或验证记录，使 agent 中断后仍能恢复。

## 2. 何时需要与不需要治理

治理式协作适合高失配、高风险、强偏好、跨角色或需要长期复用的工作。对于已经处在LLM卓越区间的任务，不应再额外增加不必要负担。

| 正向对齐任务 | AI 应做 | 人类边界 |
|---|---|---|
| 上下文压缩 | 总结、分类、抽取决策变量 | 确认是否遗漏关键利益 |
| 语义扩写 | 把笔记或提纲扩写为文本 | 确保上游结构正确 |
| 语体转换 | 调整语气和受众 | 法律、关系或声誉边界隐含时介入 |
| 结构化转换 | 生成表格、清单、JSON、SOP | 确认格式反映真实工作流 |
| 候选生成 | 提出标题、风险、边界情况、查询 | 选择、排序和验证 |

设计原则是：

> 治理不稳定的边界，而不是治理每一个 token。

## 3. 先问环境，再问人

第一问题不是"AI 能不能做"，而是：

> 决定性不确定性是否可以从环境、反馈、工具、模拟或构造出的测试中获得？

### 3.1 环境可观察型工作

事实应先被检索、检查、测试或测量，而不是过早升级给人。

| 任务 | AI 优先动作 | 不应过早问人 |
|---|---|---|
| 当前事实研究 | 检索并交叉验证来源 | "你觉得当前事实是什么？" |
| 代码正确性 | 跑测试、检查类型和运行行为 | "你觉得代码对吗？" |
| 数据分析 | 检查分布、异常、泄漏和偏差 | "你感觉异常在哪里？" |
| 产品运营 | 分析漏斗、cohort、日志和反馈 | "你觉得用户喜欢吗？" |
| 工程部署 | 检查配置、日志、依赖和 CI | "你觉得部署会失败吗？" |

### 3.2 反馈可学习型工作

有些偏好无法提前完整表达。AI 应构造对比，让偏好通过选择逐步显化。

不要问：

> 你想要什么风格？

而应问：

> 这里有三种保持原意的版本：克制专家型、锋利论证型、大众解释型。哪种最接近？哪种不可接受？

有用的中间对象包括：

- 成对比较；
- 正反样例；
- 风格轴；
- 偏好排序；
- 修改痕迹；
- 一票否决式失败条件。

### 3.3 构造试炼场

当真实反馈暂时不可得或成本过高时，AI 应构造方案可能失败的环境：

- 竞争者反应与价格战；
- 新手、低耐心或对抗性用户旅程；
- 红队与隐私滥用案例；
- 多档市场状态（bull / base / bear）；
- 法务、销售、客服、管理层和客户视角；
- 反事实、边界情况和回滚场景。

模拟不能证明真实，但可以扩大测试面并暴露隐藏假设。

### 3.4 人类治理变量

只有当剩余变量无法可靠观察、推断、验证或合法授权时，才问人。

| 变量 | 人类提供 |
|---|---|
| 事实或状态 | 确认一个无法获得的具体条件 |
| 偏好权重 | 选择哪个目标主导 |
| 授权 | 批准具体外部或不可逆动作 |
| 边界 | 定义规则何时适用或停止适用 |
| 验证信号 | 提供验收标准、专家审查或不可获得证据 |
| 资源 | 授予访问，或批准降级路径 |
| 责任 | 指定承担责任的人 |
| 停止标准 | 定义什么叫足够 |

## 4. 三层诊断栈

| 层级 | 核心问题 | 协作结果 |
|---|---|---|
| 原始失配 | 为什么普通生成可能偏离价值？ | 重参数化任务或构造控制空间 |
| 操作阻塞 | 哪个缺失控制变量阻止推进？ | 先自主修复，必要时路由给人 |
| 升级协议 | 最小人类贡献是什么？ | 提出 MSHQ、应用 GEO、恢复自治 |

五个操作域是：

1. 信息与证据；
2. 价值与规格；
3. 权限与责任；
4. 边界与时机；
5. 协调与控制表示。

定义与升级门槛见 [技术补充稿](human-assist-operational-mismatches.zh-CN.md)。

## 5. 治理式协作流程

1. **直接路由低失配工作。** 压缩、转换、起草和候选生成不需要过度治理。
2. **诊断原始失配。** 识别聚合、支持、状态、规格、拟合边界和观测-表征风险。
3. **构造任务模型。** 外化成功条件、目标状态、约束、噪声、假设和评价标准。
4. **构造搜索空间。** 包含常规、非常规、保守、进攻、可逆和延迟决策路径。
5. **向环境取证。** 检查文件、来源、工具、日志、测试、当前状态、可用证据，以及缺失的测量或通道变量，再判断是否需要问人。
6. **构造试炼场。** 生成场景、反事实、红队案例、利益相关者视角和边界情况。
7. **识别剩余操作阻塞。** 判断它是否确实由人类治理。
8. **提出 MSHQ 或实例化 GEO。** 只询问恢复自治所需变量，并给选项与安全默认。
9. **等待期间继续可逆工作。** 准备草稿、测试、矩阵和更安全替代方案。
10. **验证回答并恢复自治。** 检查答案，在边界内执行，并验证结果。
11. **提交已解决变量。** 将回答、证据或验证结果写入 agent 硬状态，作为被承认的状态转移。
12. **保存可复用判断。** 将持久条件保存为 GKO，将重复升级规则保存为 GEO。
13. **撤销过时治理。** 当政策、权限、状态、工具或偏好变化时更新对象。

多轮协作只有在每轮产生会改变下一步任务的持久对象时才有价值。没有新控制对象的"再试一次"，通常只是重复采样。

## 6. AI 应向前推进什么，不应静默决定什么

### AI 应向前推进：

- 任务模型和决策变量；
- 宽广的选项与搜索空间；
- 场景矩阵和状态矩阵；
- 依赖图和控制空间；
- 证据计划和验证清单；
- 可逆草稿、实验和准备工作；
- 最小人类问题。

### AI 不应静默决定：

- 最终价值函数；
- 预算或风险承受；
- 身份与品味；
- 外部承诺或不可逆动作；
- 法律、财务、安全、雇佣或隐私责任；
- 流畅解释是否足够作为证据；
- 旧偏好是否适用于新情境。

## 7. 协作对象

| 对象 | 用途 |
|---|---|
| 任务模型 | 外化成功条件、约束和隐藏假设 |
| 选项集 | 把开放偏好变成有边界选择 |
| 风格轴 | 让品味可对比、可检查 |
| 场景矩阵 | 暴露状态依赖决策 |
| 失败模式列表 | 暴露合理答案可能如何失败 |
| 验证清单 | 区分生成与证据 |
| GKO | 保存 agent 应知道或遵守什么 |
| GEO | 保存 agent 何时问、问谁、然后做什么 |
| MSHQ | 在一次具体交互中表达 GEO |
| 硬状态转移 | 记录行动、证据、验证或人类输入之后什么被系统承认发生了改变 |

### 7.1 MSHQ 模板

```text
我可以继续自治完成 ______。
当前唯一阻塞变量是 ______。
请确认或选择：A ______ / B ______ / C ______。
这个选择会改变 ______。
如果你不指定，我将 ______，因为它是最安全或最可逆的路径。
```

### 7.2 选项构造模板

```text
任务：
成功条件：
A. 保守 / 低风险路径：
B. 平衡路径：
C. 进攻 / 高回报路径：
D. 低成本实验：
E. 延迟决策路径：
关键取舍：
最小人类治理变量：
```

### 7.3 验证模板

```text
候选结论：
证据类型：事实 / 数据 / 测试 / 专家审查 / 用户反馈 / 模拟
当前证据强度：弱 / 中 / 强
未验证假设：
错误代价：
可逆性：
最低验证要求：
无人输入时的安全默认：
```

## 8. 场景示例

### 8.1 战略备忘录

- **AI 先做：** 构造选项矩阵、反方观点、假设、风险和低成本验证路径。
- **问环境：** 检索市场、竞品、客户、政策和内部证据。
- **人类变量：** 增长、利润、速度、声誉或风险谁主导。
- **MSHQ：** "这份 memo 应优化决策清晰、说服力、风险暴露还是完整性？若不指定，我默认决策清晰。"

### 8.2 产品路线

- **AI 先做：** 构造 feature × 用户价值 × 成本 × 可逆性 × 风险矩阵。
- **问环境：** 分析使用数据、支持工单、实验与竞品行为。
- **人类变量：** 战略优先级、预算上限、发布时间与品牌边界。
- **GEO：** 多个选项主要差在成本、速度和风险时，请项目 owner 指定主导权重。

### 8.3 代码与数据验证

- **AI 先做：** 跑测试、检查依赖、生成边界情况并执行泄漏审计。
- **问环境：** 检查 CI、运行行为、数据契约和时间戳。
- **人类变量：** 无法获得的字段语义、生产约束或验收标准。
- **MSHQ：** "请确认所有特征是否在预测时间前可用；若无法确认，我会默认存在泄漏风险并加入 lagging。"

### 8.4 外部沟通

- **AI 先做：** 准备草稿、风险和更安全措辞版本。
- **问环境：** 检查政策、关系状态、历史承诺和合同。
- **人类变量：** 是否授权发送、承诺、披露或作出保证。
- **默认：** 无人确认时不发送，只保留草稿。

## 9. 人类角色：从信息处理者到治理者

当 AI 成为默认信息处理核心后，人类能力应向上移动：

- **问题构造：** 识别错误抽象；
- **价值设计：** 区分真实价值与 proxy；
- **品味表达：** 通过样例和对比表达判断；
- **预算治理：** 定义金钱、时间、注意力、组织信用和机会成本；
- **证据判断：** 区分生成解释与已验证知识；
- **授权：** 定义自治动作与需审批动作；
- **环境设计：** 构造反馈、实验和审查机制；
- **治理记忆：** 将重复判断保存为 GKO 与 GEO；
- **硬状态更新：** 确保人类回答和验证结果改变 agent 的被承认状态，而不只是留在对话上下文中。

## 10. 质量指标与风险边界

有用的协作指标包括：

- 最终任务价值；
- 升级精确率与召回率；
- 问题最小性与认知负担；
- 自治恢复率；
- 错误自治事件；
- 不必要升级；
- 回答解除阻塞率；
- GKO/GEO 的复用与撤销质量；
- 中断后的状态恢复与可复盘性。

外部承诺、披露、删除、支付、签署、发布等不可逆动作应默认升级。高错误成本领域需要更强验证。状态不确定时，应输出条件策略，而不是伪造确定性。

## 结论

治理式协作超越聊天式提示。AI 向前推进任务中可搜索、可结构化、可模拟和可验证的部分；人类注入那些必须由人治理的最小价值、授权、预算、品味、上下文或责任变量；系统再保存持久判断并恢复 AI 自治。

最短定义是：

> 高质量人机协作 = AI 自治推进 + 构造搜索与验证环境 + 注入最小人类变量 + 硬状态更新 + 治理记忆 + 恢复自治。
