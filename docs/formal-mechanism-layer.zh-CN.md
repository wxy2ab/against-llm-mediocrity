# LLM 失败的形式化机制层

## 从失配现象到可干预组件

**状态：** 工作稿  
**主文：** [大语言模型系统的知识治理](knowledge-governance-llm-systems-local-alignment.zh-CN.md)

## 摘要

本文提出一个用于诊断 LLM 系统失败的 **形式化机制层**。它不替代主文中的六类原始失配，也不试图给错误换一套更"数学"的名称。它回答的是更接近工程决策的问题：一次失败究竟应该改规格、补观测、修信念状态、接入真实环境反馈、扩展动作接口、补充能力支持、校准能力路由，还是扩大搜索？

我们把 LLM 系统视为部分可观测环境中的近似决策系统，并把可干预组件拆为八类：**规格 / 奖励、观测可得性、信念 / 表征、动态 / 世界模型、行动 / 接口、策略先验 / 能力支持、拟合边界 / 能力路由，以及搜索 / 执行**。这八类不是互斥的错误标签，而是一组可以通过干预实验区分的诊断轴。同一次失败可以由多个机制共同造成，也可能沿执行链条由上游失配诱发下游症状。

机制层的核心原则是：

> 现象层与原始失配层说明"失败呈现为什么样"；机制层说明"应当动哪个组件"。

---

## 1. 定位：机制层是什么，不是什么

### 1.1 它是干预定位层

面对"模型答错了"，继续追问"模型为什么不够聪明"通常没有足够的操作性。至少存在八种完全不同的修复方向：

1. 真实目标没有被正确表达或评估；
2. 做决定所需的信息没有进入系统；
3. 信息已经进入系统，但没有形成正确、稳定的任务状态；
4. 系统错误预测了行动在真实环境中的后果；
5. 正确行动不在系统可用接口中；
6. 模型的策略分布几乎不支持正确解法；
7. 能力存在，但在错误场景触发，或在正确场景欠触发；
8. 正确候选可达，但当前搜索与执行过程没有找到它。

这些原因的表面表现可能相似，修法却不同。机制层的用途，就是把失败定位到可以被改变、替换、扩展或验证的系统组件上。

### 1.2 它不是新的主分类

主文提出的聚合、支持、规格、状态、拟合边界与观测-表征六类原始失配，描述的是 **任务价值与系统可达生成之间的结构性错位**。机制层则沿着系统执行链拆分：目标如何进入系统，信息如何被观察和表示，后果如何被预测，动作如何被执行，能力如何被支持和路由，以及候选如何被搜索。

因此，两层不是一一对应关系：

- 一个原始失配可能由多个机制共同产生；
- 一个机制失配也可能制造多种表面现象；
- 原始失配适合解释"为什么这类任务容易失败"；
- 机制层适合决定"下一步先做什么实验、改什么组件"。

### 1.3 它不是互斥标签集

机制层应当被表示为一个 **失配画像**，而不是强迫每个案例只能归入一类。真实系统常见的是组合失配，例如：错误评测标准使路由器进入保守审计模式，保守路由又压窄候选搜索，最终表现为"模型没有找到策略"。表面上像搜索失败，根因却同时包括规格、路由与搜索。

诊断的目标不是找到唯一标签，而是识别：

- 哪些是上游根因；
- 哪些是下游症状；
- 哪个干预成本最低、信息增益最高；
- 修复一层后，剩余瓶颈会转移到哪里。

## 2. 统一形式化

### 2.1 真实任务环境

把任务环境写成一个部分可观测决策过程：

\[
\mathcal{E}=(\mathcal{S},\mathcal{A},\mathcal{T},R^*,\Omega,\mathcal{O},\gamma).
\]

其中：

| 符号 | 含义 |
|---|---|
| $\mathcal{S}$ | 真实状态空间，包括世界状态、用户真实意图、任务背景与交互状态 |
| $\mathcal{A}$ | 理论上可采取的动作，包括文本输出、工具调用、检索、代码执行、询问用户等 |
| $\mathcal{T}(s'\mid s,a)$ | 真实状态转移：采取动作后环境如何变化 |
| $R^*(s,a,s')$ | 真实任务奖励，即人类最终关心的成功标准 |
| $\Omega$ | 系统可能接收的观测空间 |
| $\mathcal{O}(o\mid s)$ | 观测函数：真实状态如何映射为文本、图像、文件、日志或工具返回 |
| $\gamma$ | 对延迟回报的折扣或长程权重 |

对于有限时域任务，真实目标不是单个 token 的局部似然，而是最大化整条轨迹的期望价值：

\[
\tau^*=\arg\max_{\tau=(s_0,a_0,\ldots,s_H)}
\mathbb{E}\left[\sum_{t=0}^{H-1}\gamma^t R^*(s_t,a_t,s_{t+1})\right].
\]

纯文本一次性任务可以看作这个表达的退化情形：轨迹的主要动作是生成输出序列 $y$，目标简化为

\[
y^*=\arg\max_y V^*(y\mid x).
\]

### 2.2 LLM 系统实际使用的近似

部署中的 LLM 系统并不直接拥有真实环境，而是依靠一组近似组件：

\[
\mathcal{M}_\theta=
\left(
B_\theta,
\hat{\mathcal{T}}_\theta,
\hat{R}_\theta,
\pi_\theta,
r_\theta,
D,
\mathcal{A}_{\mathrm{sys}}
\right).
\]

| 组件 | 含义 |
|---|---|
| $B_\theta$ | 信念 / 状态估计器：如何从观测历史形成内部任务状态 |
| $\hat{\mathcal{T}}_\theta$ | 世界模型：如何预测行动的后果 |
| $\hat{R}_\theta$ | 内部价值判断或代理目标 |
| $\pi_\theta$ | 学得策略与 token 先验：哪些候选更容易被生成 |
| $r_\theta$ | 能力 / 模式路由器：何时激活何种知识、技能、角色或审计模式 |
| $D$ | 解码、规划、搜索、验证与执行算法 |
| $\mathcal{A}_{\mathrm{sys}}$ | 系统实际上允许调用的动作与接口集合 |

系统还会受到外部规格与评估器影响。令 $R_{\mathrm{proxy}}$ 表示训练或产品流程中的代理奖励，$R_{\mathrm{eval}}$ 表示部署时使用的评测规则。一次失败可以理解为：真实任务所需对象与上述一个或多个近似组件之间发生了具有因果作用的失配。

### 2.3 机制失配画像

令八个分量分别表示八类机制失配的严重度：

\[
\mathbf{m}=
(m_{\mathrm{spec}},m_{\mathrm{obs}},m_{\mathrm{belief}},m_{\mathrm{dyn}},
m_{\mathrm{act}},m_{\mathrm{support}},m_{\mathrm{route}},m_{\mathrm{search}}).
\]

这个向量不是要求一次性精确估计的分数，而是一种诊断记录。实际工作中，可以通过干预前后的性能变化来近似每个分量：如果只改变某个组件就显著改善结果，那么该组件更可能是因果瓶颈。

## 3. 八类机制失配

### 3.1 规格 / 奖励失配

#### 定义

真实任务奖励 $R^*$、训练代理奖励 $R_{\mathrm{proxy}}$、模型内部价值 $\hat{R}_\theta$ 与评测规则 $R_{\mathrm{eval}}$ 之间不一致：

\[
\arg\max_y R_{\mathrm{proxy}}(y)
\ne
\arg\max_y R^*(y),
\]

或评估器选择的候选不是用户真实目标下的最优候选：

\[
\arg\max_y R_{\mathrm{eval}}(y)
\ne
\arg\max_y R^*(y).
\]

#### 核心问题

系统正在优化、审计或汇报错误的目标。

#### 常见表现

- 用户需要可部署策略，系统却只优化基准超额或单一离线指标；
- 用户需要简洁脚本，系统却把工程完整性误当成首要目标；
- reward model 偏好的答案语言稳健，但不等于事实正确或任务成功；
- 代理指标逐渐取代真实目标，产生 Goodhart 式偏移；
- 生成器与评估器共享同一错误假设，使错误候选被稳定选中。

#### 诊断实验

固定数据、工具、模型与搜索预算，只改成功标准、评分规约或候选排序规则。如果结果明显改变，优先判断为规格 / 奖励失配。

#### 典型干预

- 重写任务目标与不可妥协约束；
- 区分 true objective、proxy metric 与 reporting metric；
- 修改 rubric、reward model 或验收测试；
- 加入人类偏好与领域专家审计；
- 用多目标、约束优化或分层验收代替单指标最大化。

#### 边界

如果目标已经清楚，但模型漏读了目标，属于信念 / 表征问题；如果目标被正确理解，但当前策略几乎生成不出合格候选，属于能力支持问题。

### 3.2 观测可得性失配

#### 定义

选择正确动作所需的信息没有进入系统可观测空间。这里不要求恢复完整真实状态，只要求观测包含决策所需的充分统计量。

如果存在两个状态 $s_1,s_2$，它们在当前观测机制下不可区分：

\[
\mathcal{O}(\cdot\mid s_1)=\mathcal{O}(\cdot\mid s_2),
\]

但最优动作不同：

\[
a^*(s_1)\ne a^*(s_2),
\]

那么系统仅凭当前观测无法可靠求解。

#### 核心问题

必要信息没有被看见。

#### 常见表现

- 用户没有提供关键约束，且系统无法询问；
- 最新事实、依赖版本、文件或数据库记录不可得；
- 交易成本、滑点、盘口、容量或制度约束缺失；
- 用户脑中的默认场景没有外化；
- 系统只能看到摘要，无法访问决定结论的原始证据。

#### 诊断实验

补充上下文、检索资料、上传文件、连接数据库或提出最小澄清问题。如果在不改变推理方法的情况下结果显著改善，说明观测可得性是主要瓶颈。

#### 典型干预

- RAG、浏览器、数据库与长期记忆；
- 文件、日志、监控与传感器接入；
- 最小充分澄清问题；
- 明确记录数据时点、版本、覆盖范围与缺失字段；
- 把不可观测变量转化为可测代理或显式假设。

#### 边界

"上下文中没有"属于观测失配；"上下文中有，但模型没有正确使用"属于信念 / 表征失配。增加更多无关上下文可能反而加重后者。

### 3.3 信念 / 表征失配

#### 定义

必要信息已经存在于观测历史中，但系统没有正确解析、绑定、压缩、保持或调用它。令理想信念状态为 $B^*$，则

\[
B_\theta(s_t\mid o_{\le t})
\ne
B^*(s_t\mid o_{\le t}).
\]

这里的"信念"不是要求模型显式输出概率分布，而是指所有会影响后续决策的内部任务状态。

#### 核心问题

信息看见了，但没有变成正确、稳定、可执行的状态表示。

#### 常见表现

- 长上下文中遗忘早先约束；
- 用户明确排除某方案，系统后续仍然使用；
- 文件中存在答案，但系统漏掉关键段落或错误绑定实体；
- 多个条件、角色、日期或单位之间发生错绑；
- 多轮任务状态漂移，已完成事项被重新执行；
- 系统把假设、事实、推断与决策混在同一段自然语言里。

#### 诊断实验

要求系统先抽取约束、列出已知与未知、建立状态表或结构化中间表示，再执行原任务。如果结果改善，而没有增加新事实，则偏向信念 / 表征失配。

#### 典型干预

- constraint extraction 与 schema 化输入；
- 外部 task state、memory 与 provenance tracker；
- 分块阅读、实体绑定与时间线维护；
- 明确区分事实、假设、推断、决策和未决问题；
- 在关键步骤前重新读取来源，而不是依赖压缩后的语言记忆。

#### 边界

如果状态表示正确，但系统仍错误预测"执行后会发生什么"，问题转向动态 / 世界模型。若只是生成阶段没有保持全局结构，也可能同时涉及聚合或搜索失配。

### 3.4 动态 / 世界模型失配

#### 定义

系统对行动后果的预测与真实状态转移不一致：

\[
\hat{\mathcal{T}}_\theta(s_{t+1}\mid s_t,a_t)
\ne
\mathcal{T}(s_{t+1}\mid s_t,a_t).
\]

#### 核心问题

系统误判了行动在真实环境中的后果。

#### 常见表现

- 生成的代码或 SQL 在真实运行时失败；
- 系统臆造不存在的 API、参数、权限或产品行为；
- 多步计划低估早期错误对后续步骤的传播；
- 系统仅凭语言先验猜测用户、市场、编译器或浏览器反馈；
- 离线模拟结论与部署后的真实反馈系统性偏离。

#### 诊断实验

要求系统先预测结果，再调用真实环境执行并比较预测误差。如果真实反馈反复推翻内部预测，主要瓶颈是世界模型，而不是文本表达。

#### 典型干预

- 运行代码、查询真实数据库与调用真实 API；
- 单元测试、集成测试、回测、沙盒与仿真器；
- 预测—执行—比较—修正循环；
- 将环境反馈写回状态，而不是只报告工具输出；
- 对关键动态建立校准集和误差边界。

#### 边界

有工具但预测错，是世界模型问题；没有工具或权限去获得反馈，是行动 / 接口问题。两者经常同时存在，但修复顺序不同。

### 3.5 行动 / 接口失配

#### 定义

完成任务所需的动作不在系统实际可用动作空间中：

\[
a^*\notin\mathcal{A}_{\mathrm{sys}}.
\]

动作"名义上存在但因权限、schema、延迟、可靠性或流程约束而不可调用"，也属于有效动作空间不足。

#### 核心问题

正确动作不可用，而不仅是模型没有想到。

#### 常见表现

- 任务需要浏览、执行代码、查询数据库或修改文件，但系统只能输出文本；
- 系统需要询问用户，却被强制一次性回答；
- 工具存在，但参数 schema 无法表达所需操作；
- 权限、网络、速率限制或不可逆操作门槛阻断执行；
- 系统可以提出建议，却无法验证、落地或观察结果。

#### 诊断实验

向系统开放最小必要工具、权限或交互回合，并保持模型和提示不变。如果任务从"猜测"转为可验证执行，说明动作空间是关键瓶颈。

#### 典型干预

- 增加工具、API、执行器与文件读写能力；
- 改进 action schema 与错误返回；
- 设计可恢复、可回滚的 agent workflow；
- 允许系统提出澄清、请求授权和等待异步结果；
- 把不可逆动作置于显式治理门槛之后。

#### 边界

行动 / 接口失配不等于"工具越多越好"。工具只有在可被正确观察、选择、调用和验证时才扩展有效动作空间，否则还会引入新的路由与搜索负担。

### 3.6 策略先验 / 能力支持失配

#### 定义

正确知识、算子、推理模式或候选结构在模型策略的有效支持中概率过低：

\[
\pi_\theta(y^*\mid o)\approx 0,
\]

或在现实预算 $B$ 下，正确候选几乎不可达：

\[
y^*\notin \operatorname{EffectiveSupport}_B(\pi_\theta).
\]

#### 核心问题

系统不是没有看到信息，而是没有学到足够的知识、算子或解法先验。

#### 常见表现

- 长尾领域、冷门技术栈、稀有市场机制或新兴研究方向持续答错；
- 给足上下文和清晰规格后，系统仍生成不出正确类型的候选；
- 多次采样只是产生相似错误，而不是覆盖新的高价值结构；
- 系统会复述领域材料，却不会执行领域特有的审计或构造过程；
- 正确解法需要模型从未学会的程序、证明策略或专业工作流。

#### 诊断实验

在规格、观测、状态与工具都充分的条件下进行多次采样；再加入范例、领域检索、专家模型或程序化算子。如果只有后一组干预有效，说明能力支持不足。

#### 典型干预

- few-shot 范例、领域 RAG 与结构化知识库；
- SFT、finetune、课程数据与边界案例训练；
- 专家模型、程序化生成器与领域工具；
- 把复杂能力拆成可监督、可验证的子能力；
- 用真实任务分布评估支持，而不是只看通用 benchmark。

#### 边界

观测失配是"当前任务缺信息"，能力支持失配是"即使给了信息，模型仍缺解法先验"。如果多次采样中偶尔能稳定出现正确候选，则更偏向搜索，而非支持。

### 3.7 拟合边界 / 能力路由失配

#### 定义

模型已经学到某种能力、策略、审计结构或行为模式 $X$，但它实际触发 $X$ 的区域 $M_X$ 与真实适用区域 $T_X$ 不一致：

\[
M_X\ne T_X.
\]

两个方向分别是：

\[
M_X\setminus T_X \quad \text{（过触发）},
\]

\[
T_X\setminus M_X \quad \text{（欠触发）}.
\]

#### 核心问题

能力会了，但路由错了。

#### 常见表现

- 把探索任务错误路由为风控或拒答任务；
- 把事件策略当成传统因子策略审计；
- 把简单脚本任务升级成大型系统工程；
- 应当搜索候选时过早进入"证据不足 / No-Go"模式；
- 应当严格审计时却进入顺从用户前提的续写模式；
- 正确能力在其他提示或角色下可出现，但当前上下文没有触发。

#### 诊断实验

不增加新事实、不改变可用工具，只改变任务模式、角色、正反例、路由规则或生成器—验证器分工。如果正确能力随之出现，说明问题主要在路由，而不是能力缺失。

#### 典型干预

- 显式 skill router、mode switch 与阶段状态机；
- 为"何时探索、何时审计、何时拒答"提供正反例；
- 拆分 generator、verifier、executor 与 governor；
- 对能力边界做邻域扰动测试和混淆矩阵评估；
- 训练过触发、欠触发和相邻任务的边界案例；
- 让路由决定可解释、可覆盖、可撤销。

#### 边界

能力支持失配是正确能力基本不在有效支持内；路由失配要求能力已经存在或近似存在，只是没有在正确区域触发。完整展开见 [拟合边界失配](fitting-boundary-mismatch.zh-CN.md)。

### 3.8 搜索 / 执行失配

#### 定义

真实目标、观测、信念状态、世界模型、动作空间、能力支持与能力路由已经足够接近正确，但当前搜索与执行算法 $D$ 没有找到或保持好候选：

\[
y^*\in \operatorname{EffectiveSupport}_B(\pi_\theta),
\qquad
D(\pi_\theta,B)\ne y^*.
\]

#### 核心问题

正确路径可达，但没有被搜出、选中、保持或执行到底。

#### 常见表现

- greedy decoding 被早期 token 锁定；
- 单次回答平庸，但 best-of-$N$ 中存在高质量答案；
- 局部步骤合理，整体结构却因路径依赖而崩坏；
- 初始计划错误后，后续步骤持续为其自洽化；
- 候选已经生成，但排序器、verifier 或执行器选错；
- 搜索覆盖了单变量变化，却没有覆盖关键组合。

#### 诊断实验

不补数据、不改规格、不增加新能力，只增加采样、回溯、候选比较、分支搜索或独立验证器。如果结果显著改善，偏向搜索 / 执行失配。

#### 典型干预

- best-of-$N$、self-consistency 与 beam search；
- plan-then-execute、generate-then-rank 与回溯；
- tree search、MCTS 与受约束组合搜索；
- 独立 critic / verifier 与多模型交叉评审；
- 保存中间状态、失败分支与可恢复检查点；
- 将搜索预算分配给高不确定性、高价值分支。

#### 边界

扩大搜索只有在正确候选已经位于有效支持内、评估器能够辨认它、执行环境能够验证它时才有效。否则，更大搜索只是更充分地探索错误空间。

## 4. 八层总表

| 层级 | 机制失配 | 形式化对象 | 核心诊断 | 首选干预 |
|---:|---|---|---|---|
| 1 | 规格 / 奖励 | $R^*,R_{\mathrm{proxy}},\hat R_\theta,R_{\mathrm{eval}}$ | 是否优化了错误目标？ | 改目标、rubric、reward、验收标准 |
| 2 | 观测可得性 | $\Omega,\mathcal O$ | 决策所需信息是否进入系统？ | 检索、接数据、上传文件、澄清 |
| 3 | 信念 / 表征 | $B_\theta$ | 已有信息是否形成正确任务状态？ | 状态抽取、结构化表示、外部记忆 |
| 4 | 动态 / 世界模型 | $\hat{\mathcal T}_\theta$ | 是否误判行动后果？ | 真实执行、测试、回测、反馈校准 |
| 5 | 行动 / 接口 | $\mathcal A_{\mathrm{sys}}$ | 正确动作是否可调用？ | 工具、API、权限、交互工作流 |
| 6 | 策略先验 / 能力支持 | $\pi_\theta$ | 正确解法是否在有效支持内？ | 范例、训练、RAG、专家模型、程序 |
| 7 | 拟合边界 / 能力路由 | $r_\theta,M_X,T_X$ | 能力是否在正确场景触发？ | 路由、模式控制、边界训练、角色拆分 |
| 8 | 搜索 / 执行 | $D(\pi_\theta,B)$ | 可达候选是否被找到并执行？ | 多采样、回溯、树搜索、验证器 |

## 5. 诊断协议

### 5.1 先固定失败实例

诊断前，应记录同一个可复现任务实例：输入、可用工具、模型版本、提示、随机性、预算、实际输出与验收标准。否则，不同干预之间的差异可能只是任务漂移。

### 5.2 按依赖顺序排查

建议按以下顺序提问：

1. **目标是否正确？** 如果评估标准本身错了，后续优化只会更稳定地做错事。
2. **必要信息是否可见？** 不可观测的问题不应靠语言猜测解决。
3. **可见信息是否被正确表示？** 先确认约束、实体、时间与状态没有丢失或错绑。
4. **行动后果是否被真实验证？** 对代码、市场、工具和用户反应的猜测应尽早接入反馈。
5. **正确动作是否可用？** 没有执行接口时，能力与搜索都无法转化为环境改变。
6. **正确能力是否在有效支持内？** 给足信息与预算后仍生成不出，才考虑补能力。
7. **能力是否被正确路由？** 用模式切换和边界探针区分"不会"与"没调用"。
8. **是否只是没有搜到或执行到底？** 在前七项基本成立后，再扩大搜索最有意义。

这个顺序不是严格流水线。实际诊断可以并行做低成本探针，但不应在上游条件尚未成立时，直接把全部预算投入下游搜索。

### 5.3 用最小干预做因果区分

每次只改变一个主要组件，并观察结果变化：

- 只改 rubric；
- 只补一项关键信息；
- 只增加结构化状态抽取；
- 只接入一次真实执行反馈；
- 只开放一个关键工具；
- 只提供领域范例；
- 只切换任务模式；
- 只增加搜索预算。

如果多项同时改变，虽然可能修好任务，却难以知道真正瓶颈在哪里，也难以复用修复知识。

### 5.4 记录主因、次因与证据

建议用以下格式保存诊断：

```text
失败实例：
真实成功标准：
主要失配：
次要失配：
支持证据：
最小干预：
干预结果：
剩余瓶颈：
可复用控制知识：
```

当证据不足时，应记录"未区分"，而不是强行归类。例如，单次采样失败不能区分能力支持与搜索失配；需要多采样、范例注入或专家工具等对照实验。

## 6. 容易混淆的边界

### 6.1 观测可得性 vs. 信念 / 表征

| 问题 | 观测可得性失配 | 信念 / 表征失配 |
|---|---|---|
| 必要信息是否进入上下文或工具返回？ | 否 | 是 |
| 主要故障 | 看不见 | 看见但没有正确使用 |
| 典型修复 | 补数据、检索、澄清 | 状态抽取、绑定、记忆、结构化 |

### 6.2 世界模型 vs. 行动 / 接口

| 问题 | 世界模型失配 | 行动 / 接口失配 |
|---|---|---|
| 真实反馈通道是否可用？ | 通常可用，但预测与反馈不一致 | 不可用或不可有效调用 |
| 主要故障 | 后果预测错 | 正确动作做不了 |
| 典型修复 | 执行与校准 | 增加工具、权限、schema |

### 6.3 能力支持 vs. 能力路由 vs. 搜索

| 问题 | 能力支持失配 | 能力路由失配 | 搜索 / 执行失配 |
|---|---|---|---|
| 正确能力或候选是否存在？ | 基本不在有效支持内 | 存在，但触发边界错 | 存在且已被正确激活 |
| 关键证据 | 多采样仍无正确候选；范例或训练有效 | 不加新知识，只换模式就改善 | 只扩大采样、回溯或排序就改善 |
| 主要修复 | 补能力 | 改触发条件 | 扩搜索并改执行控制 |

### 6.4 规格 vs. 评估器搜索错误

如果评估器稳定偏好错误目标，属于规格 / 奖励失配；如果评估标准正确，但在有限候选上发生噪声性误选，更接近搜索 / 执行失配。生成器和评估器共享同一模型时，两种问题尤其容易混在一起。

## 7. 与六类原始失配的关系

机制层不是六类原始失配的替代表。较稳妥的交叉映射如下：

| 六类原始失配 | 常见机制来源 | 说明 |
|---|---|---|
| 聚合失配 | 信念 / 表征、能力支持、能力路由、搜索 / 执行 | 全局约束无法由局部续写恢复时，可能需要外部状态、专门算子或结构化搜索 |
| 支持失配 | 观测可得性、能力支持、行动 / 接口、搜索 / 执行 | 高价值结构不可达，既可能因信息、能力或动作缺失，也可能因预算内搜索覆盖不足 |
| 规格失配 | 规格 / 奖励、信念 / 表征 | 目标本身可能错误，也可能已写明但被系统误读或遗忘 |
| 状态失配 | 观测可得性、信念 / 表征、动态 / 世界模型 | 状态可能不可观测、不可稳定估计，或其转移被错误建模 |
| 拟合边界失配 | 能力路由、能力支持、搜索 / 执行 | 核心机制是路由边界错位，也可能被低支持与路径锁定放大 |
| 观测-表征失配 | 观测可得性、信念 / 表征、行动 / 接口 | 决定性变量可能没有进入观测，也可能进入后没有形成可操作表征；有时需要新工具、传感器、日志、测试或原始数据接口 |

因此：

> 六类原始失配是任务—价值结构的诊断轴；八类机制失配是系统—干预结构的诊断轴。

两层同时使用时，诊断会更完整。例如，"状态失配"说明任务依赖一个未被稳定识别的潜在状态；机制层进一步区分：它究竟没有被观察、没有被正确表示，还是状态转移被世界模型误判。"观测-表征失配"则进一步要求区分：决定性变量是没有进入观测空间，还是进入后没有被编码成可操作控制变量。

## 8. 复合失配与因果链

### 8.1 为什么常常不是单一一层

八个组件存在依赖关系：规格影响观测选择与评估，观测影响信念状态，信念状态影响路由与世界模型调用，动作接口决定能否取得反馈，策略支持与路由共同决定搜索空间，搜索结果又由评估器选择。

一个常见因果链是：

```text
错误规格
→ 选择了错误证据与评测指标
→ 激活错误能力模式
→ 压窄候选空间
→ 搜索稳定收敛到错误答案
```

另一个常见因果链是：

```text
关键状态不可观测
→ 模型用默认先验填补
→ 世界模型预测偏差
→ 工具调用计划错误
→ 执行失败被误判为能力不足
```

### 8.2 主因与放大器

诊断时可以区分：

- **主因**：移除后，失败不再稳定发生；
- **必要条件**：没有它就无法成功，但它未必制造了当前错误；
- **放大器**：使错误更稳定、更难被搜索或反馈纠正；
- **下游症状**：由上游失配诱发，不应被当成唯一根因。

例如搜索窄可能是真实瓶颈，也可能只是错误路由的下游症状。只有在保持路由不变、单独扩大搜索并得到改善时，才有理由把搜索列为主要机制。

## 9. 金融事件策略案例

以"涨停 / 兴奋度事件策略"的失败分析为例，系统可能过早判断策略不可部署，并要求增加所谓正交数据。机制画像可以拆成：

| 机制层 | 案例表现 |
|---|---|
| 规格 / 奖励 | 用 benchmark-excess 代替 long-only event strategy 的真实部署目标 |
| 观测可得性 | 若缺少日内、主题、板块、盘口与交易成本数据，会限制后续识别 |
| 信念 / 表征 | 没有把"事件后关注度延续"表示为可追踪状态 |
| 动态 / 世界模型 | 错估次日可买性与多日 continuation |
| 行动 / 接口 | 没有回测器或 operator generator，只能进行语言判断 |
| 能力支持 | 候选算子族贫乏，缺少事件结构与条件 alpha 的构造先验 |
| 能力路由 | 错误进入"数据不足 / 防过拟合 / No-Go"模式 |
| 搜索 / 执行 | 只尝试少数流动性与连板变量，没有覆盖关键过滤组合 |

这个案例的主要问题不是单一的"搜索不够"，而是 **错规格 + 错动态 + 错路由 + 窄搜索**。因此，更合理的干预顺序是：

1. 把真实目标改为可买的次日开盘、绝对净收益、多日延续、成本、滑点与容量审计；
2. 用真实数据验证可买性和持有期假设；
3. 显式进入"机制转算子"模式，扩展 operator family；
4. 在修正后的审计标准下执行组合搜索；
5. 最后再判断新增数据是否提供不可替代的信息增益。

这个顺序避免了一个常见错误：把所有失败都解释成"数据不够"，从而在错误目标和错误模式下继续增加数据。

## 10. 使用原则与限制

### 10.1 机制名称不是证据

把失败称为"路由失配"并不能证明路由有问题。每个判断都应附带可复现案例、对照干预与结果变化。没有干预证据时，分类只是假设。

### 10.2 同一干预可能作用于多层

RAG 既可能补观测，也可能通过范例补能力支持；工具执行既扩展动作空间，也校准世界模型；结构化提示既可能修信念状态，也可能改变能力路由。因此，评估干预时应说明它预期改变哪个中间变量，而不仅是记录最终分数。

### 10.3 更大模型不是统一修复

扩大模型可能改善能力支持、表征与世界模型，但不会自动修复错误规格、不可观测状态、缺失权限或不恰当评估器。它也可能强化错误路由，使失败更流畅、更稳定。

### 10.4 更大搜索不是默认答案

当目标、评估器或世界模型错误时，更多搜索会更充分地优化错误对象；当动作空间缺失时，搜索无法创造不存在的接口；当能力不在有效支持内时，多采样只会重复低价值变体。

### 10.5 机制层应进入治理循环

一次成功修复不应只停留在提示词技巧。应把以下内容保存为可审计、可撤销的治理对象：

- 触发该诊断的失败模式；
- 适用边界与反例；
- 最小干预及其证据；
- 依赖的数据、工具、模型与版本；
- 失效条件与复查日期；
- 修复后暴露出的下一层瓶颈。

这样，机制层才不只是一次性解释，而能成为系统持续改进的控制语言。

## 11. 最终压缩版

形式化机制层把 LLM 任务视为部分可观测环境中的近似决策过程。它不按表面现象给失败重新命名，而是把失败定位到八类可干预组件：**规格 / 奖励、观测可得性、信念 / 表征、动态 / 世界模型、行动 / 接口、策略先验 / 能力支持、拟合边界 / 能力路由，以及搜索 / 执行**。它与六类原始失配构成交叉诊断：原始失配解释任务价值与可达生成为什么分离，机制层决定应当改目标、补信息、维护状态、接真实反馈、扩动作、补能力、改路由，还是扩大搜索。

最短地说：

> 原始失配层用于解释结构，机制层用于选择手术刀。
