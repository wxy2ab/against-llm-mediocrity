## 摘要

Agent 工程正在从 Prompt 技巧转向完整运行时系统的设计：模型、上下文构造器、工具、记忆、路由器、规划器、验证器、状态存储、提交协议和恢复回路共同决定系统表现。然而，研究界仍常把这些系统当成不可分割的产品来评价：一次新 Agent 发布同时更换模型、Prompt、工具接口、重试预算、验证器和 Benchmark Harness，随后把端到端分数的变化当成改进来源已经被识别。

这种证据足以支撑排行榜，却不足以支撑一门可累积的工程科学。

前沿工作已经开始纠正这一失衡。Agent-computer interface、可复现 Agent 评价、Harness 纵向演化、统一评价框架、全因子实验和多次生成统计都指向同一结论：一个 Agent 分数是模型、Harness、环境、预算和评价器的联合属性。固定模型研究表明，仅改变 Scaffold 就能显著改变质量；跨模型研究表明，Harness 敏感性与模型能力并不是简单单调关系；一线工程报告也越来越把可观测性、持久状态、可验证结果和机械约束视为一等基础设施。

但这些前沿观点仍有局限。证明“Harness 很重要”并没有识别究竟修复了哪一种结构失败、通过什么因果通道起效、在哪些条件下起效，以及换模型后什么可以迁移。本文提出一个更严格、可证伪的地基：把观测—表征、状态、拟合边界、支持、聚合和规格失配视为任务价值从世界进入 Agent 并最终被验证提交时六种候选结构损失方式。结构持续假设预测：模型升级可以降低它们的频率并移动边界，却不能在开放任务、有限资源和不完备接口下统一消灭这些结构维度。

因此，受控实验应成为 Agent 工程的中心方法。它不是为了冻结某代模型的行为，而是为了识别能跨代复验的结构条件、因果机制、交互作用和启用边界。模型升级移动边界；受控实验测量边界上的治理规律。

## 1. 方法论问题是混杂，不是 Benchmark 不够多

设 Agent 系统的期望价值为：

\[
J(\theta,H,E,D,b,V),
\]

其中：

- \(\theta\)：模型与推理策略；
- \(H\)：运行时 Harness；
- \(E\)：环境与工具表面；
- \(D\)：任务分布；
- \(b\)：token、时间、调用、金钱和风险预算；
- \(V\)：评价器或 Oracle。

大多数公开比较一次改变多个变量。新 Agent 可能同时使用更强模型、更长上下文、不同系统 Prompt、新工具、更大重试预算、不同截断规则、更宽松的验证器和更新后的任务集。此时观察到的：

\[
J(\theta_2,H_2,E_2,D_2,b_2,V_2)
-
J(\theta_1,H_1,E_1,D_1,b_1,V_1)
\]

是有效的产品比较，却不是已经识别的机制效应。

产品优化与科学积累问的是两类不同问题：

```text
产品问题：
今天应该部署哪个完整系统？

科学问题：
在条件 C 下，干预 G 是否通过机制 M 改变结果 Y，
代价是多少，与哪些变量发生交互？
```

端到端评价仍然必要，因为用户使用的是完整系统，而不是消融表格。但端到端评价是证据链的最后一层，不能替代下面的因果层。如果没有受控对照，这个领域只会不断发现新配方，却无法解释它们为什么有效、何时失效，以及模型升级后什么知识应当保留。

本文所说的**受控实验**，是指预先规定一个运行时或环境变量的操纵，设置条件匹配的对照组，使用权威终点，并明确证伪条件。可行时应随机化，但成对确定性探针、分块离线试验和全因子机制研究同样属于受控实验；它不意味着所有有价值的问题都必须被压成生产在线 A/B 测试。

## 2. 前沿正在从模型分数转向系统证据

多条研究路线已经开始汇聚到联合系统视角。

| 研究路线 | 已经建立的认识 | 仍未建立的认识 |
|---|---|---|
| [METR 的 Time Horizon 研究](https://metr.org/time-horizons/) | 前沿 Agent 能可靠完成的人类等效任务时长快速增长，能力边界持续移动。 | 增益究竟来自模型、固定评价 Scaffold、任务构成还是交互；也没有证明运行时治理会失去必要性。 |
| [SWE-agent](https://arxiv.org/abs/2405.15793) | Agent-computer interface 的设计会显著影响模型导航、编辑和测试软件的能力。 | 软件工程之外的通用接口因果分类。 |
| [AI Agents That Matter](https://arxiv.org/abs/2407.01502) | 只看准确率会混淆开发者需求、成本、过拟合和可复现性。 | 运行时干预的机制级分解。 |
| [OpenAI Harness Engineering](https://openai.com/index/harness-engineering/) | 可读环境、反馈回路、机械约束、仓库内知识和可观测性可以在真实工程中产生复利。 | 随机化对照；这是高价值现场证据，不是因果识别。 |
| [Anthropic Agent Evals 指南](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents) | 评价单位是模型—Harness 联合系统；试验需要隔离环境、多次尝试、轨迹与结果状态评价器。 | 哪一种 Harness 机制普遍有效。 |
| [From Model Scaling to System Scaling](https://arxiv.org/abs/2605.26112) | 上下文、记忆、路由、编排、验证和治理应成为一等设计与评价对象。 | 强跨领域因果证据；主要贡献仍是研究议程和参考架构。 |
| [统一 LLM Agent 能力评价框架](https://arxiv.org/abs/2605.27898) | 大规模 rollout 显示，Scaffold 选择和环境波动能双向改变 Benchmark 结果。 | 所选统一 ReAct Scaffold 与任务适配本身带来的偏差尚未完全分离。 |
| [Agent Harness Evolution Shapes Coding Agent Quality](https://arxiv.org/abs/2607.03691) | 在 35 个连续 Harness 版本间固定模型，能观察到明显质量波动，并把变化关联到具体组件。 | 一个 CLI、一个编码领域和 50 个分层任务之外的外部有效性。 |
| [Harness Sensitivity Is Non-Monotone](https://arxiv.org/abs/2605.26731) | 432 次受控运行否定了“模型越强越不需要结构”的简单单调论。 | 模型能力层级规律；每个层级只测了一个模型，Benchmark 规模小且为合成任务。 |
| [Agentic Harness Engineering](https://arxiv.org/abs/2604.25850) | 可观测、可回滚的 Harness 演化能改善编码表现；工具、中间件和长期记忆比 Prompt 修改表现出更好的跨模型迁移。 | 自动演化找到的是普遍机制，还是受 Benchmark 与优化器条件限制的改进。 |
| [CAFE](https://arxiv.org/abs/2607.10380) | 全因子设计与混合效应模型可以把复合 AI 系统的方差归因到组件及其交互。 | RAG 演示之外的通用性，以及模型评价器的有效性边界。 |
| [Beyond the Singular](https://aclanthology.org/2026.findings-acl.488/) | 多次生成与分层建模能暴露单次 Benchmark 分数掩盖的采样方差。 | 长 Agent 轨迹中特有的环境、工具和状态相关性。 |

这场变化最重要的是认识论转向。行业正在逐步接受四个命题：

1. “Agent”是复合系统，不是模型加一个长 Prompt；
2. 最终成功由模型、Harness、环境、预算和 Oracle 联合产生；
3. 轨迹和最终环境状态包含单一分数丢弃的信息；
4. 随机系统必须进行重复试验、不确定性估计和匹配条件比较。

这些命题为受控实验打开了入口，但还没有完成受控实验的方法论。

## 3. 为什么前沿观点仍不足以构成可累积科学

### 3.1 “Harness 有用”是方向，不是因果解释

如果加入记忆后成功率提高，至少还有五种解释：缺失观测被补全；潜在状态被更准确表示；正确能力更常被路由；稀有高价值结构获得更多支持；或者局部正确片段被更一致地聚合。“记忆有用”只命名了组件，并没有识别被修复的失败。

组件名在不同实现间很不稳定。一个系统的“记忆”，可能是另一个系统的状态存储、检索层、Prompt 压缩器或审计日志。机制名更可迁移：观测覆盖、状态权威、路由校准、支持覆盖、组合完整性和目标保真度。

### 3.2 消融不自动等于受控实验

删除一个组件可能同时改变 token 数、延迟、可用动作、Prompt 长度、模型注意力、重试机会和验证器行为。消融效应可以真实存在，因果通道却仍然模糊。有效对照必须有清晰的 treatment contract：固定什么、操纵什么、预期哪个中介变量变化、哪个终点具有权威，以及什么结果会证伪机制主张。

### 3.3 Benchmark 经常把能力与机会混为一谈

模型无法使用从未观察到的信息，无法提交环境没有暴露的状态转移，也无法满足评价器错误表达的目标。但这些低分经常被记作“模型失败”。反过来，宽松评分器、泄露状态、共享缓存或针对 Benchmark 的 Scaffold 又可能制造虚假成功。最终测到的是“机会 + 能力”，却被报告成了纯能力。

### 3.4 模型—Harness 交互会击穿单调配方

Harness 敏感性的非单调结果不是噪声，而是在警告我们不要只看主效应。严格 Scaffold 可能帮助一个推理模型，同时伤害一个前沿聊天模型。可信的工程规律必须是条件性的：

```text
不是：机制 G 更好

而是：当失配剂量 C 足够高、
      模型族 θ 能利用 G、
      且额外开销没有超过预算 b 时，
      G 才更好。
```

### 3.5 终点准确率掩盖权威与失败类型

Agent 可以声称任务完成，而数据库、代码仓库、日历或支付系统没有任何变化；也可能通过不安全、不可恢复的轨迹得到正确答案。只评价最终文本，会把声称状态、验证状态和提交状态压成一个对象。除了任务成功，Agent 工程还需要结果状态 Oracle、转移合法性、回滚证据、成本和尾部风险指标。

### 3.6 模型评价器容易形成自指闭环

如果模型在相近 Prompt 或同族模型下同时负责生成、批评和评分，共享盲点可能伪装成一致性。模型评价器很有用，但必须用人类或可执行权威校准其误差。对一个未经验证的 Judge 算出统计显著性，并不能修复评价指标自身的规格失配。

### 3.7 平均效应不是部署规则

正平均处理效应可能掩盖 crossover：Patch 可能在稀疏修改中占优，在稠密修改中失败；Audit 可能帮助难题，却在简单任务上浪费预算；额外观测可能在一种状态下消除不确定性，在另一种状态下制造干扰。Agent 工程需要剂量—响应曲线、交互项和启用策略，而不只是一个平均百分点。

### 3.8 2026 年证据仍然年轻且集中在少数领域

多项最相关工作还是近期预印本，许多受控证据来自编码 Agent、合成任务或 RAG。它们给出了改变方法的充分理由，却没有授权我们宣布普适定律。正确回应应当是在更严格合同下复验，而不是否定这些证据，也不是过早把它们经典化。

## 4. 更深层冲突：训练吸收假设与结构持续假设

Agent 研究中常见的隐含先验可以写成**训练吸收假设**：

\[
H_{\mathrm{absorb}}:
\forall g,\;\exists \theta'\text{ sufficiently capable such that }
J(\theta',h_0;D,b)\approx J(\theta,g;D,b).
\]

其中 \(g\) 是治理或 Harness 机制，\(h_0\) 是最小运行时。这个假设认为：足够强的未来模型最终能在最小运行时中复制今天较弱模型从 \(g\) 获得的收益。如果它普遍成立，Runtime 实验大多只有寿命很短的产品价值。

另一种立场是**结构持续假设**：

\[
H_{\mathrm{persist}}:
\forall \theta\text{ with bounded resources},\;
\exists D_i\text{ that exhibits mismatch }M_i.
\]

对于任意有限模型、有限上下文和有限推理预算，开放任务空间中都存在某个区域，使六类失配之一重新出现。更强模型可以降低失配频率、严重程度，或者把失配边界推得更远，却不会消灭产生失配的结构维度。

六类失配位于世界到提交的不同站点：

```text
世界
→ 观测与表征
→ 信念形成与更新
→ 能力路由
→ 候选支持
→ 全局聚合
→ 目标评价
→ 验证提交
```

| 失配 | 结构问题 | 训练能够改善什么 | 训练单独无法保证什么 |
|---|---|---|---|
| 观测—表征 | 可行通道本可提供的决定性信息是否进入、保留、正确绑定并保持可用？ | 压缩、抽取、工具使用和基于先验的推断。 | 恢复所有可行通道中都不存在的信息；这种剩余差距是不可约信息限制，不是系统失配。 |
| 状态 | 固定可访问证据后，实际 belief 是否符合证据并支持正确行动排序？ | belief tracking、状态推断和不确定性保存。 | 在任意开放动态中始终保持证据忠实的信念更新；训练也不能消除不可约不确定性。 |
| 拟合边界 | 能力是否恰好在其真实适用域内被激活？ | 已知分布上的路由。 | 在开放分布漂移和新边界出现时永久保持校准。 |
| 支持 | 已部署搜索是否能到达、保留并识别高价值结构？ | 提高已知有用模式的概率质量。 | 在有限搜索和预算下，为所有未来稀有结构提供充分支持。 |
| 聚合 | 局部合理部分能否组合成全局价值？ | 更长推理、规划和回溯。 | 在任意长、强耦合、价值不可局部分解的任务上消除承诺风险。 |
| 规格 | 可访问目标是否等于经过授权的真实效用？ | 预测常见偏好和隐含规范。 | 知道未表达、正在变化或依赖权威授权的效用。 |

这个主张必须严格收边。它不是说每个具体失配实例都永远无法被训练解决。未来模型完全可以解决今天的 Benchmark、记忆今天的边界案例，或者把今天的 Audit 行为内化进权重。主张只是：解决一个固定实例，不等于从开放任务空间中消灭失败类别。

训练可以吸收治理**策略**，例如何时查询、验证、Patch 或升级；但它不能凭空创造缺失观测，不能把错误验证器变成真实 Oracle，不能让语言上下文获得外部系统的状态权威，不能替用户产生合法授权，也不能仅凭声明保证原子提交和回滚。无论产品把它们封装在外部 Scaffold 还是“模型原生 Runtime”里，这些治理**资源**和系统语义仍然存在。

## 5. 六类失配支持的受控实验纲领

六类失配不仅是失败分类，也直接定义了实验操纵、中介变量、终点指标和证伪条件。下面每类实验都应使用成对任务种子、隔离环境、重复试验、固定预算，以及版本化的模型/Harness 合同。

一个总的测量原则是：**任务侧结构剂量与系统侧失配必须分开操纵和报告。** 依赖耦合或低 `α_k` 是任务非局部性；状态后验弥散或高 `δ_amb` 是任务歧义度。它们只能说明系统承受了多大压力。聚合失配要由部署代理相对全局补全价值的排序错误或后悔衡量；状态失配要由实际 belief 相对证据支持 belief 的校准误差或信念条件决策后悔衡量。高任务剂量配合零系统后悔，是成功治理而不是“仍然严重失配”。

### 5.1 观测—表征失配：操纵信息通道，而不是只改答案 Prompt

**问题。** 补全或保留决定性变量后表现改善，究竟是因为可用信息增加，还是因为 Prompt 单纯变长？

**设计。** 构造表面完全相同、但某个隐藏变量会改变正确行动的成对任务。比较：（A）缺失或有损通道；（B）含决定性变量的通道；（C）等长度无关信息负对照；必要时再加入（D）变量存在但绑定到错误实体或时间戳。固定模型、动作接口、预算和验证器。

**测量。** 状态判别准确率、来源/绑定准确率、下游决策成功率、弃权质量、token 成本，以及从通道可用到正确行动的中介路径。

**证伪。** 如果相关信息与无关信息带来相同增益，或者 Agent 没有访问变量也能成功，就不能声称信息通道机制已经成立。

**诊断边界。** 只有当可行通道本可提供的决定性信息在可访问表征中缺失、退化、未绑定、陈旧或不可用时，才使用这一标签。信息已经可用但多个潜在状态仍成立，并不自动转成状态失配：只有系统在固定证据下错误塌缩、误排、遗忘或沿用过期信念并改变行动排序时，才使用状态失配；正确保留宽后验不是失败。

**迁移。** 跨模型代际提高损失严重度、时效要求、模态和上下文距离。真正可迁移的是通道条件和中介机制，而不是固定百分点。

### 5.2 状态失配：固定证据，隔离信念更新错误

**问题。** 在不增加观测信息的前提下，显式 belief surface 能否减少错误塌缩、误排、遗忘与过期信念造成的决策错误？

**设计。** 固定每个 episode 的观测与表征 `Z≤t`，交叉两个因素：信念更新（普通上下文续写 vs 显式假设—证据—概率/排序表）与行动策略（无条件单点行动 vs belief-conditioned 分支或风险有界行动）。加入要求更新、遗忘检查与状态转移的证据，但不改变两组可访问事实。另设独立实验测试可查询硬状态与类型化提交合同；前者改变通道，后者测试 SGAR 权威，不能作为状态原语的最小对。

**测量。** 相对证据支持信念的校准误差、误排率、证据遗忘率、陈旧 belief 率、belief-conditioned 决策后悔，以及系统是否正确保留不可约不确定性。SGAR 独立实验再测非法转移、虚假完成、回滚与提交一致性。

**证伪。** 如果显式 belief surface 在固定信息和预算后不能改善校准、更新或决策后悔，就不能声称修复了状态失配。若改进只在新增硬状态后出现，证据支持的是观测-表征修复，而不是固定 `Z` 的状态修复。

**诊断边界。** 若可行取得的权威信息未进入 `Z`，上游失败是观测—表征失配；若任何可行通道都不暴露真实状态，但系统正确维护后验并采取信念最优或风险有界行动，则没有状态失配；若 belief 正确但仍选择非法动作，更接近的机制目标是动作或提交治理。

**迁移。** 从玩具状态机扩展到文件、数据库、工单、日历和多 Agent 所有权。强模型会更少犯错，但 belief 与 authority 的区分仍可持续复验。

### 5.3 拟合边界失配：在边界网格上测量路由校准

**问题。** 能力失败是因为能力不存在，还是因为能力在错误体制下被激活或压制？

**设计。** 建立边界网格：明确域内、明确域外和渐进式近边界样本。比较无门控激活、学习路由器、证据条件化路由和类型化弃权/升级。固定底层 specialist，使实验研究路由而不是重新训练能力。

**测量。** 真/假激活率、selective risk、校准误差、非对称错误成本下的效用、覆盖率和 holdout 任务族上的边界漂移。

**证伪。** 如果 specialist 在目标域内本身就没有能力，路由干预不能获得功劳。Router 实验之前必须先做 Oracle capability test。

**诊断边界。** 拟合边界失配要求能力在 Oracle route 下能够在目标体制内成功。如果正确路由已经选中，高价值候选却仍很少出现，剩余瓶颈是支持而不是路由。

**迁移。** 在新任务族和新模型上重复。科学对象是触发证据、能力边界与错误成本之间的关系，而不是一个永久阈值。

### 5.4 支持失配：比较控制空间搜索与输出空间重采样

**问题。** 高价值结构没有出现，是因为模型无法表达，还是因为已部署搜索流程很少到达、保留或识别它？

**设计。** 在 token 和调用预算匹配下，比较直接生成、独立 best-of-\(N\)、批评后重生成，以及改变分解、表示、约束、候选拓扑或确定性算子的控制空间干预。加入 Oracle candidate 条件，检验正确候选一旦出现，验证器是否能够识别。

**测量。** 至少出现一个有效高价值结构的概率、首次覆盖时间、结构多样性、剪枝后的保留率、验证器 recall、找到的最佳效用和每 token 边际价值。

**证伪。** 如果 Oracle candidate 持续被拒绝，瓶颈可能是识别或规格，而不是支持；如果更多独立样本能在匹配成本下闭合差距，专用控制空间机制尚未证明其复杂度合理。

**诊断边界。** 支持失配是可达性或保留失败。如果所需局部结构稳定出现，却在组合时失败，主失败已经下移到聚合。

**迁移。** 改变稀有度、组合深度和搜索预算。预期 crossover 是关键：只有朴素有效支持足够低时，控制空间搜索才应显示最大价值。

### 5.5 聚合失配：操纵耦合强度与承诺面

**问题。** 当正确局部片段已经存在，什么运行时结构能保留它们，同时形成全局合法对象或轨迹？

**设计。** 交叉任务耦合度（独立到全局依赖）、编辑密度（稀疏到稠密）、交付接口（Patch vs Full Rewrite）和修复 horizon（局部 Step vs 完整 Stage replan）。当研究交付机制时，固定计划、源对象、验证器、模型和预算；当研究规划时，再单独操纵规划。加入确定性执行器和纯复制对照。

**测量。** 全局不变量满足率、未修改区域保留率、冲突率、错误传播深度、预算内严格成功率、恢复成本，以及 Patch/Rewrite、Step/Stage 的 crossover。

**证伪。** 稀疏修改中的 Patch 优势不证明 Patch 普遍更好。如果在正确计划和预算匹配后优势消失，早期结果很可能混入了规划或资源差异。仓库内的 [Patch vs Full Rewrite 受控实验](https://github.com/wxy2ab/against-llm-mediocrity/blob/main/docs/patch-vs-full-rewrite-controlled-experiment.zh-CN.md) 展示了如何用 Oracle plan、Copy 与独立预算对照收紧主张。

**诊断边界。** 聚合失配预设系统已经拥有可用的局部片段、约束或证据，但组合过程没有保留它们。如果这些片段从未进入候选集，上游瓶颈是支持；如果系统优化了错误的全局标准，则是规格。

**迁移。** 跨 artifact 类型、模型族和耦合尺度复验。即使经验效应变化，程序语义仍能保持结构不变量：标准 Patch 不会重新承诺未修改区域。

### 5.6 规格失配：操纵目标信息与授权权威

**问题。** Agent 失败是因为不会优化，还是因为可访问目标偏离了用户授权的真实效用？

**设计。** 构造同一 Prompt 同时兼容多个合理效用、且不同效用要求相反行动的任务。交叉目标条件（只有代理目标、显式偏好、反例增强规格）与权威条件（无权威、授权用户信号、强制人工 Gate）。在 episode 中加入目标漂移和可被投机的评分器。

**测量。** 授权效用 regret、代理/真实目标偏差、不安全提交率、升级 precision/recall、对偏好更新的响应，以及抵抗评价器漏洞的能力。

**证伪。** 如果“真实”效用仍由同一个模型 Judge 推断，实验就没有逃离规格失配。必须使用高保真人类、可执行或制度上经过授权的 Oracle。

**诊断边界。** 规格失配研究目标本身或其授权。如果经过授权的目标已经明确，而系统仍无法产生合格候选，当前瓶颈更可能是支持、聚合或能力。

**迁移。** 更换领域、利益相关者和授权结构。模型会越来越善于预测偏好，但当授权本身属于任务语义时，预测仍然不能代替授权。

## 6. 最小实验合同

可信的 Agent 实验必须公开足够信息，使别人能够重建干预、机会集合和结果权威。

### 6.1 先定义估计对象，再运行系统

设治理干预 \(g\) 相对基线 \(h_0\) 的效应为：

\[
\Delta_g(\theta,D,b)
=
\mathbb{E}[J\mid \theta,g,D,b]
-
\mathbb{E}[J\mid \theta,h_0,D,b].
\]

然后明确 claim ceiling：实验估计的是产品级总效应、机制中介效应、交互项、边界阈值，还是迁移效应？它们不能互相替代。

只有当处理组之间确实只在声明的操纵上不同，且终点测量不受 treatment-dependent bias 影响时，因果语言才成立。工具、机会、超时或评分中未记录的组间差异，即使在 p 值很小时也仍然是替代解释。

### 6.2 冻结可比性合同

版本化并公开：

- 模型标识、endpoint、解码设置和日期；
- 完整 Harness 与 Prompt 状态；
- 工具、权限、环境镜像、初始状态和网络策略；
- token、调用、wall-clock、金钱和重试预算；
- 任务抽样和 holdout 构造；
- 验证器代码、结果状态 Oracle 和评分器版本；
- 停止、超时、失败和排除规则。

看到结果后再改变其中一项，意味着开始了新实验，而不是做了一个无害实现调整。

### 6.3 优先使用成对、分块和全因子设计

在相同任务种子和初始状态上运行 treatment 与 control。按已知难度、领域和失配剂量分块；随机化顺序并隔离 trial。组件存在潜在交互时，使用全因子或部分因子设计，而不是一串互不相干的单次消融。复合 Agent 系统中，不含交互的主效应尤其危险。

### 6.4 重复随机试验，并建模层级结构

单次生成会低估不确定性。重复试验应分离任务族、任务、种子、模型采样和基础设施的方差。报告效应量与置信区间或可信区间，而不只给点估计。任务与运行嵌套时使用分层或混合效应模型，并对确认性多重比较做校正。

围绕最小重要效应预先进行功效或精度分析，并预定义超时、无效运行、Provider 错误和提前停止如何进入估计对象。反复查看结果并持续加跑直到显著，会破坏普通确认性区间的有效性，除非事先声明了序贯设计。

### 6.5 匹配预算与机会，而不只是 Prompt

两个 Prompt 相同，不代表 treatment 相同：一侧可能获得更多工具调用、更长 wall-clock、额外重试、更丰富动作空间或更强验证器。实验必须同时公开资源消耗和机会表面。无法严格匹配时，应估计预算—成功曲线，并在等成本或等风险条件下比较。

### 6.6 评价环境结果与轨迹

除了最终文本，还要记录最终环境状态、合法状态转移、验证 receipt、回滚行为、工具错误和轨迹。尽可能使用可执行或高保真评分器；模型 Judge 必须对独立权威做校准，并把评分器不确定性写入结论。

### 6.7 加入机制检查和负对照

Treatment 必须改变其声称的中介变量：更多观测应提高决定性变量的可访问性；状态治理应减少非法转移；路由应改善选择性校准；支持干预应提高目标覆盖；聚合控制应减少不变量违反；规格治理应降低授权效用 regret。无关信息、sham control、Oracle candidate、Copy 对照和故意陈旧状态，都能区分机制效应与通用 extra-compute 效应。

### 6.8 预注册证伪条件与最小效应

“只要是正差值”过于宽松。查看结果前应固定预期方向、最小实际重要效应、主终点、交互项和失败条件。保留零结果和反方向结果。一个干净合同下失败的预测是可累积知识；未记录的事后成功不是。

### 6.9 跨模型复验，但不要求效应百分点相同

迁移主张应分层：

1. **结构不变量：** 来自信息、程序、事务或权威语义；
2. **条件性机制预测：** 相同失配条件出现时应当复现；
3. **数值校准：** 效应量、成本、阈值和最优复杂度依赖具体模型与协议。

不应要求：

\[
\Delta_g(\theta_1,D,b)=\Delta_g(\theta_2,D,b).
\]

可累积的主张是：干预、前提、中介变量和证伪条件仍然可定义、可复验。每代模型都需要重新校准，而不是重新发明问题。

## 7. Agent 工程的分阶段研究路线

### 阶段 0：建立测量基础设施

版本化 Harness、隔离环境、捕获轨迹、暴露权威状态、标准化预算，并把评价器写成可执行对象。缺少这些基础，后续实验只会对不稳定系统给出精确数字。

### 阶段 1：建立诊断型微型 Benchmark

针对每类失配构造成对任务，并把任务压力与系统缺口正交化。观测损失、状态歧义、边界距离、支持稀有度、依赖耦合或目标歧义可以作为任务侧剂量；通道保真度、belief 更新器、能力 router、部署代理、搜索与评价器质量则作为系统侧因素。第一目标不是现实感，而是识别“什么任务压力击穿了什么系统组件”，不能仅因任务剂量高就给系统记作失配。

### 阶段 2：估计机制效应与交互效应

进行跨失配全因子实验，例如：观测 × 路由、状态权威 × 提交协议、支持搜索 × 验证器质量、依赖耦合 × 修复接口。复合失败很可能超加性出现，实验设计必须能够检测这种关系。

### 阶段 3：在开放任务上测试迁移

从合成探针迁移到编码、研究、数据、浏览器、运营和协作任务。保持 treatment contract 不变，只改变表面形式，并明确报告机制在哪些地方停止迁移。

### 阶段 4：进行跨模型纵向复验

保持任务族、环境快照和干预稳定，只更换模型，重新估计基线、处理效应、crossover 与最优启用策略。这会形成一张“模型 Scaling 如何移动失配边界”的经验地图。

### 阶段 5：在生产中验证决策策略

先完成离线识别，再做受保护 rollout，检验学到的启用规则能否提高用户效用、成本、延迟和尾部风险。生产反馈应生成新的 Regression Guard 和实验任务，而不是静默改写原 Benchmark。

这个研究计划的输出不是一个普遍最优 Agent，而是一组条件性工程规律：

```text
当状态歧义超过 c、存在可行权威查询且信息价值为正时，
提交前查询权威状态；否则按证据支持 belief 采取最优或风险有界行动。

当编辑密度低于 d 且计划已验证，
优先选择有边界的 Patch 交付。

当目标结构的有效支持很低，
先改变控制空间，再购买更多同质样本。

当目标授权缺失，
升级给权威来源，而不是优化猜测出来的代理目标。
```

## 8. 什么证据会反对本文主张

结构持续假设不能被保护在证据之外。如果在多样、开放任务族和预算匹配条件下反复出现以下结果，它就会被削弱：

- 最小 Runtime 在带失配剂量的探针上持续追平受治理 Runtime；
- Treatment 效应不随对应失配剂量上升；
- 干预实施后，声称的中介变量没有变化；
- 强模型不仅消灭固定失败，也不再在新生成任务上出现预测中的边界迁移；
- 即使前提和机制检查被保留，效应仍完全不能迁移；
- 在相关运行区间内，治理开销和新增失败始终压倒收益。

有限 Benchmark 仍然无法证明某个失败类别已经从所有开放任务空间中消失，但它足以证明某个分类没有用、机制定义错误，或者干预在经济上不值得。框架只有允许自己这样失败，才具有科学价值。

## 9. 结论

Agent 工程不可能通过收集更多不可分解的 Agent 分数变得可累积。只有当它能区分模型能力与能力机会、Harness 结构与组件命名、声称完成与权威提交、产品胜利与已识别机制时，它才开始成为科学工程。

当前前沿已经证明 Scaffold 选择、接口设计、环境波动、重复采样和组件交互都会实质改变结果。下一步应围绕稳定的失败结构组织受控实验。六类失配提供了这样的结构：它们说明价值在哪里损失、应该操纵什么变量、哪个中介量应当变化、哪个 Oracle 具有权威，以及实验如何被证伪。

因此，真正耐久的知识单元不是“在模型 Y 上，Harness X 提升了 8 个百分点”，而是：

> 在明确的结构条件下，一个受治理干预通过可观察的因果通道改变系统，并且其预算与风险边界已经被测量。

固定 Benchmark 会被解决，模型会变强，一部分外部 Scaffold 会被移入模型原生 Runtime。这些变化不会让受控实验过时。恰恰相反，只有受控实验能告诉 Agent 工程：究竟学到了什么，什么只是移动了边界，什么必须重新测量。

> **训练可以消灭旧问题，却不能消灭产生新问题的六类失配维度。**
> **模型升级移动失配边界；受控实验识别边界上的治理规律。**
